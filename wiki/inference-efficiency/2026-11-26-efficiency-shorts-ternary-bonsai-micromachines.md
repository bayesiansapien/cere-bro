# Efficiency shorts, 2026-11-26

- **Ternary Bonsai 2.5 27B (PrismML), now independently reported.** The Decoder reports a 54GB 27B agentic coding model squeezed to **5.9GB** by restricting every weight to three values ({-1, 0, +1} plus scales). Yesterday's wiki flagged a small-account post with the same 5.9GB figure (and 98.2% retention across 20 benchmarks) as a lead, not a citation. A named outlet now confirms the release and size; the retention number still has no linked eval. See [quantization](quantization.md).
- **Weight-space micromachines** ([blog](https://papail.io/papers/wsm/), [code](https://github.com/anadim/weight-space-micromachines)). Dimitris Papailiopoulos had Claude Code run a loop: run the model, read its failures, pick ones a small exact program could fix, compile that program into weights, bolt it onto the frozen model, keep it if scores rise. Implants stay off until needed, so the model is bit-identical otherwise. A calculator takes 4-5 digit multiplication from near zero to 100%; a small vision implant lets Qwen2.5-0.5B do math on handwritten MNIST digits; a mistake detector forces a re-think (GSM8K 52% to 56%). 14 implants take Qwen3-0.6B IFEval from 58% to 72%. RL with implants on beats plain RL (GSM8K 80% vs 68%, BBH 60% vs 54%, IFEval 48% vs 46%). It closes a loop opened by the 2023 Looped Transformers as Programmable Computers paper and extends the 11-25 WeightCode / Self-WSP weight-space-programming results. Labelled a draft by the author.
- **Microsoft AI's Rocket RL infrastructure** ([PDF](https://microsoft.ai/pdf/RL-Infrastructure-at-Microsoft-AI.pdf)). RL from its own MAI Base 2 without third-party distillation, on thousands of GPUs for weeks. Three design choices: over-provision the trainer so fresh rollouts are consumed before they go stale (utilization is the wrong target, the same point ComputeWise made on 11-25); align inference and trainer to **bitwise-identical token probabilities** (summation order otherwise changes them); recover failed components independently (trainer restart about 5 minutes while rollouts continue). Via a widely shared Chinese-language read-through; the PDF body was not machine-readable in capture.
- **vLLM Singapore meetup** ([PyTorch blog](https://pytorch.org/blog/)): Inferact, NVIDIA and Alibaba Cloud on pipeline-parallel prefill optimizations, agent-written kernels, vLLM-Omni for real-time multimodal world models, RL training, and the road to Vera Rubin.
- **G-MTP is recirculating** (first covered [11-22](2026-11-22-g-mtp-gemma-4-multi-token-drafter.md)): Google's 4-layer drafter that reads the main model's KV cache and final activations, so it skips prefill; Gemma 4 31B 3.14x vs 2.60x DFlash and 2.07x EAGLE-3. New emphasis in the reposts: fine-tuning the main model alone cut drafter efficiency 36.3%, so a drafter must be re-distilled with every fine-tune.
- **Trap-proof retrieval with an 11-dimensional projection** ([2611.31442](https://arxiv.org/abs/2611.31442)), cross-source confirmed (HF + Kurate cs.LG #4). Raw E5-Large-v2 cosine puts a meaning-reversed near-copy of the answer document in the top-10 for 82-100% of queries. A small learned projection (1024 to 11 or 32 dims) drives that to zero across legal, medical, patent and finance domains up to 100K documents while keeping the right paraphrase for 93-99%. A spectral-graph accelerator serves it at 2-4 ms per query, and the per-tenant index is about 90x smaller. Kurate's weekly tournament had not scored this week's entries (every entry sits at the default score), so the Kurate side is a listing signal, not a quality ranking.
- **Kurate-listed compression papers to track:** Selection Policies for Equal-Byte Mixed-Precision Quantization of Small Language Models, and GreenDynaMix (thermal-aware dynamic mixed-precision MoE inference). Not yet on HuggingFace.
