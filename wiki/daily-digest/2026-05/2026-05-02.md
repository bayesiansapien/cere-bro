### Step-level Optimization for Efficient Computer-Use Agents

> First concrete mechanism for trajectory-aware routing in GUI agents: a small policy runs by default, two learned monitors (Stuck and Milestone) escalate to the frontier model only at high-risk junctures. No retraining, plugs on top of existing agents.

**Source:** HuggingFace Daily Papers
**Links:** [Paper](https://arxiv.org/abs/2604.27151) · [Wiki](../../ai-routing/2026-05-02-step-level-optimization-computer-use-agents.md)
**Tier:** 1 — agent trajectory routing

```
GUI interaction sequence:
  Step 1: Routine                         → small model ✓
  Step 2: Routine                         → small model ✓
  Step 3: [Stuck Monitor fires: looping]  → escalate frontier
  Step 4: Routine                         → small model ✓
  Step 5: [Milestone Monitor: verify]     → escalate frontier
  Step 6: Routine                         → small model ✓

Two failure patterns the cascade catches:
  (1) Progress stalls    — agent loops without advancing
  (2) Silent semantic drift — agent does plausible but objective-divergent actions

Result: frontier-model invocation only at high-risk junctures, not every step.
```

The paper's core observation is straightforward but had not been operationalized: GUI interaction sequences are heterogeneous — most steps are routine and a small model handles them fine; errors cluster at specific high-risk junctures. The two failure patterns identified — *progress stalls* (agent loops or fails to advance) and *silent semantic drift* (agent takes plausible-looking actions after diverging from the actual objective) — are exactly the patterns prior agent-eval work (GTA-2 04-20, Claw-Eval-Live 05-01, InteractWeb-Bench 05-01) had been measuring as failure modes without naming. This paper names them and routes around them.

The mechanism is an event-driven cascade with two *learned* monitors (not hardcoded heuristics). The Stuck Monitor reads reasoning-action sequences and detects degraded progress. The Milestone Monitor identifies semantically significant checkpoints that warrant verification. When either fires, the system escalates to the frontier model for that step only, then drops back to the small policy. The framework is modular and plugs on top of existing agents without architectural changes or model retraining.

This **directly answers the 05-01 Worth Watching prediction** — "Trajectory-aware multi-model router crossing 70% on Claw-Eval-Live (90 days)." The paper builds exactly that mechanism inside a computer-use agent, with one missing piece: it has not been evaluated on Claw-Eval-Live's task-family discrimination signal. That is now the cleanest single follow-up experiment in agent routing. If the cascade crosses 70% (the threshold no single model reaches), it resolves the question definitively.

The pairing with **Ken Huang Ch 14 (today)** matters more than either paper alone. Ch 14 documents the provider/tier routing axis inside production harnesses — fallback chains, complexity-keyword cheap routing, API-mode auto-detection, mid-session model switching. Step-level Optimization is the trajectory axis. *Stack them and you have a two-axis routing surface*: which provider × which tier × which model per step, with monitor-driven step-level decisions on top of harness-driven provider decisions. Neither paper is sufficient alone; together they describe a complete, deployable trajectory-aware routing system.

**Why it matters:** Agent failure rates >30% on multi-step tasks (six-benchmark pattern from 05-01) have been the open lever. Step-level Optimization is the first credible mechanism, and the literature now has a concrete proposal to evaluate.

**Research angle:** Three open follow-ups. (1) Claw-Eval-Live evaluation — whether the cascade crosses 70% on task-family discrimination. (2) Monitor degradation over long horizons — Stuck Monitor reads reasoning-action sequences; how does its signal hold up over 50+ step tasks where context grows? (3) KV-cache composition — when the frontier model is escalated mid-trajectory, reusing prefix KV cache from the small-model steps is the obvious efficiency win; the paper does not address it.

### Ken Huang Chapter 14 — Model Routing and Provider Abstraction (Claude Code vs Hermes)

> The most concrete public read of production routing engineering. Claude Code: compile-time provider abstraction with one fallback model, signature-stripping for cross-provider retry, plan-mode and >200K-context overrides. Hermes: runtime API-mode detection, ordered fallback chains, live OpenRouter context-window discovery cached 1 h, `switch_model` mid-session, conservative cheap-model routing keyed on message complexity.

**Source:** Ken Huang / Agentic AI Substack
**Links:** [Post](https://kenhuangus.substack.com/p/chapter-14-model-routing-and-provider) · [Wiki](../../ai-routing/2026-05-01-ken-huang-ch14-routing-provider-abstraction.md)
**Tier:** 1 — agent harness routing

```
Claude Code (compile-time, opinionated, simple):
  startup → resolve provider/model/fallback ONCE
  rules → plan_mode → cheaper, >200K context → bigger
  on failure → STRIP THINKING SIGNATURES, inject synthetic tool_results,
                retry once with single fallback model

Hermes (runtime, first-class, dynamic):
  __init__ → infer api_mode from URL+provider, build fallback chain (list),
              prewarm OpenRouter metadata in background thread
  per-turn → choose_cheap_model_route(message, cfg)
              len<160? <28 words? no `, no URLs, no complexity keyword?
              → cheap model, else primary
  on failure → _try_activate_fallback(): advance index, rebuild client, retry
  mid-session → switch_model() rebuilds client + cache eligibility +
                  compressor window + invalidates cached system prompt
```

This is the fourth chapter in Ken Huang's Claude-Code-vs-Hermes series (Ch 8 memory, Ch 12 skills, Ch 13 MCP, now Ch 14 routing) and the cleanest cross-harness routing comparison published anywhere. The two harnesses make opposite choices on the same problem — and both are internally coherent. Claude Code resolves provider, model, and fallback at compile time, then runs simple priority-chain functions: `getMainLoopModel` returns the base; `getRuntimeMainLoopModel` applies plan-mode and >200K-context overrides; `getAgentModel` resolves subagent overrides. Hermes treats every routing decision as runtime-resolved: API mode (`anthropic_messages` / `chat_completions` / `codex_responses`) inferred from URL and provider name; ordered fallback chains advanced one entry at a time; OpenRouter model metadata pulled live and cached for an hour with a 128K → 64K → … → 8K probe ladder for unknown endpoints; `switch_model` mid-session that rebuilds the API client, re-evaluates prompt-cache eligibility, updates the context-compressor window, and invalidates the cached system prompt.

The single best operational detail is **signature stripping on fallback**. Extended thinking produces cryptographically signed blocks that are model-specific. If you replay a conversation containing those blocks to a different model, the API rejects it. Claude Code automatically strips signatures before retrying with the fallback. Most hand-rolled fallback systems miss this and produce a cascade of malformed-request errors. The paper's contribution is documenting it — this engineering detail is *not* in the routing literature; it is in the harness.

The cheap-model routing in Hermes is conservative by design: any complexity signal (long message, multi-line, code block, URL, keyword from a list including "debug", "implement", "analyze", "docker") sends the query to the primary model. The trade-off is named explicitly: *false-negative cost is cents (a simple query went to the expensive model); false-positive cost is analyst time (a complex investigation went to the cheap model and missed something).* This is the production reading of the routing literature's "asymmetric cost" assumption — and it shows the field has been right about the asymmetry but vague about the mechanism.

**Why it matters:** Production routing engineering has not been documented at this level of detail before. Anything the routing literature publishes from now on is comparable to two specific public reference architectures.

**Research angle (Tier 1):** Three open threads. (1) **Surrogate routing inside `choose_cheap_model_route`.** TRACER (04-17) is the obvious upgrade — train a surrogate on session traces, gate on parity rather than keyword heuristics. (2) **Cache-aware routing.** Switch invalidates cache; SemiAnalysis (05-01) showed cache drives Opus blended price to $0.99/MTok. A router that biases toward within-cache routing until decay is the obvious efficiency move. Nobody has published. (3) **Composition with Step-level Optimization (today).** The two-axis routing surface — provider/tier × trajectory step — has neither a unified formalization nor an end-to-end evaluation.

### Compliance vs Sensibility — Reasoning Controllability in LLMs

> Instruct an LLM to use a reasoning pattern that contradicts what the task naturally calls for: it ignores the instruction and uses the task-appropriate pattern, with high accuracy either way. Reasoning types are *linearly encoded* in middle-to-late layers; mechanistic intervention raises instruction-following compliance by 29%. The operationally relevant variable is steerable.

**Source:** HuggingFace Daily Papers
**Links:** [Paper](https://arxiv.org/abs/2604.27251) · [Wiki](../../llms-foundation-models/2026-05-02-compliance-vs-sensibility-reasoning-controllability.md)
**Tier:** 2 — mechanistic interp / reasoning controllability (Tier 1 intersection: routing on reasoning mode)

```
Standard inference:
  prompt: "Solve this by induction"
  task:   actually deductive
  →  model uses deduction (parametric prior wins)
     answer correct, instruction ignored

Mechanistic intervention:
  probe finds linear direction r_induction in mid-late residual stream
  add α · r_induction during forward pass
  →  compliance with "use induction" up by 29%
     answer still correct
```

The setup is sharp. Define a "reasoning conflict" as a prompt where the user mandates one logical pattern (induction, deduction, abduction) but the task naturally calls for a different one. Measure what the model does. The finding: models prefer the task-appropriate pattern, ignore the instruction, and still get the right answer with high accuracy. That settles a quiet question in the chain-of-thought literature: *the prompt-driven reasoning pattern is largely cosmetic.* The actual reasoning the model performs is internalized parametric — and it gets stronger with model size, so larger models are *less* compliant with conflicting instructions.

The interpretability result is the load-bearing one. Standard linear probes on residual-stream activations recover induction / deduction / abduction directions in middle-to-late layers. Mechanistic intervention — adding the encoded direction to the forward pass — raises the model's compliance with the instructed pattern by up to 29%, while keeping accuracy. This means reasoning mode is a *steerable* property of the model, addressable at inference time without retraining.

The operational implication generalizes well beyond reasoning mode. **The wiki has now seen four operational properties shown to live in low-dimensional, locatable, intervention-accessible substructure.** TIP (04-16) localized distillation signal to <10% of tokens. LenVM (05-01) put length in token-level value heads. Compliance vs Sensibility (today) localizes reasoning mode to linear directions. Safety Drift (today, paired) shows safety is a vector across benchmarks, not a scalar. Four papers in three weeks: *the operationally relevant variables in an LLM are sparse, locatable, and addressable.* The next claim — *and so most of model behavior is steerable in inference* — is no longer a stretch.

**Why it matters:** If reasoning mode is a steerable direction, a router can pick *both* the model and the activation direction at inference. The control surface is bigger than the literature treats it.

**Research angle:** Three threads. (1) **Composing steering with explicit CoT.** Does forced induction via activation steering cooperate with "reason inductively" CoT, or do they conflict? (2) **Direction stability under fine-tuning.** Safety Drift (today) shows fine-tuning produces heterogeneous safety regressions; do reasoning-mode directions also drift? If yes, steering recipes need re-calibration per checkpoint. (3) **Refusal/compliance directions.** Reasoning-mode is one operational variable; refusal is another. The mechanism is plausibly the same.

### Safety Drift After Fine-Tuning — Evidence from High-Stakes Domains

> 100 fine-tuned models — including production medical and legal systems — show large *heterogeneous, often contradictory* safety changes after benign domain adaptation. Same model improves on some safety benchmarks while regressing on others. Base-model safety scores do not predict deployed-system safety. The accountability framework currently in use is empirically insufficient for high-stakes deployment.

**Source:** HuggingFace Daily Papers
**Links:** [Paper](https://arxiv.org/abs/2604.24902) · [Wiki](../../llms-foundation-models/2026-05-02-safety-drift-fine-tuning-high-stakes.md)
**Tier:** 2 — safety / evaluation

```
Base model               Fine-tuned model
safety profile (scalar)  safety profile (vector across benchmarks, mixed-sign)

Benign domain data
   ↓
- Shifts refusal thresholds (often downward in domain)
- Reweights internalized safety circuits
- Erodes calibration on out-of-domain risk classes
- Strengthens calibration on in-domain risk classes
   ↓
Net effect = heterogeneous, benchmark-dependent, mixed-sign
```

The empirical setup is the strongest part: 100 fine-tuned models, including deployed medical and legal LLMs. The findings: improvements on some safety benchmarks, regressions on others, *in the same model*. Two safety benchmarks measuring nominally the same thing disagree on direction. Base-model safety scores do not transfer to the fine-tuned descendant. The conclusion the authors land on — that current evaluation and accountability practices fail in high-stakes domains — is the obvious one, but the deeper claim is that *safety is not a scalar property of a model; it is a profile, and the profile is benchmark-dependent.*

The same-day pairing with Compliance vs Sensibility is structural. Both papers say the same thing about LLM internals from opposite sides: operationally relevant properties are vectors, not scalars. CvS shows reasoning mode is a vector (linear direction). Safety Drift shows safety is a vector (benchmark profile). The scalar reductions in current practice are misleading.

The composition with **FlashRT (today)** is the most actionable. FlashRT lowers optimization-based red-teaming cost 2–7×. Safety Drift identifies 100 fine-tuned models whose safety profile is unknown after adaptation. *Automated FlashRT-driven red-teaming of every fine-tuned model is now operationally feasible* — that is the obvious next paper. Run FlashRT against the 100 Safety-Drift models and report disclosure-graded findings on production medical and legal systems.

**Why it matters:** The Pentagon procurement framework (also today) and the medical/legal deployment regime both rely on base-model safety scores. The base-fine-tune transfer assumption is now empirically broken in 100-model evidence.

**Research angle:** (1) **Predictive metric for safety drift.** Given (base, fine-tune dataset), forecast the safety-profile delta. (2) **Steering as remedy.** If safety, like reasoning mode, is encoded in low-dim directions, post-fine-tune steering could cheaply restore base-model safety. (3) **Benchmark-of-benchmarks.** Two safety benchmarks measuring the same construct disagree systematically; the meta-evaluation problem needs a structural answer.

### FlashRT — Computationally and Memory Efficient Red-Teaming for Long-Context LLMs

> First framework to reduce compute and memory for optimization-based red-teaming attacks on long-context LLMs. 2–7× speedup, 2–4× lower GPU memory. Concrete: 32K-token attack run drops from 1 hour to <10 minutes and from 264.1 GB → 65.7 GB. Generalizes across nanoGCG, TAP, AutoDAN. The same long-context iterative-gradient primitive applies to RL post-training rollouts.

**Source:** HuggingFace Daily Papers
**Links:** [Paper](https://arxiv.org/abs/2604.28157) · [Wiki](../../inference-efficiency/2026-05-02-flashrt-efficient-red-teaming.md)
**Tier:** 1 intersection — long-context iterative-gradient efficiency

```
Iterative-gradient cost on long context:
  forward over 32K tokens → loss → backward over 32K tokens → repeat
  Most prefix tokens unchanged across iterations
  → naive memory cost is O(n_iter · n_tokens · model_size)

FlashRT structural moves:
  - Memory-efficient gradient accumulation across token chunks
  - Priority-aware long-context attention reuse (most prefix is reusable)
  - Operation reordering to hold less in fp16/bf16 activation memory at once

Result on nanoGCG @ 32K:
  GPU memory: 264.1 GB → 65.7 GB  (one-node feasible, was multi-node)
  Wall time:   1 hr     → <10 min
```

The framing is red-teaming, but the structural object is generic. Optimization-based red-teaming runs many forward/backward passes over a long shared context — the prefix is fixed, the optimization variable is small, only the variable's gradient needs to flow back through the full context. This same cost structure shows up in (1) long-context RL fine-tuning rollouts, (2) test-time search where many branches share a long prefix, (3) iterative refinement / planning over a long shared workspace. **The FlashRT efficiency primitives are generic for any long-context iterative-gradient workload.**

The concrete numbers matter for democratization. nanoGCG at 32K context dropped from a 1-hour, 264 GB run to <10 minutes and 65.7 GB. That is the difference between "academic researchers can run this" and "academic researchers cannot run this." The paper explicitly notes the compute barrier as motivation. It shifts the equilibrium of who can do high-quality optimization-based attack research — and by symmetry, who can do high-quality optimization-based defense research.

The composition with same-day **Anthropic Claude Security launch (05-01)** and **GPT-5.5 = Mythos cyber eval (05-01)** is the third leg of the cyber-equilibrium triangle. GPT-5.5 makes Mythos-tier offensive capability GA. FlashRT lowers attack tooling cost. Claude Security ships the defender productization. *Three same-week vectors, all moving the equilibrium.* Whichever side improves fastest sets the new floor.

**Why it matters:** Long-context iterative-gradient cost has been the limiting factor for both red-teaming research and RL post-training rollouts. A 2–7× speedup with 2–4× memory cut is a generational step.

**Research angle (Tier 1):** Three concrete next moves. (1) **Apply to RL post-training rollouts.** First paper to use FlashRT-style efficiency for 32K-context RL rollouts resets the long-context-RL cost baseline. (2) **Compose with NeMo-RL speculative decoding (04-30).** Forward-path speedup × backward-path speedup should multiply. (3) **Defender-side: certified-defense training / adversarial fine-tuning** uses the same compute structure — applying FlashRT here is the immediate defender response to attacker tooling improvements.

### Nemotron 3 Nano Omni — NVIDIA's Open 30B Audio-Native Multimodal Model

**Source:** HuggingFace Daily Papers
**Links:** [Paper](https://arxiv.org/abs/2604.24954) · [Wiki](../../multimodal/2026-05-02-nemotron-3-nano-omni.md)
**Tier:** 2 — multimodal foundation model (Tier 1 intersection: multimodal token reduction)

The Tier-1 intersection here is the *multimodal token-reduction* technique, which is the same primitive multimodal routing systems need: given a vision/audio input, decide which tokens are load-bearing and skip the rest. Two threads converge — multimodal routing (which tokens to send to which model) and compression (how many tokens to send at all). NVIDIA shipping this with open weights gives the open-source community a working reference for the technique at 30B scale.

The SemiAnalysis (05-01) thesis that "open won't compete down closed model pricing for frontier knowledge work" survives, but the qualifier "frontier knowledge work" is shrinking.

**Why it matters:** Open audio-native multimodal at 30B with FP4 weights is the new accessible ceiling. Pair with multimodal routing research and you have the open stack to test trajectory routing on multimodal agents.

**Research angle:** The token-reduction recipe is the single most important detail not in the abstract — whether reduction is learned per-modality, query-conditional, or static determines whether it is useful as a routing primitive. **Routing across three axes is now legible.** The 04-17 wiki note from TRACER framed query-level routing. 04-20 GTA-2 framed harness-over-model as the bottleneck. 05-01 Claw-Eval-Live framed trajectory-level routing as the open lever. Today's pair — Step-level Optimization (trajectory) plus Ken Huang Ch 14 (provider/tier) — fills in the two axes the literature was missing public artifacts for. *The composition problem — provider × tier × step in one agent — is now the cleanest architectural research question in agent routing.* Whoever publishes the first system that does all three in one stack and reports a Claw-Eval-Live number resets the agent-routing baseline.

**Operational properties are vector-valued.** TIP (04-16) showed distillation signal lives in <10% of tokens. LenVM (05-01) showed length lives in token-level value heads. Compliance vs Sensibility (today) localizes reasoning mode to linear directions in middle-to-late layers, with a 29% compliance boost from intervention. Four papers, three weeks: *the operationally relevant variables in an LLM are sparse, locatable, and intervention-accessible.* The next paper is the obvious one — *and so most of model behavior is a steerable manifold, not a black box.* The control-surface implication for routing: a router can pick *both* the model and the activation direction at inference. The reasoning-mode routing primitive does not exist yet.

The 90-day question is whether attack-tooling improvements outpace defender productization — the answer is measurable from public AISI / METR / Apollo evals.

**AI sovereignty became bilateral and structural in one day.** Pentagon excluded Anthropic from the AI-first contract for refusing a usage clause. China is requiring domestic registration of AI startups (Moonshot, StepFun considering dissolving offshore structures). Both moves are structural — corporate-form-level, not advisory. *Capability ranking no longer predicts deployment surface; procurement and registration policy do.* The wiki's research → industry pipeline now needs a third middle layer: research → procurement-compliance → deployment.
