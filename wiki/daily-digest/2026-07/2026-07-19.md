## Deep Dives

### Requential Coding: Model Compression with Self-Generated Training Data

> Most compression methods need a teacher model or original training data. Requential Coding generates its own training data, then uses it to compress the model. The data is free.

**Source:** Kurate cs.LG #7 (ai_rating=8.5/10)
**Links:** [arXiv](https://arxiv.org/abs/2607.11883)

**What is it about?**
Requential Coding is a model compression method that generates its own training data rather than relying on a teacher model or access to the original training set. The model generates synthetic data, then trains a compressed version on that data. The process is iterative: the compressed model generates new data, which is used to further compress it. This self-reinforcing loop pushes the limits of what compression can achieve without external data.

**What problem does it solve?**
Most model compression methods (distillation, pruning, quantization) require either a teacher model (which is expensive to run) or access to the original training data (which is often proprietary). Requential Coding removes both dependencies. The model compresses itself using only its own generated data. This is especially relevant for compressing models whose original training data is not public.

**What is the core novelty?**
The self-generated data loop. Standard compression methods are one-shot: compress once, done. Requential Coding iterates: the compressed model generates new training data, which is then used to compress it further. Each iteration produces better data and a better compressed model. The authors show this self-reinforcing loop achieves better compression than teacher-based methods at the same budget.

**Key takeaways**
- Model compression without a teacher and without original training data: self-generated data only.
- Iterative self-reinforcing loop: compressed model generates data, uses it to compress further.
- From the same NYU group (Andrew Gordon Wilson, Marc Finzi) that produced Diffeomorphic Optimization (Kurate cs.LG #19, also on today's board).
- Directly relevant to the wiki's compression thread: this is a new axis (data-free compression) alongside quantization, pruning, and distillation.

**Gaps in the study**
The paper is new (July 13, 2026) and hasn't been evaluated against the full suite of compression methods. The scaling behavior (does the benefit increase with model size?) is not characterized. The self-generated data quality is the bottleneck: if the model generates poor data, the compression loop degrades rather than improves.

**Industrial implication**
If Requential Coding works at scale, it changes the economics of model deployment. Any organization with a large model can compress it without access to the original training data. This is especially relevant for enterprises that fine-tune models on proprietary data and want to deploy compressed versions without sharing the data with a third-party compression service. The self-generated data loop also means the compression cost scales with the number of iterations, not the size of the original dataset.

### Statistically Undetectable Backdoors in Deep Neural Networks

> Bogdanov, Rosen, and Vafa prove that backdoors can be made provably undetectable by any statistical test. The attacker can embed a trigger that is indistinguishable from random noise until activated.

**Source:** Kurate cs.LG #11 (ai_rating=7.8/10)
**Links:** [arXiv](https://arxiv.org/abs/2607.09532)

**What is it about?**
The paper proves a theoretical result: backdoors in neural networks can be constructed to be statistically undetectable. Any test that tries to distinguish a backdoored model from a clean one will fail, because the backdoor is designed to look like random noise. The trigger is embedded in a way that is indistinguishable from the natural variation in model weights. The paper is a theoretical contribution, not an attack demonstration, but the implication is clear: current backdoor detection methods have a fundamental blind spot.

**Key takeaways**
- Provably undetectable backdoors: the attacker can embed a trigger that no statistical test can find.
- The construction is theoretical, but the proof is general: any detection method that relies on statistical properties of the weights or activations can be evaded.
- This is a companion result to the anthropic J-space safety finding (July 7): if backdoors are undetectable in weights, the only defense is runtime monitoring of the model's internal workspace.

**Gaps**
The construction is theoretical. The paper does not demonstrate a practical attack, only that one exists in principle. The trigger size and activation conditions are not characterized for real-world models.

## Global View

**The open-source parity narrative is now a consensus, not a prediction.** Three independent data points this week: tinygrad says Kimi K3 is Fable tier and GLM-5.2 is Opus tier. Alibaba admits it has no monetization plan for Qwen despite it being competitive. Scobleizer, who has been covering AI since 2016, says "in four years we won't care about models." The LongCat 2.0 parity claim from July 8 (matched GPT-5.5 at zero marginal cost) was the first crack. The Kimi K3 claim is the second. The pattern: open-weight models from Chinese labs are now competing at every tier of the capability stack, and nobody has a plan for how to make money from them. The July 8 digest predicted this: "the economic advantage of proprietary models is eroding." Three weeks later, the evidence is stronger, and the timeline is compressing.

**The J-space thread is moving from theory to practice.** The July 7 Anthropic paper defined J-space as a theoretical construct. Today, eliebakouch is applying it to real code models (Laguna XS.2) and finding that optimizer choice and training data shift the workspace. The practical finding: code-specific training produces a code-specific workspace that is very different from the general-language workspace. This is the first empirical evidence that J-space is not a fixed property of the architecture. It is shaped by what the model was trained on and how it was trained. The implication for safety: a model fine-tuned on code may have a different internal workspace than a model fine-tuned on general text, and the same J-space auditing methods may need to be recalibrated per domain.
