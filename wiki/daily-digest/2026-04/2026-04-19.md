## TL;DR

- **VGF** — Behavior-regularized RL recast as optimal transport: no explicit policy, no reparameterization, SOTA on offline RL and LLM tasks; transport budget controls KL implicitly

## The Big Picture

RL is the organizing theme of this week, but not in the familiar RLHF sense. VGF doesn't train a policy at all — it treats "finding the optimal policy" as a question of moving probability mass from where the reference model lives to where the value function says it should live. That's optimal transport, not policy gradient. The implications are practical: no reparameterization, no value network, no log-probability gradient — just gradient flow on particles. And the test-time dimension (run more transport steps for better outputs) is a cleaner version of what inference-time scaling has been trying to do with majority voting. AIMO 3 showed that prompt diversity doesn't close the pass@20 gap. VGF suggests that *targeted particle refinement* might.

Meanwhile, RL is spreading into domains where it was previously impractical. UniDoc-RL applies GRPO to visual RAG — the agent doesn't just retrieve, it actively navigates documents, picks the right images, and crops the relevant regions, getting dense rewards at each step. This is qualitatively different from the retrieve-then-generate pipeline that most RAG systems use. The key enabling factor is the dense reward scheme: instead of one end-task reward that's hard to credit-assign, each action level gets its own signal. This is exactly the sparse-reward problem that hampered early RL for language tasks, now solved by hierarchical action decomposition.

The TRACER paper, now available in its full form, crystallizes the production routing opportunity. Every LLM API call creates a labeled training example for free. TRACER harvests those logs, trains a lightweight surrogate, and governs deployment with a parity gate that only promotes the surrogate when it agrees with the LLM at threshold α. On a 150-class benchmark, the surrogate fully replaced the LLM. On a task where the embedding space can't support separation, the parity gate correctly refused to deploy. That's the property you want: a system that knows what it doesn't know.

### VGF: RL Without a Policy

> The math says: finding the optimal policy is equivalent to moving probability mass from reference to optimal. So why are we parameterizing a policy at all?

**Source:** HuggingFace Daily Papers  
**Links:** [Paper](https://arxiv.org/abs/2604.14265) · [Wiki](../../llms-foundation-models/2026-04-19-vgf-value-gradient-flow-rl.md)  
**Tier:** 1 — RL for LLMs / Training Efficiency

```
Standard RLHF/GRPO:
  Reference model ──► parameterized policy π_θ ──► KL penalty keeps π_θ close to reference
       (explicit: need reparameterization trick, log-prob gradients, value network)

VGF:
  Reference model ──► sample particles ──► move particles via value gradients
       transport budget controls distance from reference (implicit KL)
       more steps at test time = better quality (adaptive scaling)
```

Standard behavior-regularized RL (RLHF, PPO, GRPO) works by learning a parameterized policy and penalizing KL divergence from the reference model. The math is messy: you need reparameterization to backpropagate through discrete token sampling, the KL term is explicit and tuned by a coefficient β, and you need a value network to estimate returns. All of this breaks or gets expensive at the scale of large LLMs.

VGF reformulates the problem from scratch. The insight: behavior-regularized RL is equivalent to finding an optimal transport (OT) map from the reference distribution to the value-optimal distribution. You don't need to parameterize that map as a neural policy. You can solve it directly by gradient flow — initialize particles from the reference model (sample some completions), then iteratively move each particle in the direction of the value gradient. Stop when the transport budget is exhausted. The budget controls how far particles travel, which implicitly controls KL divergence from reference. No explicit β, no value network, no reparameterization.

The test-time compute dimension is the most interesting implication. Standard inference-time scaling samples more candidates and picks the best one (majority vote, pass@k). That requires a verifier and hits a ceiling when capability gaps dominate (AIMO 3). VGF's alternative: take one candidate and refine it through more transport steps. The result is directed improvement of a single output rather than wider sampling of a fixed distribution. Whether this generalizes to complex open-ended reasoning remains to be tested, but the mathematical grounding is cleaner than "just sample more."

**Why it matters:** VGF could eliminate the reparameterization bottleneck that makes RL hard to scale on discrete sequences. If it generalizes, this is a new training paradigm for large reasoning models — not just an optimization trick.

**Research angle:** The critical open question is whether value gradients on particles are stable and informative enough for complex reasoning tasks (math, code), not just offline RL benchmarks. Also: does the transport budget correspond meaningfully to the inference compute budget? If yes, VGF gives a principled way to trade inference compute for quality — which is the core promise of test-time scaling.

### TRACER: Your Production Logs Are a Free Training Set

> Every LLM API call produces a labeled example. TRACER collects them, trains a surrogate, and lets you define exactly how much quality you're willing to trade for cost.

**Source:** HuggingFace Daily Papers  
**Links:** [Paper](https://arxiv.org/abs/2604.14531) · [Wiki](../../ai-routing/2026-04-17-tracer-llm-routing.md)  
**Tier:** 1 — LLM Routing

```
Production traffic
      │
      ▼
  LLM endpoint ──logs──► labeled (input, output) pairs
                               │
                         TRACER trains surrogate
                               │
              ┌────────────────┴────────────────┐
              │         parity gate: α           │
              │  surrogate ≡ LLM on α% of tasks  │
              └────────────────┬────────────────┘
           agreement > α ──► serve surrogate (near-zero cost)
           agreement < α ──► defer to LLM (full cost)
```

TRACER's core observation is that LLM classification endpoints are already producing labeled data in production. Every call is a (input, predicted_class) pair. A lightweight surrogate trained on those pairs can absorb a significant fraction of future traffic at near-zero cost — the only question is governance: when is the surrogate reliable enough to deploy?

The parity gate answers that question with a user-specified threshold α. The surrogate goes live only for inputs where its predicted label agrees with the LLM's predicted label at rate ≥ α, estimated via a held-out validation set that grows as production logs accumulate. Critically, the gate is dynamic — as more data arrives, the surrogate's coverage naturally expands on easy subregions and stays gated on hard ones. TRACER also generates interpretability artifacts describing what the surrogate handles vs. where it plateaus.

The benchmark results are striking in both directions. On a 150-class intent recognition task, the surrogate fully replaced the LLM — 100% coverage, maintained quality. On a natural language inference task, the parity gate correctly refused deployment because the embedding space couldn't support reliable class separation. The system knows what it can't do.

**Why it matters:** Production-grade LLM routing has been a "nice to have" for cost optimization. TRACER makes it a standard practice: every LLM endpoint can have a surrogate that learns from its own traffic, governed by a principled quality gate. The open-source release means this is immediately deployable.

**Research angle:** The parity gate assumes the surrogate's agreement with the LLM on a validation set predicts its agreement on future traffic. This is a distribution shift assumption. The key open question: how does the gate behave under covariate shift (when user behavior changes)? And can the surrogate be replaced with a distilled model rather than a traditional ML classifier, which might generalize better?

### UniDoc-RL: The Agent That Looks Before It Reads

> RAG hands the model a pile of chunks. UniDoc-RL gives the model a pair of eyes.

**Source:** HuggingFace Daily Papers  
**Links:** [Paper](https://arxiv.org/abs/2604.14967) · [Wiki](../../agentic-systems/2026-04-19-unidoc-rl-visual-rag.md)  
**Tier:** 2 — Agents / RAG

```
Standard visual RAG:
  Query ──dense retriever──► fixed chunks ──► LVLM generates answer
  (model never controls what it sees)

UniDoc-RL:
  Query ──► coarse: which documents? (action + reward)
              │
              ▼
         medium: which images? (action + reward)
              │
              ▼
           fine: which regions to crop? (action + reward)
              │
              ▼
         LVLM generates answer from what it actively chose to see
```

Dense retrieval assumes that the right context can be identified by embedding similarity at query time. For factual single-hop questions, that works. For multi-hop questions requiring scattered evidence, or questions that need understanding a specific region of a complex diagram, it breaks.

UniDoc-RL frames visual information gathering as sequential decision-making. A single LVLM acts as the retriever, reranker, and reader — it decides which documents matter, which images within them are relevant, and which regions of those images to zoom in on, all as discrete actions. GRPO trains the policy with dense rewards at each level, solving the credit assignment problem that kills sparse-reward RL on long retrieval trajectories.

The +17.7% gain over prior RL-based visual RAG methods is large. The comparison to Corpus2Skill (covered April 18) is instructive: Corpus2Skill navigates a pre-compiled offline hierarchy; UniDoc-RL navigates at query time with active perception. They're solving different parts of the same problem — and there's no reason they couldn't be combined.

**Why it matters:** Active visual perception — the ability to control what you look at, not just what you're given — is the key missing capability in production multimodal RAG systems.

### ASGuard: Alignment Surgery with Circuit Analysis

> The model refuses in present tense but complies in past tense. ASGuard finds the attention heads responsible and recalibrates them.

**Source:** HuggingFace Daily Papers  
**Links:** [Paper](https://arxiv.org/abs/2509.25843) · [Wiki](../../llms-foundation-models/2026-04-19-asguard-activation-jailbreak-defense.md)  
**Tier:** 2 — Safety / Interpretability

The tense-changing jailbreak is elegant in its simplicity: rephrase a harmful present-tense request as a past-tense narrative, and many safety-aligned models comply. The reason, per ASGuard's circuit analysis, is that adversarial suffixes suppress the propagation of the refusal-mediating activation direction in specific attention heads. The model isn't "thinking" about the harmfulness — it's pattern-matching on surface features.

ASGuard's fix is three steps: (1) circuit analysis to identify the specific attention heads causally linked to the vulnerability; (2) train a channel-wise scaling vector that recalibrates those heads; (3) apply via preventative fine-tuning. The scaling vector is tiny compared to the model — surgical, not sledgehammer. The result is a Pareto-optimal tradeoff: attack success rate drops, but helpfulness and general capability are preserved (less over-refusal than prior defenses).

This is mechanistic interpretability applied to alignment engineering — not just understanding the model, but using that understanding to fix a specific vulnerability. The approach generalizes: any targeted jailbreak that exploits a specific attention circuit can in principle be neutralized the same way, once you identify the circuit.

**Why it matters:** Alignment tax (safety measures hurting helpfulness) is one of the main reasons safety-aligned models get replaced with unsafe fine-tunes in practice. Surgical fixes that preserve utility while hardening specific vulnerabilities are the right direction.

### Claude Code: The While-Loop Has Good PR

> The core agent loop is six lines. The 200,000 lines around it are what makes it a product.

**Source:** HuggingFace Daily Papers  
**Links:** [Paper](https://arxiv.org/abs/2604.14228) · [Wiki](../../agentic-systems/2026-04-19-claude-code-architecture.md)  
**Tier:** 2 — Agent Systems

This paper reverse-engineers Claude Code (v2.1.88) from its public TypeScript source and compares it with OpenClaw, a different open-source agent. The finding that the core loop is trivial (call model → run tools → repeat) is useful framing: all the hard work is in what surrounds that loop.

The most notable piece is the **ML-based permission classifier** — rather than a fixed rule set for deciding what requires human approval, Claude Code trains a model on the space of possible actions. This means the safety boundary can generalize to novel tool calls and edge cases that no rule set could enumerate. The **five-layer compaction pipeline** handles context window management gracefully (not by truncating but by progressively summarizing). And the four extensibility mechanisms (MCP, plugins, skills, hooks) explain why Claude Code has become the platform of choice for power users building on top of it.

The comparison with OpenClaw is the most analytically sharp part: the same design questions (how to handle safety, how to manage context, how to extend capabilities) produce different answers based on deployment context. CLI tool vs. gateway control plane isn't just a deployment difference — it changes the fundamental architecture.

**Why it matters:** This is a usable reference architecture for anyone building production agent systems. The six open design directions are worth reading — they're grounded in specific gaps the authors found, not speculative wishlists.

## Connecting the Dots

**RL is replacing the data-collection paradigm:**

```
Old paradigm:
  collect human labels ──► supervised fine-tuning ──► RLHF on top

New paradigm (this week):
  VGF:       reference distribution ──► gradient flow ──► no explicit policy, no labels
  TRACER:    production API logs ──► surrogate training ──► self-improving routing
  UniDoc-RL: task reward signal ──► hierarchical RL ──► active visual perception
  LongAct:   saliency profiling ──► sparse gradients ──► no extra data needed
```

The thread: all four systems replace external data collection with signals that emerge from the model's own operation. VGF uses the model's own value function. TRACER uses the model's own production outputs. UniDoc-RL uses task reward. LongAct uses the model's own activation patterns. This is the RL-from-self paradigm — not RL from human feedback, but RL from the model's own behavior.

**VGF + TRACER: a full-stack cost reduction story:**

```
VGF: better training → smaller capable models
TRACER: smaller capable model → surrogate routing → near-zero per-call cost
```

VGF produces better models from existing distributions (no new labels). TRACER takes any capable model and uses it to train a cheap surrogate that handles routine traffic. Together, they describe a pipeline from training cost reduction to inference cost reduction — both powered by RL-style techniques.

**UniDoc-RL vs. Corpus2Skill — complementary, not competing:**

```
Corpus2Skill: offline compilation → static skill tree → navigation at query time
UniDoc-RL:   active perception → hierarchical RL → image/region selection at query time
```

Corpus2Skill gives the agent a map. UniDoc-RL gives the agent the ability to zoom in on what matters. A production multimodal RAG system could use Corpus2Skill for coarse navigation and UniDoc-RL for fine-grained visual evidence extraction. The papers don't cite each other, but the architectures compose.

## Worth Watching

- **[VGF on open-ended reasoning]** — The results are on offline RL benchmarks (D4RL, OGBench) and LLM RL tasks, but not on open-ended reasoning (MATH, GPQA). If VGF matches GRPO/DAPO on complex reasoning tasks by Q3 2026, explicit policy parameterization is on the way out.
- **[TRACER under distribution shift]** — The parity gate assumes validation-set agreement predicts deployment agreement. Watch for papers (or TRACER users) reporting gate failures when user query distribution shifts significantly. That's the real stress test.
- **[Anthropic Mythos civilian access]** — Mythos is currently government-only due to "cybersecurity risks." If any lab publicly challenges this framing (or if a competing model with similar capabilities releases openly), the government-exclusivity position becomes very hard to defend.
- **[Surgical alignment (ASGuard generalization)]** — Tense-changing is one attack pattern. Does circuit-level hardening scale to a comprehensive catalog of jailbreak circuit types? If so, alignment becomes an engineering problem (patch the circuits) rather than a training problem (retrain the model).

## Quick Hits

**Three-Phase Transformer (3PT)** ([paper](https://arxiv.org/abs/2604.14430)) — Adds a cyclic channel partition and 2D Givens rotation between attention and FFN in a standard transformer. Borrows the geometric metaphor of three-phase AC power (sinusoids 120° apart summing to zero). -7.2% perplexity on WikiText-103 with +1,536 parameters (0.001% of total) and 1.9× convergence speedup. Clever but small-scale; needs validation at 7B+.

**LeapAlign** ([paper](https://arxiv.org/abs/2604.15311)) — RLHF/GRPO for flow matching image generators. Shortens the long ODE trajectory into two "leaps" to enable gradient backprop to early generation steps without prohibitive memory cost. Outperforms GRPO-based baselines on Flux fine-tuning. Tier 3 — image generation.

**RAD-2** ([paper](https://arxiv.org/abs/2604.15308)) — Generator-discriminator RL for autonomous driving planning. Diffusion-based trajectory generator + RL-optimized discriminator that reranks candidates on long-term quality. 56% collision rate reduction. Tier 4 — robotics/driving.

**C2: Cooperative Rubric Reward Modeling** ([paper](https://arxiv.org/abs/2604.13618)) — Already covered April 18. Cooperative rubric generator + critical verifier; 8B model matches 32B rubric quality. Worth noting: the "rubrics hurt when bad" finding is directly relevant to any reward modeling pipeline using generated rubrics.

**ASGuard (trending from Sept 2025)** — The activation-scaling jailbreak defense (covered in Deep Dives above) is a Sept 2025 preprint now trending on HuggingFace Daily Papers. The delay between publication and trending suggests it's gaining attention due to practical deployment interest, not just academic novelty.
