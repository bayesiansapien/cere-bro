### Agentic World Modeling: A Taxonomy That Actually Lands

> L1 predicts one step. L2 runs multi-step rollouts. L3 revises its own model when it's wrong. Most deployed agents haven't cleared L1.

**Source:** HuggingFace Daily Papers (Apr 27)  
**Links:** [Paper](https://arxiv.org/abs/2604.22748)  
**Tier:** 2 — Agentic reasoning / world models

```
Levels × Laws taxonomy:

LEVELS:
  L1 Predictor  → one-step local transition operators
  L2 Simulator  → multi-step, action-conditioned rollouts respecting domain laws  
  L3 Evolver    → autonomously revises own model on prediction failure

GOVERNING-LAW REGIMES:
  Physical   → robotics, navigation
  Digital    → GUI agents, web agents, coding agents
  Social     → multi-agent interaction, negotiation
  Scientific → lab automation, hypothesis generation
```

The key insight: you can't evaluate a world model without knowing which regime it's operating in. A coding agent's world model needs to satisfy digital laws (deterministic execution, version control, file system semantics). A lab automation agent needs to satisfy scientific laws (experimental constraints, measurement uncertainty, reproducibility). Transferring a world model from one regime to another requires regime-specific retraining, not just fine-tuning.

The L3 Evolver level — autonomously revising its own model when predictions fail — maps onto the Hope architecture (04-28, incoming) and DeepSeek V4's Engram module (04-25). Both are architectural approaches to L3-style continual adaptation. The taxonomy provides the framework; Hope and Engram are first implementation attempts.

At 211 upvotes, this is one of the most-upvoted papers of the week. For a survey paper, that's notable — it suggests the community recognizes the unification need.

**Research angle:** The paper proposes "decision-centric evaluation principles." What does that mean concretely for digital-regime agents (coding, GUI)? The prior benchmarks (GTA-2 from 04-20, Dr3 from 04-18) measure specific capabilities; this taxonomy asks for evaluation that spans level-regime pairs. Whether this can be operationalized into a concrete benchmark suite is the open question.

### Stochastic KV Routing: Depth as the New Compression Axis

> Temporal KV cache compression is crowded. Depth-wise sharing is not — and it composes with temporal approaches.

**Source:** HuggingFace Daily Papers (Apr 28, referenced Apr 27)  
**Links:** [Paper](https://arxiv.org/abs/2604.22782)  
**Tier:** 1 — KV cache / inference efficiency

The KV cache compression literature has almost exclusively targeted the temporal axis: which tokens to evict, when to evict them, how to approximate evicted content. H2O, StreamingLLM, paged attention — all temporal. Stochastic KV Routing works on the depth axis instead: how many layers actually need their own KV state?

The approach is elegant: during training, each layer randomly decides whether to attend to its own KV states or borrow from a preceding layer. This stochastic process forces the model to be robust to various depth-sharing configurations. At deployment, you can share cache across layers in whatever pattern matches your hardware constraints — the model was trained to handle all of them. For larger models in data-constrained settings, it even shows regularization benefits.

The memory saving is significant: if you can share cache across every other layer, you halve the KV cache footprint with minimal quality loss.

```
Prior work on KV compression:
  H2O, StreamingLLM, paged attention  → temporal axis (which tokens)
  Multi-Query, GQA                     → query axis (how many heads)
  MLA (DeepSeek V2)                    → projection axis (low-rank compression)
  Stochastic KV Routing                → depth axis (which layers share)
```

**Research angle:** The depth and temporal axes are orthogonal — a model trained with Stochastic KV Routing could also use temporal eviction (H2O, etc.) simultaneously. Whether the benefits compose additively or sub-additively is the key experimental question.
