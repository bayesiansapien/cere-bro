## The Big Picture

No new papers today — HuggingFace doesn't curate on weekends. But the weekend brought two pieces of context that matter for how GPT-5.5 actually gets used.

OpenAI's guidance to "rebuild prompts from scratch" for GPT-5.5 is unusual. The conventional wisdom since GPT-4 has been that prompts are broadly transferable across versions. The fact that OpenAI is explicitly recommending a fresh baseline suggests GPT-5.5's behavior diverges enough from 5.4 that existing prompts actively suppress its capabilities. Role definitions specifically — which many practitioners had abandoned as cargo-cult prompt engineering — are apparently back as a meaningful signal.

The investment banking study is more substantive than most AI capability studies. 500 practitioners, junior banking tasks, a clear definition of "client-ready." Not one output passed. This is a useful calibration: in a domain with explicit quality standards and sophisticated evaluators, AI outputs at the current frontier are starting points, not endpoints. The contrast with SemiAnalysis's GPT-5.5 coding endorsement (04-24) is instructive: the quality bar differs enormously between domains. Code can be run and verified. Financial analysis has softer evaluation criteria — and apparently still fails.

## Connecting the Dots

The "rebuild your prompts for GPT-5.5" guidance connects back to the Claude Code postmortem (04-24). Anthropic said strict system prompts limited response detail — a system-layer behavior change. OpenAI is saying role definitions have returned as meaningful — a model-layer behavior change. Both observations point at the same pattern: the interface between user instructions and model behavior is less stable across model versions than practitioners assume. What works for 5.4 actively hurts on 5.5. This is a prompt brittleness problem that will only compound as model update cadences accelerate.
