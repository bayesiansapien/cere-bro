## The Big Picture

Five papers this week — TIP (04-16), LongAct (04-18), STOP, AVR, and W-RAC (all today) — have now converged on the same core claim from five different levels of the stack: **most computation in AI systems is wasted, and you can identify what to discard.** TIP discards uninformative tokens in distillation. LongAct discards uninformative gradient positions. STOP discards failing reasoning paths before they finish. AVR discards unnecessary reasoning format stages. W-RAC discards the text-generation step in RAG chunking. Five papers, five granularities, one week.

This is no longer a scattered observation. It's a convergence. The field has absorbed the insight that neural systems are dramatically over-computed for most inputs, and the research frontier has shifted to: *where exactly* do you find the decision boundary between necessary and wasted compute, and can you learn it cheaply enough that the savings justify the overhead?

The surprise today is the dark side. Maximal Brain Damage shows that the same machinery used to identify important parameters for efficiency is also the machinery for finding the attack surface. Two sign-bit flips collapse a 30B model from 78% to 0%. The parameters that matter most for efficiency are the parameters that matter most for disruption. As compression research gets better at identifying high-salience weights — LongAct found them by magnitude, TIP by entropy — it also gets better at producing a map for adversarial attacks. These two research lines are converging toward each other, and the field hasn't noticed yet.

### STOP: Cut Your Losses Before the Path Goes Nowhere

> Parallel reasoning generates many candidate paths. Most of the failing ones fail *early*. STOP learns to recognize them at the prefix — before the compute is spent.

**Source:** HuggingFace Daily Papers  
**Links:** [Paper](https://arxiv.org/abs/2604.16029) · [Wiki](../../inference-efficiency/2026-04-20-stop-path-pruning-parallel-reasoning.md)  
**Tier:** 1 — Inference Efficiency / Parallel Reasoning

```
Parallel reasoning paths:
  Path A: [prefix] → ... → ✓ (correct answer)
  Path B: [prefix] → early error → ... waste ... → ✗
  Path C: [prefix] → early error → ... waste ... → ✗

STOP:
  [STOP token prepended to each prefix]
       │
  Learned gate: "Should this path continue?"
       │
  Path B, C pruned here ──► compute saved, no waste
       │
  Path A continues ──► correct answer
```

The taxonomy STOP introduces is the most useful conceptual contribution. Four categories of path pruning: signal from inside the model (internal) vs. from an external judge, and whether the signal is hand-crafted (non-learnable) or trained (learnable). Prior work spread across three of the four quadrants. Learnable internal methods — what STOP is — were unexplored.

Why learnable internal? External judges are expensive (another model call). Non-learnable heuristics are brittle (entropy thresholds miss domain-specific failure patterns). A learned token that reads the prefix and predicts path quality is cheap (one token, trained alongside the model) and generalizes (it learns what failure looks like in this specific task distribution).

The 84% → 90% AIME25 result is under a *fixed compute budget*. This isn't just reducing cost at fixed quality — it's improving quality at fixed cost, by reallocating compute from doomed paths to productive ones. At larger scale, where parallel budgets are 32-128 paths, the savings compound.

**Why it matters:** Every parallel reasoning system is currently paying the full compute cost of every path, including the ones that fail from move 3 onward. STOP is the first learnable method to cut this waste at the source.

**Research angle:** Two open questions. First: does STOP generalize to open-ended reasoning (code, math proofs, long-horizon agents)? The AIME25 results are on constrained math. Open-ended tasks have fuzzier failure signals — can the super-token still learn to detect them? Second: what does the super-token actually learn? Is it detecting syntactic errors in the prefix, logical inconsistencies, or something more abstract? The interpretability of the learned gate matters for knowing when to trust it.

### AccelOpt: The Kernel Whisperer That Learns From Its Own Mistakes

> Expert GPU kernel optimization without any experts. An LLM agent that accumulates a memory of what works and what doesn't, improving across iterations.

**Source:** HuggingFace Daily Papers  
**Links:** [Paper](https://arxiv.org/abs/2511.15915) · [Wiki](../../inference-efficiency/2026-04-20-accelopt-gpu-kernel-optimization.md)  
**Tier:** 1 — GPU Optimization / Hardware

```
Iteration 1:
  Generate kernel variant
       │
  Benchmark on Trainium → 49% throughput
       │
  Record: (slow_kernel, fast_kernel) → optimization memory
       │
Iteration N (memory grows):
  Query memory: "Here are N slow-fast pairs. Generate a better variant."
       │
  Benchmark → 61% throughput (Trainium 1)
```

AWS Trainium has a different programming model than CUDA — it uses NKI (Neuron Kernel Interface), which requires understanding Trainium's specific memory hierarchy (HBM, SBUF, PSUM, compute engines). This expertise is scarce. Hiring kernel engineers for each new hardware generation is expensive. AccelOpt's answer: accumulate the expertise in a memory of slow-fast kernel pairs, and use an LLM to mine patterns from that memory.

The memory is the key insight. Without it, the LLM can't improve across iterations — it's pattern-matching from its weights, which don't contain Trainium-specific knowledge. With memory, each benchmark run becomes a labeled example that improves future generations. This is the same insight as TRACER (04-17): the model's own outputs are better training data than anything you'd hand-curate.

The cost number is striking: 26x cheaper than Claude Sonnet 4 at matched quality, using open-source models. This tells us kernel optimization from examples is a well-structured enough task that model capability (beyond a threshold) is not the bottleneck — the memory scaffold is. The same lesson as TRACER's parity gate: once you have the right framing and context, cheap models do the job.

**Why it matters:** If this scales to other accelerators (Blackwell, future Trainium generations), it breaks the dependency on per-hardware kernel specialists. Every new accelerator gets a self-improving optimization agent that bootstraps from its own benchmarks.

**Research angle:** Three open questions the wiki should watch. First: does memory transfer across hardware generations? A Trainium 1 slow-fast memory should be partially useful for Trainium 2 — the architecture changed but not completely. Second: what's the memory curation strategy? The paper doesn't say how it decides which pairs to retain when memory grows large. The curation policy determines whether the memory stays useful or becomes noisy. Third: 61% peak throughput leaves 39% on the table. The remaining gap likely requires genuinely novel reasoning — operator fusion, memory access patterns — that can't be expressed as pattern-matching from prior examples. What class of optimizations is beyond this approach?

### Maximal Brain Damage: Two Bits to Rule Them All

> The same insight that identifies important weights for compression also identifies them for catastrophic disruption. The field is building a target map for adversarial attacks.

**Source:** HuggingFace Daily Papers  
**Links:** [Paper](https://arxiv.org/abs/2502.07408) · [Wiki](../../inference-efficiency/2026-04-20-maximal-brain-damage-sign-bit-flips.md)  
**Tier:** 1 — Model Security / Compression

The finding is stark: two sign-bit flips in carefully-chosen parameters collapse ResNet-50 accuracy by 99.8% on ImageNet. Two flips into different experts in Qwen3-30B — a 30-billion-parameter model — drop reasoning accuracy from 78% to 0%. No optimization, no data, no gradient. Just a single forward-backward pass on random inputs to score each parameter's vulnerability.

Why sign bits? In standard floating-point formats (float32, float16, bfloat16), the sign bit controls the direction of a parameter's effect. A large positive weight that contributes strongly to a prediction becomes a large negative weight — an equally strong push in the wrong direction. The most influential parameters are the most disruptable by a sign flip: the parameter's magnitude is both the source of its influence and the magnitude of the damage when flipped.

This is the efficiency paradox. LongAct (04-18) found that high-magnitude KV activations are the positions where attention does real work — and used this to focus sparse RL updates. TIP (04-16) found high-entropy and overconfident positions are the tokens that actually carry learning signal. Standard quantization preserves high-magnitude weights at higher precision. All of these insights identify the same thing: the small subset of parameters that matter most. Deep Neural Lesion finds those same parameters and makes them targets.

The defense is principled: identify the vulnerable sign bits (same method) and protect them selectively. You don't need to protect all parameters — just the critical fraction. The paper shows this is feasible.

**Why it matters:** As the efficiency research community gets better at finding and protecting important parameters, it's also — inadvertently — publishing better target maps. The connection between compression research and adversarial robustness hasn't been drawn explicitly yet in either community. It needs to be.

**Research angle:** Does the sign-bit vulnerability scale with quantization level? 4-bit and 2-bit quantized models have fewer bits per parameter — does this make them more or less vulnerable to targeted bit flips? Also: the MoE result is particularly interesting. Two flips into *different* experts zeroed out reasoning on Qwen3-30B. This suggests MoE routing may be especially brittle — the routing logic and expert weights are both small targets.

### GTA-2: The Benchmark That Measures What Actually Matters

> Frontier models fail below 50% on single-step tool use. On multi-step workflows, top models reach 14.39%. But switch to Manus or OpenClaw as the execution harness, and the numbers change substantially.

**Source:** HuggingFace Daily Papers  
**Links:** [Paper](https://arxiv.org/abs/2604.15715) · [Wiki](../../agents-tool-use/2026-04-20-gta-2-tool-agent-benchmark.md)  
**Tier:** 2 — Agent Benchmarks

```
Evaluation tier         Best model     With advanced harness
──────────────────────────────────────────────────────────
GTA-Atomic (single tool)   <50%            —
GTA-Workflow (multi-step)  14.39%         substantially higher
```

GTA-2's two-tier design is the right way to think about agent capability. Atomic tool use is a necessary condition for workflow completion — if you can't reliably invoke a single tool correctly, multi-step coordination is impossible. The sub-50% on atomic tasks means we haven't even solved the prerequisite yet.

The 14.39% workflow number is the headline, but the harness finding is the real result. Advanced frameworks (Manus, OpenClaw) substantially improve workflow completion beyond what model capability alone predicts. This is a direct, empirical validation of what the Claude Code architecture analyses (04-17, 04-19) found by inspection: the loop recovery logic, permission system, and context management are what separate functional agents from stochastic text generators. GTA-2 quantifies it. A model with a sophisticated harness outperforms a stronger model with a naive harness.

This is now the third benchmark in the wiki (after OccuBench 04-16 and DR3-Eval 04-18) measuring the same fundamental gap: realistic multi-step tasks expose failures that standard benchmarks miss. The measurement is converging. The field knows the gap exists. The open question is whether the gap closes through model scaling, harness engineering, or both — and which faster.

**Why it matters:** If harness design dominates model capability for real-world tasks, investment in agent infrastructure may have a higher ROI than model capability research — at least for the near term.

### 1D Ordered Tokens: Token Structure as Infrastructure for Test-Time Scaling

> Whether test-time search can steer generation isn't just about the search algorithm or the verifier. It's about whether the intermediate states mean anything. 1D coarse-to-fine tokens do; 2D grid tokens don't.

**Source:** HuggingFace Daily Papers  
**Links:** [Paper](https://arxiv.org/abs/2604.15453) · [Wiki](../../inference-efficiency/2026-04-20-1d-ordered-tokens-test-time-search.md)  
**Tier:** 2 — Inference Efficiency / Test-Time Scaling

```
2D grid tokenization:
  [patch_1][patch_2][patch_3]...  ← no semantic meaning until near-complete
  Verifier: "I can't evaluate this partial output."
  Search: can't steer early → no benefit

1D coarse-to-fine tokenization:
  [global_shape][coarse_detail][medium_detail][fine_detail]
  Verifier: "The global shape is wrong at 20% completion." → prune early
  Search: can steer from the beginning → significant benefit
```

The insight is architectural: test-time scaling isn't just a function of compute budget and search algorithm. It requires intermediate states that carry semantic signal. A 2D grid tokenizer produces patches — spatially incomplete at any prefix. A coarse-to-fine 1D tokenizer produces a hierarchical description — semantically meaningful at any prefix (the first 20% of tokens describe the global structure).

The extreme demonstration is training-free text-to-image generation: pure test-time search over token sequences, guided by a verifier, without training an AR model at all. This works *only* because 1D tokens produce evaluable intermediate states. It's inference compute substituting for training compute in a way that's impossible with 2D tokens.

The connection to the test-time scaling debates in the wiki:
- AIMO 3 (04-17): model capability 4x more important than prompt diversity
- VGF (04-19): transport-step refinement as an alternative to wider sampling
- STOP (04-20): prune failing paths early
- 1D tokens (04-20): make intermediate states evaluable in the first place

These are not competing answers. 1D tokens is a prerequisite: without evaluable intermediate states, STOP and VGF have nothing to work with. Coarse-to-fine structure is the infrastructure that makes inference-time scaling possible.

### AVR: The Model That Knows When Not to Think

> Visual reasoning models apply full chain-of-thought to questions like "what color is the car?" AVR trains them to pick the minimally sufficient format. 50-90% token reduction, maintained accuracy.

**Source:** HuggingFace Daily Papers  
**Links:** [Paper](https://arxiv.org/abs/2604.14568) · [Wiki](../../inference-efficiency/2026-04-20-avr-adaptive-visual-reasoning.md)  
**Tier:** 2 — Inference Efficiency / Visual Reasoning

```
Current VRMs:
  "What color is the car?" → [Observe scene] → [Reason about attributes] → [Conclude] → "red"
  Cost: 300 tokens for a 5-token answer

AVR:
  "What color is the car?" → [Perception-Only] → "red"
  Cost: 20 tokens
  
  "Is the red car in front of the blue truck?" → [Full Reasoning] → ...
  Cost: appropriate
```

The root cause is training distribution: current visual reasoning models are trained on full reasoning chains uniformly, so they apply full reasoning uniformly. AVR retrains with FS-GRPO (a GRPO variant with format-aware rewards) that gives bonus reward for selecting a shorter format when that format is sufficient for correctness. The model learns frugality.

The 50-90% token reduction is large. The range makes sense: perception-intensive tasks (object color, counting, spatial relationships) benefit most. Complex reasoning tasks (multi-step logic, spatial inference) need the full format and aren't over-pruned.

**Why it matters:** Visual reasoning is one of the highest-token-cost applications in production deployment. A 50-90% token reduction on perception-heavy workloads translates directly to inference cost, and through that, to the viability of visual AI products.

## Industry Pulse

- **[Opus 4.7 tokenizer inflation is real and large](https://simonwillison.net/2026/Apr/20/claude-token-counts/#atom-everything)** — Simon Willison documents that Opus 4.7 uses 1.46x the tokens of Opus 4.6 for raw text (tested on the Opus 4.7 system prompt itself). For high-resolution images, the gap reaches 3.01x — though Willison clarifies this is mostly from Opus 4.7's higher image resolution support (up to 2,576px vs. previous limits). At the same $5/M input and $25/M output pricing, users migrating from 4.6 should expect ~40% higher costs on text-heavy workloads. The Anthropic announcement cited 1.0–1.35x; Willison found 1.46x on their own system prompt, at the high end of the published range.

- **[Qwen3.5-Omni SOTA across 215 audio-visual benchmarks](https://arxiv.org/abs/2604.15804)** — Alibaba's latest in the Qwen family hits the omnimodal frontier: 256k context, MoE architecture for both text and speech modules, 10 languages, and a new ARIA alignment system for streaming speech. Beats Gemini 3.1 Pro on key audio tasks. The Qwen series is now competitive across coding (Qwen3.6, covered 04-19), efficiency (sparse MoE), and omnimodal reasoning. The open-source frontier is advancing on multiple dimensions simultaneously.

- **[Agentic loop deep dive: Claude Code vs. Hermes Agent](https://kenhuangus.substack.com/p/chapter-3-the-query-agent-loop-claude)** — Ken Huang's Chapter 3 dissects the production agent loop in detail: Claude Code's 7 named continue sites (state machine, prevents retry spirals) vs. Hermes' thread-safe shared IterationBudget (prevents runaway across parent-child agent trees). The technical delta between these two designs maps directly to GTA-2's finding that harness design dominates model capability.

## Connecting the Dots

**The selective-compute convergence — five papers, five levels:**

```
TIP (04-16):     token level     — discard uninformative tokens in distillation (10% signal)
LongAct (04-18): gradient level  — discard uninformative gradient positions (sparse RL)
STOP (04-20):    path level      — discard failing reasoning paths at the prefix
AVR (04-20):     format level    — discard unnecessary reasoning stages
W-RAC (04-20):   pipeline level  — discard LLM text generation from chunking decisions
```

Five papers in five days, five different levels of the inference stack, one claim: *identify what's necessary and discard the rest.* This is no longer a scattered theme — it's a research paradigm shift. The field has moved from "compute everything, pick the best result" to "find the decision boundary between necessary and wasted computation."

The practical implication: these methods stack. A system that uses STOP (path level), AVR (format level), and W-RAC (pipeline level) simultaneously gets multiplicative efficiency gains. None of these methods require knowing about the others. The architecture for "selective inference" is emerging organically, layer by layer.

**The efficiency-vulnerability paradox (Maximal Brain Damage vs. the field):**

```
Compression research: find important parameters → protect them at higher precision
Saliency research:    find important parameters → focus gradient updates on them
AccelOpt:             find slow-fast patterns → accumulate them in memory

Maximal Brain Damage: find important parameters → flip two sign bits → collapse everything
```

The same identification machinery that powers this week's efficiency papers is exactly the DNL attack. LongAct identifies high-magnitude KV positions. TIP identifies high-entropy tokens. Standard quantization keeps high-magnitude weights at float16 while compressing others. Deep Neural Lesion scores every parameter by impact — and finds the same high-magnitude, high-influence weights that every compression paper has been curating.

As compression research matures, it publishes better target maps. This connection hasn't been drawn explicitly in either the compression or adversarial communities. It should be.

**GTA-2 closes the loop on Claude Code analysis:**

The wiki has been tracking Claude Code architecture for four days (04-17, 04-19, 04-20). The consistent finding from three different analyses: the agent loop is trivial; the recovery logic and surrounding systems are what matter. GTA-2 provides the first *quantitative* external validation. The same experiments that show 14.39% on workflows also show that advanced harnesses (Manus, OpenClaw) substantially improve this number — without changing the underlying model. The Claude Code state machine analysis today (7 named continue sites, IterationBudget, reactive compact) is now directly interpretable as the mechanism behind harness-driven performance differences.

## Worth Watching

- **[STOP on open-ended reasoning]** — AIME25 is constrained math. If STOP generalizes to code generation and open-ended reasoning tasks by Q3 2026, it becomes a standard component of every parallel reasoning deployment. If it doesn't, it's a special-case optimization for formal math.
- **[Sign-bit protection as a compression constraint]** — DNL identified a small fraction of vulnerable bits that need protection. If a compressed model can maintain a bit-flip-protected subset of parameters without significant quality loss, adversarial robustness and compression are compatible. If not, they're in direct tension. Check for papers combining compression + bit-flip hardening.
- **[Opus 4.7 real-world cost impact]** — Simon Willison found 1.46x inflation on a single system prompt. Teams with long system prompts (Claude Code, enterprise contexts) should be auditing their actual token inflation before migrating. The 40% cost increase is not evenly distributed — prompt-heavy use cases get hit harder.
- **[AccelOpt memory transfer across hardware generations]** — Trainium 2 is available and Trainium 3 is coming. If AccelOpt's slow-fast memory from Trainium 1 transfers usefully to Trainium 2 (partial architecture similarity), the approach scales to new hardware without full restarts. Watch for follow-up papers or AWS reports on Trainium 3 kernel optimization using AccelOpt-style memory.

## Quick Hits

**W-RAC** ([paper](https://arxiv.org/abs/2604.04936)) — RAG chunking costs cut 51.7% by routing only the *planning* step (which IDs group together) to the LLM, not the text generation step. Eliminates hallucination in chunk content. The decoupling insight is clean: the LLM doesn't need to write the chunks, it just needs to decide the groupings. → [Wiki](../../inference-efficiency/2026-04-20-w-rac-retrieval-aware-chunking.md)

**PRL-Bench** ([paper](https://arxiv.org/abs/2604.15411)) — 100 physics research tasks from PRL papers (Aug 2025+, post-training-cutoff). Every frontier model below 50%. Tests genuine research workflow, not knowledge retrieval. Third consecutive scientific benchmark showing the same gap (after InfiniteScienceGym 04-16 and DR3-Eval 04-18). → [Wiki](../../agents-tool-use/2026-04-20-prl-bench-physics-benchmark.md)

**Agentic Loop Chapter 3** ([post](https://kenhuangus.substack.com/p/chapter-3-the-query-agent-loop-claude)) — Detailed side-by-side of Claude Code's 7 continue sites (named state machine) vs. Hermes Agent's IterationBudget (shared counter across agent tree). The `refund()` method — returning one iteration credit for internal programmatic calls that don't count toward user-visible actions — is a design detail worth copying. → [Wiki](../../agents-tool-use/2026-04-20-query-agent-loop-claude-vs-hermes.md)

**Qwen3.5-Omni** ([paper](https://arxiv.org/abs/2604.15804)) — SOTA on 215 audio-visual benchmarks. The ARIA streaming speech alignment system (fixes text/speech tokenizer rate mismatch in real-time conversations) is the technical contribution worth watching for production voice AI. Tier 2 given it's primarily a scale + ARIA paper, not a new architecture. → [Wiki](../../multimodal/2026-04-20-qwen35-omni.md)

**ArtifactNet** ([paper](https://arxiv.org/abs/2604.16254)) — Detects AI-generated music by extracting codec-level residuals (the physical artifacts neural audio codecs imprint on audio). 4M parameters, F1=0.9829 on unseen generators — 49x fewer params than prior SOTA. Codec-aware training cuts cross-codec probability drift 83%. Tier 3 — forensics / audio.

**PersonaVLM** ([paper](https://arxiv.org/abs/2604.13074)) — Long-term personalized multimodal LLM: proactive memory extraction, multi-turn reasoning from memory, personality inference over time. +22.4% on Persona-MME benchmark vs. baseline. Tier 3 — personalization / multimodal.

**EdgeDetect** ([paper](https://arxiv.org/abs/2604.14663)) — Federated IDS for 6G-IoT: median-based binarization compresses gradient updates to {+1, -1} (32x reduction), Paillier homomorphic encryption protects from honest-but-curious servers. 98% accuracy, 96.9% communication reduction. Tier 3/4 — federated learning / IoT security.

**NTIRE 2026 Video Saliency** ([paper](https://huggingface.co/papers/2604.15628)) — Challenge overview for video saliency prediction. Tier 4.

**TIPSv2** ([paper](https://huggingface.co/papers/2604.15628)) — Enhanced point-supervised vision-language pretraining. Tier 3.

**VEFX-Bench** ([paper](https://huggingface.co/papers/2604.15715)) — Video editing + effects benchmark. Tier 3.

**LaviGen** ([paper](https://huggingface.co/papers/2604.15453)) — 3D layout generation repurposing 3D generative models. Tier 4.
