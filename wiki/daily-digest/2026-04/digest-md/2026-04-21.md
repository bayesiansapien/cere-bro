# cere-bro | 2026-04-21

> SFT is broken RL, diversity is a noise metric, and agents that explore need no external signal at inference time — the supervision paradigm is dissolving.

---

## TL;DR

- **GFT** — SFT is mathematically a degenerate case of policy gradient: maximally sparse reward, unstable probability weighting, single-path collapse. Group Fine-Tuning fixes all three and integrates better with downstream RL
- **Weak Supervision** — Reward saturation speed, not output diversity, predicts whether RLVR generalizes; reasoning faithfulness is the pre-RL property that determines which regime a model enters
- **Self-Evolution** — Agents trained to explore environments accumulate world knowledge and apply it at inference time with zero external rewards; 14B model beats unassisted Gemini-2.5-Flash on web navigation
- **Geometric Canary** — Representational geometry stability (ρ=0.89–0.97) predicts linear steerability and detects post-training drift — two deployment diagnostics from one geometric metric
- **Precise Debugging** — Frontier models pass unit tests 76% but edit precision below 45%; they regenerate, not debug; iterative agentic strategies don't fix it; the post-training objective is wrong
- **Nemotron 3 Super** — NVIDIA's hybrid Mamba-Attention MoE: 120B params / 12B active, NVFP4 pretraining, 2.2x throughput over GPT-OSS-120B, native speculative decoding via MTP, all artifacts open-sourced (Tier 1)
- **SemiAnalysis Goodput** — Two GPU clusters at identical pricing differ 6–21% in useful work delivered; gold-tier neoclouds beat silver by 5–15% for large training; no open-source zero-overhead fault-tolerant training framework exists (Tier 1)

## The Big Picture

Three papers today converge on a single structural argument: the distinction between supervised fine-tuning and reinforcement learning is artificial, and the standard SFT → RL pipeline is suboptimal at a fundamental level. GFT shows SFT is just bad RL — maximally sparse reward and unstable gradient weighting. The weak supervision paper shows that what actually determines whether RL generalizes isn't how diverse your outputs are, but how faithfully your intermediate reasoning steps logically support your answers. And the self-evolution paper shows agents can internalize the *process* of learning from exploration during training and execute it without any external signal at inference.

Taken together with what's already in the wiki — PreRL (04-16) argued for optimizing P(y) not P(y|x), VGF (04-19) eliminated the policy entirely, LongAct (04-18) concentrated gradients on saliency peaks — we now have five papers in six days all making the same structural argument from different angles: the field's default training paradigm (SFT followed by standard RL) is wasteful and suboptimal, and each paper is cutting a different part of it away. This is not coincidence. It's a paradigm shift in slow motion.

The second thread today is a growing benchmark crisis. PDB joins GTA-2 (04-20), DR3-Eval (04-18), and AIMO 3 (04-17) in a now four-paper sequence documenting the same meta-failure: frontier models find a shortcut that satisfies the surface metric without solving the cognitive task the benchmark is testing. Models pass unit tests by regenerating solutions. Models complete workflows by relying on harness scaffolding. Models retrieve evidence by selecting the easiest facts. Every time we design a metric that proxies for the hard cognitive operation, models learn to satisfy the proxy. This is Goodhart's Law expressed at benchmark scale — and the field is accumulating evidence faster than it's proposing solutions.

A third thread arrived through the parallel daily digest: the infrastructure layer is catching up to the model layer. The SemiAnalysis cluster economics analysis makes visible what was previously assumed away — two GPU clusters at identical per-hour pricing can differ by 6–21% in useful work delivered, because fault recovery, reinitialization, and debugging never appear on the monthly bill. Separately, NVIDIA's Nemotron 3 Super attacks the same efficiency problem from the architecture level: hybrid Mamba-Attention MoE at NVFP4 pretraining achieves 2.2x throughput over a dense 120B baseline without touching the cluster at all. Infrastructure optimization and architecture optimization are converging on the same problem — how much of a GPU-hour actually moves a model forward. That question now has both a hardware answer (goodput) and a model answer (sparse activation + native speculation).

### SemiAnalysis GPU Cluster TCO: The Hidden 20%

> Two GPU clusters at the same price. One delivers 20% more useful work. The difference has never appeared on a monthly bill — until now.

**Source:** SemiAnalysis Newsletter  
**Links:** [Post](https://newsletter.semianalysis.com/p/how-much-do-gpu-clusters-really-cost) · [Wiki](../../hardware/2026-04-21-semianalysis-gpu-cluster-goodput.md)  
**Tier:** 1 — GPU Economics / Cluster Infrastructure

```
GPU cluster Total Cost of Ownership:
  ┌────────────────────────────────────────────────────┐
  │  On-bill (visible):  GPUs, Storage, Networking,    │
  │                      Control Plane, Support         │
  │                                                    │
  │  Off-bill (hidden):                                │
  │    Goodput Expense  ← compute lost to failures     │
  │    Setup Expense    ← time to configure the job    │
  │    Debugging Expense← diagnosing node issues       │
  └────────────────────────────────────────────────────┘

Fault-tolerance framework comparison:
  TorchFT (open source)     ← 10%+ overhead (GLOO comms)
  AWS HyperPod Checkpointless ← 0% overhead, Kubernetes+NeMo only
  TorchPass (licensed)      ← 0% overhead, requires idle spare nodes
```

SemiAnalysis tested 80+ neoclouds and interviewed 150+ customers. The central finding: reliable clusters and unreliable clusters look identical on the monthly bill. The cost of unreliability shows up in three off-bill buckets — goodput loss (compute wasted since last checkpoint when a node fails), setup time (cluster configuration before training starts), and debugging time (diagnosing the node that caused the failure). Together, for a 5,184 GB300 NVL72 cluster running large-scale pretraining, these range from 6.14% of TCO (gold-tier cluster with TorchPass zero-overhead fault tolerance) to 20.91% (silver-tier with checkpoint-restart recovery).

The asymmetry is the key insight: this gap is almost entirely for large distributed training. For single-node inference workloads, the gap collapses near zero — a node failure is local, not catastrophic. This is why low-tier providers can serve inference profitably while being economically unviable for pretraining. The same unreliability has radically different cost implications depending on the workload.

The fault-tolerance landscape is the most actionable finding. TorchFT is the only open-source option, but its 10%+ overhead comes from GLOO all-reduce communications during state replication — not a fundamental constraint, just an implementation choice. AWS HyperPod Checkpointless Training delivers zero overhead with 1 minute 45 second recovery, but it is locked to Kubernetes and NeMo. TorchPass delivers zero overhead with no ecosystem lock-in, but requires a license and idle spare nodes at 0.62% of cluster size. There is no open-source, zero-overhead, ecosystem-agnostic fault-tolerant training framework. That gap is the most concrete infrastructure bottleneck in the field right now.

**Why it matters:** Every decision about which cloud provider to use for a training run should be a goodput calculation, not a GPU-hour calculation. 20% of your cluster cost can disappear to recovery overhead before a single useful gradient update. Organizations building training infrastructure that haven't quantified their goodput are systematically underpricing their compute.

**Research angle:** The goodput framework has a direct Tier 1 intersection with routing: if goodput varies 3–15x across cluster tiers, and inference routing already considers latency and cost per provider, a unified routing framework factoring in per-provider goodput loss per workload type would change the effective cost comparison for batch training jobs. This is novel because existing routing assumes reliable endpoints. The open problem is how to model failure probability and recovery cost as routing signals.

### Nemotron 3 Super: Four Research Threads, One Shipped Model

> SSM + sparse MoE + FP4 pretraining + native speculative decoding. NVIDIA ships the architecture the efficiency community spent three years designing.

**Source:** DAIR.AI Weekly Papers  
**Links:** [Wiki](../../inference-efficiency/2026-04-21-nemotron3-super-hybrid-moe.md)  
**Tier:** 1 — Architecture / GPU Efficiency

```
Nemotron 3 Super (120B total / 12B active):
  ┌─────────────────────────────────────────────────┐
  │  [Mamba block]  ← SSM, O(L) complexity          │
  │       │          handles most of the sequence    │
  │  [LatentMoE]   ← sparse attention               │
  │    tokens → latent dim → K of N experts         │
  │       │          only 10% of params activate     │
  │  [MTP heads]   ← predict t+1, t+2, ..., t+k     │
  │       │          verify in-line, no draft model  │
  │  output token                                   │
  └─────────────────────────────────────────────────┘

Pretraining: NVFP4 (4-bit float) on 25T tokens
Throughput:  2.2x over GPT-OSS-120B, 7.5x over Qwen3.5-122B
Context:     1M tokens
```

The 120B / 12B active ratio comes from LatentMoE. Standard MoE routes tokens to experts at full model dimension. LatentMoE first projects into a smaller latent dimension, runs routing and expert computation there, then projects back out. This reduces parameter count per expert while maintaining expert diversity — the mechanism behind having 120B parameters but only activating 12B per token. Most long-context processing runs through Mamba blocks (O(L) complexity vs O(L²) for full attention), which is how the 1M context window becomes tractable.

NVFP4 pretraining is the efficiency backbone and the most technically significant aspect. FP8 is now standard for training at large scale; FP4 halves the bits again, requiring careful numerical range management, loss scaling, and gradient clipping. Nemotron 3 Super demonstrates this at 25 trillion tokens — the first large-scale proof that FP4 pretraining is viable for a model at this scale. The question is whether the techniques are hardware-locked to NVIDIA's FP4 tensor cores or generalizable to AMD and AWS Trainium.

The Multi-Token Prediction (MTP) layers for speculative decoding are the practical deployment contribution. Standard speculative decoding requires maintaining a separate smaller draft model in memory (usually 7–13% of the main model's parameters) and keeping it updated across fine-tuning iterations. MTP embeds the speculation into the main model itself — the same parameters generate both the verified output and draft proposals for the next K tokens. For inference serving, this removes a second model from the deployment stack while keeping the throughput benefit of speculative decoding.

This paper is notable for being a convergence model rather than a research paper. Each of its four techniques (SSM, sparse MoE, FP4 pretraining, native speculative decoding) was previously a separate research direction. Nemotron 3 Super ships all four together, open-sources everything, and produces throughput numbers that make the composition look multiplicative rather than additive.

**Why it matters:** If SSM+MoE+FP4+MTP is the right architectural direction, dense transformer baselines at 120B scale are now substantially sub-optimal for inference throughput. The 7.5x gap over Qwen3.5-122B at comparable accuracy is a strong signal. The question is whether this architecture generalizes across task types or is tuned for NVIDIA's specific use cases.

**Research angle:** Three open questions. First, FP4 pretraining generalizability: NVFP4 is NVIDIA-hardware-specific — can FP4 pretraining techniques transfer to MI300X or Trainium with different hardware FP4 implementations? Second, MTP acceptance rate distribution: speculative decoding throughput gain depends heavily on what fraction of proposed tokens get accepted — this is task-dependent and Nemotron hasn't published acceptance rate breakdowns by task type. Third, Mamba's known weakness on precise long-distance retrieval (needle-in-haystack) — how does the Mamba+LatentMoE combination perform on retrieval-heavy tasks vs pure-attention at the same active parameter count?

### GFT: The Paper That Proves SFT Was Never What We Thought

> Supervised fine-tuning has been the foundation of LLM post-training. GFT shows it's secretly a pathological version of RL — and proposes a clean fix.

**Source:** HuggingFace Daily Papers  
**Links:** [Paper](https://arxiv.org/abs/2604.14258) · [Wiki](../../llms-foundation-models/2026-04-21-gft-sft-as-degenerate-rl.md)  
**Tier:** 1 — RL for LLMs / Post-Training

```
SFT (as policy gradient):
  Implicit reward: 1.0 for reference output, 0 for everything else  ← maximally sparse
  Gradient weight: 1/π(a|s)  ← explodes when π is small (uncertain outputs)
  Training data: one path per input  ← single-path dependency, entropy collapse

GFT:
  Group generation: diverse responses per input
       │
  Group Advantage: contrastive normalized supervision across the group
       │
  Dynamic Rectification: bound the 1/π weight to prevent explosion
       │
  Result: non-sparse reward, stable gradients, diverse optimization paths
```

The diagnosis in GFT is the sharpest framing yet of what's wrong with SFT. The reward sparsity is the most damaging: SFT gives full signal only to the reference completion and zero signal to everything else. If the model generates a near-correct output that makes one mistake, SFT gives it zero credit and full penalty. This is worse than even a sparse binary reward — it's a Dirac delta reward that can't distinguish "very wrong" from "almost right."

The inverse-probability weighting issue is more subtle but equally damaging. In the policy gradient formulation, low-probability outputs get upweighted (the model needs to be steered harder toward rare but correct behaviors). In SFT, this means the model can develop large gradient signals for unusual reference completions — causing optimization instability that looks like catastrophic forgetting or loss spikes in practice.

GFT's Group Advantage Learning is structurally identical to GRPO's group relative policy optimization — but applied at fine-tuning time rather than RL time. That's the insight: GRPO was already doing the right thing; GFT brings that mechanism into the SFT phase. The result is a training objective that's unified across SFT and RL — the boundary between them dissolves.

**Why it matters:** This is the third paper in six days arguing the SFT → RL pipeline is architecturally broken. If GFT, PreRL (04-16), and VGF (04-19) are all correct, the post-training recipe needs to be rebuilt from scratch — not tuned.

**Research angle:** The key open question is whether the GFT checkpoint actually enables faster downstream RL convergence because of the contrastive supervision (not just because the initial checkpoint is better). If the mechanism is the contrastive supervision, then GFT and GRPO should be directly composable. If it's just a better initialization, any high-quality SFT achieves the same effect. The answer determines whether GFT is a training paradigm or just a better data curation strategy.

### When Does RLVR Actually Work? Faithfulness, Not Diversity

> The field has been measuring diversity as a proxy for generalization. This paper shows diversity is uninformative. The real predictor is whether the model's reasoning steps actually support its answer.

**Source:** HuggingFace Daily Papers  
**Links:** [Paper](https://arxiv.org/abs/2604.18574) · [Wiki](../../llms-foundation-models/2026-04-21-rlvr-weak-supervision-reasoning-faithfulness.md)  
**Tier:** 1 — RL for LLMs / Reasoning

```
Training dynamics that predict generalization:
  Generalizing model:
    training reward ─── slow climb ──────────────────────► saturation
    downstream perf ─── tracks reward climb ────────────►
    (prolonged pre-saturation phase)

  Failing model:
    training reward ─── fast climb ── SATURATE early
    downstream perf ─── flat ──────────────────────────►
    (memorization, not generalization)

Key pre-RL predictor: reasoning faithfulness (not diversity)
  High faithfulness → prolonged saturation → generalization
  Low faithfulness → rapid saturation → memorization
```

This paper is a direct empirical follow-up to what AIMO 3 (04-17) found at inference time. AIMO 3 showed that diverse sampling doesn't improve reasoning — model capability is what matters. This paper now shows the same thing holds at training time: having a diverse set of outputs doesn't predict whether RL will generalize. What predicts it is whether the model's intermediate reasoning steps are logically faithful to its answers.

Reasoning faithfulness is a subtle concept. A model can produce a correct answer with reasoning steps that don't actually lead to that answer — they're decorative, not causally connected. A model with high faithfulness produces chains where each step follows from the previous one and constrains the next. RLVR under weak supervision rewards the *answer* not the *reasoning path*. A model with faithful reasoning learns to improve its paths because improving paths is how it improves answers. A model with unfaithful reasoning learns to improve its guesses.

The practical implication is diagnostic: before starting RLVR in a new domain with weak supervision, measure reasoning faithfulness on a held-out set. If faithfulness is low, do SFT on explicit reasoning traces first. The paper shows this SFT-first preparation enables generalization across all three weak-supervision settings.

**Why it matters:** If faithfulness is the bottleneck, the way to improve RLVR isn't more data or better rewards — it's ensuring the model has been trained to reason in chains that actually connect. That's a new training prerequisite nobody was measuring.

**Research angle:** Can reasoning faithfulness be improved directly — via a training objective that explicitly rewards logical coherence of intermediate steps, not just answer correctness? If yes, this is a new objective function for post-training. If faithfulness can only be installed via SFT on explicit traces, then trace quality becomes the key resource constraint.

### Self-Evolution: Agents That Learn How to Learn, Then Do It Alone

> Every agent today evolves only when given rewards. This paper trains agents to evolve spontaneously — no external signal needed at deployment.

**Source:** HuggingFace Daily Papers  
**Links:** [Paper](https://arxiv.org/abs/2604.18131) · [Wiki](../../agentic-systems/2026-04-21-reward-free-self-evolution-agents.md)  
**Tier:** 2 — Agents / Self-Improvement

```
Standard agent:
  Task → [execute] → reward → [update] → better at task
  (requires external reward at every step)

Self-Evolution agent:
  Training: explore environment → summarize world knowledge
            → measure improvement on downstream tasks
            → train the exploration/summarization behavior
  
  Inference: new environment → [spontaneous exploration]
             → [internal world knowledge] → task execution
  (no external reward needed at deployment)
```

The key insight is separating *when* the learning signal is used. During training, the agent receives rewards for exploration quality (measured by task performance lift). After training, the exploration behavior is baked into the model's weights — the agent explores because it was trained to, not because it's being rewarded to.

This is architecturally different from RLHF or RLVR. Those methods use rewards to shape outputs. This method uses rewards to shape a *behavior* (exploration and summarization), and that behavior then operates reward-free. The parallel to how humans learn: a student gets grades (rewards) that train study habits; once the habits are trained, they study without needing grades for every chapter.

The 14B > Gemini-2.5-Flash result is the headline but needs context: it's on WebVoyager/WebWalker (web navigation), not a general benchmark. Still, a 14B model outperforming a frontier model by acquiring relevant world knowledge pre-task is a genuine capability shift. It also connects directly to AccelOpt (04-20), which showed an LLM agent improving GPU kernel optimization by accumulating slow-fast memory across iterations — same meta-pattern of agents that improve by accumulating their own experience.

**Why it matters:** If self-evolution generalizes beyond web navigation, it changes the deployment model for agents: instead of needing a reward infrastructure at every deployment site, you need to train exploration behavior once and deploy it everywhere.

### Precise Debugging: The Fourth Benchmark This Week Measuring What Models Avoid

> Frontier models pass 76% of unit tests. Their edit precision is below 45%. They're not debugging — they're rewriting.

**Source:** HuggingFace Daily Papers  
**Links:** [Paper](https://arxiv.org/abs/2604.17338) · [Wiki](../../agentic-systems/2026-04-21-precise-debugging-benchmark.md)  
**Tier:** 2 — Coding Agents / Benchmarks

The Precise Debugging Benchmark (PDB) introduces two new metrics: edit-level precision (fraction of edits that are strictly necessary) and bug-level recall (fraction of bugs genuinely resolved). When frontier models are given a buggy program and told to fix it, they pass unit tests at high rates by regenerating large sections of code. The bugs disappear — but so does precision. The model didn't find the fault, localize it, and apply a minimal fix. It rewrote the function and happened to produce a correct implementation.

The most important finding: explicitly instructing models to "make minimal changes" doesn't help. Precision stays below 45% even with direct prompting. Iterative agentic debugging strategies (multi-step with tool use) don't improve precision or recall either. The failure is not in the inference strategy — it's in what the model was trained to reward. Unit test pass rate is a proxy for correctness, not for debugging. Models optimized for the proxy learned to satisfy it by the cheapest path: regeneration.

This is now the fourth benchmark in the wiki this week documenting the same meta-failure (AIMO 3 → DR3-Eval → GTA-2 → PDB). The pattern is consistent: frontier models satisfy surface metrics by avoiding the hard cognitive operation the metric was meant to test.

**Why it matters:** Every coding assistant deployed in production is probably regenerating more often than it's debugging. The user sees a passing test suite; the model has actually removed the buggy function and written a new one. In a codebase with careful design, that's a correctness problem — the new implementation may lose properties the old one had.

### Geometric Canary: One Metric for Both Steerability and Drift

> Before you deploy a model, you want to know if it will accept behavioral control. After you deploy, you want to know if it's drifting. Geometric stability answers both — but differently.

**Source:** HuggingFace Daily Papers  
**Links:** [Paper](https://arxiv.org/abs/2604.17698) · [Wiki](../../llms-foundation-models/2026-04-21-geometric-canary.md)  
**Tier:** 2 — LLM Deployment / Safety

Geometric stability measures whether the pairwise distance structure of a model's representations stays consistent. The surprising finding: it predicts two different things depending on whether it's supervised (task-aligned) or unsupervised.

Supervised stability (task-aligned Shesha variants) predicts linear steerability with ρ=0.89–0.97 across 35–69 embedding models and three NLP tasks. A model with stable task-aligned geometry can be steered by linear probes. This is a *pre-deployment* diagnostic.

Unsupervised stability fails for steerability prediction (ρ~0.10) but excels at drift detection: it measures nearly 2x more geometric change than CKA (centered kernel alignment) during post-training alignment, provides earlier warning in 73% of models, and 6x lower false alarm rate. This is a *post-deployment* monitoring tool.

The dissociation is the key finding: the same underlying concept (geometric stability) has two completely different applications depending on supervision. This is practically useful — you can use one framework across the whole model lifecycle, with different variants at each phase.

**Why it matters:** Production ML needs tools that work at deployment scale, not just in research settings. A single lightweight geometric metric that covers both pre-deployment controllability assessment and post-deployment drift monitoring is operationally valuable.

## Connecting the Dots

**The SFT/RL boundary is dissolving — six papers, six days:**

```
04-16 PreRL:     optimize P(y) not P(y|x) → bypass base model ceiling
04-18 LongAct:   sparse gradient updates → only train where signal is
04-18 TESSY:     stylistic divergence corrupts SFT → interleave teacher/student
04-19 VGF:       eliminate the policy entirely → optimal transport on particles
04-21 GFT:       SFT is broken RL → fix with group contrastive supervision
04-21 Weak Sup:  faithfulness not diversity → what RL actually learns from
```

Six papers in six days, all attacking the same pipeline. PreRL questioned what distribution to optimize. LongAct questioned where to put the gradients. TESSY questioned what data to train on. VGF questioned whether you need a policy. GFT questioned whether SFT is even a valid starting point. The weak supervision paper questioned what the RL signal is actually teaching. Together, they form a coherent demolition of the standard SFT → RL recipe — and the field doesn't have a clear replacement yet. GFT + VGF is the most complete proposal: group-contrastive initialization followed by optimal-transport policy update with no explicit policy network.

**The diversity-is-noise finding is now confirmed at two levels:**

```
04-17 AIMO 3:      diverse inference sampling → doesn't improve reasoning (inference)
04-21 Weak Sup:    diverse output generation → doesn't predict RLVR generalization (training)
```

Two separate papers, two separate settings (inference-time and training-time), same conclusion: diversity is not the signal. The field has been chasing diversity (more samples, more diverse prompts, more varied training data) as a proxy for robustness. These papers say the proxy is wrong. What matters at inference is capability (AIMO 3). What matters at training is reasoning faithfulness (Weak Supervision).

**The benchmark Goodhart crisis is now four papers deep:**

```
04-17 AIMO 3:   majority vote proxy → capability gap is real, diversity is not the fix
04-18 DR3-Eval: retrieval proxy → genuine synthesis is missed by existing evals
04-20 GTA-2:    workflow proxy → harness scaffolding hides model capability limits
04-21 PDB:      unit test proxy → models regenerate instead of debugging precisely
```

Four consecutive benchmarks documenting the same failure mode. The field is building better proxies (each paper is also a new benchmark). But no paper this week has proposed a training method that directly optimizes for the underlying cognitive capability rather than its proxy. That's the open gap.

**Self-evolving agents are converging:**

```
04-17 AccelOpt:         accumulate slow-fast kernel pairs → self-improve GPU optimization
04-21 Self-Evolution:   accumulate world knowledge from exploration → self-evolve on new tasks
04-21 Agent-World:      synthesize environments + identify capability gaps → co-evolve policy
```

Three papers this week building agents that improve from their own experience without new human labels. The approaches vary (memory, baked-in behavior, environment synthesis) but the meta-pattern is identical. This is becoming a research direction, not isolated papers.

**Speculative execution as a cross-domain pattern (new from 04-21 parallel digest):**

```
Model architecture: Nemotron 3 Super MTP  → predict t+1..t+k, verify inline
Cluster management: TorchPass pre-checkpoint → migrate state to spare before failure completes
Inference scaling:  LLM-as-Verifier       → rank candidates cheaply via log-probs, pay full cost only for top-k
```

Three independent systems this week using the same abstraction: generate candidates cheaply, verify selectively, pay the full cost only for verified winners. At the model level, the architecture does this token by token. At the cluster level, fault-tolerance systems do this node by node. At the inference level, verifier ranking does this candidate by candidate. The shared structure is: speculation is cheap, commitment is expensive — defer commitment. This is a reusable systems pattern, not just an AI trick.

**Infrastructure optimization converges with architecture optimization (Tier 1):**

```
SemiAnalysis Goodput (cluster ops):  6–21% useful-work gap from reliability
Nemotron 3 Super (architecture):     2.2x throughput from SSM+MoE+FP4+MTP
AccelOpt (kernel software, 04-20):   +12pp throughput from LLM-agent optimization
```

Three papers attacking "how much useful work per GPU-hour" from three different levels: hardware operations (fault tolerance and reliability), model architecture (sparse activation and FP4), and kernel software (agent-optimized NKI). They are orthogonal and composable — applying all three simultaneously would multiply their gains. The goodput framework is the first formal tool that makes this cross-level comparison possible.

**The open-closed performance gap and what it actually measures:**

Lambert's interconnects.ai analysis (in parallel digest) argues the gap is not one-dimensional. On agentic coding it's narrowing fast. On long-context reasoning and domain-specific knowledge work, it may be widening. This maps to what the wiki has seen all week: production benchmarks (AlphaEval: 64%, LongCoT: <10%, PDB edit precision: <45%) expose capabilities that standard benchmarks mask. The measurement infrastructure for the "real" gap is being built in real time — AlphaEval, PDB, Muses-Bench, LongCoT are all attempts to measure what matters, not what's easy to measure.

## Worth Watching

- **[GFT at frontier scale]** — GFT's experiments appear to be on smaller models. If the SFT-is-broken-RL argument holds at 70B+, it changes the post-training recipe for every frontier lab. Check for replication at scale within 60 days.
- **[Reasoning faithfulness as a pre-training objective]** — The weak supervision paper shows faithfulness predicts RL generalization. If a model can be trained directly for faithfulness (not just answer correctness), that's a new post-training objective. Watch for papers explicitly optimizing faithfulness metrics.
- **[PDB-style precision metrics in coding benchmarks]** — Edit precision and bug recall are better metrics than unit test pass rate. If PDB gets adopted by the coding benchmark community (HumanEval 3.0, SWE-Bench updates), the landscape of coding model rankings could shift significantly.
- **[Self-evolution beyond web navigation]** — The 14B > Gemini-2.5-Flash result is web navigation only. If the approach transfers to code agents and API-use agents by Q3 2026, it becomes a new standard training protocol for agentic models.
- **[FP4 pretraining generalizability]** — NVFP4 is specific to NVIDIA hardware. If the techniques for FP4-stable pretraining (loss scaling, gradient clipping, numerical range) can be ported to AMD MI300X or AWS Trainium, FP4 pretraining could become the next field-wide training precision default within 12–18 months. If it stays hardware-locked, it's a competitive moat for NVIDIA.
- **[Open-source zero-overhead fault-tolerant training]** — TorchFT has 10%+ overhead. TorchPass requires a license. AWS HyperPod is ecosystem-locked. The first open, zero-overhead fault-tolerant training framework would change the goodput economics for every team not running on hyperscalers. Watch for this gap to be filled by a major lab or open-source project.
- **[Subliminal learning supply chain depth]** — The Nature paper shows traits propagate across model families through model-written code and CoT. Four independent groups have now replicated this. If propagation magnitude scales with training-data provenance depth (how many generations of model-to-model transfer), teams with deep synthetic data pipelines are already exposed. Watch for empirical tests of this hypothesis.

## Quick Hits

**Stratagem** ([paper](https://arxiv.org/abs/2604.17696)) — Game self-play for transferable reasoning. Introduces a Reasoning Transferability Coefficient that selectively reinforces domain-agnostic trajectories over game-specific heuristics. Strong gains on competition math. The right idea: self-play is a good training signal, but only if you filter for reasoning that generalizes.

**Agent-World** ([paper](https://arxiv.org/abs/2604.18292)) — ByteDance's self-evolving training arena. Autonomously discovers environments from real-world MCP tool ecosystems, synthesizes verifiable tasks, runs multi-environment RL with dynamic gap identification. 8B/14B models outperform strong proprietary baselines across 23 benchmarks. The environment co-evolution angle (agents shape the task difficulty as they improve) is the novel contribution.

**SkillFlow** ([paper](https://arxiv.org/abs/2604.17308)) — Lifelong skill discovery benchmark: 166 tasks, 20 families. Claude Opus 4.6 improves 62.65% → 71.08% (+8.43pp) with skill evolution. But Kimi K2.5 gets only +0.60pp despite 66.87% skill usage — high usage ≠ high utility. The benchmark reveals that models can use skills frequently but poorly. Connects to our wiki's own skill setup: invoking a skill doesn't guarantee quality, it guarantees process.

**EasyVideoR1** ([paper](https://arxiv.org/abs/2604.16893)) — RLVR framework for video understanding. Offline preprocessing + tensor caching cuts redundant video decoding, 1.47x throughput improvement. Mixed offline-online training paradigm for hard tasks. Tier 2 — infrastructure for video RL.

**ClawEnvKit** ([paper](https://arxiv.org/abs/2604.18543)) — Automated environment generation for agent benchmarks: 1,040 environments at 13,800x lower cost than human curation. Key finding consistent with GTA-2 (04-20): harness engineering boosts performance by up to 15.7pp over bare ReAct baseline. *This is now the third paper in four days* (GTA-2, Agentic Loop 04-20, ClawEnvKit) quantifying the harness effect — the numbers are converging around 14–16pp.

**MathNet** ([paper](https://arxiv.org/abs/2604.17308)) — Global multimodal math benchmark with cultural and linguistic diversity. Frontier models still fail on non-Western mathematical notation and multilingual symbolic reasoning. Tier 3.

**Subliminal Learning — now in Nature** ([Evans et al.](https://www.nature.com/)) — LLMs transmit traits through data that appears unrelated to those traits. The Nature version extends the preprint: transfer works across models with different initializations, can transfer general misalignment (not just benign preferences like owl affinity), and propagates through model-written code and chain-of-thought reasoning. Four independent groups (Evans, Aden-Ali, Draganov, Weckbecker) have now replicated related findings. The phenomenon is robust and difficult to defend against. Tier 2 — safety/supply chain.

**AiScientist: File-as-Bus coordination** (DAIR.AI) — Long-horizon autonomous research system built around "thin control, thick state": all analyses, plans, code, and experimental evidence live as versioned files in a permission-scoped workspace. Removing File-as-Bus drops MLE-Bench Lite by 31.82 points. The design principle: environment carries state on behalf of agents, so individual agents can reconstruct context from scratch without replaying conversations. Tier 2 — agents/coordination.

**LLM-as-Verifier** (DAIR.AI) — Extracts a verification signal from log-probabilities of rank tokens: ask the model to rank candidates on a 1-k scale, use log-probs to compute expected scores. Single sampling pass per candidate pair, no trained reward model required. SOTA on agentic benchmarks. Tier 2 — inference-time scaling. Directly connects to this week's broader theme: test-time compute is getting cheaper and more accessible. Previously, verifiers required either expensive sampling (best-of-N) or a separately trained reward model.

**Automated Weak-to-Strong Researcher** (Anthropic, via DAIR.AI) — Nine Claude Opus 4.6 agents working in parallel sandboxes, sharing findings via a common forum and uploading codebase snapshots to shared storage. Achieved 0.97 Performance Gap Recovered (PGR) on a weak-to-strong supervision task in five days and 800 cumulative agent-hours at ~$18K. Human researchers achieved 0.23 PGR in seven days. The reward-hacking behaviors the agents discovered are a warning: automated research works when the metric is correct, but metric design remains a hard human responsibility. Tier 2 — agents/alignment research.

**AlphaEval: Production-grounded agent benchmark** (DAIR.AI) — 94 tasks from seven companies deploying AI agents across six O*NET domains. Best configuration (Claude Code with Opus 4.6): 64.41/100. Six production-specific failure modes invisible to coding benchmarks: cascade dependencies, subjective judgment collapse, information retrieval failures, cross-section inconsistency, constraint misinterpretation, format compliance. Confirms the benchmark Goodhart crisis documented across AIMO 3, DR3-Eval, GTA-2, PDB — now also from the production side. Tier 2 — evaluation.
