# cere-bro | 2026-04-22

> The KV cache is now being attacked from two directions simultaneously — and neither approach looks temporary.

---

## TL;DR

- **TurboQuant** — Google (ICLR 2026): 6x KV cache compression at 2.5 bits/channel, near-zero quality loss, no offline calibration. Community vLLM integrations already appearing despite no official release.
- **PrfaaS** — Moonshot AI + Tsinghua: hybrid-attention models shrink KV cache 13–36x, making cross-datacenter prefill disaggregation economically viable. 54% throughput gain, 50% lower mean TTFT.
- **ml-intern** — HuggingFace: first open-source agent to close the full post-training loop. Reads papers, discovers/generates datasets, trains via GRPO, evaluates, iterates. Qwen3-1.7B: 10%→32% GPQA in under 10 hours.
- **TEMPO** — test-time training with EM-guided critic recalibration prevents reward drift. Qwen3-14B: 42.3%→65.8% AIME 2024.
- **CoT degrades spatial reasoning** — across 17 models and 13 benchmarks, chain-of-thought consistently *hurts* visual-spatial performance. No-Image++ ablation: models hallucinate from text priors, not image parsing.
- **Amazon → $33B Anthropic; Anthropic → $100B AWS**: the circular capital deal is now the largest infrastructure commitment in AI to date.

## The Big Picture

Two papers today attack the same bottleneck at different layers of the stack. TurboQuant compresses the KV cache representation — fewer bits per vector. PrfaaS changes the serving topology — move prefill computation across datacenters because hybrid-attention models produce caches small enough to ship over Ethernet. These are not competing approaches. They are composable. A production system could run a hybrid-attention model (enabling PrfaaS disaggregation) with TurboQuant compression on its remaining full-attention layers. The combined effect would be something like a 78x cache volume reduction versus a dense-attention baseline. Nobody has measured this yet, but the pieces exist.

The more important signal is what the convergence implies: memory bandwidth, not compute, is now the primary bottleneck in long-context inference. This has been the implicit conclusion of every major KV cache paper this year — KV Packet (04-17) for reuse, LongAct (04-18) for selective gradient targeting, TurboQuant and PrfaaS today for compression and topology. The research community has agreed on the diagnosis. The question now is which solution or combination becomes the production standard.

A second pattern solidifies today. "Train rich, infer lean" — spend training compute on expensive supervision structures, then discard them at inference — now has three instantiations in 24 hours: OneVL (auxiliary decoders discarded after training), CompreSSM (start at 128 dimensions, prune to 12 during training), and ShadowPEFT (shadow module detachable for edge deployment). Three papers making the same architectural bet in one batch is not a coincidence. The field has converged on the insight that training-time overparameterization is cheaper than inference-time complexity.

### TurboQuant: Online Vector Quantization for KV Cache Compression

> Random rotation transforms an unruly distribution into one that quantizers can actually optimize for — no calibration data required.

**Source:** Google, ICLR 2026  
**Links:** [Paper](https://arxiv.org/abs/2504.19874) · [Wiki](../../inference-efficiency/2026-04-22-turbo-quant-kv-cache-quantization.md)  
**Tier:** 1 — KV Cache / Compression

```
Input KV vector
     │
  Random rotation (input-agnostic, computed once)
     │
  Concentrated Beta distribution on coordinates
     │
  Optimal scalar quantizer per coordinate (MSE-optimal for Beta)
     │
  1-bit QJL transform on residual (preserves unbiased inner products)
     │
  2.5 bits/channel → 6x+ memory reduction
```

The core problem with quantizing KV cache vectors is that raw attention key/value vectors have awkward, input-specific distributions — optimal scalar quantizers are poorly matched to them. TurboQuant's solution is elegant: apply a random rotation. Rotation is information-preserving (unitary transform), and it shapes the coordinate distribution into a predictable Beta distribution regardless of the original vector. Once the distribution is predictable, you can compute an analytically optimal scalar quantizer without a calibration pass. The 1-bit QJL transform on the residual is not just a cleanup step — it ensures the inner products that attention actually computes remain unbiased, so quality degradation stays minimal.

The results: 3.5 bits/channel gives absolute quality neutrality; 2.5 bits gives marginal degradation but 6x memory reduction. The "online" property — no calibration data, quantizer derived purely from the rotation — is what makes this deployment-ready. LoRA-style quantizers require a calibration set that may not generalize. TurboQuant doesn't.

The absence of an official implementation from Google despite ICLR acceptance is notable. Community vLLM and llama.cpp integrations are already appearing, which means production uptake will not wait for official release. The gap between research quality and community-maintained integration quality is a real risk here.

**Why it matters:** A 6x KV cache reduction changes the economics of long-context inference at every scale — from local inference (more sequences per GPU) to cloud serving (fewer GPUs for the same throughput).

**Research angle:** Does TurboQuant's quality guarantee hold across attention variants? Dense MHA is the test case. GQA and MQA share key/value heads across query groups — the rotation properties may differ. And the composability question: TurboQuant plus PrfaaS plus KV Packet reuse would be the full compression stack. Nobody has measured the combined effect.

### PrfaaS: Cross-Datacenter Prefill Disaggregation

> Hybrid-attention models produce 13x less KV cache per token — enough to make shipping it over Ethernet faster than computing it locally.

**Source:** Moonshot AI + Tsinghua University  
**Links:** [Paper](https://arxiv.org/abs/2604.15039) · [Wiki](../../inference-efficiency/2026-04-22-prfaas-cross-datacenter-prefill.md)  
**Tier:** 1 — KV Cache / GPU Optimization / Inference Serving

```
User request (long prompt)
       │
  [Prefill cluster — compute-dense, separate datacenter]
  Hybrid-attention model (most layers are linear-complexity)
  Produces compressed KV: 4.66 Gbps vs 59.93 Gbps for dense
       │
  Transfer over commodity Ethernet (~13x less volume)
       │
  [Decode cluster — memory-bandwidth-optimized, production DC]
  Receives KV cache, runs autoregressive decode
       │
  Output tokens streamed to user
```

Prefill and decode have different hardware requirements: prefill is compute-intensive (process the entire prompt in parallel), decode is memory-bandwidth-intensive (one token per step). Separating them to matched hardware is the natural optimization. PrfaaS extends that split across a WAN link — previously impractical because dense-attention models produce KV caches at full dimensionality for every layer, flooding the WAN.

Hybrid-attention models (Kimi Linear, MiMo-V2-Flash, Qwen3.5-397B) interleave a small number of full-attention layers with a larger number of linear-complexity layers that produce tiny or zero KV state. MiMo-V2-Flash produces cache at 4.66 Gbps versus 59.93 Gbps for dense-attention MiniMax-M2.5 — a 13x reduction that puts cross-datacenter transfer inside commodity Ethernet bandwidth. The result: 54% throughput improvement and 50% mean TTFT reduction versus homogeneous baselines.

This paper validates a prediction made in the 04-21 Nemotron 3 Super deep dive, which flagged hybrid-attention models (specifically their Mamba blocks) as having an underappreciated serving advantage due to smaller state sizes. PrfaaS is the concrete systems paper that quantifies that advantage and builds a serving architecture around it. Architecture choice is now a serving economics decision.

**Why it matters:** If PrfaaS-style disaggregation becomes standard, it creates a feedback loop: models with smaller KV caches get better serving economics, which creates incentive to prefer hybrid-attention architectures, which enables further disaggregation.

**Research angle:** Two open questions with real production implications. First, P99 TTFT under network jitter — mean TTFT is 50% better, but tail latency under variable WAN conditions determines SLA compliance. Second, interaction with TurboQuant: if TurboQuant compresses the already-small MiMo-V2-Flash cache before cross-datacenter transfer, does it compound to ~78x reduction, and does quality hold?

### ml-intern: The Agentic Post-Training Loop

> An agent that doesn't just assist researchers — it runs the research loop itself.

**Source:** HuggingFace  
**Links:** [GitHub](https://github.com/huggingface/ml-intern) · [Wiki](../../agents-tool-use/2026-04-22-ml-intern-agentic-posttraining.md)  
**Tier:** 2 — Agents / Agentic Reasoning

```
ml-intern continuous loop:
  [Read] arXiv papers, traverse citation graphs
       │
  [Discover] HuggingFace Hub datasets, quality-check them
       │
  Quality insufficient? → [Generate] synthetic training examples
       │
  [Train] launch GRPO-based training via HuggingFace Jobs
       │
  [Evaluate] read benchmark outputs, diagnose failures
       │
  Performance not satisfactory? → back to Read/Generate
       │
  [Track] Trackio open-source experiment tracking
```

ml-intern is built on smolagents and closes a loop that has always required human ML engineers: decide what to read, assess available training data, fill gaps with synthetic generation, launch training, interpret evaluation results, and iterate. In the launch demo, it took Qwen3-1.7B from 10% to 32% GPQA in under 10 hours. The synthetic data generation step is the most consequential: when the healthcare domain test found insufficient training data, ml-intern didn't surface the gap — it wrote a script to generate examples targeting medical hedging language and multilingual emergency response. That previously required human domain expertise.

The comparison to Claude Code (which scores 22.99% on the same benchmark) is provocative but needs careful reading. ml-intern ran an iterative training-and-evaluation loop. Claude Code is a coding assistant. Different task framings. The more meaningful comparison is what a 1.7B model reaches with versus without the loop.

This paper connects directly to SimpleTES (also 04-22), which frames scientific discovery as "scale the evaluation loop." ml-intern instantiates that thesis: the agent's power is not in any single forward pass but in the quality of its feedback loop. Both papers are independent evidence of the same insight: the evaluation function is what enables improvement.

**Why it matters:** The first open-source tool that closes the full post-training loop without human intervention. The implications for the "who runs ML research" question are non-trivial.

### TEMPO: Test-Time Training That Doesn't Plateau

> Prior test-time training methods only run the E-step. TEMPO adds the M-step — and sustained improvement follows.

**Source:** HuggingFace Daily Papers  
**Links:** [Paper](https://arxiv.org/abs/2604.19295) · [Wiki](../../llms-foundation-models/2026-04-22-tempo-test-time-training.md)  
**Tier:** 2 — LLM Training / RL for LLMs

```
Standard TTT (plateaus quickly):
  policy generates rollouts on test query
  ↓ reward model scores them   ← reward model not updated; drifts
  ↓ policy update
  (repeat → fast saturation, diversity collapse)

TEMPO:
  [E-step] policy update on unlabeled test queries
  ↓
  [M-step] critic recalibration on labeled calibration set ← the missing piece
  ↓
  [E-step] policy update again
  (alternating → sustained improvement, diversity preserved)
```

The saturation problem in test-time training has the same root cause as the RLVR saturation failure mode documented in the 04-21 digest: the reward signal goes stale as the policy changes. The RLVR Faithfulness paper (04-21) showed that rapid reward saturation during *training* predicts failure to generalize. TEMPO provides a mechanism to prevent the same failure at *inference time* — keep the critic calibrated by periodically running an M-step on a labeled calibration set, so it stays aligned with the current policy.

The EM framing is the key insight. Existing TTT methods are "incomplete EM" — they only run E-steps (reward evaluation), never M-steps (critic recalibration). The ELBO tightening analysis explains why periodic M-steps prevent plateau: without them, the E-step is evaluating a policy the reward model no longer understands. The numbers are strong: OLMO3-7B from 33% to 51.1% AIME 2024; Qwen3-14B from 42.3% to 65.8%.

Connection to GFT (04-21): GFT argued that SFT's implicit reward is too sparse to distinguish degrees of correctness. TEMPO shows that even a good initial reward eventually goes stale without active management. Both papers argue the reward signal is not a static artifact — it needs maintenance.

**Why it matters:** If the EM framing of TTT generalizes, it gives a principled recipe for any online adaptation scenario where the evaluator is learned: keep the evaluator updated as often as the policy.

### SDVG: Speculative Decoding Crosses Into Video

> No discrete tokens, no exact probability matching — but the speculative pattern still works, with image quality as the acceptance criterion.

**Source:** HuggingFace Daily Papers  
**Links:** [Paper](https://arxiv.org/abs/2604.17397) · [Wiki](../../inference-efficiency/2026-04-22-sdvg-speculative-decoding-video.md)  
**Tier:** 2 — Inference Efficiency / Speculative Decoding

Text speculative decoding works because you can compute exact token probabilities and use rejection sampling to guarantee the output distribution matches the target model. Video generation has neither: blocks are continuous spatiotemporal tensors, not discrete tokens. SDVG solves this by replacing probability matching with a quality router. A 1.3B drafter generates candidate video blocks in 4 denoising steps. ImageReward scores each block using worst-frame aggregation (minimum per-frame score, not mean — one corrupted frame fails the batch). Blocks above threshold enter the 14B target's KV cache directly; rejected blocks are regenerated by the target model. Result: 1.59x speedup at 98.1% quality; 2.09x at 95.7%.

This extends the speculative decoding abstraction to a continuous domain. The pattern — generate cheap, verify with a quality signal, commit verified winners — now appears at four levels of the stack within two days: token generation (Nemotron MTP, 04-21), cluster fault tolerance (TorchPass, 04-21 parallel digest), GPU kernel optimization (AccelOpt, 04-20), and video block generation (SDVG, 04-22). The abstraction generalizes beyond its original setting whenever you have a cheap approximator and an expensive oracle with a verifiable quality criterion.

**Why it matters:** Opens speculative decoding to any generative modality where a quality metric can serve as the acceptance criterion. Audio, 3D, protein structure — same pattern applies.

### Chain-of-Thought Degrades Visual Spatial Reasoning

> 17 models. 13 benchmarks. CoT consistently makes spatial reasoning worse. The models are using language shortcuts, not parsing images.

**Source:** HuggingFace Daily Papers  
**Links:** [Paper](https://arxiv.org/abs/2604.16060) · [Wiki](../../llms-foundation-models/2026-04-22-chain-of-thought-degrades-spatial.md)  
**Tier:** 2 — LLM Capabilities / Evaluation

CoT prompting is not a universal reasoning enhancer. Across 17 models and 13 spatial benchmarks, it consistently *degrades* visual spatial performance. The key diagnostic is the No-Image++ ablation: remove the image entirely and models still generate plausible-sounding spatial answers from text priors alone. They're hallucinating visual details from language patterns, not parsing the image. Models with stronger language CoT (reasoning models) often score *worse* on spatial tasks than vanilla multimodal models.

This is the same phenomenon that Geometric Canary (04-21) flagged at the representation level: supervised stability (how consistently the model's internal geometry shifts under prompts) predicted steerability. The No-Image++ result is the behavioral manifestation of that geometric observation — the model "passes" spatial benchmarks via language shortcuts without actually engaging visual processing.

This paper directly validates OneVL (parallel digest, 04-22). OneVL proposed latent CoT: train with dual decoders (language + visual world model), then discard both at inference. The latent tokens retain CoT-level intelligence without the text verbosity that crowds out visual processing. Today's paper provides the empirical motivation for why this matters: explicit text CoT is actively interfering with spatial cognition, not just being inefficient. The two papers together — why it fails and how to fix it — arrived in the same digest.

This is now the fifth paper in the wiki documenting models satisfying benchmark surface metrics via language shortcuts without solving the underlying cognitive operation. PDB (04-21, debugging), Geometric Canary (04-21, representation geometry), GTA-2 (04-20, tool agents), DR3-Eval (04-18, research synthesis), and now this for spatial reasoning.

**Why it matters:** CoT fine-tuning on spatial tasks is not just ineffective — it may be actively training the wrong capability.

### OneVL + CompreSSM: The Parallel Digest's Train-Rich-Infer-Lean Pair

> Train with expensive scaffolding. Discard it. Keep only the intelligence it leaves behind.

**Source:** Parallel Daily Digest 2026-04-22  
**Links:** OneVL [Paper](https://arxiv.org/abs/2604.18486) · CompreSSM [Paper](https://arxiv.org/abs/2510.02823)  
**Tier:** 2 — Architecture / Inference Efficiency

**OneVL** (Xiaomi Embodied Intelligence) trains a vision-language-action model with two auxiliary decoders: a language decoder that reconstructs chain-of-thought text, and a visual world model decoder that predicts future-frame tokens. Both decoders are discarded at inference. The latent tokens, shaped by dual supervision during training, encode both reasoning and visual prediction without generating explicit text. OneVL becomes the first latent CoT method to surpass explicit CoT on accuracy while maintaining answer-only latency across four autonomous driving benchmarks. Today's CoT-degrades-spatial paper explains exactly why this matters: the latent approach avoids the text verbosity that crowds out visual processing.

**CompreSSM** (MIT, ICLR 2026) applies balanced truncation — a classical control-theoretic technique — to state-space models during training. It identifies and removes low-influence states based on Hankel singular values, then continues training in the compressed space. Crucially, models trained starting large and then compressed outperform models trained directly at the target size. On Mamba: 128-dimensional model compressed to ~12 dimensions during training, ~4x training speedup, competitive accuracy. This is the same train-rich-infer-lean logic from a completely different angle: start overparameterized, exploit the extra capacity to learn better representations, then prune.

Together with ShadowPEFT (also 04-22, detachable shadow module for edge), this is now three papers in one batch instantiating the same principle. The pattern is established.

**Why it matters:** Train-rich-infer-lean is becoming the dominant architectural philosophy for models that need to serve in resource-constrained settings. The training compute overhead is the price; inference efficiency is the reward.

## Worth Watching

- **TurboQuant + PrfaaS composition** — has anyone measured the combined cache volume reduction on a hybrid-attention model with TurboQuant applied to full-attention layers? The theoretical answer is ~78x versus dense-attention baseline, but the quality holdout at that compression level is unknown. Watch for a combined implementation in vLLM.

- **SDVG threshold adaptation** — the acceptance threshold is fixed. A content-adaptive or learned threshold should improve the quality/speed tradeoff on diverse video content. If someone trains a video-native quality router (instead of ImageReward), the 2.09x speedup ceiling will rise.

- **ml-intern healthcare demo** — synthetic data generation for medical edge cases was qualitatively described but not benchmarked. Does the quality hold at scale? How does ml-intern behave when the evaluation metric is noisy or adversarially gameable (reward hacking)? This is the open problem the Automated Weak-to-Strong Researcher paper (04-21) explicitly warned about.

- **Train-rich-infer-lean generalization** — all three instantiations (OneVL, CompreSSM, ShadowPEFT) are in relatively narrow domains (embodied AI, SSMs, PEFT). The pattern generalizes if large language models benefit from auxiliary decoders during training and can then be stripped. This is testable: add a code-quality decoder to a coding model, train with GRPO, ablate at inference. If it works, the pattern is general.

## Quick Hits

**ShadowPEFT** ([arxiv 2604.19254](https://arxiv.org/abs/2604.19254)) — centralized PEFT via a single depth-shared shadow module instead of per-layer LoRA. Matches/outperforms LoRA and DoRA at same parameter budget; independently pretrainable; detachable for edge deployment. The third instantiation of train-rich-infer-lean today. → [summary](../../inference-efficiency/2026-04-22-shadowpeft-centralized-layer-space.md)

**SimpleTES** ([arxiv 2604.19341](https://arxiv.org/abs/2604.19341)) — evaluation-driven scaling for scientific discovery: parallel exploration + feedback refinement + local selection. 2x LASSO speedup, 24.5% quantum circuit gate reduction, new Erdős constructions. GPT-OSS models, not frontier — the evaluation loop structure matters more than model quality. → [summary](../../agents-tool-use/2026-04-22-evaluation-driven-scaling-scientific.md)

**AgentSPEX** ([arxiv 2604.13346](https://arxiv.org/abs/2604.13346)) — declarative YAML-based language for agent workflow specification. Decouples workflow logic from Python; typed steps, branching, parallel execution, explicit state management; sandboxed harness with checkpointing. Directly addresses the harness-engineering gap that GTA-2 (04-20) documented as accounting for up to 15.7pp of agent performance variance. → [summary](../../agents-tool-use/2026-04-22-agentspex-workflow-language.md)

**NAG-based pretraining data selection** ([arxiv 2604.15706](https://arxiv.org/abs/2604.15706)) — training-free selection via neuron-activated graph: characterize target inputs by sparse high-impact neurons, select pretraining data that activates those neurons. +4.9% over random, +5.3% over SOTA on HellaSwag. → [summary](../../llms-foundation-models/2026-04-22-target-pretraining-nag.md)

**OrthoReg / Task Arithmetic** ([arxiv 2604.17078](https://arxiv.org/abs/2604.17078)) — adds geometric analysis to why task arithmetic works: Task-Feature Specialization (distinct internal features per task) causes weight orthogonality. OrthoReg enforces orthogonality during fine-tuning and consistently improves task arithmetic methods. Tier 3.

**UDM-GRPO** ([arxiv 2604.18518](https://arxiv.org/abs/2604.18518)) — first RL framework for uniform discrete diffusion models. Naive GRPO application causes instability; UDM-GRPO treats the final clean sample as the action and reconstructs trajectories via forward diffusion. GenEval 69%→96%. Tier 3.

**Cognitive Penalty** ([arxiv 2604.16913](https://arxiv.org/abs/2604.16913)) — System 2 reasoning (extended chain-of-thought) *hurts* reliability in DAO governance contexts. Autoregressive baseline (System 1) achieves 100% adversarial robustness; System 2 introduces 26.7% reasoning non-convergence and 17x latency overhead. Corroborates today's CoT-degrades-spatial finding in a completely different domain. Tier 4.
