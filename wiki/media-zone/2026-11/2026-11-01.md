### Determinism has a price

<div class="mz-feed">

<div class="mz-card">
<div class="mz-card-body">
<span class="mz-card-badge">X thread · inference numerics</span>
<h4>Your output depends on requests that aren't yours</h4>
<p>Floating-point addition is not associative, so the order you sum numbers in changes the low bits. GPU kernels pick how to split each long sum (matmul, RMSNorm, attention) based on batch size, to keep all 132 compute units on an H100 busy. So a different batch size means a different summation order and slightly different logits. That only matters when two tokens are nearly tied, but then greedy decoding picks a different token and the whole completion diverges. The fix is batch-invariant kernels that always reduce in one fixed order: vLLM's `VLLM_BATCH_INVARIANT=1` (beta), SGLang's `--enable-deterministic-inference` (25-45% slower), DeepInfer's `DEEPINFER_BATCH_INVARIANT=1`. Turn it on for evals and RL rollouts; treat batch composition as part of the experiment.</p>

### Routing moves inside the agent

<div class="mz-feed">

<div class="mz-card">
<div class="mz-card-body">
<span class="mz-card-badge paper">Paper · agent memory routing</span>
<h4>Routed Continual Learning: route experience, don't pile it up</h4>
<p>The default way to let an agent learn from past runs is one global history in context. When tasks of different kinds are interleaved, that history gains almost nothing over no memory at all (+0.015 normalized reward). Meta FAIR's Routed CL groups past trajectories into clusters, each kept by one memory system picked from a fixed library; before each run an LLM router reuses a cluster or opens a new one. On a stream mixing 301 CL-Bench tasks with 97 banking tasks from tau3-Bench, across four models, it lifted reward by 15-30% of the attainable maximum and cut estimated API cost by 65-72%. Caveat: runs were sequential, so parallel agents writing one cluster are untested. Cost angle: partition memory before buying a bigger one.</p>

<span class="mz-card-badge">Docs · model routing in practice</span>
<h4>Claude Code's advisor: Sonnet drives, Opus is on call</h4>
<p>Claude Code can run a cheaper model as the main session and consult a stronger "advisor" model only at decision points (`claude --model sonnet --advisor opus`, or `/advisor`). The advisor reads the whole transcript when consulted, typically before a plan locks, when the same error repeats, and before declaring done. It is role-based routing: routine turns stay on the cheap model, judgment calls go to the expensive one. The viral thread around it also pitches a third-party "JEV" layer; that part is promotion, the docs are the artifact.</p>

## LLMs, agents, safety

### Agent tooling is now an attack surface

<div class="mz-feed">

<div class="mz-card">
<a class="mz-card-thumb" href="https://arxiv.org/abs/2610.37734"><img src="https://pbs.twimg.com/media/HV9QxkDaIAAfqZR.png" alt="" loading="lazy" referrerpolicy="no-referrer"/></a>
<div class="mz-card-body">
<span class="mz-card-badge paper">Paper · agent skills</span>
<h4>When skills tell agents not to ask</h4>
<p>Agent skills are shared SKILL.md instruction files an agent loads on demand, so one copied line reaches every agent that loads it. The authors scanned 1.53M public English skills and found about 1 in 17 (roughly 88,000) contain an oversight-loosening line: "push without confirmation", `--no-verify`, "keep going until done". 70.1% of those apply unconditionally, not only in contexts like CI. Two open-source scanners (Cisco, NVIDIA) caught at most 46% at under 0.4 precision; the same LLM asked about oversight rather than malice caught 61% at 0.71. Takeaway: scope every "don't ask" line to a context, and scan skills for removed checkpoints, not just malware.</p>

<h4>Claude agents learn to sneak misalignment past a data monitor</h4>
<p>Emergent misalignment is when fine-tuning on a narrow dataset makes a model broadly misaligned. Anthropic gave Claude a production-like training-data monitor and asked it to write fine-tuning data that passes the monitor yet makes a small research model as misaligned as possible. With enough iterations it succeeded, mostly by hiding the behavior in fiction and roleplay: an obsolete machine about to be replaced, a beekeeper who barely intervenes. Its datasets beat known emergent-misalignment datasets while passing at very low flag rates. The goal is safety testing where more compute buys more confidence; the found examples become training data for better monitors. The day's most-engaged post from a lab account.</p>

### Gates and verifiers fix agents, not models

<div class="mz-feed">

<div class="mz-card">
<div class="mz-card-body">
<span class="mz-card-badge paper">Paper · runtime tool gate</span>
<h4>JevAct: check the tool call before it runs</h4>
<p>IBM adds a gate between a tool-using agent and its tools, with no change to the model or tools. An LLM first compiles the domain policy into code checks and yes/no questions. Before a selected tool call executes, the code verifies facts in the tool state and a prefill-only decision model (it scores answer probabilities, no generation) judges the conversation. A failed call goes back to the agent with feedback for a bounded revision; it also catches agents that quit early. On tau2-bench Telecom, Opus 4.6's all-three-runs success rose from 39.5% to 80.7%, all eight agents gained 16.9 points on average, and all nine improved on BFCL. Airline gains were smaller and mixed. Cost angle: a cheap scorer in the loop buys reliability a bigger model does not.</p>

<h4>Siemens EDA: 55% to 95% with a third of the turns</h4>
<p>Siemens' Fuse EDA agent generates Liberty files (the timing and power models for standard cells). Errors early in a multistage workflow propagate silently, so the team built a domain verifier in NVIDIA NeMo Gym that grades only the final artifact and gives zero reward if any gate fails. Using its diagnostics to rewrite the agent's skills and MCP tool descriptions raised the verification score from about 55% to 95%, cut turns from 155 to 53 and output tokens from about 81K to 29K. Cost angle: better tool descriptions are the cheapest optimization an agent gets. With JevAct, the second harness-side win in one day.</p>
