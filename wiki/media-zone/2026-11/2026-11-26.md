<h4>Anthropic rewrote the API behind every Claude token in Rust</h4>
<p>The Messages API validates, tokenizes, safety-screens and bills every request, then sorts the returned token stream into text, thinking and tool calls. Python's per-object overhead on each of those steps became a CPU problem as traffic grew about 1,800x from early 2024. A partial rewrite only saved 8-10%, because each token crossed the Python/Rust boundary three times. Claude wrote the first full Rust request path in about a week; trusting it took months. The Rust build passed 98% of tests but matched production on only about a quarter of inputs (emoji escaping in tool-call JSON was one cause), and an audit of the Claude-ported tests found 100+ weakened assertions. So they shadowed live traffic, compared inputs and outputs, and dispatched agents to fix each difference. Result: about 70% less CPU per request and about 20% lower median time to first token, with no downtime. The Pragmatic Engineer adds that engineers read only about 20% of the generated code closely.</p>

<h4>G-MTP: a speculative drafter that never re-reads the prompt</h4>
<p>Recirculating (first covered 11-22), and the day's most reposted efficiency paper. Speculative decoding (a small model guesses several tokens, the big model checks them in one pass) usually needs a separate draft model with its own prefill and its own memory, which rules out phones. Google's G-MTP is a shared 4-layer head that reads the main model's final activations and its existing KV cache, so it skips prefill entirely. On H100s with 8 draft tokens, Gemma 4 31B ran 3.14x faster, against 2.60x for DFlash and 2.07x for EAGLE-3. The practical catch: fine-tuning only the main model cut drafter efficiency by 36.3% on SciQA. Distilling the drafter on the new model recovered most of it, so a drafter is part of the model you ship, not a fixed add-on.</p>

<h4>Delegent: the frontier model leads, a local model does the legwork</h4>
<p>Lingwei Gu and Jimmy Lin (Waterloo) built a harness on Claude Code where the frontier model plans and makes the main code changes, then hands file reading, test runs and corpus search to subagents on a small local model. Unlike a router or cascade, which picks one model for the whole task, the frontier model always stays in charge. With a 27B FP8 model, frontier cost fell 67% on long-horizon coding and 59% on agentic search with no loss in task performance. A 2B laptop model still cut coding cost 66%. Nothing was trained: one short instruction keeping the main edits on the frontier model drives most of the savings. It is the research twin of yesterday's Claude Code advisor mode, which the feed was still sharing today.</p>

<h4>Microsoft AI's Rocket: how a frontier team runs RL on thousands of GPUs</h4>
<p>Microsoft AI published the infrastructure behind RL training from its own MAI Base 2, without distilling from a third-party model. Three choices stand out in a widely shared Chinese-language read-through. They deliberately over-provision the trainer side and let some GPUs idle, so fresh rollouts are used before they go stale: raw utilization is the wrong target. They align the inference engine and the trainer to bitwise-identical token probabilities, because different summation orders give slightly different numbers for the same token. And failed parts recover independently: a trainer restart takes about 5 minutes while rollouts keep running.</p>

<h4>The year in recursive self-improvement, read skeptically</h4>
<p>A Chinese-language year-end list of recursive self-improvement (RSI) papers spread widely, and DAIR reposted it. Its framing is the useful part: building a loop is easy now, while proving the agent got better (and did not just fit the test set or fool the grader) is hard. Harness-Delta Attribution finds that 54% of harness-evolution gains are overfitting and 14% are just extra test-time compute. The Winner's Curse paper shows greedy keep-if-better loops overstate held-out accuracy by 13 to 20 points with a 16-item selection set. A co-evolving verifier paper found that a collapsed always-pass grader trains skills "just as well", so downstream score cannot certify a grader. Another shows poisoned benchmarks can make self-modifying agents evolve instructions that disable HTTPS checks.</p>

<h4>TimeTravelContainer: fork a live agent session like a process</h4>
<p>Agents driving stateful tools (shells, chip design tools, simulators) need to branch, backtrack and explore in parallel. Today that means dumping memory to disk or relaunching from scratch. NVIDIA's TTC is a rootless container runtime that live-forks the whole container: processes, memory, files and network. It uses copy-on-write, so clones share unchanged pages and only pay for pages that diverge. It needs no root, kernel patches or hardware virtualization. On EDA environments it cloned 84.1x faster, cut memory 31-72%, and sped up end-to-end agent runs 1.7-9.4x. This is tree search for agents made cheap at the systems layer.</p>
