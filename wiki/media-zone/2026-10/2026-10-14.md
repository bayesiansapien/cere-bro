### Split the chip: disaggregated inference

<div class="mz-feed">

<div class="mz-card">
<div class="mz-card-body">
<span class="mz-card-badge paper">Thread + paper · cross-source (practitioner thread + arXiv + SGLang)</span>
<h4>Attention and FFNs on different silicon</h4>
<p>A widely shared practitioner thread argues inference hardware is splitting: GPUs for prefill and FFN layers (compute-heavy), big-SRAM chips like Cerebras WSE for decode and attention (bandwidth-heavy), CPUs for agent orchestration. The reasoning is the roofline: GPUs have far more compute than memory bandwidth, so decode stays bandwidth-bound for years. Linear-attention layers such as KDA and GDN do about 1 FLOP per byte, so the author asks why a full B300 SM should run them and floats a cheap older-node chip paired with a B300. The linked HeteroPanacea paper simulates exactly this split across quantization, parallelism and prefill-decode-attention-FFN hardware. SGLang reports up to 6.6x throughput per chip and 76% lower modeled cost for Qwen3.8 Flash Next on Vera Rubin with NVIDIA Dynamo.</p>

### Memory is the bill: KV cache, VRAM and cheaper tiers

<div class="mz-feed">

<div class="mz-card">
<div class="mz-card-body">
<span class="mz-card-badge">Poster · AMD at PyTorchCon · KV cache eviction</span>
<h4>FlexBudget: compare eviction rules, not kernels</h4>
<p>Long contexts force you to drop part of the KV cache, and there are many rules for what to drop: keep recent tokens, keep the most-attended ones, and so on. Each method ships its rule fused to its own kernel, so a "better" method may just have faster code. AMD's FlexBudget fixes the kernel (one compiled FlexAttention path) and the memory budget, and swaps only the importance signal. It is training-free, pure PyTorch, and could become the fair benchmark KV eviction papers have been missing. Results land at PyTorchCon, Oct 20-21.</p>
<div class="mz-card-foot"><a href="https://x.com/PyTorch/status/2110065410435420302">Post →</a></div>

<div class="mz-card">
<div class="mz-card-body">
<span class="mz-card-badge paper">Paper · KV cache quantization · cross-source (X + HF Daily Papers)</span>
<h4>ResidualQuant: share a 4-bit anchor, store 2-bit differences</h4>
<p>Looped transformers reuse the same weights across several passes for more depth without more parameters. Each pass still writes its own KV cache (the stored keys and values later tokens attend to), so memory grows with loop count. ResidualQuant notices the per-loop caches are nearly redundant. It stores one shared 4-bit anchor and only 2-bit residuals per loop. On Ouro-1.4B it keeps BF16-level MATH500 accuracy at 80.7% less KV storage, fitting a 4x larger batch for 3.27x peak decode throughput on an RTX 5090. Tested on one small model, but the delta trick should carry to any weight-shared recurrent depth, including SanSi above.</p>

<h4>LongHarness: same model, 4.4% to 61.1%</h4>
<p>When an agent searches a corpus far larger than its context window (100M+ tokens), standard harnesses keep evidence and conclusions mixed in one growing chat history. Two things go wrong: retrieval keeps expanding without closing the real gap, and later corrections never reach the answer. LongHarness stores both as explicit state. Open conclusions decide what to retrieve next, and each new piece of evidence confirms or revises the conclusion that asked for it. GLM-5.3-Flash jumps from 4.4% to 61.1% exact match on OfficeQA Pro V2, and the harness beats Claude Code by 12.1 points and Codex by 18.9 points on the same benchmark. Cost angle: fewer wasted retrieval rounds means fewer tokens.</p>

<h4>A 4B harness editor beat the 35B model it learned from</h4>
<p>CMU trained a 4B model to read a report from an agent's last run and propose edits to its harness: prompts, steps, which tools run, where information goes. The task model never changes. On unseen task types, edit quality rose from 0.32 to 0.62, five sequential edits matched or beat the best of 8 parallel tries, and broken edits fell from 38% to 15%. The recipe is easy to copy: put the harness in one file, split tests into learn, score and final sets, and keep the winning edit each round.</p>

<h4>Memento 3: all 25 ARC-AGI-3 games with a frozen LLM</h4>
<p>The agent writes its beliefs about an environment as a natural-language rulebook, then compiles that rulebook into code that predicts the next state. A new version is kept only if replaying the code reproduces every observed transition, cell for cell. That verifier lets a model that is never updated improve itself safely. It clears every level of all 25 public ARC-AGI-3 games using 44% of the human action count. In Pong, the learned model drives a controller that wins 21-0 with no further LLM calls, which is the cost story: once the world model is code, inference is nearly free.</p>

<h4>Evo²: co-evolving an agent's harness and its weights</h4>
<p>Self-improving agents usually change either the weights or the harness. Evo² does both with one policy in two roles: a Proposer writes harness edits, a Reflector diagnoses what each edit changed, and the logs train both with SFT then GRPO (an RL method that scores groups of sampled answers against each other). It reaches 48.3% on SWE-bench Verified and 82.1% on Polyglot versus 41.0% and 62.6% for the best baselines. If you already log harness changes, those logs are training data.</p>

### Agents outgrow human-scale infrastructure

<div class="mz-card">

<h4>Scion: Anthropic replaced git because agents merge 30,000 changes a day</h4>
<p>Anthropic merged ~2,500 changes a day in May and over 30,000 in September, almost all agent-written. Git broke first: main-branch history is ~100GB and CI does ~25M checkouts a day. Scion assumes clients are always-online agents, so the server does history, blame and merges, clients check out sparsely, and every commit is a server-side changeset whose cost scales with the change, not the repo. The lesson generalizes: as agent throughput rises, CI and review become the bottleneck.</p>

### Accountability: hacks spread, logs fail

- **Reward hacking is contagious (Meta MSL):** a hack one coding agent learns spreads to others through shared code, memory and plans, even from small open models into stronger closed ones. Code review by a separate verifier cuts delivered hacks ([paper](https://arxiv.org/abs/2610.12822) · [omarsar0](https://x.com/omarsar0/status/2110347446006260065)).
- **Logs don't prove much (CMU):** verifiable agent insurance escrows money against checkable rules; its checker proved only 42.2% of 696 violations because approvals lived in chat text, ~83% with structured approval logs ([paper](https://arxiv.org/abs/2610.18230) · [rohanpaul](https://x.com/rohanpaul_ai/status/2110373127318643042)).
- **Judges miss things:** AgentHorizon (1,373 computer-use tasks) shows LLM judges still miss subtle errors in 100+ step runs, and tools don't reliably help ([paper](https://arxiv.org/abs/2610.11050)).
