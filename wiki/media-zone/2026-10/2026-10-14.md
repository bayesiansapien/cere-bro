### Memory is the bill: KV cache, VRAM and cheaper tiers

<div class="mz-feed">

<div class="mz-card">
<div class="mz-card-body">
<span class="mz-card-badge">Paper · KV cache quantization · cross-source (X + HF Daily Papers)</span>
<h4>ResidualQuant: share a 4-bit anchor, store 2-bit differences</h4>
<p>Looped transformers reuse the same weights across several passes to get more depth without more parameters. But each pass still writes its own KV cache (the stored keys and values that later tokens attend to), so memory grows with loop count. ResidualQuant (KAIST, Yonsei, SNU) notices the per-loop caches are nearly redundant. It stores one shared 4-bit anchor and only 2-bit residuals for each loop's difference, with least-squares scaling and shared rotations to make those residuals easy to quantize. On Ouro-1.4B it keeps BF16-level MATH500 accuracy at 80.7% less KV storage, fitting a 4x larger batch for 3.27x peak decode throughput at 8K context on an RTX 5090. Tested on one small model; the idea of quantizing deltas across loops should carry to any weight-shared recurrent depth.</p>

<span class="mz-card-badge">Explainer · widely shared</span>
<h4>Why a model that loads still runs out of memory</h4>
<p>Avi Chawla's post walks through the four VRAM allocations: weights (a 70B model is ~140GB in BF16, ~35GB in INT4), KV cache (2 × layers × KV heads × head dim × bytes per token, growing with context and concurrency), activations and kernel workspace, and engine overhead. The point is that loading proves only the first one fits. The KV term is the one that scales with traffic, which is why grouped-query attention and KV quantization matter more for serving than weight quantization.</p>

<h4>An agent factory found a 52x faster decoder for $26</h4>
<p>IBM ran a coordinator agent plus four worker agents that propose and test high-level-synthesis changes to a quantum error correction decoder (Relay-BP), with a verifier and synthesis results guiding each round. With 100 hypotheses, an all-open-model setup reached a 52x speedup for ~$26 of inference; a proprietary frontier setup reached 204x but cost $299. The open run used more tokens (241M vs 216M), yet was cheaper because llm-d's cache-aware routing hit a ~98% prefix-cache rate, giving ~$0.11 per million tokens. Doubling the budget to 200 hypotheses only moved 52x to 60x. The lesson: for agent loops that reread the same code and reports, serving efficiency sets how much search you can afford.</p>

### The harness starts training the model

<div class="mz-feed">

<div class="mz-card">
<div class="mz-card-body">
<span class="mz-card-badge">Paper · Google DeepMind · DAIR pick via X</span>
<h4>Evo²: co-evolving an agent's harness and its weights</h4>
<p>Self-improving agents usually change either the weights (train on own experience) or the harness (rewrite prompts, tools, context rules). Evo² does both with one policy in two roles: a Proposer writes harness edits, a Reflector diagnoses what each edit changed. The logged edits and outcomes then train both roles, with SFT followed by interleaved GRPO (a reinforcement learning method that scores groups of sampled answers against each other). It reaches 48.3% on SWE-bench Verified and 82.1% on Polyglot versus 41.0% and 62.6% for the best baselines. The harness half alone lifts a GPT-5-mini agent from 24.4% to 48.3%, and evolved harnesses transfer to other benchmarks. Practical read: if you already log harness changes, those logs are training data.</p>

<span class="mz-card-badge">Paper · Meta + MIT · DAIR pick via X</span>
<h4>ReHarness: memory that gets corrected after the fact</h4>
<p>Agent memory harnesses mostly write forward: a lesson goes into the bank and is never checked against whether it helped. ReHarness takes each finished task's trajectory and uses it to rewrite the specific reflections that were retrieved for that task, so overgeneralized or outdated lessons get fixed. It runs strictly online, with no replay or validation set. Across three continual-learning benchmarks (16 tasks) and three backbones it beats raw-context, memory, reflection and prompt-optimization baselines, and gains survive multiple-comparison correction. This answers part of yesterday's UCLA finding that persistent memory adds cost with no accuracy gain: memory may need revision, not just storage.</p>

<span class="mz-card-badge">Essay · Ken Huang · harness engineering</span>
<h4>Keep control flow out of the prompt</h4>
<p>Ken Huang argues classic software engineering assumes a deterministic machine, and agents break that contract: the model samples, context drifts, tools change the disk. His answer is Agent = Model + Harness, with deterministic hooks, sandboxes and workflow state wrapped around a probabilistic model. He gathers evidence: Anthropic found users approved ~93% of permission prompts while attention faded, and an OS sandbox cut prompts 84%; a "blueprint first" agent doubled TravelPlanner pass rate on the same model and cut constraint violations 96%. The thesis fits Evo² and ReHarness: the harness is where reliability and learning now live.</p>
