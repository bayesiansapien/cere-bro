<span class="mz-card-badge paper">Paper · efficient attention taxonomy</span>
<h4>MiTA: attention is a temporary MLP, so route it or shrink it</h4>
<p>Self-attention can be read as a two-layer MLP whose weights are the keys and values, built fresh for every input, with softmax as the activation. Its hidden width equals the sequence length, which is why it gets more expressive and more expensive as context grows. The paper sorts efficient attention into a five-axis taxonomy where every method either routes tokens to part of that MLP (MoE attention, top-k, sparse selection) or compresses it (linear attention). MiTA does both: a few landmark queries gather top-k key-value pairs as flexible routed experts, plus a narrow shared expert. Tests are vision-only so far. Pedro Domingos' one-line version ("an attention head is a fast-weight MLP") and a Chinese-language thread that framed DSA-style sparse attention as MoE routing carried it.</p>

<span class="mz-card-badge paper">Paper · numerics</span>
<h4>Softmax and cross-entropy have two rounding bugs</h4>
<p>Google DeepMind's Barron, Gnanapragasam and Tschannen show that the standard "subtract the max logit" softmax still breaks. When one logit is far ahead (a margin of about 5.5 in bf16, 16.6 in fp32), the target gradient rounds to exactly zero while the others stay positive. In distillation, the gradient should vanish as the student matches the teacher, but it stalls at a noise floor and pushes the student away. Computing the small residual directly fixes both, removes "slingshot" loss spikes in grokking runs and keeps students on their teachers. Toy scale only, but it is a few lines in the loss kernel. The day's most-shared paper among researchers, carried by alphaXiv and Christian Szegedy.</p>

<span class="mz-card-badge">Explainer · KV cache quantization</span>
<h4>Six ways to shrink the KV cache, and why weight quant doesn't</h4>
<p>Quantizing weights leaves the KV cache (the stored keys and values of past tokens) at 16 bits, and that cache grows with context and concurrency. The thread walks through FP8 caches, INT8/INT4, scale granularity, KIVI (keys grouped per channel, values per token, usable at 2 bits without fine-tuning), mixed precision that keeps recent tokens sharp, and outlier-aware schemes. Its key caveat matches the MiniMax KV4 result from 10-23: a smaller cache fits more requests but does not guarantee faster decode, so measure quality and latency against an unquantized cache.</p>

<h4>Hy-Nomas: a world model that lives in its KV cache</h4>
<p>Tencent's open interactive video world model generates one segment at a time. <h4>An 8B tool picker beats a 402B model</h4>
<p>When an agent has more than 10,000 tools, their descriptions cannot fit in context and a retriever can only rank by relevance. Meta and Carnegie Mellon train small Qwen3 models to plan substeps, retrieve candidates for each, and commit one tool per substep, first with SFT on about 20,000 ToolBench instructions, then RL that rewards covering the right tools at a good rank. The point: tool selection is a routing step that does not need a frontier model.</p>

### Simple beats elaborate

<span class="mz-card-badge paper">Paper · agent memory (HF + DAIR)</span>
<h4>Naive RAG beats agentic memory systems</h4>
<p>Raw-RAG is just dense retrieval plus reranking over the untouched conversation history. Across four long-term memory benchmarks it ranks first in six of seven settings, ahead of Mem0, MemOS and Memora, and ingests in 0.3 hours instead of 3.2 to 27. The reason is evidence: rewriting history into memory entries drops the relations and dependency paths an answer needs, and readers do worse even with full access to the rewritten stores. Elvis Saravia's "RAG is so back" post made it the most-shared agent paper of the day. Run this baseline before adding a memory layer.</p>

<h4>Fold your subagents back into the main loop</h4>
<p>Anthropic's agent-building note says many enterprise systems end up copying the org chart, one subagent per department and a dispatcher on top, and lose detail at every handoff. One main loop that loads skills and tools on demand often works better; a customer ran about 2x faster after merging. The warning is concrete: merging a customer-service subagent broke a task that used to pass, because the main agent skipped asking the logistics specialist for delivery times. Validate every merge with end-to-end evals, and keep subagents for parallel research, independent checks and context isolation.</p>
