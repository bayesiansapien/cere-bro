### The memory bill keeps climbing

- **HBM breaks the memory price curve (cost).** A widely shared forecast puts HBM at about $35/GB by 2030, more than double today, with a possible ~$640B market. Memory usually gets cheaper as volume grows. HBM4 is getting harder to make.
- **HBM4 takes half the demand by 2027.** HBM4 and HBM4E are projected to reach 48% of HBM demand as Nvidia Rubin ships. Older HBM3E 8-Hi also doubles its share to 17%, which the poster reads as custom ASICs widening the market.
- **Nvidia wants the HBM base die on TSMC 3nm (new tonight).** Nvidia reportedly requires Samsung, Micron and SK hynix to build the logic base die of its next custom HBM at TSMC. That lets Nvidia swap memory suppliers as prices rise, and TSMC wins whichever one gets the order.
- **Nvidia's take per gigawatt doubled.** Jensen Huang says Nvidia's revenue opportunity per gigawatt of AI capacity is now over $40B, from selling CPUs, networking and full systems, not just GPUs. Ethernet switching is reportedly growing 49% a year against 36% for AI servers.
- **China's power-chip build-out.** A widely reposted count has China building about 69 power-semiconductor fabs across 58 suppliers, amplified by Elon Musk. Power devices are the unglamorous half of datacenter electrification.
- **Process research to watch.** The Semiconductor Newsletter's weekly monitor flags that pulsed-plasma etch recipes do not transfer between chamber sizes, a university-built 13.5 nm EUV source for resist screening (615 exposures so far), and La-rich ALD coatings that cut chamber erosion by over 75% ([newsletter](https://thesemiconductornewsletter.substack.com/p/weekly-monitor-on-semiconductor-process-265)).

### Placing compute well: co-design and cheap planners

<div class="mz-feed">

<div class="mz-card">
<div class="mz-card-body">
<span class="mz-card-badge paper">arXiv 2610.22230 · Meta</span>
<h4>Meta on AMD MI350X: redesign beats port by 1.5x</h4>
<p>Meta runs NVIDIA, AMD and its own MTIA chips side by side, but years of CUDA-specific tuning make models run poorly when moved as-is. Using recommendation training on MI350X against B200, the paper gives three rules: reshape the model around the chip (MI350X has 1.6x the HBM of B200), pick kernels with an analytical performance model instead of warm-up tuning, and use agentic workflows to port CUDA code and write chip-aware kernels. The result is up to 1.5x training throughput over a direct port. Meta calls it the first hyperscaler report on AMD training in production, and the work is upstreamed to PyTorch, Triton and ROCm. Picked up quietly off a small paper-curation account.</p>

<h4>Coding-agent teams: cheap models should only plan</h4>
<p>Teams of coding agents beat a solo agent but cost 3 to 7 times more. <span class="mz-card-badge paper">arXiv 2610.21375 · Stanford + Toronto · DAIR pick</span>
<h4>Memorilla: a whole document set in 16 tokens</h4>
<p>Long context is expensive because every retrieved document is paid for again in prefill and in KV cache (the stored attention keys and values for every token in context). Memorilla encodes documents once into reusable embeddings. For each query, a learned module gathers what matters from the whole collection and writes it into just 16 "memory tokens" in a frozen LLM's input embedding space. On FactKG it scores 84.33% against 80.43% with the full context, using 108x fewer tokens for the source documents, and it beats Mem0 and MemoRAG on five of eight benchmarks. Used as agent memory over its own growing history, a TextWorld agent's success rose from 18.6% to 24.2% with less wandering. It is soft-prompt compression rather than KV eviction, so the open question is how it holds up on exact-recall tasks where compression usually breaks. Surfaced by Elvis Saravia and DAIR Academy.</p>

<div class="mz-card-body">
<span class="mz-card-badge">X thread · serving explainer</span>
<h4>Continuous batching, explained</h4>
<p>LLM decoding makes one token per sequence per forward pass, and nobody knows a request's length until it emits a stop token. Static batching fixes the batch up front, so a 30-token answer keeps its slot until a 400-token neighbour finishes. The GPU still pays the full weight read from HBM for a mostly empty batch. Continuous batching re-schedules after every pass, so finished requests leave and queued ones join at once. In Anyscale's OPT-13B test on one A100, the gain grew with output-length variance, reaching 23x over naive Hugging Face serving with vLLM. A clear refresher on why serving cost depends on traffic mix.</p>

<h4>A diffusion LLM on AMD's laptop NPU</h4>
<p>AMD engineers ran LLaDA-8B-Instruct, a masked diffusion language model that fills in many tokens in parallel, on the XDNA2 NPU in a Ryzen AI MAX+ 395. At sequence length 128 the NPU took 504 ms per forward pass at 36 W. CPU INT4 took 843 ms at 110 W. That makes the NPU 1.67x faster and 8.9x better on energy. The poster covers the INT4 quantization and graph-partitioning pipeline needed to fit it. Diffusion LMs suit NPUs because prefill-style parallel passes match their dense-matmul design.</p>

### Measuring what agents learn, and what it costs

<div class="mz-feed">

<div class="mz-card">
<div class="mz-card-body">
<span class="mz-card-badge paper">arXiv 2610.08902 · Meta</span>
<h4>Agent Plasticity: self-improvement per dollar</h4>
<p>Most agent benchmarks test a model once. This paper freezes weights and lets agents play chess, Go, Hex and NetHack, rewriting their own tools and notes after each round, then scores them on held-out games. "Plasticity" is held-out gain per dollar of learning cost. Claude Fable 5 rose from 37.5% to 73.3% on hard held-out chess. GPT-5.6 Sol gained 298 points per $1,000 against 57 for Fable 5. The best final agent is not the most efficient learner, and gains often transfer only partly out of distribution.</p>

### Memory and data you can check

<div class="mz-feed">

<div class="mz-card">
<div class="mz-card-body">
<span class="mz-card-badge paper">arXiv 2610.22209 · Amazon</span>
<h4>FEB-30: QA scores hide broken agent memory</h4>
<p>Agent-memory benchmarks grade the final answer, which mixes the memory store with retrieval and answer writing, so a strong LLM can cover for a broken store. Amazon scripted 30 fact histories into 147 documents so the correct memory state is known after each one. On a Mem0/Hindsight-style system, direct state scores and QA scores differed by 16.8 points on average and disagreed on pass/fail for 21% of histories. The system picked the right memory action, such as update or reinforce, only 20.1% of the time. If you ship agent memory, test the stored facts after each update.</p>
