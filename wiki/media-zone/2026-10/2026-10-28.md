## Routing, KV cache, compression, GPU

### Beating the memory wall on a laptop

Local decoding reads every weight once per token, so a 5.2 GB 4-bit 9B model on a 153 GB/s M5 caps out near 29 tok/s no matter how fast the GPU is. The only way past that is more tokens per weight read.

<div class="dg-title">One weight read, 7.5 tokens out</div>
<div class="dg-sub">The big model never stops deciding; it just checks a whole tree of guesses per pass.</div>

## LLMs, agents, safety

### The cheap check wins: verification and memory, priced

<div class="mz-feed">

<div class="mz-card">
<a class="mz-card-thumb" href="https://arxiv.org/abs/2610.34577"><img src="https://pbs.twimg.com/media/HVpZWWRbsAAUVQK.jpg" alt="" loading="lazy" referrerpolicy="no-referrer"/></a>
<div class="mz-card-body">
<span class="mz-card-badge paper">Paper · harness verification</span>
<h4>Where to put the checker in a coding-agent harness</h4>
<p>Alibaba and Cornell compare 17 verification designs across seven frontier coding models. Checks can happen at four points: the first instructions, reminders during the run, a gate before the agent may finish, or an independent critic at the end. Instructions and reminders give small, model-dependent gains. Gates help more but can blow up cost. A separate critic gives the best accuracy per dollar: +5.9 to 9.5 points on Terminal-Bench and +3.9 to 6.6 on SWE-bench Verified, at 1.13 to 1.25x base cost.</p>

<a class="mz-card-thumb" href="https://arxiv.org/abs/2610.34073"><img src="https://pbs.twimg.com/media/HVpXSgvboAAkRGx.jpg" alt="" loading="lazy" referrerpolicy="no-referrer"/></a>
<div class="mz-card-body">
<span class="mz-card-badge paper">Paper · agent memory</span>
<h4>The "memory tax": why agent memory loses to plain RAG</h4>
<p>On LongMemEval, PersonaMem and MINT-Eval, many dedicated memory systems score below naive retrieval over the raw history, and cost more. The paper splits net value into memory benefit (questions memory answers that RAG misses) and memory tax (questions RAG gets that memory loses). The tax comes from rewriting the history, which drops or distorts facts. Retrieving from raw history alongside memory and reranking both cuts it. This is the second paper in two days making this point, after yesterday's Raw-RAG result that plain retrieval over chat history beats agent memory.</p>
<div class="mz-card-foot"><a href="https://arxiv.org/abs/2610.34073">Read the paper →</a></div>

<div class="mz-card">
<div class="mz-card-body">
<span class="mz-card-badge paper">Paper · cheap verifier routing</span>
<h4>Jev-as-a-Judge: a 187x cheaper RAG claim checker, with a catch</h4>
<p>A label-only verifier (Jev) lands within 0.6 points of GPT-6 Astra's accuracy on 495 human-labelled RAG claims, at 187x lower cost. But it approves 23.2% of unsupported claims against Astra's 14.1%. A confidence-gated cascade cut the Astra bill, yet routing the same share at random saved about as much. For routing, that means the confidence gate added nothing over a coin flip. Measure false-approval rate, not headline accuracy.</p>

<div class="mz-card">
<div class="mz-card-body">
<span class="mz-card-badge paper">Paper · failure attribution</span>
<h4>OAT: find the failing agent step by learning only from successes</h4>
<p>OAT trains on about 100 successful trajectories and models how normal agent behavior evolves in latent space, using neural controlled differential equations. On a failed run, each step gets an anomaly score for how far it drifts from that path. It beats GPT-5 prompting by about 20% F1 in-domain and 7% cross-domain. It needs no LLM call at inference, so it runs in milliseconds, 200 to 5000x faster.</p>

### Small specialist models eat document parsing

- **OXR-1.0 (SoMark, 1.3B):** ranks first on olmOCR-Bench, OmniDocBench and DocParsingBench and is the fastest of 21 models tested. A small layout model boxes blocks, the 1.3B reader handles each box ([GitHub](https://github.com/SoMarkAI/OXR), [HF](https://huggingface.co/SoMarkAI/OXR-1.0)).
- **Its training trick is a self-improvement loop:** a general VLM flags wrong or uncertain pages, groups the failure reasons, then generates new labeled pages per group. No human labeling ([@rohanpaul_ai](https://x.com/rohanpaul_ai/status/2115121750535278824)).
- **OCRia-1 (LlamaIndex, 4B):** aims at hard tables (nested headers, merged cells, no borders), with 91.5% on ParseBench and 92.9% on olmOCR-bench ([blog](https://www.llamaindex.ai/blog/parse-ocria-1)).
- **Cost angle:** two sub-5B models topping parsing boards on one 24GB GPU means document ingestion no longer needs a frontier VLM call per page.
