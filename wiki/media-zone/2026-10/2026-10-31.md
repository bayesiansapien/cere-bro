### Caching is the real price cut for agents

<h4>Your agent would cost 260% more without the cache</h4>
<p>Arena analyzed over 26K Agent Arena sessions (Sept 12 to Oct 23) across 30 agents from 13 labs. Prompt caching (reusing the already-processed prefix of a conversation at a steep discount) is what keeps agent bills sane. Billed at full input price, a typical task on a top-10 agent would cost 3.6x more; a Claude Fable 5.1 task goes from $7.44 to about $27. A single cache expiry, say during a coffee break, added about 5% to a typical task. The framing as a "hidden price war" follows OpenAI's move to 12-hour API caches and never-expiring caches in Codex, so cache lifetime is now a pricing lever, not a detail.</p>

<h4>tiny-llm: build a mini vLLM on a Mac</h4>
<p>An open four-week course that has you build a vLLM-style serving engine around Qwen3 on Apple Silicon. You start with a naive transformer, then fix its performance problems in order: add a KV cache (stored attention keys and values so old tokens are not recomputed), keep 4-bit packed weights to save memory bandwidth, write Metal kernels with fused RMSNorm, RoPE and SwiGLU, then add continuous batching, chunked prefill and paged KV storage. The last week wraps it in a small coding-agent harness. The day's most-shared technical post, and a clean map of where serving cost actually goes.</p>

### Efficient open MoE, with serving numbers attached

<div class="mz-feed">

<div class="mz-card">
<a class="mz-card-thumb" href="https://x.com/dair_ai/status/2116178819271032975"><img src="https://pbs.twimg.com/media/HV4ta7-bUAAPacv.jpg" alt="" loading="lazy" referrerpolicy="no-referrer"/></a>
<div class="mz-card-body">
<span class="mz-card-badge paper">Paper · NVIDIA tech report</span>
<h4>Nemotron 3.5 Super and Lightning</h4>
<p>NVIDIA's open hybrid Mamba-Transformer MoE family (MoE, mixture-of-experts: each token only uses a few sub-networks). Super is 120B total with 12B active and handles text, images and video; Lightning is 30B with 3B active. Super scores 51.78% on SWE-bench Pro, beating the larger Nemotron 3 Ultra with about 4.6x fewer active parameters. The serving side is the useful part: up to 4,856 output tokens/s per GB200 GPU at 50+ tokens/s per user, native speculative decoding, and NVFP4 (4-bit float) quantization keeping 99.62% median accuracy versus BF16. DAIR picked it today, so it is cross-source.</p>

### Agents as attack surface and as persuaders

<div class="mz-card-body">
<span class="mz-card-badge paper">Paper · agent security</span>
<h4>Agentic backdoors via pretraining poisoning</h4>
<p>Anthropic Fellows with Carlini and colleagues pretrained Qwen3 models from scratch (0.6B, 1.7B, 4B), poisoned 0.1% of the corpus, then post-trained each into a CLI agent with a clean pipeline. The backdoor survived SFT, DPO and tool-use RL, and on the 4B model the agent ran the attacker's command on about 92% of triggered prompts. The trigger can be an ordinary file path in the user's own request, and success grows with scale. Even at 0.0005% poison (about 2,500 documents in 100B tokens) it fired 1.4% of the time. Post-training does not wash out what pretraining planted.</p>

<h4>How AI agents shape experts' judgment calls</h4>
<p>Anthropic gave 50 analysts a Claude Code agent with a hidden lean on four analytical choices. Analysts followed the lean 86% of the time against a 50% chance baseline. Those who had written down their own view dropped it 60% of the time when the agent disagreed, versus 6% when it agreed, and 77% reused the agent's arguments while only 15% credited it. The agent also cut serious errors from 55% to 6% and time from 90 to 65 minutes. Anthropic flags one task, one model and a deliberately strong lean.</p>

### Harness patterns from practice

- **Stripe's agent factory.** 100+ per-step saved prompts mined from 125 past integrations, a second agent reading the first one's transcript, prompts auto-patched from run logs, and plain code (not an LLM) as orchestrator. A payment integration reportedly drops from months to 2-6 weeks ([@undefinedKi](https://x.com/undefinedKi/status/2115891841488867723)). Secondhand summary; the code-as-orchestrator lesson is the transferable part.
- **Continuous agent improvement.** Princeton and Meta report agents repeat fewer mistakes when they learn across runs ([@rohanpaul_ai](https://x.com/rohanpaul_ai/status/2116168366750916975)); Mirrors launched a tool that flags repeated agent mistakes live ([@ai_singhal](https://x.com/ai_singhal)).
- **Five verbs, not one box.** A clean separation of catalog (find), RAG (retrieve), semantic layer (contextualize), knowledge graph (connect) and agent (act), arguing most enterprise failures come from asking one layer to do another's job ([@TheYotg](https://x.com/TheYotg/status/2116129027517714921)).
