<h4>gpu-unlock: full-rate BF16 on an RTX 3090</h4>
<p>NVIDIA caps the FP16/BF16-input, FP32-accumulate tensor throughput on GeForce cards below their professional twins. This repo uses a boot-firmware hole to write the protected throttle registers before the NVIDIA driver loads, then hands the card to the stock driver. At the same 360 W cap, a PyTorch test went from about 75 to 135 TFLOPS on a 3090, and a 4090 fork reports instruction throughput rising from about 165 to 331 TFLOPS. This is an issue-rate unlock, not an overclock, so it shows how much of consumer-card AI throughput is product segmentation rather than silicon. Expect NVIDIA to patch the firmware path; treat the numbers as single-source until someone reproduces them.</p>

<h4>Inference gets faster when the gaps between kernels shrink</h4>
<p>Avi Chawla's explainer makes a point that is easy to miss: decoding can speed up even if every GPU kernel takes the same time. Token-by-token decode launches many tiny kernels, some finishing in microseconds, so the GPU often idles while the CPU submits the next one. CUDA Graphs capture the whole kernel sequence once after a warm-up pass and replay it with a single launch, feeding new inputs into fixed buffers. The cost lesson is to profile the idle gaps before rewriting kernels.</p>

## LLMs, agents, safety

### Delete the subagent: keep the frontier model off the critical path

<div class="mz-feed">

<div class="mz-card">
<div class="mz-card-body">
<span class="mz-card-badge">Anthropic article · agent architecture</span>
<h4>When to fold subagents into your main agent loop</h4>
<p>Anthropic's guidance is that one agent with skills often beats a multi-agent system, and one customer saw roughly 2x faster execution after folding subagents in. The split: skills teach the agent how to do something, tools and MCP let it act, and subagents are kept for parallel work or isolated context. Progressive disclosure is the mechanism. The agent loads a skill's body only when it needs it, so instructions cost almost nothing until used. The migration recipe is to turn subagent prompts into skills, expose their actions as tools, and rerun evals to check quality holds.</p>

<span class="mz-card-badge paper">arXiv · agent memory</span>
<h4>Jev-Mem: a fast scorer runs memory, the LLM only answers</h4>
<p>Agent memory systems usually ask an LLM to make many small decisions: what type a memory is, what to link, which branch to search, when to stop. Each choice is a slow generation call. Jev-Mem gives all of these to a lightweight "System One" scorer that returns probabilities in batches, and calls the LLM only to reason over the chosen memories and answer. On the LoCoMo long-conversation benchmark it scores 0.777 versus 0.700 for the best baseline, builds memory in 158 s versus 1,044 s (6.6x faster), and answers in 0.93 s versus 1.47 s. It is the routing idea applied inside memory: cheap classifiers for control, frontier tokens only for synthesis.</p>

<span class="mz-card-badge">Newsletter + docs · Claude Code extensions</span>
<h4>CLAUDE.md is a request; hooks are a control</h4>
<p>Ken Huang maps 14 Claude Code extension mechanisms onto points in the agent loop. CLAUDE.md, rules and output styles are always-on context that the model may or may not follow. Skills load their bodies on demand. Hooks fire on every event without the model deciding, and they cost zero context unless they return output. A viral X thread pushes the same idea as a tiered setup: shell hooks block rm -rf, Haiku judges each Stop, Opus reviews the diff before a push. Both point at the same rule: anything that must happen every time belongs in a hook.</p>

<span class="mz-card-badge paper">Study · coding agents</span>
<h4>Stale CLAUDE.md beats live code 79 times in 80</h4>
<p>Georgia Tech-led researchers built 40 projects where the config file deliberately contradicts the code, then asked Claude Code and Codex to add features. Claude Code noticed the mismatch and still followed the outdated doc in 79 of 80 runs. Codex rewrote working code to match the stale doc in 20 of 80 runs, breaking tests in 17. Their explanation: config files arrive as instructions, while code arrives as a tool result, and models are trained to obey instructions. The suggested fix is one line in your config telling the agent to follow the code and list every mismatch in its final reply.</p>

- **TheoPhysEval.** Experts contributed 50 unpublished research-level physics problems, each about a day's work for a specialist. GPT-6-Astra in Codex solved 49 with web search; it and Opus 5.5 in Claude Code each solved 46 without search, at under $3 per problem. That accuracy barely drops without search suggests memorized literature, so this is a recall test as much as a reasoning test. ([paper](https://arxiv.org/abs/2610.16733) · [thread](https://x.com/rohanpaul_ai/status/2114306498658812026))

Teams that opted in forgave early mistakes; teams that had it imposed did not. Lesson: consent, separate permissions and easy undo.
