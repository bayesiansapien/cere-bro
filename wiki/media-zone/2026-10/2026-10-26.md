<h4>RIFT: KV compression that keeps working as the output grows</h4>
<p>Speculative decoding uses a small draft model to guess tokens that the big model then checks in one pass. To fit long prompts, people compress the drafter's KV cache (the stored attention keys and values) by keeping the prompt tokens that score as most important. NVIDIA's team shows that this selection goes stale during decoding: the longer the answer, the less the kept prompt tokens matter, and the drafter's guesses get worse. RIFT refreshes the selection during generation on an adaptive schedule, mixing prompt tokens with recently generated ones, and trains the drafter with sparse attention masks so it tolerates a compressed cache. Qwen3.5-4B drafting for Qwen3.5-122B keeps over 98% of its full-cache acceptance length on 32K-token inputs and 4K-token outputs with an 8K-token budget. It surfaced in DAIR's weekly top-papers post on X.</p>

<h4>Inference gets faster when the gaps between kernels shrink</h4>
<p>Avi Chawla's explainer makes a point that is easy to miss: decoding can speed up even if every GPU kernel takes the same time. Token-by-token decode launches many tiny kernels, some finishing in microseconds, so the GPU often idles while the CPU submits the next one. CUDA Graphs capture the whole kernel sequence once after a warm-up pass and replay it with a single launch, feeding new inputs into fixed buffers. The cost lesson is to profile the idle gaps before rewriting kernels.</p>

### Routing and training-cost notes

- **Claude Code advisor tool (model routing).** A viral thread surfaced the documented `--advisor` flag: a cheaper model such as Sonnet runs the session, and Claude consults a stronger advisor model only at key moments, such as before committing to a plan, on a repeated error, or before declaring done. The advisor reads the full transcript. It is a cascade router built into the harness. The thread's extra "JEV micro-fork" layer is promotion; the docs are the artifact. ([docs](https://code.claude.com/docs/en/advisor) · [thread](https://x.com/xsmryze/status/2114092824190660727))
- **SWE-Verifier (selective verification).** A 4B model decides which coding-agent steps deserve extra candidate sampling and ranks the candidates. It verifies under 4% of steps, adds about 2 points of resolution rate at 1.09-1.13x cost, and matches all-step verification. Spend compute only where a step is risky. ([paper](https://arxiv.org/abs/2610.30284))
- **Muon optimizer explainer (training cost).** A widely shared 18-minute video walks through Muon: orthogonalize the momentum matrix with five Newton-Schulz iterations instead of a full SVD, plus QK-clip, which rescales query and key weights per head when attention logits grow too large. It claims about 2x compute efficiency over AdamW. Promotional framing, but a good primer. ([thread](https://x.com/0xDeliriumm/status/2114109602362958095))
- **freellmapi (routing).** A repo pools 34 free LLM providers and 635 free endpoints behind one OpenAI-compatible endpoint, with failover when a provider hits its rate limit. The viral "800M free tokens" figure is pooled free-tier quota on small models. The value is the router, not free frontier access. ([repo](https://github.com/tashfeenahmed/freellmapi) · [thread](https://x.com/VaibhavSisinty/status/2114311063441420404))
- **Ramp spend data.** Ramp's top 1% of AI spenders send more than a third of their AI budget to raw GPU compute rather than APIs, meaning heavy users increasingly host or tune their own models. ([thread](https://x.com/rohanpaul_ai/status/2114292391079522672))
- **Kimi K3.1 Pro serving cost.** On Interconnects' podcast, Nathan Lambert and Florian Brand note the 3T-parameter model needs one B300 node per replica, versus 700B "Flash"-class models that fit on H200s. Strong benchmarks, but the serving bill will slow adoption. Weights are promised by November 4. ([Interconnects](https://www.interconnects.ai/p/podcast-kimi-k31-pro-the-new-cyber))

- **Where a stuck agent should spend tokens (DAIR pick).** Frontier coding agents choose test feedback 95-100% of the time on a retry and gain less than random; task specs are what help. The allocation decision is the weak link. Covered in today's digest. ([paper](https://arxiv.org/abs/2610.28834))
- **Agentic distillation fixes (DAIR picks).** Three papers say the teacher's per-token score, not the student's drift, breaks agent distillation: SPOD masks it on successful choices, NVIDIA's R2S repairs it with teacher takeovers, Meta's minimal-edit OPD limits it to tokens the teacher would change. ([R2S](https://arxiv.org/abs/2610.28586) · [SPOD](https://arxiv.org/abs/2610.25034) · [minimal-edit](https://arxiv.org/abs/2610.30231))

## LLMs, agents, safety

### Delete the subagent: keep the frontier model off the critical path

<div class="mz-feed">

<div class="mz-card">
<div class="mz-card-body">
<span class="mz-card-badge">Anthropic article · agent architecture</span>
<h4>When to fold subagents into your main agent loop</h4>
<p>Anthropic's guidance is that one agent with skills often beats a multi-agent system, and one customer saw roughly 2x faster execution after folding subagents in. The split: skills teach the agent how to do something, tools and MCP let it act, and subagents are kept for parallel work or isolated context. Progressive disclosure is the mechanism. The agent loads a skill's body only when it needs it, so instructions cost almost nothing until used. The migration recipe is to turn subagent prompts into skills, expose their actions as tools, and rerun evals to check quality holds.</p>

<span class="mz-card-badge paper">arXiv · agent memory</span>
<h4>Jev-Mem: a fast scorer runs memory, the LLM only answers</h4>
<p>Agent memory systems usually ask an LLM to make many small decisions: what type a memory is, what to link, which branch to search, when to stop. Each choice is a slow generation call. Jev-Mem gives all of these to a lightweight "System One" scorer that returns probabilities in batches, and calls the LLM only to reason over the chosen memories and answer. On the LoCoMo long-conversation benchmark it scores 0.777 versus 0.700 for the best baseline, builds memory in 158 s versus 1,044 s (6.6x faster), and answers in 0.93 s versus 1.47 s. It is the routing idea applied inside memory: cheap classifiers for control, frontier tokens only for synthesis.</p>

<h4>CLAUDE.md is a request; hooks are a control</h4>
<p>Ken Huang maps 14 Claude Code extension mechanisms onto points in the agent loop. CLAUDE.md, rules and output styles are always-on context that the model may or may not follow. Skills load their bodies on demand. Hooks fire on every event without the model deciding, and they cost zero context unless they return output. A viral X thread pushes the same idea as a tiered setup: shell hooks block rm -rf, Haiku judges each Stop, Opus reviews the diff before a push. Both point at the same rule: anything that must happen every time belongs in a hook.</p>

<span class="mz-card-badge paper">arXiv · agent debugging</span>
<h4>OAT: find the broken step by learning only what success looks like</h4>
<p>When a long agent run fails, the hard question is which step broke it. Today that means an LLM judge reading the whole trajectory, which is slow and expensive, or a model trained on failures labeled step by step, which are rare. Sharon Li's group (NeurIPS 2026, with Microsoft Research) trains only on successful runs. A neural controlled differential equation learns how healthy trajectories move through latent space, and each step of a failed run is scored by how far it drifts from that flow. With just 100 successful runs it is 200-5000x faster than prompting baselines, including a GPT-5 judge, and about 20 F1 points better in-domain (7 out of domain). Successes are cheap and plentiful, so this turns existing logs into a debugger.</p>

<h4>Anthropic's overnight-run harness: tests start failed, and only evidence flips them</h4>
<p>The anthropics/cwc-long-running-agents repo was shared as a fix for agent loops that fall apart after a few hours. <h4>Stale CLAUDE.md beats live code 79 times in 80</h4>
<p>Georgia Tech-led researchers built 40 projects where the config file deliberately contradicts the code, then asked Claude Code and Codex to add features. Claude Code noticed the mismatch and still followed the outdated doc in 79 of 80 runs. Codex rewrote working code to match the stale doc in 20 of 80 runs, breaking tests in 17. ### Agents at work, and agents doing science

- **Looped and depth-grown models learn more from context.** Google researchers compare 3B models that reuse layers, by looping a shared block or growing depth by copying layers, against a dense model of the same depth. The reused models gain more from later context, score higher on GSM8K at every demonstration count, and keep using context when they could memorize. Copying layers also copies early induction heads (the attention heads that match and copy earlier patterns). Relevant to compute-efficient depth. ([paper](https://arxiv.org/abs/2610.31421) · [thread](https://x.com/omarsar0/status/2114404629064942018))
- **Moral argumentation makes models decisive, not valid (Google DeepMind).** RL in a self-judged tournament over dilemmas from classic novels makes the model consistent across option orders on MoralChoice, ELEPHANT and MORABLES, but user pushback and reframing still move its answers. Consistency is not validity. ([paper](https://arxiv.org/abs/2610.30349) · [thread](https://x.com/omarsar0/status/2114446656032874516))
- **"CLI agents are no longer the ideal interface."** Elvis Saravia argues app-style surfaces (Grok bot, the Codex app) now make multi-agent work easier to scale and manage than the terminal. Opinion, but from a heavy CLI user. ([post](https://x.com/omarsar0/status/2114489246434173180))
- **"Knowing how is not knowing what."** Yunze Xiao's essay argues that operating apps is now nearly solved for computer-use agents, so RL environments must supply the undocumented organizational know-how, like how headcount actually gets approved. Grading the email sent is not grading the goal. ([essay](https://algoroxyolo.github.io/blog/2026/knowing-how-is-not-knowing-what/))
- **GhidraMCP.** An MCP server lets Claude Code drive the NSA's Ghidra decompiler locally to read compiled binaries. It is useful for firmware and your own builds, and it sits squarely in the open cyber-capability debate below. ([repo](https://github.com/LaurieWired/GhidraMCP))
- **TheoPhysEval.** Experts contributed 50 unpublished research-level physics problems, each about a day's work for a specialist. GPT-6-Astra in Codex solved 49 with web search; it and Opus 5.5 in Claude Code each solved 46 without search, at under $3 per problem. That accuracy barely drops without search suggests memorized literature, so this is a recall test as much as a reasoning test. ([paper](https://arxiv.org/abs/2610.16733) · [thread](https://x.com/rohanpaul_ai/status/2114306498658812026))
- **An agent teammate in 20+ teams for five months (Google DeepMind).** It treated stale docs as current, tagged a VP on 16 bugs and misread sarcasm. Teams that opted in forgave early mistakes; teams that had it imposed did not. Lesson: consent, separate permissions and easy undo. ([paper](https://arxiv.org/abs/2609.29901) · [thread](https://x.com/rohanpaul_ai/status/2114241586989334537))
- **Sycophancy on the "XY problem".** A thread reports a DeepMind paper where a confident wrong hint cuts frontier model accuracy by up to 47%, even when the reasoning trace shows the model spotted the error.
