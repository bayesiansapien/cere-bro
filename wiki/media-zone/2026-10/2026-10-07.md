### Looped models get an efficiency stack

Looped (recurrent-depth) models run each token through the same layers several times, buying more compute without more parameters. The catch is serving: every pass adds KV cache (the stored attention keys and values), so fewer requests fit on a GPU.

<div class="dg-title">Old tokens are compressed once, read by every loop</div>
<div class="dg-sub">Hybrid Latent Attention keeps a short exact window and a compact latent memory shared across passes.</div>

<h4>Hybrid Latent Attention: 4.0-8.8x more requests per GPU for looped LMs</h4>
<p>Virginia Tech keeps the last 128 tokens exact and squeezes older ones into small latent vectors that attention reads directly, so every loop reuses them without rebuilding anything. On Ouro looped models, throughput rose up to 7.4x at 16K tokens while accuracy stayed above 97% of the original on math, knowledge and reasoning. Gains grow with context length. You can retrofit an existing looped checkpoint by training only the new parts. This removes the main serving objection to looped models.</p>

<h4>LiFT: train with 2 loops, run 16 at inference</h4>
<p>Looped transformers usually get worse if you run more loops than they were trained on. LiFT trains each loop to correct the previous velocity estimate toward the flow-matching target, instead of jumping straight to the answer. A model trained with 2 loops keeps improving up to 16 loops, beating a larger DiT on ImageNet with about 60% fewer parameters and 52% less inference compute. Test-time depth becomes a dial you turn after training.</p>

### Making it small: distillation, RL memory, kernels, on-device

<div class="mz-feed">

<div class="mz-card">
<div class="mz-card-body">
<span class="mz-card-badge paper">Paper · RL memory</span>
<h4>LoGRA: RL post-training in up to 45.7% less memory</h4>
<p>LoGRA keeps the useful part of each gradient as a low-rank sketch, a compact matrix that is enough both to update the model and to sync the policy to the rollout engine. A predicted-KL step control estimates how much the policy will change before each update and scales it down if needed. It trained a 27B model for 1,100+ steps on one 8-GPU node, where dense Adam runs out of memory. Cost angle: RL that used to need a cluster fits on one node, which matters now that RL is the biggest compute line item.</p>
<div class="mz-card-foot"><a href="https://arxiv.org/abs/2610.06647">Paper →</a> · <a href="https://x.com/yifanzhang_/status/2107573903543660544">@yifanzhang_</a> · <a href="../../llms-foundation-models/2026-10-07-logra-low-rank-gradient-rl.md">wiki summary</a></div>

<div class="mz-card-body">
<span class="mz-card-badge paper">Paper · distillation</span>
<h4>Harness-Aware Distillation: a small agent that beats its 8B teacher</h4>
<p>When you shrink an agent, the harness (the code managing memory, tools and feedback) stays. So the student only needs to learn to act correctly on harness information. HAD asks the same teacher for an action with and without that information and trains the student to prefer the "with" action, dropping pairs that contradict the records. No reward labels needed. The student reaches 63.4% on unseen ALFWorld tasks against 47.0% for the best baseline and beats its teacher.</p>

### How much harness does an agent need?

<div class="mz-feed">

<div class="mz-card">
<div class="mz-card-body">
<span class="mz-card-badge paper">Paper · Apple · the minimalist case</span>
<h4>One coding agent with a shell beats four multi-agent ML systems</h4>
<p>Apple re-ran four published ML-engineering harnesses (search trees, memory layers, specialist teams) on one codebase with the same model, hardware and 24-hour budget. Giving the model a shell instead of a chat box was the only change that clearly mattered. With GLM 5.2 the minimal agent medaled on 62.5% of Kaggle tasks against 47.1% for the best published harness. Adding parallel agents and a message channel dropped it from 55.7% to 33.3%. MIT's JAZ makes the same point for memory: expose prompt and history as code variables and a plain loop beats Letta (69.9% vs 61.8%) and ACE at under half the cost.</p>

<div class="mz-card">
<div class="mz-card-body">
<span class="mz-card-badge paper">Paper · NVIDIA · the co-evolution case</span>
<h4>VERA: train the harness and the model together</h4>
<p>VERA turns benchmark trajectories into 9,000+ restartable sandboxes with rubric scoring, then updates both model weights and harness. A harness edit is kept only if it passes self-tests and adds 5+ points on a dev set. At 27B the co-evolved agent scores 71.6 on AutoCoWorkBench, above Claude Opus 4.8. RSR closes the loop the other way: Qwen-3.8-27B solves tasks under three harnesses, the traces are rewritten as runbooks and re-run under a generic harness, and Terminal-Bench 2 pass@3 rises from 57.0% to 74.2%. The harness explores; the weights keep what it found.</p>
