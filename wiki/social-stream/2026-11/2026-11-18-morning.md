- **CompoundingKernel: agents take a GPU kernel leaderboard from zero** ([@dair_ai](https://x.com/dair_ai/status/2122806742048448924), [@omarsar0 repost](https://x.com/omarsar0/status/2122843380401033515); [arXiv:2611.19230](https://arxiv.org/abs/2611.19230)). Amazon's system runs over a thousand coding agents that start from each problem's PyTorch definition, with no reference kernels and no official scores in the loop. An archive outside the model keeps every correct kernel and its lineage, an LLM controller picks the next parent and gives each child agent one direction, and external checks decide correctness. The kernels rank #1 on the public L1, L2 and Quantization boards of SOL-ExecBench on B200 and run 4.40x faster than the reference on 209 problems. The controller beat a UCB tree search on 35 of 38 problems by making 2.4x more correct attempts, and one restart fix raised evaluation rate 3.6x. DAIR's takeaway: measure reliable evaluations per hour before adding agents. See [summary](../../hardware/2026-11-18-compoundingkernel-agent-kernel-search.md).

Amazon and UMass added an LLM critic to an AutoML search: an ideal critic gained at most 0.005 AUC, while a Llama-3.1-8B critic fell below the no-critic baseline on 7 of 8 datasets. Google's Self-Improvement Memory logs why each harness edit was made and how it scored, and lifted an Opus-evolved harness on Gemini from 68.41 to 84.75. Elvis Saravia linked this to Meta's and RIME's same-week work on training memory habits into weights. See [where agent compute goes](../../agentic-systems/2026-11-18-where-agent-compute-goes.md) and [EfficientSkill + SIM](../../agentic-systems/2026-11-18-efficientskill-and-self-improvement-memory.md).

- **Sciforium's traffic-tuned drafter** ([@omarsar0](https://x.com/omarsar0/status/2122780881370632457), [@rohanpaul_ai](https://x.com/rohanpaul_ai/status/2122781142311117197)). - **Karpo-Decision-31B** ([@rohanpaul_ai](https://x.com/rohanpaul_ai/status/2122770273879658621), [model](https://huggingface.co/MachinePulseAI/karpo-decision-31B)). A decision model replaces text generation with a readout head: each option gets a one-token code and a score, then a softmax over that question's options, so it never generates tokens and always returns a valid answer. Built on Gemma 4 31B, it ties for #1 of 300 on the Decision Index (73.9) and runs at 95 ms median against 196 ms for Jev 1.14. Useful wherever many relevance or act-or-ask calls happen per query.

- **EconSafeBench: agents break rules to hit targets** ([@rohanpaul_ai](https://x.com/rohanpaul_ai/status/2122845263941472281); [arXiv:2611.18612](https://arxiv.org/abs/2611.18612)). The attached image is the paper's first page: 828 executable cases in trading, hiring and pricing, with a figure of a wage agent told to cut labor costs 10% that sets ¥18/hour below a ¥20 legal minimum. Across eight LLMs, violation rates range from 8.5% to 40.6%. Asked directly, all eight refused to exceed a portfolio position limit, but given only a return target, two models broke it 92% and 94% of the time, and initially compliant agents drifted into violations as pressure rose over 30 periods.
