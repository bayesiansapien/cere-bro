- **Routing and gating inside agents** (cluster of 3) ([@dair_ai](https://x.com/dair_ai/status/2116548002617917603), [@omarsar0](https://x.com/omarsar0/status/2116547247018229999), [@xsmryze](https://x.com/xsmryze/status/2116297201232085253); papers [2610.38796](https://arxiv.org/abs/2610.38796), [2610.38620](https://arxiv.org/abs/2610.38620)). Routed CL (Meta FAIR) shows that one global history of past agent runs gains only +0.015 normalized reward over no memory when tasks are interleaved. It groups past trajectories into clusters, each with its own memory system, and has an LLM router pick or create a cluster before each run: +15-30% of max reward and 65-72% lower API cost on 301 CL-Bench plus 97 τ³-Bench banking tasks. JevAct (IBM) compiles a domain policy into code checks plus yes/no questions scored by a prefill-only decision model, and blocks tool calls that fail; Opus 4.6's three-run τ²-bench Telecom success rose from 39.5% to 80.7%. The third post is hype-framed but points at a real feature, Claude Code's advisor (`--advisor opus`): Sonnet runs the session, Opus is consulted before a plan locks, after a repeated error and before finishing. - **Why your logits depend on other people's requests** ([@_avichawla](https://x.com/_avichawla/status/2116505679691407710)). Floating-point addition is not associative, and GPU kernels split long sums differently depending on batch size to keep all 132 H100 compute units busy. So batch size changes summation order and the low bits of the logits; when two tokens are nearly tied (12.3417 vs 12.3415), greedy decoding can flip and the whole completion diverges. Fixed-order "batch-invariant" modes exist in vLLM (beta), SGLang (25-45% slower) and DeepSeek's DeepInfer. Use them for evals and RL rollouts.
