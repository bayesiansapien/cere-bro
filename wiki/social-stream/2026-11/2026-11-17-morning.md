## Posts

- **Agent token cost: learn from past sessions, fold subagents, compile skills (cluster of 4)** ([@rohanpaul_ai](https://x.com/rohanpaul_ai/status/2122466371594580269), [@rohanpaul_ai paper link](https://x.com/rohanpaul_ai/status/2122466375419732173), [@suraj_sharma14](https://x.com/suraj_sharma14/status/2122374135913628065), [@_avichawla](https://x.com/_avichawla/status/2122449740973641824); [TokenEconomizer paper](https://arxiv.org/abs/2610.22732), [Anthropic guide](https://claude.com/resources/articles/building-agents-when-to-fold-subagents-into-your-main-agent-loop)). TokenEconomizer is an external controller from UC Berkeley and Microsoft that reads each finished coding-agent session. It injects repository facts the agent keeps rediscovering, drops tools that history says won't be called, and uses a judge model to redirect an agent stuck in a failing loop. Across Claude Code, Codex and GitHub Copilot CLI on 277 SWE-Bench tasks, mean per-task cost falls 18.4-30.9%, with Pass@1 up in 4 of 5 settings. Anthropic's Applied AI guide makes the matching harness argument: a single agent loop with skills and tools loaded on demand often beats multi-agent setups on quality, cost and speed, and loading on demand cut Claude Code's system prompt by over 80% on newer models. One company halved runtime by collapsing its multi-agent harness. The "Skills 2.0" repost (Swamp) turns a repeated skill into a workflow the agent builds once and replays, claiming 8x fewer tokens; that claim is the tool's own. See [TokenEconomizer](../../agentic-systems/2026-11-17-tokeneconomizer.md) and [agent harness engineering](../../agentic-systems/agent-harness-engineering.md).

- **Batch makespan for agent workloads** ([@dair_ai](https://x.com/dair_ai/status/2122428754127729037); [arXiv:2611.16661](https://arxiv.org/abs/2611.16661)). The Ling team at Ant Group treats an agent batch (evals, RL rollouts, synthetic data) as one scheduling problem across GPUs and sandboxes. For hybrid models it splits GPU memory between the KV cache (stored attention state) and the recurrent state, keeps each trajectory on the worker holding its cache, and gives scarce sandbox slots to the chain with the most work left. Batch completion time drops 10.4-65.0% on BFCL, SWE-bench Multilingual, WideSearch and MCP-Atlas with unchanged scores. DAIR's takeaway: look at scheduling before buying more GPUs. See the [summary](../../inference-efficiency/2026-11-17-batch-makespan-agent-workloads.md).

- **Self-improving agents need hidden scorers and gates (cluster of 3)** ([@omarsar0](https://x.com/omarsar0/status/2122429507756069008), [@rohanpaul_ai](https://x.com/rohanpaul_ai/status/2122412646972744045), [@TheTuringPost](https://x.com/TheTuringPost/status/2122353376424059360); [AutoRL](https://arxiv.org/abs/2611.17790), [EvoTrias](https://arxiv.org/abs/2611.15309)). AutoRL runs perceptor agents that watch a live RL run, three proposer agents that diagnose problems, and an orchestrator that applies fixes by hot update or checkpoint restart. It lifts Qwen3 on AIME 2024 from 46.67% to 66.67% and LongCat-Flash-Lite agentic coding pass@1 from 52.29% to 65.13%. Huawei's EvoTrias splits code evolution into three owners: a controller plans the search, a coding agent writes code, and an evaluator the agent cannot read scores it. It led on 6 of 7 math tasks, cut token cost per run 64% versus a 4-agent baseline, and raised OR-Tools solver quality 13.2%. The Turing Post list leads with papers showing many self-improvement gains are benchmark gains, not task gains. See [agent shorts](../../agentic-systems/2026-11-17-agent-shorts-memory-teams-evolution.md).
