## Posts

- **Agents that build their own training environments and improve their own harness (cluster of 6)** ([@omarsar0](https://x.com/omarsar0/status/2110467939057168849) on [AutoEnvScaling](https://arxiv.org/abs/2610.14163), [@Xudong07452910](https://x.com/Xudong07452910/status/2110574383622434939) on [Harness²](https://arxiv.org/abs/2610.14224), [@omarsar0](https://x.com/omarsar0/status/2110006902331769049) on [Evo²](https://arxiv.org/abs/2610.13025), [@gordonhu608](https://x.com/gordonhu608/status/2110400049515728911) on [Tev](https://arxiv.org/abs/2610.18868), [@dair_ai](https://x.com/dair_ai/status/2110490882332053673) on [Behavioral Self-Rewarding](https://arxiv.org/abs/2610.12598), [@bibryam](https://x.com/bibryam/status/2110111370268024981)). AutoEnvScaling turns environment design into a terminal task: a proposer agent reads the solver's rollouts and writes new RL environments, with up to 25x more valid environments than prompt-only generation at up to 75% lower cost each, and one Qwen3.6-35B-A3B in both roles gains 12.2 points on Terminal-Bench 2.1. Harness² (the Chinese-language thread explains it well) proposes a harness edit, runs old and new versions under the same conditions, keeps edits whose behavior is better, and logs how each edit was made so future edits improve; up to +11.8 points with no ground-truth verifier. Evo² (covered 10-14) trains one policy as both harness editor and reviewer, reaching 48.3% on SWE-bench Verified. Tev-Gym builds 1,170 environments from hidden "latent world" specs so progress can be rewarded per step. Behavioral Self-Rewarding adds small bounded pairwise preferences when every rollout in a GRPO group passes or fails, so the group still teaches something (Qwen3-14B 32.1% to 34.7% on SWE-bench Verified). @bibryam pushes back on harness taxonomies that fold sandboxing and persistence into the harness: those are infrastructure. Wiki: [harness and environment self-improvement](../../agentic-systems/2026-10-15-harness-and-environment-self-improvement.md).

- **Claude Code: plan in a script, run on cheap models (cluster of 4)** ([@thedelost](https://x.com/thedelost/status/2110472847084650726) linking the [dynamic workflows docs](https://code.claude.com/docs/en/workflows), [@mirku21](https://x.com/mirku21/status/2110475821441753116) linking the [advisor docs](https://code.claude.com/docs/en/advisor), [@VaibhavSisinty](https://x.com/VaibhavSisinty/status/2110555039228113103), [@aakashgupta](https://x.com/aakashgupta/status/2110579165682680269)). The two viral posts use hype framing ("pure goldmine") but point at real docs. Dynamic workflows are JavaScript scripts Claude writes and a runtime executes: the script holds the loop, branches and intermediate results, so dozens to hundreds of subagents can run while the main model's context holds only the final answer. The docs list quality patterns such as independent agents adversarially reviewing each other's findings. The first post also promotes "JEV engineering" for millisecond micro-decisions, which reads as decision-model promotion. Separately, Claude agent tracing is in public beta (latency, tokens and tool calls per step, with an opt-in detailed mode), and a Claude Code update sorts sessions by whether they need you and gives a recap card on return. @aakashgupta ties that to Gloria Mark's finding that an interruption costs about 23 minutes to recover from.

- **Databricks: 6x faster fine-tune at "98% utilization"** ([@FeitengLi](https://x.com/FeitengLi/status/2110554188098810125)). A Qwen3.8-27B fine-tune already showing 98% GPU utilization went from 7h44m to 1h17m by using fused kernels matched to the model's linear-attention layers (removing many small kernel launches) and repacking samples to remove padding. The poster's comment: routine work. The lesson is that utilization measures busy, not useful. Wiki: [efficiency shorts](../../inference-efficiency/2026-10-15-efficiency-shorts.md).

- **HobbyLM: a 1B sparse MoE in ~300 GPU-hours** ([@NammaCoimbatore](https://x.com/NammaCoimbatore/status/2110417010094137669)). A two-person team in Coimbatore trained a 1B-parameter sparse mixture-of-experts from scratch on 4 H200s in 76 hours, compared against ~123K GPU-hours for Sarvam-1. No paper or benchmarks in the post. Treat it as a cost anecdote.

- **System One decision models on the research side (cluster of 2)** ([@_reachsumit](https://x.com/_reachsumit/status/2110288646448509181) on [JevGPT](https://arxiv.org/abs/2610.18272), [@_vmlops](https://x.com/_vmlops/status/2110360484742582600) on JevEval). JevGPT runs fast System One judges in parallel to check sources and return original passages, under a GPT planner that sets evidence goals. DeepEval's JevEval scores model outputs with explicit questions and calibrated probabilities rather than a generated score. Both sit next to the Jeva architecture paper. Wiki: [Jeva and the System One cluster](../../ai-routing/2026-10-15-jeva-system-one-models-first-principles.md).
