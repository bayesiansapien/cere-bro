- **US government suspends Fable 5 and Mythos 5 (cluster of 5)** ([@ClaudeDevs](https://nitter.net/ClaudeDevs/status/2065597942602531163#m), [@Scobleizer](https://nitter.net/Scobleizer/status/2065609390070419506#m), [@ns123abc](https://nitter.net/ns123abc/status/2065611349883760820#m), [@kilocode](https://nitter.net/kilocode/status/2065609685382684849#m) · [Anthropic statement](https://www.anthropic.com/news/fable-mythos-access)). Anthropic's statement: the US government, "citing national security authorities," issued an export-control directive to suspend all access to Fable 5 and Mythos 5 by any foreign national, inside or outside the US, including Anthropic's own foreign-national employees. The net effect is that Anthropic had to abruptly disable both models for all customers to comply; all other Claude models are unaffected. The announcement card (a stark black card reading "STATEMENT ON / The US government directive to suspend access to Fable 5 and Mythos 5") was reposted identically across the cluster. Anthropic says the government's concern appears to be a method of "jailbreaking" Fable 5 that essentially consists of asking the model to read a codebase and fix its software flaws, and that it validated the demonstrated capability is "widely available from other models (including OpenAI's GPT-5.5)" and used daily by defenders. ClaudeDevs adds that new sessions fall back to the user's default model or Opus 4.8 and existing Fable 5 sessions end with an error. Scoble reports an SF entrepreneur whose build was killed mid-run and argues the order "hurts American national security" because companies were using Mythos to close their own security holes. ns123abc relays Commerce Secretary Lutnick's letter to Dario Amodei: export controls on any location outside the US, all foreign persons within the US, license required for export, re-export, or domestic transfer. - **Anthropic resets all rate limits** ([@ClaudeDevs](https://nitter.net/ClaudeDevs/status/2065621176735646006#m)). Amid the disruption, ClaudeDevs reset 5-hour and weekly rate limits for all users, presumably to soften the blow of users being bumped off Fable 5 onto other models mid-workflow.

- **NVIDIA AgentPerf: Blackwell runs 20x more agents per megawatt than Hopper** ([@nvidia](https://nitter.net/nvidia/status/2065543509478670375#m) · [NVIDIA blog](https://nvda.ws/4fHQpvp)). NVIDIA and Artificial Analysis launched AgentPerf, billed as the industry's first agentic-AI infrastructure benchmark. The motivation: an AI agent chains dozens to hundreds of model calls, using tools and gathering context until a task is done, and existing benchmarks were not built for that workload. In the first published round, the Blackwell Ultra NVL72 platform leads, with the GB300 NVL72 delivering up to 20x more agents per megawatt than Hopper. This is a real efficiency-per-watt number for agentic serving, the hardware-side counterpart to today's agent-efficiency papers.

- **Google Gemini-SQL2 hits state-of-the-art text-to-SQL on BIRD** ([@GoogleResearch](https://nitter.net/GoogleResearch/status/2065475343205740911#m)). Google introduced Gemini-SQL2, a text-to-SQL system powered by Gemini 3.1 Pro, claiming state-of-the-art on the competitive BIRD benchmark, which measures execution-verified accuracy (the generated SQL not only looks right, it runs and returns the correct result). The thread stresses that complex business contexts make accurate SQL generation hard, and that improved SQL understanding feeds Google's broader data services.

- **kilocode ships REVIEWS.md, repo-specific review standards** ([@kilocode](https://nitter.net/kilocode/status/2065585134380671263#m) · [blog.kilo.ai](https://blog.kilo.ai/p/code-reviews-md)). Most AI review tools run a generic rubric on every repo and miss what a team actually cares about. kilocode's REVIEWS.md is an open-standard Markdown file (like a README, but for a review agent) that defines repo-specific conventions, and the attached image shows an example with error-handling rules ("flag any unhandled promise," "require typed error returns") and style rules ("don't nitpick line length," "enforce named exports"). A Code Review Memory mode watches how you respond to PRs (dismissing nitpicks, acting on error-handling comments) and proposes updating REVIEWS.md to match, even opening the PR. This is the same "compile the user's standards into a gate" pattern as today's TRACE paper in the digest.
