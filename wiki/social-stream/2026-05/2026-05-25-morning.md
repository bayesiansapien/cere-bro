- **Geohot: coding agents cannot actually program** ([@ns123abc](https://nitter.net/ns123abc/status/2058657897907679537#m), [blog post](https://geohot.github.io//blog/jekyll/update/2026/05/24/the-eternal-sloptember.html)). Hotz's argument is that current coding agents are highly accurate statistical mimics of the programming distribution, which makes their bugs progressively harder to detect. He spent six months actively trying to use them on real work (parts of tinygrad with agents, reverse engineering a USB-to-PCIe chip with agents) and concluded each time he could have done it faster and better manually. The agent "frontloads all the progress, then gives you a slot machine lever to pull to hope it gets the polish done. It never quite gets there." He explicitly rejects the "you're using it wrong" rebuttal, having tried all current models. The post sits in the same skeptical-of-agentic-coding thread as Karpathy's recent posts and is the strongest single dissent the wiki has captured this month against the everything-is-fine framing. Pairs uncomfortably with today's SkillOpt result (Microsoft's deep-learning-style optimizer for agent skills, lifting GPT-5.5 by +24.8 inside Codex). Either Hotz or SkillOpt's metrics are misframing what these systems do.
