# automate

Sets up a fully automated daily pipeline: farmers pull from sources, Claude generates the digest, git pushes — all without any manual intervention. Supports macOS (LaunchAgent) and Linux (cron).

Run this once after `/bootstrap`. Re-run it any time to change the schedule or regenerate the scripts.

---

## Instructions

### Step 1: Verify prerequisites

Check that:
- `wiki-config.json` exists (bootstrap has run)
- `CLAUDE.md` is the customized version, not the placeholder
- Git remote is configured: `git remote get-url origin`
- `connectors/` directory exists with at least one farmer script

If any are missing, tell the user to run `/bootstrap` first.

---

### Step 2: Find the claude binary

Run: `which claude`

If not found, try common locations:
- `~/.local/bin/claude`
- `/usr/local/bin/claude`
- `/opt/homebrew/bin/claude`

Store the full path. If not found, tell the user to install Claude Code first.

---

### Step 3: Detect platform and collect preferences

Detect OS: run `uname -s` — `Darwin` = macOS, `Linux` = Linux.

Ask the user:
> "What time do you want the daily digest to run? (default: 9:00 AM local time)"

Ask if Gmail farmer is enabled (check `wiki-config.json` → `sources.gmail`).

Ask if they want to confirm the repo path:
> "I'll use this as your wiki directory: `<absolute path of current directory>`. Is that correct?"

---

### Step 4: Write `scripts/daily-update.sh`

Create `scripts/daily-update.sh` in the repo root with the content below. Fill in actual values for `WIKI_DIR`, `CLAUDE_BIN`, `PYTHON_BIN`, and the scheduled hour.

```bash
#!/bin/bash
# Daily wiki update — auto-generated by /automate
# Re-run /automate to regenerate this file.

WIKI_DIR="<absolute path to wiki repo>"
CLAUDE_BIN="<path to claude binary>"
PYTHON_BIN="$(which python3)"
LOG="$WIKI_DIR/.claude/logs/daily-update.log"
TODAY=$(date +%Y-%m-%d)
MONTH=$(date +%Y-%m)

mkdir -p "$WIKI_DIR/.claude/logs"

# Guard 1: skip if before scheduled hour
SCHEDULED_HOUR=<hour>
CURRENT_HOUR=$(date +%H)
if [ "$CURRENT_HOUR" -lt "$SCHEDULED_HOUR" ]; then
  echo "[$TODAY $(date +%H:%M:%S)] Before ${SCHEDULED_HOUR}:00 — skipping." >> "$LOG"
  exit 0
fi

# Guard 2: skip if today's digest already exists (manual run already done)
DIGEST_PATH="$WIKI_DIR/wiki/daily-digest/$MONTH/$TODAY.md"
if [ -f "$DIGEST_PATH" ]; then
  echo "[$TODAY $(date +%H:%M:%S)] Digest already exists — skipping." >> "$LOG"
  exit 0
fi

echo "[$TODAY $(date +%H:%M:%S)] Starting daily update..." >> "$LOG"

cd "$WIKI_DIR" || exit 1

# Pull latest changes
git pull --rebase origin main >> "$LOG" 2>&1 || true

# Run Gmail farmer (requires local OAuth token — only works on this machine)
# GMAIL_ENABLED placeholder — set to true or false based on wiki-config.json
if [ "<GMAIL_ENABLED>" = "true" ]; then
  echo "[$TODAY $(date +%H:%M:%S)] Running Gmail farmer..." >> "$LOG"
  "$PYTHON_BIN" "$WIKI_DIR/connectors/gmail/farmer.py" >> "$LOG" 2>&1 || \
    echo "[$TODAY $(date +%H:%M:%S)] Gmail farmer failed — continuing without it." >> "$LOG"
fi

# Claude handles HuggingFace + RSS farming and full digest generation
"$CLAUDE_BIN" \
  --dangerously-skip-permissions \
  -p "Today is $TODAY. Generate the daily wiki digest in full. Steps:
1. Run the huggingface-farmer subagent to fetch today's HuggingFace papers into raw/huggingface/.
2. Run the rss-farmer subagent to fetch today's RSS posts into raw/rss/.
3. Read raw/gmail/$TODAY-starred.md if it exists (Gmail starred emails already fetched).
4. Follow the full ingest and digest workflow from CLAUDE.md: write summary pages, update concept pages, write today's digest at wiki/daily-digest/$MONTH/$TODAY.md in the newsletter format, update index.md, append to log.md.
5. git add all changes, commit with message 'wiki: daily digest $TODAY', and push to origin main.
Do not stop until the digest is committed and pushed." \
  >> "$LOG" 2>&1

echo "[$TODAY $(date +%H:%M:%S)] Done." >> "$LOG"
```

Make it executable: `chmod +x scripts/daily-update.sh`

### Step 5: Set up the scheduler

#### macOS — LaunchAgent

Create `scripts/<wiki-name>.daily.plist` with the content below. Fill in `<wiki-name>`, `<absolute-path-to-script>`, `<hour>`, and `<wiki-dir>`:

```xml
<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE plist PUBLIC "-//Apple//DTD PLIST 1.0//EN" "http://www.apple.com/DTDs/PropertyList-1.0.dtd">
<plist version="1.0">
<dict>
    <key>Label</key>
    <string>com.<wiki-name>.daily</string>

    <key>ProgramArguments</key>
    <array>
        <string>/bin/bash</string>
        <string><absolute-path-to-script>/scripts/daily-update.sh</string>
    </array>

    <key>StartCalendarInterval</key>
    <dict>
        <key>Hour</key>
        <integer><hour></integer>
        <key>Minute</key>
        <integer>0</integer>
    </dict>

    <!-- Runs on wake if the scheduled time was missed while sleeping -->
    <key>RunAtLoad</key>
    <true/>

    <key>StandardOutPath</key>
    <string><wiki-dir>/.claude/logs/launchd-stdout.log</string>
    <key>StandardErrorPath</key>
    <string><wiki-dir>/.claude/logs/launchd-stderr.log</string>

    <key>EnvironmentVariables</key>
    <dict>
        <key>PATH</key>
        <string>/Users/<username>/.local/bin:/usr/local/bin:/opt/homebrew/bin:/usr/bin:/bin:/usr/sbin:/sbin</string>
        <key>HOME</key>
        <string>/Users/<username></string>
    </dict>
</dict>
</plist>
```

Then tell the user to run these two commands:

```bash
cp scripts/<wiki-name>.daily.plist ~/Library/LaunchAgents/
launchctl load ~/Library/LaunchAgents/com.<wiki-name>.daily.plist
```

**Important note about macOS sleep behavior:** If the Mac is asleep at the scheduled time, macOS fires the job when the machine next wakes — as long as it's still the same calendar day. So opening the laptop at any point before midnight will trigger the run. The Guard 2 in the script prevents double-runs if you already generated the digest manually that day.

#### Linux — cron

Tell the user to run `crontab -e` and add this line (replacing `<hour>` and `<path>`):

```
0 <hour> * * * /bin/bash <absolute-path-to-wiki>/scripts/daily-update.sh
```

For systemd-based Linux (if cron is not available), offer to generate a `.service` + `.timer` unit file instead.

### Step 5b (optional): social-media agent cadence

The daily job above rebuilds everything once a morning. If you want the **Media Zone** (the social feed) to stay current through the day, install the two extra agents that ship as templates. They are cheap-capture vs expensive-rebuild, split on purpose:

- **`templates/scripts/cerebro-feed-capture.sh.template`** — captures the X home feed (`farmer.py --feed-only`, deduped so each run only adds new posts) + YouTube, then ranks. No LLM, so it can run often. Recommended schedule: the gap hours between your heavier runs (e.g. 12:00 and 18:00). Install via `templates/launchagents/com.cerebro.feed-capture.plist.template`.
- **`templates/scripts/cerebro-mediazone-refresh.sh.template`** — the expensive step: captures fresh, then invokes Claude to rewrite ONLY today's Media Zone page (not the daily digest), commits, and pushes. Recommended: 2× a day (e.g. 15:30 + 21:00), with the morning job as the day's first rebuild = 3× total. It shares the morning job's mutex so two Claude calls never overlap. Install via `templates/launchagents/com.cerebro.mediazone-refresh.plist.template`.

Because `--feed-only` writes a uniquely-named file per capture and the ranker ranks every one, the Media Zone synthesis unions all of the day's captures (deduped by tweet id) — the feed is scanned comprehensively, nothing is dropped. Fill the same `{{REPO_PATH}}`/`{{HOME}}`/`{{CLAUDE_BIN}}` placeholders, `chmod +x`, copy the plists to `~/Library/LaunchAgents/`, and `launchctl bootstrap gui/$(id -u) <plist>`. LinkedIn deliberately stays one mild pass/day (in the morning job) to avoid bot detection — do not add it to the frequent capture.

### Step 6: Verify and confirm

Run a dry-run check:
```bash
bash -n scripts/daily-update.sh && echo "Script syntax OK"
```

Then confirm to the user:

```
Automation is set up.

Script: scripts/daily-update.sh
Schedule: <time> daily (<platform> <LaunchAgent/cron>)
Gmail farmer: <enabled/disabled>
Log file: .claude/logs/daily-update.log

What happens each day at <time>:
1. Gmail farmer pulls your starred emails into raw/gmail/
2. HuggingFace and RSS farmers run via Claude subagents
3. Claude ingests all new sources, writes summary pages, updates concept pages
4. Daily digest written to wiki/daily-digest/YYYY-MM/YYYY-MM-DD.md
5. Everything committed and pushed — site rebuilds automatically on GitHub Pages

If you manually run /digest before <time>, the scheduled run detects the digest
already exists and exits silently. Both modes work.

To check the log: cat .claude/logs/daily-update.log | tail -50
To uninstall (macOS): launchctl unload ~/Library/LaunchAgents/com.<wiki-name>.daily.plist
```
