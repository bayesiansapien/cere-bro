# publish

Sets up and deploys the Astro site to GitHub Pages. Verifies configuration, builds the site, and walks the user through enabling Pages.

---

## Instructions

When invoked, follow these steps.

---

### Step 1: Verify prerequisites

Check that:
1. `wiki-config.json` exists (bootstrap has run)
2. `site/` directory exists (site template was copied by bootstrap)
3. `site/astro.config.mjs` has the user's GitHub username and repo name
4. Git remote is set: `git remote get-url origin`

If any of these are missing, tell the user what's missing and how to fix it.

---

### Step 2: Check site configuration

Read `site/astro.config.mjs` and `wiki-config.json`. Verify:
- `site` URL matches `https://<githubUsername>.github.io`
- `base` path matches `/<githubRepo>`

If they don't match, fix them now.

Read `site/src/layouts/Base.astro` and verify the wiki name and GitHub link match wiki-config.json. Fix if needed.

---

### Step 3: Install dependencies and test build

```bash
cd site
npm install
npm run build
```

If the build fails:
- Check `site/src/data/wiki.json` — this is generated by `npm run prebuild` which runs `scripts/build-data.mjs`. If wiki/ is empty, the build may warn but should still produce a working (empty) site.
- Check for any import errors or missing files.
- Fix issues before proceeding.

If the build succeeds, tell the user: "Build succeeded. Site is in site/dist/."

---

### Step 4: Check GitHub Actions workflow

Verify `.github/workflows/deploy-pages.yml` exists. If not, copy it from `templates/site/.github/workflows/deploy-pages.yml`.

The workflow triggers on push to `main` when files in `site/**` or `wiki/**` change.

---

### Step 5: Commit and push

Ask the user if they want to push now. If yes:

```bash
git add site/ .github/ wiki-config.json
git commit -m "chore: set up site and deploy workflow"
git push origin main
```

---

### Step 6: Enable GitHub Pages

Tell the user:

```
After pushing, enable GitHub Pages in your repo settings:

1. Go to https://github.com/<username>/<repo>/settings/pages
2. Under "Source", select "GitHub Actions"
3. Save

The first deployment will start automatically when the push completes.
Your site will be live at: https://<username>.github.io/<repo>/

GitHub Actions status: https://github.com/<username>/<repo>/actions

The first build takes 2–3 minutes. After that, every push to main that
changes site/ or wiki/ files triggers an automatic rebuild.
```

---

### Step 7: Verify deployment

If the user wants to verify, ask them to check the Actions tab and confirm the workflow ran successfully. Once live, the site URL is: `https://<githubUsername>.github.io/<githubRepo>/`

---

### Custom domain (optional)

If the user wants a custom domain:

1. In repo Settings → Pages → Custom domain: enter their domain
2. In their DNS provider, add a CNAME record pointing to `<username>.github.io`
3. Update `site/astro.config.mjs`:
   ```javascript
   site: 'https://their-custom-domain.com',
   base: '/',  // no subpath with custom domain
   ```
4. Rebuild and push.

---

### Subsequent deploys

After the initial setup, every `git push origin main` that changes `site/**` or `wiki/**` files triggers an automatic rebuild. The user does not need to run `/publish` again — just push.

Manual rebuild: go to Actions → Deploy site to GitHub Pages → Run workflow.
