# cere-bro starter

A self-maintaining research wiki powered by Claude Code. Drop papers, posts, and RSS exports into `raw/` — Claude synthesizes them into a knowledge base and a live site.

---

## What you get

- **Wiki** — structured markdown pages: source summaries, concept pages, daily digests
- **Atlas** — visual dashboard: topic heatmaps, cumulative growth charts, momentum strips
- **Browse** — tabbed index of every wiki page
- **Auto-deployment** — GitHub Actions pushes your site to GitHub Pages on every commit

Topics, tiers, and sources are fully yours to define. This starter is not pre-loaded with anyone else's interests.

---

## Quick start

### 1. Copy this folder to your new wiki directory

```bash
cp -r cere-bro-starter/ ~/my-research-wiki/
cd ~/my-research-wiki/
```

### 2. Initialize a git repo and open Claude Code

```bash
git init
git remote add origin https://github.com/<your-username>/<your-repo>.git
claude  # opens Claude Code in this directory
```

### 3. Run the bootstrap skill

In the Claude Code session, type:

```
/bootstrap
```

Claude will ask you:
- Your name and background
- Your research topics and how you want them tiered
- Your GitHub username and repo name (for site deployment)
- Which sources you want to configure (Gmail, RSS, HuggingFace)

It will then create your customized `CLAUDE.md`, set up the wiki structure, and configure the site.

### 4. Drop source files into `raw/` and start ingesting

```bash
# HuggingFace papers
raw/huggingface/2026-05-01-attention-is-all-you-need.md

# RSS exports
raw/rss/2026-05-01-tldr-ai.md

# Gmail starred emails
raw/gmail/2026-05-01-starred.md
```

Then in Claude Code:
```
/ingest
```

## Available skills

| Skill | What it does |
|-------|-------------|
| `/bootstrap` | One-time setup: define your topics, tiers, and create your customized `CLAUDE.md` |
| `/ingest` | Process new raw sources into wiki pages and update concept pages |
| `/digest` | Write today's daily digest from all available raw sources |
| `/publish` | Set up and deploy the Astro site to GitHub Pages |
| `/lint` | Health check: orphan pages, stale concept pages, missing index entries |

## Directory layout

```
my-research-wiki/
├── CLAUDE.md                  # Your customized instructions (generated by /bootstrap)
├── wiki-config.json           # Your topic configuration (generated by /bootstrap)
├── raw/                       # Source files (never modified by Claude)
│   ├── huggingface/           # HuggingFace paper summaries
│   ├── rss/                   # RSS feed exports
│   └── gmail/                 # Gmail starred emails
├── wiki/                      # Claude-owned synthesis (created by /bootstrap)
│   ├── <your-topic>/
│   ├── daily-digest/
│   ├── index.md
│   └── log.md
├── connectors/                # Farmer scripts (copied by /bootstrap)
│   ├── gmail/
│   ├── rss/
│   └── huggingface/
└── site/                      # Astro site (copied by /bootstrap)
```

## Setting up farmers (optional)

Farmers automate pulling from sources daily. After `/bootstrap` copies the connector scripts:

**Gmail starred emails:**
```bash
cd connectors/gmail
pip install -r requirements.txt
python setup.py           # one-time OAuth setup
python farmer.py          # pulls last 24h of starred emails
```

**RSS feeds** — edit `connectors/rss/feeds.txt` with your RSS URLs, then:
```bash
cd connectors/rss
pip install -r requirements.txt
python farmer.py
```

**HuggingFace papers:**
```bash
cd connectors/huggingface
pip install -r requirements.txt
python farmer.py          # fetches today's HF Daily Papers
```

Automate with cron or a daily shell script:
```bash
# In a shell script or cron job:
python connectors/gmail/farmer.py
python connectors/rss/farmer.py
python connectors/huggingface/farmer.py
# Then open Claude Code and run /digest
```

## Deploying the site

1. Create a public GitHub repo
2. In Claude Code: `/publish`
3. In GitHub repo settings → Pages → Source: GitHub Actions
4. Push — site builds automatically at `https://<username>.github.io/<repo>/`

## Sharing with your team

Each teammate:
1. Gets their own copy of this folder (or clones your repo as a template)
2. Runs `/bootstrap` with their own topics and GitHub account
3. Gets a completely different wiki tuned to their interests

The wiki structure and site code are the same. The knowledge base and attention hierarchy are entirely theirs.
