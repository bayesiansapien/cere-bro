# Exciting New Series and Recommendation of a new Substack for young generation

<p>We have just completed our series on Claude Code Harness Patterns. We recently discovered that the <a href="https://github.com/nousresearch/hermes-agent">Hermes Agent </a>Framework has a compelling harness architecture, and we thought it would be fascinating to compare it with Claude Code. This new series spans 15 chapters. The first 10 chapters revisit the patterns we covered in our Claude Code series, and we have added 5 extra chapters to address other important patterns.</p><p>At a high level, Claude Code is TypeScript, SDK-first, and Anthropic-backed &#8212; designed to be embedded as a library. Hermes Agent is Python, CLI and gateway-first, and model-agnostic &#8212; designed to be deployed as a service. You point it at any of 200+ models via OpenRouter, connect it to Slack or Telegram, and get a self-improving agent with a built-in learning loop.</p><p>Several subscribers have written in asking for a comparison between OpenClaw and Hermes Agent, which I understand &#8212; it seems like the more direct matchup. Covers</strong></h2><p>Fifteen chapters, each on a distinct harness pattern. Every chapter shows real code from both systems, a side-by-side comparison, and a concrete application to a <strong>Defensive Cyber Agent</strong> &#8212; the vertical domain where these patterns matter most.</p><p><strong>1 &#8212; The Harness Paradigm.</strong> The foundational split: model provides intelligence, harness provides control. QueryEngine vs AIAgent. Async generator streaming vs synchronous loop. The IterationBudget pattern for capping runaway agents.</p><p><strong>2 &#8212; Tool Architecture and the Tool Contract.</strong> Every action the agent can take must be defined, validated, and declared safe or dangerous before it executes. Claude Code&#8217;s buildTool factory with Zod schemas vs Hermes&#8217;s registry.register() pattern. isConcurrencySafe, isReadOnly, isDestructive &#8212; the behavioral declarations that let the harness make intelligent execution decisions.</p><p><strong>3 &#8212; The Agent Loop.</strong> The heartbeat of every autonomous agent: model call &#8594; tool execution &#8594; result injection &#8594; repeat. Claude Code&#8217;s while(true) with seven named continue sites and explicit transition reasons vs Hermes&#8217;s iteration counter with IterationBudget. How the loop design determines debuggability, error recovery, and audit trail quality.</p><p><strong>4 &#8212; Permission Systems and Safety Guardrails.</strong> The layer that answers &#8220;should this be allowed?&#8221; before every tool call. Claude Code&#8217;s five permission modes (default/auto/plan/acceptEdits/bubble) with classifier-driven automation vs Hermes&#8217;s regex-based dangerous command detection and interactive approval callbacks. Three-tier permission design for cyber agents: auto-allow recon, analyst-approve probing, CISO-approve remediation.</p><p><strong>5 &#8212; Tool Orchestration and Execution.</strong> What happens when the model wants to call five tools at once. Claude Code&#8217;s partitionToolCalls &#8212; grouping by isConcurrencySafe into concurrent and serial batches &#8212; vs Hermes&#8217;s _should_parallelize_tool_batch heuristic with _PARALLEL_SAFE_TOOLS sets and path-overlap detection. Abort handling and synthetic tool results for interrupted executions.</p><p><strong>6 &#8212; Context Management at Scale.</strong> Every LLM has a finite context window; every real task eventually exceeds it. Claude Code&#8217;s five-strategy pipeline (snip &#8594; micro-compact &#8594; collapse &#8594; auto-compact &#8594; reactive) ordered by cost, with a circuit breaker after three failures, vs Hermes&#8217;s single ContextCompressor backed by Anthropic prompt caching. Compliance-aware compaction that always preserves initial threat indicators.</p><p><strong>7 &#8212; Multi-Agent Coordination.</strong> How complex tasks escape the single-context trap. Claude Code&#8217;s AgentTool with five execution modes (sync/async/fork/teammate/remote), git worktree isolation, and SendMessage routing vs Hermes&#8217;s delegate_tool with ThreadPoolExecutor, independent IterationBudget per child, and mixture_of_agents for parallel model aggregation. SOC team architecture: coordinator, recon, forensics, remediation agents.</p><p><strong>8 &#8212; Memory Systems and State Persistence.</strong> Three memory tiers: working memory in the conversation, episodic memory across sessions, procedural memory in reusable runbooks. Claude Code&#8217;s file-based transcripts with eager flush and auto-injected CLAUDE.md attachments vs Hermes&#8217;s SQLite FTS5 session store with LLM-powered search and autonomous skill creation. Threat-actor profiling that persists across sessions.</p><p><strong>9 &#8212; Observability and Debugging.</strong> How you know what the agent is doing and why it failed. Claude Code&#8217;s query chain IDs for distributed tracing, headless profiler checkpoints, and branded AnalyticsMetadata type to prevent PII leakage vs Hermes&#8217;s JSONL trajectory saving, RedactingFormatter, and _detect_tool_failure for real-time error surfacing. A CyberAuditLogger that outputs SIEM-compatible event streams.</p><p><strong>10 &#8212; Production Deployment Patterns.</strong> Claude Code&#8217;s SDK async generator interface, 30 compile-time feature flags, and four-provider abstraction (Anthropic/Bedrock/Vertex/Azure) vs Hermes&#8217;s CLI/gateway dual entry points, HERMES_HOME profile isolation for multi-tenant deployments, built-in cron scheduling, and 200+ models via OpenRouter. Air-gapped deployment, SIEM streaming, docker-compose for the full stack.</p><p><strong>11 &#8212; Hook / Event-Driven Automation.</strong> The event layer that lets a harness react to file changes, tool invocations, task completions, and timers without polling. Claude Code&#8217;s ten hook event types (preToolUse, postToolUse, agentStop, fileEdited, etc.) with askAgent and runCommand actions vs Hermes&#8217;s cron scheduler and gateway callbacks. A complete 24/7 SOC agent hook configuration: confidence gate before remediation, SIEM push after every scan, nightly vulnerability sweep.</p><p><strong>12 &#8212; The Skill System.</strong> How agents accumulate and reuse procedural knowledge. Claude Code&#8217;s CLAUDE.md auto-injection (simple, static, no security scanning) vs Hermes&#8217;s full skill lifecycle: SKILL.md frontmatter with platform filtering and secret injection, four-tier progressive disclosure, agent-managed creation with atomic writes and rollback on security scan block, skills_guard.py with 80+ threat patterns across nine categories, and the Skills Hub marketplace with GitHub and well-known source adapters.</p><p><strong>13 &#8212; MCP Integration.</strong> The Model Context Protocol as the USB-C of AI agents &#8212; a standard that lets any agent connect to any tool server without custom integration code. Claude Code&#8217;s TypeScript async client with mcp__server__tool namespacing and requiredMcpServers on sub-agents vs Hermes&#8217;s dedicated background event loop, MCPServerTask per server, exponential backoff reconnection, SamplingHandler for server-initiated LLM requests, and _sanitize_error credential stripping.</p><p><strong>14 &#8212; Model Routing and Provider Abstraction.</strong> The decision layer between &#8220;agent needs an LLM&#8221; and &#8220;this specific endpoint gets called.&#8221; Claude Code&#8217;s compile-time provider abstraction with getRuntimeMainLoopModel, getAgentModel priority chain, and FallbackTriggeredError with thinking-signature stripping vs Hermes&#8217;s runtime api_mode auto-detection from URLs, ordered fallback chains, fetch_model_metadata with 1-hour OpenRouter cache, switch_model for live mid-session switching, and smart_model_routing for per-turn cost optimization.</p><p><strong>15 &#8212; Structured Output and Schema-Constrained Generation.</strong> Constraining the model&#8217;s free-text output to a validated JSON schema &#8212; distinct from tool input validation (cc2). Claude Code&#8217;s SYNTHETIC_OUTPUT_TOOL_NAME trick (wrapping the schema as a fake tool), MAX_STRUCTURED_OUTPUT_RETRIES budget, and typed error_max_structured_output_retries result vs Hermes&#8217;s tool-use forcing pattern (portable across all providers), explicit retry loop with error feedback injected as messages, and batch_runner.py for parallel structured extraction at scale.</p><p>Every chapter ends with a Defensive Cyber Agent code sketch. By chapter 15, those sketches compose into a working SOC automation system.</p><p>Cyber defense is the right vertical because the constraints are real and the stakes are high. A port scan without authorization is a legal problem. A host isolation without analyst approval takes down production. A context window that drops the initial indicators of compromise loses the investigation thread. Every harness pattern has a direct, high-stakes analog in this domain &#8212; which makes it the best stress test for whether the patterns actually work.</p><p>The sketches are composable.
