You set it as <code>output_config.effort</code>, and it takes one of five levels. It is not a token budget with a new name. It changes how hard the model works on a response, and that shows up in every kind of token the model produces, not just the length of the prose. Set it low and you get shorter answers, fewer tool calls, and less reasoning, all at once. That makes effort the single highest-leverage line in a fleet's cost policy, and the single easiest one to set wrong by leaving it at the default everywhere.</p><p>The free half of this post is what the dial actually controls and why one setting fleet-wide is the wrong default.  The paid half is a router that picks effort per task from the kind of work it is, so your cheap traffic runs cheap and only the hard tasks pay for depth.</p><h2>Five levels, and one of them is the <code>high</code> is the default, and it is exactly identical to omitting the field. That last fact is the one that costs teams money. If you never set effort, every request in your fleet runs at <code>high</code>, including the classification calls and the format-fixing calls that would return an identical useful answer at <code>low</code> for a fraction of the tokens. The default is not free. It is a choice you made by not choosing, and it is the more expensive choice on most routine traffic.</p><p><code>ultracode</code>, if you have seen it referenced anywhere, is not one of these levels. The API set is these five. Anything else is a 400 or a typo.</p><h2>The dial moves more than length</h2><p>The reason effort beats the old thinking budget is what it reaches. The prose gets shorter. The thinking gets shallower. And the model makes fewer tool calls, with leaner arguments, because the tool-call tokens are output tokens too and the same signal governs them. That third effect is the one people miss. If you run an agent at <code>low</code> effort to save money, you are not just getting terser answers, you are getting an agent that reaches for fewer tools and does less work per turn. That is sometimes exactly right, for a triage step that should stay shallow, and sometimes exactly wrong, for the audit step that needs every tool it can justify.</p><p>Because it is a behavioral signal and not a hard cap, effort does not guarantee a token ceiling. It biases the model, it does not fence it. So you tune effort to the task's need for depth, and you keep <code>max_tokens</code> as the actual safety limit. That is the free half: five levels, <code>high</code> is the default you pay for by default, and the dial moves prose, tools, and thinking as one. The paid half makes it operational with a router that sets effort from the task itself.</p><h2>Book announcement: Fable 5 Harness</h2><p>This ten-part series is turning into a book: <strong>Fable 5 Harness</strong>.</p><p>I am excited about this because the series has outgrown the shape of a newsletter thread.
