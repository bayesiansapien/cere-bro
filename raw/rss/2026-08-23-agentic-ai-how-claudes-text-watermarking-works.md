# How Claude’s Text Watermarking Works

<p><strong><span>1.0 Executive Summary: How Claude Implements Text Watermarking</span></strong></p><p><span>Claude embeds statistical text watermarks directly during autoregressive token generation using cryptographic context-seeded tournament sampling (</span><a href="https://www.anthropic.com/news/claude-text-watermark"><span>Anthropic, 2026</span></a><span>; DeepMind SynthID-Text, </span><a href="https://www.nature.com/articles/s41586-024-08025-4"><span>Nature 2024</span></a><span>). The system operates through an integrated three-stage pipeline:</span></p><blockquote><p><strong><span>1.  Context-Seeded Pseudo-Random Generation:</span></strong><span> At each generation step t, the model takes a sliding window of the preceding h tokens (typically h=3) and hashes them alongside a 256-bit secret master key using HMAC-SHA256. This derives a deterministic pseudo-random seed s_t that is completely unpredictable to observers lacking the secret key.</span></p><p><strong><span>2.  Multi-Hash Tournament Selection:</span></strong><span> The derived seed instantiates m independent pseudo-random hash functions (m=3) that assign binary bit values {0, 1} to every token in the vocabulary. Candidate tokens generated by the model&#8217;s Softmax distribution are organized into a balanced binary elimination tournament tree. In each pairwise match, tokens with higher hash bit signatures defeat lower ones, while ties are resolved probabilistically in direct proportion to the model&#8217;s Softmax probabilities. This tournament selection guarantees that the expected winning probability of any token equals its exact model probability&#8212;preserving 100% distributional fidelity with zero perplexity increase.</span></p><p><strong><span>3.  Zero-LLM Fast Verification:</span></strong><span> Text provenance is audited without loading model weights or evaluating neural networks. An auditing service equipped with the secret key and BPE tokenizer replays the sliding context windows across the document, extracts the observed bit values, and computes a standard Normal Z-score. For sequences between 50 and 100 tokens, the accumulated bit bias provides overwhelming statistical separation (Z &gt;= 4.75, p &lt; 10^{-20}) against unwatermarked human or third-party text, evaluating over 50,000 tokens per second per CPU core.</span></p></blockquote><p><span>This whitepaper specifies the end-to-end mathematical formulation, tournament execution logic, zero-LLM statistical hypothesis tests, adversarial perturbation resilience, and production reference implementations.</span></p><p><strong><span>2.0 Foundations of Autoregressive LLM Sampling</span></strong></p><p><span>Autoregressive language models generate text sequentially by predicting one token at a time. At step t, given an input context sequence of preceding tokens x_1 through x_{t-1}, the transformer layers compute a vector of unnormalized logits z_t across the vocabulary V. The model transforms these logits into a normalized probability distribution P(x_t | x_{&lt;t}) through the Softmax function:</span></p><p><strong><span>[ PYTHON REFERENCE IMPLEMENTATION ]</span></strong></p><p><em><span># Normalized next-token probability distribution over vocabulary V</span></em></p><p><span>P(x_t == v | x_&lt;t) = exp(z_t[v] / Temperature) / sum(exp(z_t[j] / Temperature) </span><strong><span>for</span></strong><span> j in V)</span></p><p><span>In standard unwatermarked inference, sampling draws random numbers from an unseeded system entropy source. Common sampling strategies (such as temperature scaling, top-k filtering, or top-p nucleus sampling) truncate or reshape this distribution before drawing a uniform random float to select the final token. Because these random draws are unkeyed and independent of the text history, the resulting text carries no intrinsic signature of its origin.</span></p><p><span>Figure 1 contrasts this standard sampling path with Claude&#8217;s context-seeded watermarking architecture, highlighting the integration of the HMAC-SHA256 seed generator and tournament sampler.</span></p><div Context-Seeded Watermark Sampling</span></em></p><p><span>As shown in Figure 1, the watermarking architecture replaces the unseeded stochastic sampler with a deterministic cryptographic PRF. By hashing the preceding context tokens with a secret key, the model derives a dedicated pseudo-random seed for each step. This seed drives a set of binary hash functions that guide candidate selection without distorting the underlying token probabilities.</span></p><p><strong><span>3.0 The SynthID-Text &amp; Claude Watermarking Mechanics</span></strong></p><p><span>The watermarking engine builds on three core primitives: the </span><strong><span>Secret Master Key</span></strong><span>, the </span><strong><span>Sliding Context PRF</span></strong><span>, and the </span><strong><span>Multi-Hash Signature Vector</span></strong><span>.</span></p><p><strong><span>3.1 Secret Key Governance &amp; Context Hashing</span></strong></p><p><span>System security rests on a 256-bit master symmetric key, Key K, stored in Hardware Security Modules (HSMs) or enterprise Key Management Services (</span><a href="https://www.nist.gov/itl/ai-risk-management-framework"><span>NIST, 2023</span></a><span>). The key is never exposed in client prompts, model outputs, or inference logs.</span></p><p><span>At generation step t, the sampler inspects a sliding window of the preceding h tokens:</span></p><p><strong><span>[ VERIFICATION TELEMETRY ]</span></strong></p><p><span>Context Window Payload: W_t = [x_{t-h}, x_{t-h+1}, ..., x_{t-1}]</span></p><p><span>In production deployments, the history length h is set between 3 and 4 tokens. A window of h=3 provides strong statistical power while retaining resilience against localized edits. The engine derives a 256-bit seed s_t via Hash-based Message Authentication Code (HMAC-SHA256):</span></p><p><strong><span>[ VERIFICATION TELEMETRY ]</span></strong></p><p><span>s_t = HMAC_SHA256(Key K, BPE_Encode(W_t))</span></p><p><span>Because HMAC-SHA256 functions as a cryptographically strong PRF, third parties without Key K cannot predict s_t or distinguish the generated output stream from unwatermarked text, preventing adversaries from reverse-engineering the watermark signature.</span></p><p><strong><span>3.2 Multi-Hash Signature Functions</span></strong></p><p><span>Using the derived seed s_t, the engine evaluates m independent pseudo-random hash functions, g_1, g_2, ..., g_m. Each function maps any candidate vocabulary token v in V to a binary bit value:</span></p><p><strong><span>[ VERIFICATION TELEMETRY ]</span></strong></p><p><span>g_k(s_t, v) -&gt; {0, 1},  where k in {1, 2, ..., m}</span></p><p><span>For a standard configuration with m=3 hash functions, every candidate token receives a 3-bit signature vector:</span></p><p><strong><span>[ VERIFICATION TELEMETRY ]</span></strong></p><p><span>Signature(v) = [ g_1(s_t, v), g_2(s_t, v), ..., g_m(s_t, v) ]</span></p><p><span>Bit_Score(v) = sum(g_k(s_t, v) for k in 1..m)  in {0, 1, ..., m}</span></p><p><span>Under the null hypothesis (human writing or unwatermarked text), token selections are independent of the seed, yielding an expected bit score of exactly m / 2 (1.5 bits for m=3). The goal of tournament sampling is to favor tokens with higher bit scores (e.g., scores of 2 or 3) while preserving the exact probability distribution of the model.</span></p><p><strong><span>4.0 The Tournament Sampling Algorithm: Unbiased Distortion-Free Generation</span></strong></p><p><span>Earlier watermarking methods, such as the Green-Red list scheme (</span><a href="https://arxiv.org/abs/2301.10226"><span>Kirchenbauer et al., 2023</span></a><span>), bias generation by adding a fixed constant delta to the raw logits of green-listed tokens before computing the Softmax. While straightforward, logit shifting distorts the distribution tails, increases perplexity, breaks syntax formatting in code generation, and degrades reasoning on technical benchmarks.</span></p><p><span>Claude uses </span><strong><span>Tournament Sampling</span></strong><span> (DeepMind SynthID-Text; </span><a href="https://www.nature.com/articles/s41586-024-08025-4"><span>Nature, 2024</span></a><span>) to eliminate this distortion. Tournament sampling constructs a balanced binary tree across candidate tokens, executing pairwise matches that prioritize watermark bit signatures while maintaining exact probability weights.</span></p><p><strong><span>4.1 Binary Tournament Tree Execution</span></strong></p><p><span>Consider an engineering prediction step where the model assigns probabilities to four candidate tokens following the context  &#8221;The distributed consensus protocol coordinates state replication across all ...&#8221;:</span></p><blockquote><p><strong><span>&#8226;  </span></strong><span>&#8220;replicas&#8221;: Probability = 0.52 | Hash Signature = [1, 0, 1] | Bit Score = 2</span></p><p><strong><span>&#8226;  </span></strong><span>&#8220;nodes&#8221;: Probability = 0.28 | Hash Signature = [0, 1, 0] | Bit Score = 1</span></p><p><strong><span>&#8226;  </span></strong><span>&#8220;members&#8221;: Probability = 0.12 | Hash Signature = [0, 0, 1] | Bit Score = 1</span></p><p><strong><span>&#8226;  </span></strong><span>&#8220;validators&#8221;: Probability = 0.08 | Hash Signature = [1, 0, 0] | Bit Score = 1</span></p></blockquote><p><span>Figure 2 illustrates the pairwise tournament bracket structure, demonstrating how probability masses combine and how bit signatures resolve match ties.</span></p>
