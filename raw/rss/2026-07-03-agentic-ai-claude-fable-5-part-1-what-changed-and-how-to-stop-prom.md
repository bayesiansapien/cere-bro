# Claude Fable 5 (Part 1): What Changed, and How to Stop Prompting It Like Opus

<p>I spent my first full day on Claude Fable 5 doing what I always do with a new frontier model: I threw my existing prompts at it, watched half of them underperform, and then rebuilt my setup from the API docs instead of from habit. This post is the result. It covers what Fable 5 is (with the marketing fog burned off), which claims floating around this week check out and which don't, and the prompting shift that matters more than any benchmark number. </p><p>The short version: Fable 5 is the first model where my carefully engineered step-by-step prompts made output worse. The model plans better than my scaffolding does. The leverage has moved from writing clever instructions to building the loop around the model, which is memory, verification, boundaries, and an effort dial you must learn to use. </p><p>The analysis below, including the fact-check of the claims circulating this week and the prompting shift, is free. The paid section at the end is the day-one playbook: the five prompt blocks I now paste into every Fable 5 session, the two loops (verifier and memory) with working diagrams, and a weekend harness project with concrete deliverables. If you build on Claude for a living, that second half is the part you'll paste into your own setup tomorrow. </p><h2>What Fable 5 is</h2><p>Facts first, because a lot of secondhand summaries are sloppy. These come from Anthropic's platform docs and the API itself, not from screenshots of screenshots. </p><p>Fable 5 is Anthropic's most capable generally available model, the first of the Claude 5 family, sitting in a new tier above Opus. The model id is <code>claude-fable-5</code>. It shares its underlying model with Claude Mythos 5 (<code>claude-mythos-5</code>), which you cannot buy your way into: Mythos is available only through Anthropic's Project Glasswing partner program, without the extra dual-use safety measures Fable ships with. Same capabilities, same pricing, different gate. </p><p>The numbers that matter for your budget and your architecture: </p><ol><li><p>Pricing is $10 per million input tokens and $50 per million output tokens. That is double Opus 4.8 on input ($5/$25) and more than triple Sonnet 5 ($3/$15 sticker). </p></li><li><p>Context is 1M tokens, and unlike earlier long-context tiers there is no long-context premium. Max output is 128K per request. </p></li><li><p>The tokenizer is the same one Opus 4.8 uses, so if you're migrating from Opus 4.7 or 4.8 your token counts stay roughly flat. Coming from Sonnet or older models, re-measure with <code>count_tokens</code> before trusting any budget. </p></li><li><p>Thinking is always on. You cannot disable it. Sending <code>thinking: {type: "disabled"}</code> returns a 400 error, and so do <code>temperature</code>, <code>top_p</code>, <code>top_k</code>, <code>budget_tokens</code>, and assistant prefills. The API surface got smaller, on purpose. </p></li><li><p>One gotcha nobody puts in the launch posts: Fable 5 requires 30-day data retention. If your org runs zero data retention, every single request 400s with an unhelpful <code>invalid_request_error</code>. Check your retention config before you debug your payload. </p></li></ol><p>A single request on a hard task can run many minutes. That is not a bug or a timeout you should tune away; the model gathers context, builds, and verifies inside one turn. Plan for streaming and asynchronous check-ins, not blocking HTTP calls with 60-second timeouts. </p><h2>Fact-checking the week-one folklore</h2><p>Several summaries of Fable 5 are making the rounds, and before writing this I ran the load-bearing claims through a multi-source verification pass against Anthropic's own pages (<a href="https://www.anthropic.com/news/claude-fable-5-mythos-5">the launch announcement</a>, <a href="https://platform.claude.com/docs/en/pricing">the pricing docs</a>, <a href="https://www.anthropic.com/glasswing">the Glasswing page</a>, and <a href="https://platform.claude.com/docs/en/build-with-claude/prompt-engineering/prompting-claude-fable-5">the Prompting Claude Fable 5 guide</a>). Here is what survived and what didn't. </p><p><strong>Confirmed.</strong> The pricing ($10/$50, on five separate Anthropic pages). The Fable/Mythos split. Mythos 5 is gated behind Project Glasswing, the critical-infrastructure security program Anthropic announced in April with twelve founding partners (AWS, Apple, Google, Microsoft, NVIDIA, CrowdStrike, and others) plus 40-some vetted organizations; the biology trusted-access program you may have read about is announced as a plan, not a live program. The official "Prompting Claude Fable 5" guide exists and says, verbatim, that skills developed for prior models "are often too prescriptive for Claude Fable 5 and can degrade output quality." It recommends effort as the primary intelligence-latency-cost control, verifier subagents, and file-based memory. That guidance is the spine of this article. </p><p><strong>Confirmed, but attribute it.</strong> The benchmark claims are real in the narrow sense that Anthropic makes them: the announcement says Fable 5 scores highest among frontier models on Cognition's FrontierCode (even at medium effort), calls it "the state of the art model on CursorBench," demos rebuilding a web app from screenshots alone, and quotes Stripe compressing a 50-million-line codebase migration from about two months into a day. None of that is independently audited yet. Repeat it as "Anthropic claims," not as fact, and be suspicious of any summary that adds SWE-Bench numbers, because the announcement doesn't contain any. </p><p><strong>Distorted.</strong> The fallback story is the big one. The version going around says Fable 5 "transparently falls back to Opus 4.8 and you are not charged." Half true. On consumer surfaces like Claude.ai the fallback ships built in and you're told when it happens. On the API it is opt-in: a declined request just stops with <code>stop_reason: "refusal"</code> unless you passed the <code>fallbacks</code> parameter. Billing is also more precise than "not charged": a refusal before any output is not billed at all, a mid-stream refusal bills the tokens already streamed, and the Opus 4.8 rescue bills at Opus 4.8's own rates (with the replayed input at the cache-read discount). The circulating "5 to 8 percent fallback rate" is a mangled version of Anthropic's actual launch statement that more than 95% of sessions involve no fallback at all. If you build on the API and skip the opt-in, a false positive doesn't degrade gracefully. It fails. </p><p><strong>Contradicted.</strong> "Highly resistant to jailbreaks, none found in testing" did not survive contact with July. Anthropic's own <a href="https://www.anthropic.com/news/redeploying-fable-5">redeployment post</a> documents a jailbreak reported by Amazon serious enough that Fable 5 and Mythos 5 access was suspended in late June while a retrained cybersecurity classifier shipped; it now blocks that attack in more than 99% of attempts, and, by Anthropic's own admission, flags benign requests more often than before. I started my day-one testing two days after the redeployment, which is probably why my security-adjacent prompts tripped the classifier as often as they did. More on that below. </p><p><strong>Unverified.</strong> "Claudish," the claim that Fable 5 develops a private shorthand language in long multi-agent sessions, has no source anywhere I could find. It's a catchy name bolted onto a real but more boring documented behavior: deep into long sessions the model can drift into dense arrow-chain shorthand in user-facing summaries, and Anthropic publishes a prompt block to counter it (I include it in the paid section). Nobody needed to invent a language for that. </p><p>The meta-lesson from the fact-check: even mostly-accurate writeups blur the line between vendor claims and audited facts, garble one number, and invent one term. Verify the load-bearing claims against the platform docs before you wire money or architecture to them. </p><h2>The prompting shift: your best Opus prompts are now dead weight</h2><p>This is the y1="21" y2="14"></line></svg></button></div></div></div></a></figure></div><p>For three model generations we compensated for planning weakness by doing the planning ourselves: numbered step lists, "think step by step," long behavior checklists, skills files that read like flight manuals. Fable 5 plans better than those crutches, and the crutches now get in the way. When I ran an old 22-step migration prompt, the model followed my steps faithfully, including the three steps that were wrong for the new codebase. When I replaced the whole thing with the goal, the reason behind it, and the constraints, it found a better sequence than mine and finished in fewer turns. </p><p>The replacement pattern is short enough to memorize: </p><pre><code>I'm working on [larger project] for [who it's for], 
because [what the outcome enables]. 
 
Current state: [brief context, attached files]. 
Constraints: [what must not change, what must be true at the end]. 
 
[The goal.] Lead with the outcome when you report back. </code></pre><p>The "because" clause is not politeness. Fable 5 measurably uses intent to make micro-decisions you didn't specify: which of two equivalent refactors to pick, what to do when a test conflicts with a comment, when to stop polishing. Anthropic's own guidance says the model performs better when it understands why, and one day in, I believe it. Give it the reason and delete the step list. </p><p>The second lever is effort, and it replaces every "think harder" incantation you've ever written. </p><div <code>low</code> to <code>max</code> and a default of <code>high</code>. Two things surprised me. First, <code>xhigh</code> is not the everyday setting; it's for the hardest coding and agentic runs, and on routine work it just buys you slower, more deliberate output. Second, <code>low</code> and <code>medium</code> on Fable 5 often beat what <code>xhigh</code> produced on previous models, which flips the cost argument: the expensive model at low effort can be the cheap option. </p><pre><code>response = client.messages.create( 
    model="claude-fable-5", 
    max_tokens=16000, 
    output_config={"effort": "high"},  # low | medium | high | xhigh | max 
    messages=[{"role": "user", "content": task}], 
) </code></pre><p>Note what is absent from that call: no <code>thinking</code> block, no temperature, no top_p. On Fable 5 you omit the thinking parameter entirely because thinking is always on, and the raw chain of thought is never returned. If you want a readable summary of the reasoning, request <code>thinking: {type: "adaptive", display: "summarized"}</code>; the default leaves thinking blocks empty, which in a streaming UI looks like a long silent pause before output. Set it explicitly or your users will think the app hung. </p><h2>How the safety layer works</h2><p>Fable 5 runs classifiers on incoming requests aimed at offensive cybersecurity, biology and life sciences, and attempts to extract its raw reasoning. The fix is four lines, plus the opt-in: </p><pre><code>response = client.beta.messages.create( 
    model="claude-fable-5",

    betas=["server-side-fallback-2026-06-01"],

)

    handle_refusal(response.stop_details) </code></pre><p>With the <code>fallbacks</code> parameter, a declined request is re-served by Opus 4.8 inside the same call, and you can detect the switch from the <code>fallback</code> block in the content. Without it, the request just stops. Memory files give the model a place to write lessons that survive the session, and Fable 5 is notably better than its predecessors at using them. Human steering happens at the level of goals and outcome review, not step approval. </p><p>The direction of travel matters: harnesses built for Opus were heavy on prescriptive steps and frequent handoffs, and on Fable 5 you should delete most of that. Fewer mandated checkpoints, longer autonomous runs, and much stronger emphasis on the verifier and the memory layer. Start from less structure than feels safe, measure, and add back only what the failures justify. </p><p>That's the analysis.
