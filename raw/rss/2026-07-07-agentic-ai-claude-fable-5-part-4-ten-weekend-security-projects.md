# Claude Fable 5, Part 4: Ten Weekend Security Projects

<p><a href="https://kenhuangus.substack.com/p/claude-fable-5-what-changed-and-how">Part 1</a> covered the prompting shift, <a href="https://kenhuangus.substack.com/p/claude-fable-5-part-2-loop-engineering">part 2</a> covered loops, <a href="https://kenhuangus.substack.com/p/claude-fable-5-part-3-memory-engineering">part 3</a> covered memory. Part 4 is for a narrower reader: security architects, agentic AI engineers, and CISOs, and it swaps concepts for projects. Ten of them, each runnable in a weekend, each generic enough that you don't need my codebase to follow along, and each built on the same pattern the series has been moving toward: a cheap model preps the job, Fable 5 plans or audits it, and a cheap model does the execution. The frontier model touches the judgment-dense middle. It never touches the typing.</p><p>Here's the split. The free half covers the pattern itself, when to skip it entirely, and the fallback-routing and cost realities you need before you spend a token on any of this, all checked against primary sources and named practitioner reports rather than vibes. The paid half is the ten projects, a reusable job-packet template you can copy for any of them, and the tripwires I'd hand to a team before its first project with this model.</p><h2>The pattern, and maker-never-grader discipline wearing a security hat. Prep is a cheap model turning your actual environment (an architecture, an API list, an MCP inventory) into a job packet Fable 5 can reason over without you re-explaining your stack every time. Plan or audit is Fable 5 at <code>high</code> or <code>xhigh</code> effort, spending its premium exactly where premium buys something: catching the threat model gap, the redundant OAuth grant, the missing rate limit. Execute hands the plan to a cheap model, because typing out a well-specified plan doesn't need the frontier model's judgment. Verify closes the loop with a fresh-context grader checking the diff against the plan, not against the executor's account of what it did.</p><p>The pattern earns its keep on the right kind of task and one short response, a cheap model one-shots it faster and for less. Fable 5 earns its price on work with branches, where the right answer depends on judgment calls the model has to make and defend: threat modeling an agent stack, deciding which of twenty MCP grants to revoke, auditing a diff against a spec you didn't write down cleanly enough yourself. If you can't articulate what the judgment call is, you're about to pay frontier prices for autocomplete.</p><h2>Test your fallback routing before you budget tokens</h2><p>Anthropic's <a href="https://www.anthropic.com/news/claude-fable-5-mythos-5">launch statement</a> is direct about this: "When Fable's classifiers detect a request related to cybersecurity, biology and chemistry, or distillation, the response is automatically handled by Claude Opus 4.8 instead." Users are told when it happens, and a request that falls back isn't billed at Fable's rates. For this audience that's not a footnote, it's routing information: security work is exactly the category most likely to get rerouted mid-project, and you want to know that before you plan a weekend around Fable-specific behavior that might not show up.</p><p>The latest update matters if your weekend project touches code security. Anthropic <a href="https://www.anthropic.com/news/redeploying-fable-5">restored Fable 5 access on July 1</a> after the June suspension and said the new classifier blocks the Amazon-reported bypass technique in more than 99 percent of cases. The catch is the same one security teams will feel first: Anthropic also says benign coding and debugging requests now get flagged more often. Treat the redeploy as a reason to test routing earlier, not as a reason to assume the safety layer disappeared.</p><p>The precise mechanics are a level more specific than the launch post's prose. if response.stop_reason == "refusal":
    print(response.stop_details.category)  # cyber, bio, frontier_llm, reasoning_extraction</code></pre><p>Run your actual project prompts through this before you commit to any of them. Project 1 (threat modeling your own stack) and project 10 (red-teaming your own AI features) are the two most likely to trip <code>cyber</code>, and if half your session reroutes to Opus 4.8, that's useful to know before the build plan depends on Fable-specific behavior.</p><p>One more implementation trap: Message Batches do not support server-side fallback. Anthropic's fallback docs say a refused batch item still comes back as a succeeded result with <code>stop_reason: "refusal"</code>, and you have to collect those items, strip Fable thinking blocks from multi-turn histories, and resubmit them to the fallback model yourself. That matters for project 10, because red-team harnesses almost always become batch jobs once the first version works.</p><h2>The cost reality, from people who found out the hard way</h2><p>The instinct to trust vendor framing over independent testing paid off here. GitLab's own <a href="https://about.gitlab.com/blog/mythos-class-claude-fable-5-on-gitlab/">launch post</a> says Fable 5 "self-corrects through verification loops, catches its own mistakes, and stays on-task across complex multi-step operations," attributed to unnamed early testers with no benchmark attached; it's a partnership announcement, and it reads like one. CodeRabbit ran an actual benchmark and reported the sharper edge of the same behavior: "In our coding task benchmark, Fable 5 often kept working until the harness cut it off. That makes the model feel capable, but it also makes it expensive and slower in agent workflows that do not have strong stop rules." Same underlying trait, described by a vendor as a feature and by an independent tester as a cost risk. Believe the second one when you're setting a budget.</p><div class="captioned-image-container"><figure><a class="image-link image2 is-viewable-img" Scrimba's CEO, Per Borgen, posted on X that a single Fable 5 session burned 1.3 million tokens, and Bleeping Computer reported that Fable drained a $100 Max-plan daily allowance in a single short test. Neither number is independently audited math, so treat the dollar amounts as directional, not certified. The direction is the point: this is a model that can spend a full project budget in one under-scoped cycle if nothing is watching the meter. Every project below assumes the task budgets and stop rules from part 2 are already wired in, not optional polish you add later.</p><p>The subscription story changed too. Anthropic's redeploy note says Fable 5 counted against up to 50 percent of weekly usage limits through July 7, 2026, then moved to usage credits. If you're running these projects through Claude Code, Claude.ai, or Cowork instead of the API, put the usage-credit check next to the token budget. A project that looks free because it sits inside a subscription can still stop in the middle when the account policy changes under it.</p><p>That's the free half.
