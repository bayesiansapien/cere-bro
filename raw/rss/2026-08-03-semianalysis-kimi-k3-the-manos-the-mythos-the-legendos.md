# Kimi K3, The Manos, The Mythos, The Legendos

<p style="text-align: justify;">Kimi K3 took the world by storm at its announcement, sweeping leaderboards and establishing itself as the open frontier model. While the community is eager to understand how Kimi K3 works, many have been surprised by the unconventional techniques driving its performance. This article serves as a primer to understanding the core techniques of the Kimi K3 model architecture.</p><h1 style="text-align: justify;"><span>Kimi Delta Attention</span></h1><p style="text-align: justify;"><span>Kimi Delta Attention (KDA) is the linear attention layer in Kimi K3&#8217;s hybrid attention mechanism. We trace the origins of KDA, starting from linear attention, DeltaNet, Gated DeltaNet (GDN), then to KDA.</span></p><h2 style="text-align: justify;"><span>Linear Attention</span></h2><p style="text-align: justify;"><span>The derivation of linear attention stems from </span><strong><span>removing the softmax operation in the standard softmax attention</span></strong><span>. The computational complexity of both equations are O(</span><em><span>Ld</span></em><span>&#178;), thereby making the computation linear. Comparing the new equations with softmax attention&#8217;s equation, we see that </span><strong><span>softmax attention requires accessing all past key and value vectors</span></strong><span>, whereas </span><strong><span>linear attention compresses all past key and value vectors</span></strong><span> </span><strong><span>into one hidden state S</span></strong><span>.</span></p><p style="text-align: justify;"><span>We reinterpret the new equations as an </span><strong><span>online learning objective</span></strong><span>. We view matrix S as an associative memory that stores the associations between key vector k and value vector v, and we retrieve v by multiplying S with k. We can then interpret the first equation as </span><strong><span>continuously updating the matrix S at every position to perfect the retrieval</span></strong><span>. Finally, we can interpret the vt @ kt.T term as the gradient of loss function -(S @ kt.T) @ vt with respect to S.</span></p><div class="latex-rendered"></div><h2 style="text-align: justify;"><span>DeltaNet</span></h2><p style="text-align: justify;"><span>Under the online learning objective view, we see the values of matrix S will grow unboundedly: old and new information gets blurred together in S as the sequence grows, which destabilizes learning. Without softmax giving well-scaled and bounded outputs, linear attention typically lags behind softmax attention on long-range recall tasks.</span></p><p style="text-align: justify;"><span>DeltaNet improves upon linear attention by </span><strong><span>changing the loss function to minimizing the L2 norm of the value retrieval</span></strong><span>. Unlike linear attention&#8217;s loss function, DeltaNet&#8217;s loss function regularizes the growth of S. This creates a new matrix S update rule, the Delta Rule, as below:</span></p><div class="latex-rendered"></div><p style="text-align: justify;"><span>Source: </span><a href="https://www.youtube.com/watch?v=d0HJvGSWw8A"><span>Linear Attention and Beyond (Interactive Tutorial with Songlin Yang)</span></a></p><p style="text-align: justify;"><span>The Delta Rule becomes the basis of DeltaNet&#8217;s attention equation:</span></p><div class="latex-rendered"></div><p style="text-align: justify;"><span>Conceptually, S&#8348;-1 @ k&#8348; - v&#8348; represents the associations irrelevant to the current key and value, and DeltaNet performs targeted removal of those associations.</span></p><h2 style="text-align: justify;"><span>Gated DeltaNet</span></h2><p style="text-align: justify;"><span>GDN and KDA are adaptations of DeltaNet. Gated DeltaNet applies the LSTM forget gate </span><em><span>alpha </span></em><span>on the matrix S, allowing the model to control memory lifespan with weight decay. KDA further expands </span><em><span>alpha</span></em><span> into a diagonal matrix that enables fine-grained per-channel memory decay and positional awareness.</span></p><div class="captioned-image-container"><figure><a class="image-link image2" href="https://substackcdn.com/image/fetch/$s_!IjUm!,f_auto,q_auto:good,fl_progressive:steep/https%3A%2F%2Fsubstack-post-media.s3.amazonaws.com%2Fpublic%2Fimages%2Ffbf7f177-b0a4-4c28-b958-de5b04fa57a9_866x129.png" target="_blank"><div class="image2-inset"><source type="image/webp" /><img alt="" class="sizing-normal" height="129" src="https://substackcdn.com/image/fetch/$s_!IjUm!,w_1456,c_limit,f_auto,q_auto:good,fl_progressive:steep/https%3A%2F%2Fsubstack-post-media.s3.amazonaws.com%2Fpublic%2Fimages%2Ffbf7f177-b0a4-4c28-b958-de5b04fa57a9_866x129.png" width="866" /><div></div></div></a><figcaption class="image-caption">Source: <a href="https://arxiv.org/abs/2510.26692">Kimi Linear</a></figcaption></figure></div><div class="captioned-button-wrap"><div class="preamble"><p class="cta-caption">Thanks for reading SemiAnalysis! This post is public so feel free to share it.</p></div><p class="button-wrapper"><a class="button primary" href="https://newsletter.semianalysis.com/p/kimi-k3-the-manos-the-mythos-the?utm_source=substack&amp;utm_medium=email&amp;utm_content=share&amp;action=share"><span>Share</span></a></p></div><h2 style="text-align: justify;"><span>FlashKDA Algorithm</span></h2><p style="text-align: justify;"><span>Moonshot developed FlashKDA, their custom kernels for KDA, and </span><a href="https://github.com/MoonshotAI/FlashKDA/tree/master"><span>open-sourced it</span></a><span>. Here we explain the algorithm and derive the arithmetic intensity.</span></p><h3 style="text-align: justify;"><span>Algorithm</span></h3><p style="text-align: justify;"><span>First, let&#8217;s start from an alternative formulation of the recurrence formula:</span></p><div class="highlighted_code_block"><pre class="shiki"><code class="language-python">u_t = beta_t * (v_t - (D_t @ S_t-1).T @ k_t)
S_t = D_t @ S_t-1 + k_t @ u_t.T
o_t.T = q_t.T @ S_t</code></pre></div><p><span>Here, D_t is the diagonal matrix of the alpha forget gate, and u_t is the delta in the delta rule. For decode, the kernel roughly follows the formula. For prefill, we parallelize the operation by unrolling the recurrence formula in chunks of tokens, in order to efficiently execute the operations on GPUs. Assume we unroll token i to j, and the starting state is S_i-1, we get:</span></p><div class="highlighted_code_block"><pre class="shiki"><code class="language-python">S_j = D_j:i @ S_i-1 + sum(D_j:t+1 @ k_t @ u_t.T, t=i:j)
o_j.T = q_j.T @ S_j
      = q_j.T @ D_j:i @ S_i-1 + sum(q_j.T @ D_j:t+1 @ k_t @ u_t.T, t=i:j)</code></pre></div><p style="text-align: justify;"><span>D_j:i refers to the cumulative decay from token i to j: D_j @ D_j-1 @ D_j-2 @ &#8230; @ D_i. In FlashKDA&#8217;s matrix form, the formula becomes:</span></p><div class="highlighted_code_block"><pre class="shiki"><code class="language-python">S_out = D_j:i @ S_in + K_restore.T @ U
M_qk = tril(Q_decay @ K_inv.T)
O = Q_decay @ S_in + M_qk @ U</code></pre></div><p style="text-align: justify;"><span>The vector to matrix mapping is as follows:</span></p><ul><li><p style="text-align: justify;"><span>S_in refers to the state at the starting position of a chunk</span></p></li><li><p style="text-align: justify;"><span>S_out refers to the state at the end position of a chunk</span></p></li><li><p style="text-align: justify;"><span>K_restore is the matrix form of D_j:t+1 @ k_t</span></p></li><li><p style="text-align: justify;"><span>Q_decay is the matrix form of q_j.T @ D_j:i</span></p></li><li><p style="text-align: justify;"><span>Q_decay @ K_inv.T the matrix form of q_j.T @ D_j:t+1 @ k_t, derived from (q_j.T @ D_j:i) @ (D_t:i^-1 @ k_t)</span></p></li><li><p style="text-align: justify;"><span>M_qk is the causal mask, so it&#8217;s a lower triangular matrix</span></p></li></ul><p style="text-align: justify;"><span>U is the matrix form of unrolled u_t. To compute this, we apply UT transform and compute the following:</span></p><div class="highlighted_code_block"><pre class="shiki"><code class="language-python">B = Diag(beta) @ (V - K_decay @ S_in)
L = StrictTril(Diag(beta) @ K_decay @ K_inv.T)
U = (I + L)^-1 @ B</code></pre></div><p style="text-align: justify;"><span>Please consult </span><a href="https://sustcsonglin.github.io/blog/2024/deltanet-2/"><span>Songlin Yang&#8217;s blog post</span></a><span> and </span><a href="https://arxiv.org/abs/2510.26692"><span>Kimi Linear paper section 3.1</span></a><span> for the full derivation. Note that here U corresponds to the pseudo-value term in the Kimi Linear paper.</span></p><p style="text-align: justify;"><span>Implementation-wise, FlashKDA launches 2 kernels: K1 and K2. K1 prepares chunk-level tensors in parallel, including:</span></p><div class="highlighted_code_block"><pre class="shiki"><code class="language-python">a = exp2(cumsum(g))
K_decay = Diag(a) @ K
Q_decay = Diag(a) @ Q
K_inv = Diag(a)^-1 @ K
K_restore = a[-1] * K_inv
L = StrictTril(Diag(beta) @ K_decay @ K_inv.T); INV = (I + L)^-1
M_qk = tril(Q_decay @ K_inv.T)</code></pre></div><p style="text-align: justify;"><span>Here </span><code>a</code><span> is the cumulative decay, where each element is the cumulative decay at a token position. </span></p><p style="text-align: justify;"><span>K2 performs chunk-level recurrent computation:</span></p><pre><code>U = INV @ Diag(beta) @ (V - K_decay @ S)
O = Q_decay @ S + M_qk @ U
S = Diag(a[-1]) @ S + K_restore.T @ U</code></pre><h3 style="text-align: justify;"><span>Complexity Analysis</span></h3><p><span>Here we analyze the complexity of an attention head. For decode, the critical path computations are:</span></p><ul><li><p><span>D_t @ S_t-1: Element-wise multiplication, D &#215; D</span></p></li><li><p><span>S_t-1.T @ k_t: D &#215; D &#215; 1</span></p></li><li><p><span>k_t @ u_t.T: D &#215; 1 &#215; D</span></p></li><li><p><span>q_t.T @ S_t: 1  D &#215; D</span></p></li></ul><p><span>The decode kernel roughly performs 7*D&#178; FLOPs.</span></p><p><span>Reading and writing the FP32 recurrent state dominates the memory traffic, so the memory traffic is roughly 8*D&#178; bytes.</span></p><p style="text-align: justify;"><span>For prefill, the critical path of K1 is at computing L, INV, and M_qk.</span></p><ul><li><p style="text-align: justify;"><span>L: C &#215; D &#215; C</span></p></li><li><p style="text-align: justify;"><span>INV: </span><a href="https://github.com/MoonshotAI/FlashKDA/blob/1ce47ea3bb22c84eb9cc665028399cf35e8ffb0b/csrc/smxx/utils.cuh#L190"><span>Neumann factorization</span></a><span>, performs 6 C &#215; C &#215; C matrix multiplications</span></p></li><li><p style="text-align: justify;"><span>M_qk: C &#215; D &#215; C</span></p></li></ul><p style="text-align: justify;"><span>For K2,</span></p><ul><li><p style="text-align: justify;"><span>K_decay @ S: C &#215; D &#215; D</span></p></li><li><p style="text-align: justify;"><span>Q_decay @ S: C &#215; D &#215; D</span></p></li><li><p style="text-align: justify;"><span>M_qk @ U: C &#215; C &#215; D</span></p></li><li><p style="text-align: justify;"><span>INV @ B: C &#215; C &#215; D</span></p></li><li><p style="text-align: justify;"><span>K_restore.T @ U: D &#215; C &#215; D</span></p></li></ul><p style="text-align: justify;"><span>Combining K1 and K2, FlashKDA performs 12*C^3 + 8*C&#178;*D + 6*C*D&#178; FLOPs. Since we analyzed at the chunk level (chunk size C), assuming sequence length T &gt;&gt; C, the overall FLOPs is T/C * O(C*D&#178;) = O(T*D&#178;).</span></p><p style="text-align: justify;"><span>For memory traffic:</span></p><ul><li><p style="text-align: justify;"><span>K1 read Q, K, g: C &#215; D</span></p></li><li><p style="text-align: justify;"><span>K1 write and K2 read Q_decay, K_decay, K_restore: C &#215; D</span></p></li><li><p style="text-align: justify;"><span>K1 write and K2 read INV, M_qk: C &#215; C</span></p></li><li><p style="text-align: justify;"><span>K2 read V and write O: C &#215; D</span></p></li><li><p style="text-align: justify;"><span>K2 read and write S once per kernel: D &#215; D</span></p></li></ul><p style="text-align: justify;"><span>In total, FlashKDA accesses 3 * 2*C*D + 2 * (3 * 2*C*D + 2 * 2*C*C) + 2 * 2*C*D = 8*C&#178; + 22*C*D bytes. At the kernel level, it accesses T/C * (8*C&#178; + 22*C*D) + 8*D&#178; ~ O(TC + TD + D&#178;).</span></p><p style="text-align: justify;"><span>This concretely shows that the computational complexity of KDA:</span></p><ul><li><p style="text-align: justify;"><span>Prefill: Linear to sequence length for both computation and memory</span></p></li><li><p style="text-align: justify;"><span>Decode: Constant to sequence length for both computation and memory</span></p></li></ul><h1 style="text-align: justify;"><span>Kimi Linear</span></h1><p style="text-align: justify;"><span>Moonshot trained Kimi Linear models as proof of concept for their KDA design, so we can infer Kimi K3&#8217;s architecture design from Kimi Linear. Comparing the K3 release tech blog with Kimi Linear, we see Kimi K3 shares the shared expert count, the hybrid linear attention ratio, and the general attention module design.</span></p><div B/s</span></p></li></ul><ol><li><p><span>Assuming uniform expert routing, each GPU is assigned </span><em><span>t * K / E</span></em><span> tokens</span></p></li><li><p><span>Assuming uniform expert routing, an average </span><em><span>1 / E</span></em><span> tokens are local to the source GPUs, so each GPU dispatches </span><em><span>(t*K/E) * (1-1/E)</span></em><span> tokens</span></p></li><li><p><span>Each token is a d dimensional vector, so the communication volume per token is </span><em><span>d * P</span></em></p></li><li><p><span>The communication volume per GPU is </span><em><span>(t*K/E) * (1-1/E) * d * P</span></em></p></li><li><p><span>The communication time T_comm  = </span><em><span>(t * K * d * P) / (E * B) * (1-1/E)</span></em></p></li><li><p><span>The SwiGLU computation involves 3 matrix multiplications:</span></p><ol><li><p><span>Up (First) projection: </span><em><span>d</span></em><span> to </span><em><span>m</span></em></p></li><li><p><span>Gate projection: </span><em><span>d</span></em><span> to </span><em><span>m</span></em></p></li><li><p><span>Down (Second) projection: </span><em><span>m</span></em><span> to </span><em><span>d</span></em></p></li></ol></li></ol><p><span>&#9;So the computation is </span><em><span>2*d*m + 2*d*m + 2*m*d = 6*d*m</span></em><span> FLOPs per token</span></p><ol start="7"><li><p><span>The computation time per GPU is </span><em><span>T_comp = (6*d*m) * (t*K/E) / F</span></em></p></li><li><p><span>The communication to computation time ratio is</span></p><p><em><span>T_comm / T_comp</span></em></p><p><em><span>= ((t * K * d * P) / (E * B) * (1-1/E)) / ((6*d*m) * (t*K/E) / F)</span></em></p><p><em><span>= (P*F) / (6*m*B) * (1-1/E)</span></em></p></li></ol><p><span>We believe this formula also motivates an increase in expert intermediate dimension to 3072 in not just Kimi K2 to K3, but all recent open weight models, including DeepSeek V4 Pro, MiniMax M3, MiMo V2.5 Pro, and Inkling. As hardware improves and expert weight precision reduces to save memory capacity, the compute throughput increases, so one way of reducing the ratio is by increasing the expert intermediate
