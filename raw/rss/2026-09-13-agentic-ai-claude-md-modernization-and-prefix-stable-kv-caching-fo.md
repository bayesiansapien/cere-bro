# CLAUDE.md Modernization and Prefix-Stable KV Caching for Claude Code

<p><code>CLAUDE.md</code> loads on every Claude Code session: trim it to a static bootstrap, split memory by volatility, and compile <code>.kb/</code> in byte-stable order so multi-turn Key-Value (KV) prefix hits survive.</p><h2>Free outline: what the paid section covers</h2><ol><li><p>Why <code>/doctor</code> and the memory docs now treat long <code>CLAUDE.md</code> files as a liability, not a badge of rigor.</p></li><li><p>Five modernization steps: diagnose, offload, dateless model IDs, prune generic standards, condense memory sync rules.</p></li><li><p>Prefix caching mechanics: left-to-right hash match, block boundaries, and why one byte change at token N invalidates everything after N.</p></li><li><p>Local failure modes: dynamic headers, shuffled file order, CRLF vs LF, trailing whitespace.</p></li><li><p>Volatility hierarchy: keep <code>CLAUDE.md</code> static; put architecture in low-churn files; append session logs at the bottom.</p></li><li><p>Production scripts: <code>build-context.sh</code> with alphabetical <code>LC_ALL=C</code> sort, LF normalization, and a prefix-integrity audit.</p></li><li><p>Repo safety net: pre-commit CRLF fix plus <code>.gitattributes</code> <code>eol=lf</code> for memory markdown.</p></li><li><p>Session automation: real <code>.claude/settings.json</code> <code>SessionStart</code> hooks, plus a <code>make claude</code> wrapper; verification order and production takeaways.</p></li></ol><div class="paywall-jump"></div><h2>Going Deeper: modernize CLAUDE.md, then lock the prefix</h2><p>Claude Code loads project memory into the context window at session start. Anthropic's memory guidance targets under about 200 lines per <code>CLAUDE.md</code>, prefers path-scoped rules for specialized guidance, and uses <code>/doctor</code> (v2.1.206+) to propose trims for checked-in content the model can derive from the codebase. See the official pages on <a href="https://code.claude.com/docs/en/memory">memory</a>, <a href="https://code.claude.com/docs/en/best-practices">best practices</a>, and <a href="https://code.claude.com/docs/en/debug-your-config">configuration diagnostics</a>.</p><p>Prefix caching is a separate constraint. Anthropic's prompt cache keys on the exact rendered prefix up to each breakpoint. One changed byte before a breakpoint invalidates every later cached segment. Put stable instructions first; put volatile content last. <code>/doctor</code> inside the repository first. Current Claude Code builds treat <code>/doctor</code> as an actionable checkup: installation health, unused extensions, duplicate local memory against checked-in files, slow hooks, and (from v2.1.206) proposals to trim checked-in <code>CLAUDE.md</code> material Claude can recover by reading the tree. Confirm before applying any proposed edit.</p><p>Next, offload non-essential rules. Deep tool manuals, environment bootstrap essays, and architecture tours belong in <code>docs/</code>, <code>ARCHITECTURE.md</code>, or path-scoped <code>.claude/rules/</code> files. Keep the root bootstrap file limited to what must apply on every turn: build/test commands, non-default conventions, and project-specific workflow gates.</p><p>Update model references. Prefer family aliases (<code>sonnet</code>, <code>haiku</code>) or dateless major IDs such as <code>claude-sonnet-5</code> where your provider documents them. Dated snapshot IDs pin weights; convenience aliases for older generations can move. The authoritative maps live in <a href="https://code.claude.com/docs/en/model-config">Claude Code model configuration</a> and <a href="https://platform.claude.com/docs/en/about-claude/models/model-ids-and-versions">model IDs and versions</a>.</p><p>Prune implicit coding standards. Lines such as "always handle errors gracefully" or "use descriptive variable names" burn prefix tokens and dilute the few rules that actually differ from model defaults. Keep rules that encode your team's feature loop, review gates, and forbidden operations.</p><p>Condense memory tracking. Replace multi-paragraph logging liturgies for <code>AUDIT.md</code>, <code>progress-report.md</code>, or <code>USERS.md</code> with one outcome rule: after code changes, update the tracking files so they match the tree. Specificity belongs in a short template at the bottom of each tracking file, not in the always-on bootstrap.</p><p>Figure 2 orders those five steps as a single maintenance loop you can run after every model or harness upgrade.</p><div class="captioned-image-container"><figure><a class="image-link image2" href="https://substackcdn.com/image/fetch/$s_!hXqU!,f_auto,q_auto:good,fl_progressive:steep/https%3A%2F%2Fsubstack-post-media.s3.amazonaws.com%2Fpublic%2Fimages%2F0689e203-59ab-44da-92cc-7b3b45120608_2400x599.png" target="_blank"><div class="image2-inset"><source type="image/webp" /><img alt="Figure 2: Five-step CLAUDE.md modernization loop" class="sizing-normal" height="599" src="https://substackcdn.com/image/fetch/$s_!hXqU!,w_1456,c_limit,f_auto,q_auto:good,fl_progressive:steep/https%3A%2F%2Fsubstack-post-media.s3.amazonaws.com%2Fpublic%2Fimages%2F0689e203-59ab-44da-92cc-7b3b45120608_2400x599.png" title="Figure 2: Five-step CLAUDE.md modernization loop" width="2400" /><div></div></div></a></figure></div><p><em>Figure 2: Five-step CLAUDE.md modernization loop</em></p><h3>How prefix caching works under the hood</h3><p>When the client sends a turn, the backend sees one structured token sequence. Conceptually:</p><p><code>[System / tools] &#8594; [CLAUDE.md + static docs] &#8594; [Conversation history] &#8594; [Current input / code delta]</code></p><p>The inference stack scans left to right and looks up whether the cryptographic hash of the prefix matches a recent precomputed KV matrix. On a hit through token N, the engine reuses attention states for those N tokens instead of recomputing them, which cuts time-to-first-token for the shared prefix.</p><p>Providers allocate cache state on token-block boundaries (commonly discussed in 1024-token chunks for many serving stacks; Anthropic also documents model-dependent minimum cacheable prefix lengths). If the first 5,000 tokens of project instructions stay identical, early blocks hit. If token 4,100 changes (a timestamp, a reordered file, a CRLF insertion), the block that contains that token misses, and every later block must recompute because attention depends on all prior tokens.</p><p>Figure 3 shows that failure: a one-token edit in block 5 collapses reuse for blocks 5 through the end of the request.</p><div class="captioned-image-container"><figure><a Keep warnings on stderr so a SessionStart hook does not inject noisy audit text into the model context.</p><p>Audit first. This fragment scans each <code>.kb/*.md</code> file, flags CRLF, and warns when volatile header keys sit in the first five lines:</p><pre><code>set -euo pipefail
KB_DIR=".kb"; OUT="scripts/.compiled_context.md"
RED=$'\033[0;31m'; YEL=$'\033[0;33m'; NC=$'\033[0m'
mkdir -p "$(dirname "$OUT")"
while IFS= read -r file; do
&#9;grep -q $'\r' "$file" &amp;&amp; echo -e "${RED}CRLF:${NC} $file" &gt;&amp;2
&#9;if head -n 5 "$file" | grep -Ei '(date:|time:|updated:|version:)'; then
&#9;&#9;echo -e "${YEL}volatile header:${NC} $file" &gt;&amp;2
&#9;fi
done &lt; &lt;(find "$KB_DIR" -maxdepth 1 -name "*.md" | LC_ALL=C sort)</code></pre><p>Then compile. The same sorted list is concatenated with trailing spaces stripped and carriage returns removed so the artifact is LF-only:</p><pre><code>{
&#9;echo "&lt;!-- GENERATED STATIC CONTEXT - DO NOT EDIT DIRECTLY --&gt;"
&#9;find "$KB_DIR" -maxdepth 1 -name "*.md" | LC_ALL=C sort | while IFS= read -r f; do
&#9;&#9;echo -e "\n&lt;!-- START FILE: $f --&gt;"
&#9;&#9;sed 's/[[:space:]]*$//' "$f" | tr -d '\r'
&#9;&#9;echo -e "\n&lt;!-- END FILE: $f --&gt;"
&#9;done
} &gt; "$OUT"
echo "OK: wrote $OUT" &gt;&amp;2</code></pre><p>Compare unsorted discovery order to the C-locale sort with two <code>md5sum</code> hashes when you want an explicit shuffle warning. The Layer-2 guard is the volatile-header scan: <code>date:</code> / <code>version:</code> in the first five lines threaten early cache blocks even when the rest of the file is stable.</p><p>Wire the artifact into the static prefix with an import or an explicit include from <code>CLAUDE.md</code>, or have a SessionStart hook print only a short hash confirmation while Claude reads the committed memory files directly. Do not dump the entire compiled blob through SessionStart stdout on every turn unless you intend that blob to become conversation context.</p><h3>Git pre-commit hook and <code>.gitattributes</code></h3><p>Hooks only protect machines that install them. Still use a local pre-commit to normalize staged memory files, and commit <code>.gitattributes</code> so every clone checks out LF.</p><pre><code>set -euo pipefail
STAGED_FILES=$(git diff --cached --name-only --diff-filter=ACM \
&#9;| grep -E '^(\.kb/|CLAUDE\.md$)' || true)
[ -z "$STAGED_FILES" ] &amp;&amp; exit 0

while IFS= read -r file; do
&#9;[ -f "$file" ] || continue
&#9;if grep -q $'\r' "$file"; then
&#9;&#9;echo "Normalizing CRLF &#8594; LF: $file"
&#9;&#9;# portable LF rewrite without GNU-only sed -i assumptions
&#9;&#9;tmp=$(mktemp)
&#9;&#9;tr -d '\r' &lt; "$file" &gt; "$tmp" &amp;&amp; mv "$tmp" "$file"
&#9;&#9;git add "$file"
&#9;fi
done &lt;&lt;&lt; "$STAGED_FILES"</code></pre><p>Mark the hook executable with <code>chmod +x .git/hooks/pre-commit</code>. Add repository policy:</p><pre><code>CLAUDE.md text eol=lf
*.md text eol=lf

keys</h3><p>Several circulating snippets invent fields such as <code>autoExecuteHooks</code>, <code>onSessionStart</code>, and <code>allowList</code> under a <code>~/.config/claude-code/settings.json</code> path. Claude Code does not use that schema. User settings live at <code>~/.claude/settings.json</code> (on Windows, <code>%USERPROFILE%\.claude\settings.json</code>). Shared project settings live at <code>.claude/settings.json</code>. Hooks nest under the documented <code>hooks</code> object. See <a href="https://code.claude.com/docs/en/settings">Settings</a> and <a href="https://code.claude.com/docs/en/hooks">Hooks</a>.</p><p>Use a <code>SessionStart</code> command hook with matcher <code>startup</code> (add <code>resume</code> / <code>compact</code> if you need re-compile after those events):</p><pre><code>{
&#9;"hooks": {
&#9;&#9;"SessionStart": [
&#9;&#9;&#9;{
&#9;&#9;&#9;&#9;"matcher": "startup",
&#9;&#9;&#9;&#9;"hooks": [
&#9;&#9;&#9;&#9;&#9;{
&#9;&#9;&#9;&#9;&#9;&#9;"type": "command",
&#9;&#9;&#9;&#9;&#9;&#9;"command": "bash scripts/build-context.sh &gt;/dev/null"
&#9;&#9;&#9;&#9;&#9;}
&#9;&#9;&#9;&#9;]
&#9;&#9;&#9;}
&#9;&#9;]
&#9;}
}</code></pre><p>Stdout from SessionStart commands is injected into Claude's context. That is why the compiler prints audits to stderr and why the hook redirects stdout to <code>/dev/null</code> after writing <code>scripts/.compiled_context.md</code> on disk. Keep SessionStart hooks fast; Anthropic documents them as startup/resume automation, not as a place for heavyweight builds.</p><p>For a belt-and-suspenders local workflow that does not depend on hooks:</p><pre><code>.PHONY: claude
claude:
&#9;@bash scripts/build-context.sh
&#9;@claude</code></pre><p>Verification order on every cold start:</p><ol><li><p>Alphabetical <code>LC_ALL=C</code> ordering of <code>.kb/*.md</code>.</p></li><li><p>LF normalization and trailing-space strip.</p></li><li><p>Clean overwrite of <code>scripts/.compiled_context.md</code>.</p></li><li><p>Claude Code launch with a predictable static prefix ahead of the growing conversation tail.</p></li></ol><p>Optional hardening: emit a SHA-256 of the compiled file to stderr and fail CI if the hash drifts when only whitespace or file order changed in the source tree.</p><h2>Key Takeaways</h2><ol><li><p>Treat <code>CLAUDE.md</code> as a cold, short bootstrap. Target the official under-200-line guidance and let <code>/doctor</code> propose trims for discoverable content.</p></li><li><p>Offload tool manuals and architecture into docs or path-scoped rules so the always-on prefix stays small and stable.</p></li><li><p>Prefer documented model aliases or dateless major IDs over hard-coded dated strings that force rule churn.</p></li><li><p>Delete generic coding platitudes; keep only project-specific workflow and safety rules.</p></li><li><p>Split memory by volatility: static head, low-churn architecture, append-only session logs at the bottom.</p></li><li><p>Prefix caching is exact-byte matching. One mid-prefix edit, CRLF drift, or shuffled concat order invalidates every later block.</p></li><li><p>Ship <code>build-context.sh</code> with C-locale sort, LF rewrite, volatile-header warnings on stderr, and a single generated artifact.</p></li><li><p>Enforce LF with a pre-commit hook plus <code>.gitattributes</code>; do not rely on hooks alone for teammates and CI agents.</p></li><li><p>Automate with real <code>SessionStart</code> hooks in <code>.claude/settings.json</code> or a <code>make claude</code> wrapper. Do not copy invented <code>autoExecuteHooks</code> / <code>onSessionStart</code> schemas.</p></li><li><p>Keep SessionStart stdout quiet; write compiled context to disk and load it through the static
