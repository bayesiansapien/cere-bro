# Claude Fable 5, Part 7: Moving a Production Fleet Off Opus 4.8

<p><a href="https://kenhuangus.substack.com/p/claude-fable-5-what-changed-and-how">Part 1</a> covered the prompting shift. <a href="https://kenhuangus.substack.com/p/claude-fable-5-part-2-loop-engineering">Part 2</a> covered loops. <a href="https://kenhuangus.substack.com/p/claude-fable-5-part-3-memory-engineering">Part 3</a> covered memory. <a href="https://kenhuangus.substack.com/p/claude-fable-5-part-4-ten-weekend">Part 4</a> turned the loop into a security project portfolio. <a href="https://kenhuangus.substack.com/p/claude-fable-5-part-5-fable-scanner">Part 5</a> built the Fable Scanner. <a href="https://kenhuangus.substack.com/p/f99bab01-2c43-495b-a121-8ea40f679681">Part 6</a> turned recurring instructions into ten Fable-native agent skills. This one is the on-ramp I should have written earlier: you already run Opus 4.8 in production, and you want to move that fleet to Fable 5 without a day of surprise 400s and a surprise line on next month's bill.</p><p>Part 1 was about the words you send. This part is about the request body and the harness around it. The two are separate migrations, and the second one is the one that pages you when production traffic hits the wrong branch.</p><p>Everything below is free. The paid section has the migration linter that diffs your existing request against Fable 5's requirements, plus the ordered cutover procedure I use so a migration is one reversible path at a time, not a big-bang switch.</p><h2>The request that used to be valid</h2><p>The trap in this migration is that your current request body looks fine. It is valid JSON, it works against Opus 4.8, and three of its fields now return a hard 400 on Fable 5. Nothing warns you until the call fails in production.</p><p>Three parameters that older harnesses set as a matter of habit are rejected outright. Any non-default <code>temperature</code>, <code>top_p</code>, or <code>top_k</code> returns a 400 on every request, because adaptive thinking is always on for this model and does not accept sampling controls. A <code>thinking</code> block set to <code>disabled</code>, or one carrying a manual <code>budget_tokens</code>, is rejected the same way. If your harness tuned temperature per task, or set a thinking budget to control cost, those knobs are gone and the request fails until you remove them.</p><div If your conversation history carries <code>thinking</code> or <code>redacted_thinking</code> blocks from earlier assistant turns, and you switch models mid-conversation, or a request falls back to Opus, those blocks are tied to the model that produced them. The new model ignores them, so nothing errors. It also still bills them as input tokens. A migration that leaves old thinking blocks in the history pays for context that does nothing.</p><h2>The cost model changes in your favor, mostly</h2><p>The pricing news is better than the parameter news. Fable 5 costs $10 per million input tokens and $50 per million output. Opus 4.8, the model your refused requests fall back to, costs exactly half that at $5 and $25. So an Opus 4.8 fallback does not raise your per-token cost, it halves it. If you carried an assumption from anywhere that the fallback is the expensive path, drop it.</p><div class="captioned-image-container"><figure><a class="image-link image2 is-viewable-img"
