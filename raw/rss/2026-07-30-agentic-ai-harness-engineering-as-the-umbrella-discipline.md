# Harness Engineering as the Umbrella Discipline

<p><em>If you follow my substack, you may know I have talked a lot about harness engineering in the past. The following are just examples:</em></p><ul><li><p><a href="https://kenhuangus.substack.com/p/stop-blaming-the-model-join-my-live">Join My Live &#8220;Hands-On Harness Engineering with Claude&#8221; Workshop</a></p></li><li><p><a href="https://kenhuangus.substack.com/p/chapter-1-the-harness-paradigm-claude">Chapter 1: The Harness Paradigm (Claude Code vs. Hermes...)</a></p></li><li><p><a href="https://kenhuangus.substack.com/p/found-from-claude-code-chapter-1">Found from Claude Code: Chapter 1: The Harness Paradigm</a></p></li><li><p><a href="https://kenhuangus.substack.com/p/what-a-secure-harness-for-agentic">What a Secure Harness for Agentic AI Actually Is</a></p></li><li><p><a href="https://kenhuangus.substack.com/p/the-claude-code-leak-10-agentic-ai">The Claude Code Leak: 10 Agentic AI Harness Patterns That Change Everything</a></p></li></ul><p>The reason for this article is to revisit the concept, and I argue that Harness Engineering is the Umbrella Discipline for Agentic AI development and workflow.</p><p>Let us trace the evolution of the terminologies. </p><p>First, everyone was talking about <strong>Prompt Engineering</strong> &#8212; finding the exact sequence of words to steer a model. Soon after came <strong>Context Engineering </strong>(RAG and token optimization), followed by <strong>Loop Engineering</strong> (ReAct and self-correction cycles). Then <strong>Graph Engineering</strong> took over as the hottest topic, as teams moved from single agents to multi-agent systems. And now I want to put a name on the next piece of this puzzle: <strong>Memory Engineering</strong>.</p><p>I should be upfront that Memory Engineering is not (yet) an industry-standard term. As far as I can tell, I am coining it here. But given how the last four terms played out &#8212; each one showing up right when the community needed language for a problem it was already solving in practice &#8212; I expect this one to catch on too. <strong>Long-term, persistent state across sessions</strong> is already the open problem every serious agent builder is fighting with; it just doesn't have a name yet.</p><p>Figure 1 shows the order these terms entered the community's vocabulary, ending with Memory Engineering as the newest addition. Each term did not replace the one before it &#8212; it named a new layer of the same underlying problem as agents got more capable and more autonomous.</p><div class="captioned-image-container"><figure><a class="image-link image2" href="https://substackcdn.com/image/fetch/$s_!Nz-k!,f_auto,q_auto:good,fl_progressive:steep/https%3A%2F%2Fsubstack-post-media.s3.amazonaws.com%2Fpublic%2Fimages%2Fd5dd0938-50f5-4cae-9ef7-18bd604dcf6a_1024x186.png" target="_blank"><div class="image2-inset"><source type="image/webp" /><img alt="Figure 1: The Buzzword Timeline" class="sizing-normal" height="186" src="https://substackcdn.com/image/fetch/$s_!Nz-k!,w_1456,c_limit,f_auto,q_auto:good,fl_progressive:steep/https%3A%2F%2Fsubstack-post-media.s3.amazonaws.com%2Fpublic%2Fimages%2Fd5dd0938-50f5-4cae-9ef7-18bd604dcf6a_1024x186.png" title="Figure 1: The Buzzword Timeline" width="1024" /><div></div></div></a></figure></div><p>Figure 1: The Buzzword Timeline</p><p>It is easy to view this constant stream of terms as mere marketing buzzwords. But they reflect something real: the community's rapid shift from writing clever text prompts to building complex, autonomous systems.</p><p>More importantly, there is a unified, durable concept that brings all of these ideas together: Harness Engineering.</p><h2>Harness Engineering as the Core Discipline</h2><p>In traditional IT, software engineering provided the architecture, control flows, and execution environments needed for code to run predictably.</p><p>In the agentic era, foundation models act as probabilistic reasoning engines. But a bare reasoning engine cannot run safely or reliably in production on its own. It needs something around it.</p><p>The agent harness is that surrounding software infrastructure &#8212; the control plane, memory systems, runtime environment, and guardrails &#8212; that enables a probabilistic model to work reliably.</p><p>Figure 2 shows Harness Engineering as the umbrella discipline, with the five techniques hanging underneath it as specializations, not competitors. backend, and database management, Harness Engineering serves as the primary discipline. The individual terms represent specialized technologies and sub-disciplines within it:</p><ol><li><p>Prompt Engineering: structuring core system instructions, personas, and output schemas.</p></li><li><p>Context Engineering: dynamically managing token windows, dynamic context injection, and state.</p></li><li><p>Loop Engineering: designing execution feedback loops that let agents inspect tool outputs and retry.</p></li><li><p>Memory Engineering: managing short-term working state and long-term persistent storage across sessions. This is very different from context engineering, which focuses on the current active session. </p></li><li><p>Graph Engineering: structuring multi-agent orchestration, routing, and task topologies.</p></li></ol><p>The parallel to pre-agentic software is close enough to be useful, not just decorative. </p><p>Figure 3 places the two eras side by side.
