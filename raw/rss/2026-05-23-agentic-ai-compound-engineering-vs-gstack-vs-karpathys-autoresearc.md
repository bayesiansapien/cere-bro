# Compound Engineering vs. gstack vs. Karpathy’s Autoresearch vs. Superpowers vs. Recursive Self-Improvement

<p>These five things get lumped together, but they sit at different layers of the stack &#8212; philosophy, role library, research automation, agentic skill framework, and a theoretical capability. Here&#8217;s how they actually differ and when to reach for each.</p><h2><strong>1. Compound Engineering (Kieran Klaassen / Every)</strong></h2><p>A philosophy and workflow, not a tool. Every unit of work is treated as an investment so the next unit is cheaper. The loop is <strong>Brainstorm &#8594; Plan &#8594; Work &#8594; Review &#8594; Compound</strong>, with the <em>compound</em> step explicitly codifying patterns, decisions, and failures into files (AGENTS.md, skills, docs) that future agents consult automatically.</p><ul><li><p>Form factor: <strong>A reference plugin for Claude Code</strong> (27 agents, 14 skills, 20 commands, MCP server) plus a written methodology.</p></li><li><p>Time split: <strong>~80% planning + review, ~20% coding</strong></p></li><li><p>Learning mechanism: <em>Human triggers /workflows:compound</em> after a feature; agent reflects and writes lessons into project knowledge files.</p></li><li><p>Strength: <strong>Durable institutional memory</strong> for a real codebase shipped by humans + agents.</p></li></ul><h2><strong>2. gstack (Garry Tan)</strong></h2><p>An opinionated personal <strong>skill pack</strong> for Claude Code &#8212; 23 tools that turn the agent into a virtual org: CEO, Eng Manager, Designer, Reviewer/QA Lead, Security Officer (OWASP/STRIDE), Release Engineer, Doc Engineer, Retro, etc. Tan reports producing 10&#8211;20k LOC/day with it while running YC.</p><ul><li><p>Form factor: <strong>Slash commands + skills</strong> you drop into Claude Code.</p></li><li><p>Philosophy: <strong>Role-based delegation</strong> &#8212; one human plays general contractor across multiple specialist personas.</p></li><li><p>Learning mechanism: <em>Implicit</em>, lives in the prompts/skills themselves; the user updates the skills as their taste evolves.</p></li><li><p>Strength: <strong>Fast cold-start.</strong> You inherit Tan&#8217;s opinions on shipping discipline (design polish, QA in a real browser, security review, release hygiene) without inventing them.</p></li></ul><h2><strong>3. Karpathy&#8217;s Autoresearch</strong></h2><p>A fundamentally different game. It&#8217;s an <strong>autonomous ML research harness</strong> where an AI agent mutates <em>train.py</em>, runs a 5-minute training experiment, scores against a single scalar metric, keeps or reverts via git, and loops &#8212; ~12 experiments/hour, ~100 overnight.</p><ul><li><p>Form factor: <strong>Three files: program.md</strong> (the research direction in plain English), <em>train.py</em> (the only thing the agent edits), <em>prepare.py</em> (locked).</p></li><li><p>Result: <strong>~700 experiments over 2 days</strong> yielded ~20 real improvements and an 11% speedup on already-tuned nanochat. Tobi L&#252;tke trained a 0.8B model overnight that beat his prior 1.6B by 19%.</p></li><li><p>Learning mechanism: <em>Git history</em> is the memory; branch log is read before each next hypothesis.</p></li><li><p>Strength: <strong>Anything with one editable file and one measurable scalar</strong> &#8212; model training, prompt tuning, kernel optimization.</p></li></ul><h2><strong>4. Superpowers (obra)</strong></h2><p>An <strong>agentic skills framework</strong> for Claude Code that enforces test-driven, spec-driven development with sub-agents getting fresh context windows per task. Skills cover brainstorm &#8594; write spec &#8594; write plan &#8594; execute (with checkpoints) &#8594; code review.</p><ul><li><p>Form factor: <strong>Plugin marketplace install</strong> for Claude Code.</p></li><li><p>Philosophy: <strong>Process discipline</strong> (TDD, checkpointed sub-agent execution) over personas.</p></li><li><p>Learning mechanism: <em>The skill library itself</em> is the curated knowledge; sub-agents prevent context pollution between tasks.</p></li><li><p>Strength: <strong>When you want guard-rails</strong> &#8212; specs before code, tests before implementation, fresh context per task to prevent drift.</p></li></ul><h2><strong>5. Recursive Self-Improvement (RSI)</strong></h2><p>The umbrella <strong>theoretical capability</strong>, not a product: a system that improves the very mechanism that produces its improvements. Karpathy publicly framed <em>autoresearch</em> as a small, scoped step toward RSI &#8212; nanoGPT was first a teaching repo, then a llm.c port target, then a research harness, and now a benchmark for LLM coding agents that optimize their own training.</p><ul><li><p>Form factor: <strong>A property a system exhibits</strong>, not a repo. Autoresearch is an instance constrained to one file and one metric; broader RSI would let the agent modify its own evaluation, tooling, and goals.</p></li><li><p>Relation to the others: <strong>Compound Engineering</strong> is <em>human-in-the-loop</em> RSI at the workflow level (lessons feed next loop). <strong>Autoresearch</strong> is <em>bounded</em> RSI at the model-weights level. <strong>gstack</strong> and <strong>Superpowers</strong> are <em>not</em> RSI &#8212; they&#8217;re fixed scaffolding around an unchanging agent.</p></li><li><p>Strength of the concept: <strong>Useful as a design lens</strong> &#8212; ask what is the loop, what gets codified, and who closes it?</p></li></ul><blockquote></blockquote><h2><strong>Quick Comparison</strong></h2>
