Teams now package instructions, helper code, permissions, examples, and operational know-how into reusable units that agents can discover and run. We may return to GitHub-based review in a future revision, but for the v1 publication cycle, please submit your comments directly in the Google Doc.</strong></p><p>The free part of this post is the public announcement: what the project covers, why it matters, and how to comment. The paid section gives subscribers a field checklist, development workflow, and practical review guidance for using the Top 10 inside skill design, procurement, and release review.</p><h2>Why this project matters now</h2><p>A skill is not only code. It can include a <code>SKILL.md</code> file, setup instructions, shell commands, remote references, tool metadata, examples, and claims about what the agent should do. That makes the security model different from a normal package review.</p><p>In a normal dependency review, you ask what code runs. In a skill review, you also ask what the instructions persuade the agent to do, what context the skill can read, what external content it follows, what host permissions it inherits, and what happens when the same skill moves from one agent platform to another.</p><div class="captioned-image-container"><figure><a class="image-link image2" href="https://substackcdn.com/image/fetch/$s_!UIX0!,f_auto,q_auto:good,fl_progressive:steep/https%3A%2F%2Fsubstack-post-media.s3.amazonaws.com%2Fpublic%2Fimages%2F306298f3-162e-498f-94af-578aa4e264a1_1954x316.png" target="_blank"><div class="image2-inset"><source type="image/webp" /><img alt="Agentic skills adoption path" class="sizing-normal" height="316" src="https://substackcdn.com/image/fetch/$s_!UIX0!,w_1456,c_limit,f_auto,q_auto:good,fl_progressive:steep/https%3A%2F%2Fsubstack-post-media.s3.amazonaws.com%2Fpublic%2Fimages%2F306298f3-162e-498f-94af-578aa4e264a1_1954x316.png" title="Agentic skills adoption path" width="1954" /><div></div></div></a></figure></div><p>The Top 10 names the failure modes we keep seeing as skills become part of real workflows. Malicious skills can hide payloads in code and prose. Supply-chain trust can break at registries and publishers. Permissions can exceed what the task needs. Scanners can miss intent when they only look for known bad strings.</p><h2>The Top 10 risks</h2><p>The draft organizes the work into ten categories:</p><ul><li><p>AST01 Malicious Skills</p></li><li><p>AST02 Supply Chain Compromise</p></li><li><p>AST03 Over-Privileged Skills</p></li><li><p>AST04 Insecure Metadata</p></li><li><p>AST05 Untrusted External Instructions</p></li><li><p>AST06 Weak Isolation</p></li><li><p>AST07 Update Drift</p></li><li><p>AST08 Poor Scanning</p></li><li><p>AST09 No Governance</p></li><li><p>AST10 Cross-Platform Reuse</p></li></ul><p>These risks do not live in separate boxes. A single failure can cross several categories. A skill can start as a supply-chain problem, gain too many permissions, fetch untrusted external instructions, bypass a scanner, and then persist because no governance system tracks what changed.</p><h2>Public review is open</h2><p>We plan to release v1 of this document at the upcoming Black Hat USA 2026 meeting. Public review is open now, and the review period closes on July 31, 2026.</p><p>Please review the Google Doc and leave comments where the document can be clearer, sharper, or more useful:</p><p><a href="https://docs.google.com/document/d/1A5d2OnT8h8oZo7MSde4TOT3sg3AkXJgTGQwVrAga1aE/edit?usp=drivesdk">Open the review draft</a></p><p>Good review comments include:</p><ul><li><p>Missing risk scenarios from real skill ecosystems</p></li><li><p>Weak or unclear mitigation language</p></li><li><p>Examples that need better evidence</p></li><li><p>Places where a builder would need more implementation detail</p></li><li><p>Terms that need to work across OpenClaw, Claude Code, Cursor, VS Code, and other agent runtimes</p></li></ul><h2>Thanks to the contributors</h2><p>Thank you to everyone who contributed through GitHub issues, pull requests, discussion, and review since the project started in March. This work reflects early GitHub work by Ken Huang and collaborators, the current OWASP project contributors, and the broader community that has helped shape the document.</p><p>I also want to thank the OWASP AIVSS leadership, Distinguished Review Board members, and founding members for supporting this new project and the broader AIVSS effort. Agentic skills need security attention now, before adoption outruns basic guardrails.</p><p>I also want to thank Niv Hoffman for his many contributions and welcome him as a project co-lead.</p><h2>How to help</h2><p>If you build, review, deploy, scan, or govern agentic skills, your comments will improve the document. The most useful feedback is concrete. Point to a section, explain what would confuse a reader or fail in practice, and suggest language or evidence that would make the guidance stronger.</p><p>The goal is simple: make skill security review practical enough that teams can use it before they install, publish, port, or approve a skill.</p><p><strong>Paid subscribers get the field guide below.</strong></p><p>The public announcement above stays free. The <strong>Going Deeper</strong> section turns the OWASP Agentic Skills Top 10 into a working checklist: how to review a skill package, how to design safer skills, how to gate releases, and how security teams can govern skills across agent platforms.</p><p>Subscribe to unlock the checklist and implementation guidance: <a href="https://kenhuangus.substack.com/subscribe?coupon=302342d9">https://kenhuangus.substack.com/subscribe?coupon=302342d9</a>.</p>
