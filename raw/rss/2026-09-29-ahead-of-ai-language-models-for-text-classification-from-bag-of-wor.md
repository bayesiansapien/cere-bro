Language modeling and classification in the pre-transformer era</h2><p>For completeness, before we put Jev in context (no pun intended), I thought it made the most sense to start chronologically. In this section, I want to take a brief tour of applied text classification via naive Bayes, logistic regression, and the more classic (deep) neural networks before transformer-based models came along.</p><h3>1.1 Bag-of-words: naive Bayes, logistic regression, and XGBoost</h3><p>Back in the day, when I was a grad student 15 years ago, even though recurrent neural networks already existed (more on that later), text classification was usually done with a bag-of-words representation because it was straightforward and could get good results on moderately sized datasets.</p><p>In short, we can think of the bag-of-words representation as a method that makes free-form text input of different lengths compatible with classic classifiers (naive Bayes, Logistic Regression, SVMs, Random Forest, XGBoost, to name a few), which expect a fixed-size input vector.</p><p>Popular real-world applications include anything from news article classification to email spam filtering. And yes, allegedly even Gmail&#8217;s original spam filter used a Naive Bayes model with a bag-of-words representation.</p><p>As a side note, <a href="https://arxiv.org/abs/1410.5329">I wrote about this</a> approach exactly 12 years ago. bag-of-words model starts by building the vocabulary, which consists of all unique words in the training set (optionally, one can get rid of so-called stopwords like &#8220;a&#8221; and &#8220;the&#8221;, which are words that carry little to no semantic meaning in most contexts).</p><p>A bag-of-words representation results in these fixed-size inputs by assigning each word in a vocabulary its own position in a vector. We then count how often each word occurs in a document. For example, if we have a vocabulary of 50,000 unique words, it produces a fixed-size vector with 50,000 entries, regardless of whether the input consists of only ten words or 300k words. Note that most entries are zero because each document contains only a small subset of the vocabulary. (Instead of representing the raw counts, there are also normalization schemes like TF-IDF.)</p><p>Then, once we have these word frequency vectors, we can train a classifier on a labeled training set, such as emails labeled as spam or non-spam. For example, a logistic regression model would then learn feature weights that correlate certain words (and word counts) with particular labels. For instance, certain words might increase the predicted spam probability, and others may decrease it.</p><p>This approach is computationally cheap and can work well when particular words provide strong clues about the label. In a simple classification task such as spam classification, this is often enough to get quick, reasonably accurate results.</p><p>But one of the biggest downsides of this approach is that, because of the nature of the bag-of-words representation, it loses word order. So, for example, &#8220;the dog bites the man&#8221; and &#8220;the man bites the dog&#8221; produce identical vectors despite describing different events.</p><p>(There are some workarounds to preserve some local order by adding word pairs or longer sequences, called n-grams, as features, although this increases the vocabulary size.)</p><p>Despite the shortcomings, I still think that a bag-of-words has its place in certain low-stakes applications because it&#8217;s so cheap, and a bag-of-words representation + logistic regression remains my go-to baseline for every text classification problem, since it&#8217;s so easy to implement.</p><div class="captioned-image-container"><figure><a class="image-link image2 is-viewable-img" But the downside still is that we would lose the sentence structure and word order.</p><p>However, more sophisticated neural network architectures avoid the bag-of-words workaround: convolutional neural networks (CNNs) and recurrent neural networks (RNNs), which can take word embeddings as input.</p><h4>1.2.1 Word embeddings</h4><p>First, before feeding the input texts into a model, we have to convert them into a suitable representation. At each step, they combine the current word embedding (discussed in the previous section) with a hidden state from the previous step. We can think of the hidden state as a fixed-size vector that summarizes the text processed so far, so this makes word order matter, because rearranging the words changes the sequence of state The classification (scoring) head maps the output representation to a single scalar score. We then apply softmax across the candidate scores to obtain a probability distribution and return the highest-probability option.</p><p>The main point here is that the proposed head has one output per class. Each class description produces its own representation, which the same head scores via the output layer (which is essentially a logistic regression model):</p><p>where</p><ul><li><p><em>s<sub>i</sub></em> is the scalar score for class label <em>i</em>;</p></li><li><p><em>w</em> is a learnable weight;</p></li><li><p><em>b</em> is a learnable bias unit;</p></li><li><p><em>h<sub>i</sub></em> is the output of the transformer before the classification head.</p></li></ul><p>For <em>N</em> candidates, this produces <em>N</em> scores. Softmax then returns <em>N</em> probabilities. The learned parameters and stay the same when <em>N</em> changes.</p><p>Note that for <em>h<sub>i</sub></em>:</p><ul><li><p>BERT-style encoder models use the final hidden state of the <code>[CLS]</code> token (optionally passed through a pooling layer);</p></li><li><p>GPT-style autoregressive models typically use the final non-padding token&#8217;s hidden state, which we need because of the autoregressive nature as discussed earlier (the last non-padding token can attend to the preceding text, instructions, and candidate description).</p></li></ul><p>Then, we fine-tune the model and the scoring head jointly using cross-entropy loss against the correct option. Since all candidates share the same scoring head, we can change the number and descriptions of the options without changing the architecture. But again, how well this works on unfamiliar tasks depends on the training data.</p><p>By the way, why BERT- or GPT-style transformer-based models over simpler RNN and CNN architectures mentioned earlier? From a technical perspective, the approach outlined above works with either. But transformer-based models scale really well, meaning they can be pre-trained on larger datasets and benefit more than other models. Also, they can make good use of the information provided in the context (thanks to attention). So, if we want our model to generalize well to different target tasks without explicit fine-tuning on each one, pre-training a transformer-based model on a high-quality dataset likely gets us closer than RNN- or CNN-based models.</p><h2>5. Jev architecture and training algorithm</h2><p>So, how come Jev does so well on so many different tasks (from movie reviews to something arbitrary like playing Tetris)? Unfortunately, the architecture, algorithm, and training data details are not public. In short, calibration adjusts the model&#8217;s probability estimates so they better match observed class frequencies.</p><p>For example, consider once more our IMDb movie classification problem. A model might assign a review 74% positive and 26% negative. These are probability estimates, but the model may be overconfident or underconfident. We cannot assume that the numerical values are reliable without evaluating calibration. I.e., predictions of 74% positive and 54% positive both yield the class label &#8220;positive&#8221; at a 50% threshold, although the model expresses more confidence in the 74% case.</p><div Temperature scaling divides the model&#8217;s logits by a temperature (<em>T</em>) value before applying softmax. We learn <em>T</em> (a positive number) by minimizing the cross-entropy loss on the calibration dataset while keeping the model weights fixed. A temperature above 1 reduces confidence in the highest-probability class, while a temperature between 0 and 1 increases it. We then use this same temperature for new predictions. Because this scaling preserves the ordering of the logits, the predicted class remains unchanged when we select the highest-probability class.</p><h3>5.2 Reinforcement learning with calibration rewards (RLCR)</h3><p>Jev&#8217;s RLCD training method remains proprietary, but a related idea we can discuss is <em>Reinforcement Learning with Calibration Rewards</em> (RLCR), which was introduced in the 2025 <a href="https://arxiv.org/abs/2507.16806">Beyond Binary Rewards: Training LMs to Reason About Their Uncertainty</a> paper. Under ideal conditions, that is enough to obtain calibrated predictions without an additional penalty.</p><p>I.e., using a simple coin flip example analogous to the movie review classification, the two classes are &#8220;heads&#8221; and &#8220;tails.&#8221; If it&#8217;s a biased coin that lands heads 80% of the time (in expectation), the true probabilities are 80% heads and 20% tails. On a representative training set, when we optimize cross-entropy, the model will already learn these as a side-effect of minimizing cross-entropy (negative-log-likelihood).</p><p>So, in short, if the model learns the true class probabilities, its predictions are calibrated and an additional penalty is unnecessary. (And Brier loss has the same theoretical optimum as cross-entropy, as described in <a href="https://www.tandfonline.com/doi/abs/10.1198/016214506000001437">Strictly Proper Scoring Rules, Prediction, and Estimation</a> by Gneiting and Raftery, 2007.)</p><p>In practice, however, we never train to the real optimum (in expectation) but train on a finite dataset. </p><p>So, once a neural network correctly classifies most training examples, it can further reduce cross-entropy on the training set by becoming more confident. These confidence estimates may then generalize poorly to the test set and new data. </p><p>For example, in <a href="https://proceedings.mlr.press/v70/guo17a.html">On Calibration of Modern Neural Networks</a>, Guo et al. (2017) observed &#8220;neural networks can overfit to NLL without overfitting to the 0/1 loss.&#8221;</p><p>That means test accuracy can still improve while test cross-entropy worsens. So overfitting can show up in the probability estimates even when classification accuracy continues to improve.</p><p>Adding Brier loss changes how prediction errors are weighted during training. But whether this improves calibration needs to be checked on held-out data, of course. (The modest improvement in my experiment is an empirical observation for this setup, and we should not assume that adding Brier will always help.)</p><p>In my experiments (see previous figure), adding the Brier loss to cross-entropy provided only a very small additional calibration benefit. </p><p>But the motivation is more direct in RL contexts, such as described in RLCR, where we measure answer correctness and don&#8217;t already minimize cross-entropy. So, in RL contexts, the Brier term adds an incentive to report accurate confidence alongside the reward for answer correctness.</p><p></p><h2>6. Who is Jev for?</h2><p>Now that we covered Jev in reasonable detail, who is Jev for? Based on my assessment, it&#8217;s a pretty big target audience that intersects between people who a) want to save time by not having to fine-tune a custom classifier for every decision task and b) want to save money over using &#8220;the big guns&#8221; like GPT-6 and similar LLMs.</p><p>There are also lots of interesting use cases to think of. Here it could be used as</p><ul><li><p>a pre-screener for regular LLM-agent harnesses to scan our contexts for prompt injection;</p></li><li><p>select the reasoning effort level for a model;</p></li><li><p>select a skill.md from your registered skill library;</p></li><li><p>use it as a judge for evaluation or self-refinement;</p></li><li><p>find relevant files for context building.</p></li></ul><p>The list is practically endless. Someone even posted a <a href="https://arxiv.org/abs/2609.30216">survey on arXiv</a> analyzing 2,170 Jev-related projects that have sprung up recently in just a few days.</p><h3>6.2 About Jev clones and local Jevs</h3><p>Since Jev&#8217;s launch, 100s, if not 1000s, of quick Jev clones have sprung up. Most of the ones I checked out were just quick examples fine-tuning a ModernBERT or Qwen model with SFT and adding a Jev-like API.</p><p>Based on what I can tell, none of them achieves the same level of performance as Jev on such a breadth of tasks. Comparing these projects to Jev is like comparing Alpaca (the early instruction-finetuned LLM based off of the original LLaMA open-weight model) to GPT-6. Sure, it may work similarly in spirit, but your mileage will vary on real-world tasks.</p><p>No offense, but they seem like quick projects to jump on the hype train, and I don&#8217;t want to plug a specific one here.</p><p>One exception here might be the <a href="https://github.com/urchade/GLiNER">GLiNER</a> project, which has been around for ~3 years ago, and while it&#8217;s not fundamentally the same, it can be used for similar things. However, based on a <a href="https://github.com/AbdelStark/jev-benchmarks/blob/main/results/reports/btzsc-pilot-v1.md">benchmark</a>, Jev is definitely stronger.</p><div There are many solid alternatives. But what makes Jev so popular is not a unique idea (as mentioned before, classifiers existed for a long time) but the fact that it performs so well at so many diverse tasks. The only task where it allegedly doesn&#8217;t do well (as a reader told me) is legal reviews in non-English languages. (But the weak multilingual performance can be circumvented by connecting it to a cheap translation model, e.g., GPT -6 Luna with a small latency overhead.)</p><h2>Conclusion</h2><p>All in all, at first glance, Jev doesn&#8217;t seem to offer anything fundamentally new. After all, one might say that &#8220;it&#8217;s just a classifier&#8221; (with a nice API on top of it). However, it works surprisingly well across a huge range of tasks. In that sense, it&#8217;s the plug-and-play version of dedicated classifiers.</p><p>Sure, experts will still fine-tune specialist models, but the bar to justify fine-tuning a specialized model is now much higher, since it&#8217;s easy to just throw a Jev or Jev-like at it and get good-enough results.</p><p>Also, I don&#8217;t expect Jev and Jev-likes to unlock new capabilities or solve previously unsolvable tasks. However, if we make such models part of our agent harnesses to aid the expensive GPT-6 or Opus 5.5 models in decision-making within that harness, using agent harnesses could become much faster and cheaper in the future.</p><p> </p><div><hr /></div><p>If you found this article useful, consider becoming a paid <a href="https://magazine.sebastianraschka.com/subscribe">subscriber</a> to Ahead of AI.
