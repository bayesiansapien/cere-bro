# Why Are We Still Governing AI Agents Like Software? (Tim Tyler, Gravitee)

**Channel:** AI Engineer
**Published:** 2026-10-27
**Source:** https://www.youtube.com/watch?v=h8jgniNJcbQ

## TL;DR
Gravitee argues that agents should be governed like employees, not like software. Its "Agent Accountability" model borrows a century of HR controls and splits governance into three stages. Assignment names every agent: a unique identity plus a named human sponsor. Alignment bounds every action: a role, plus authority that narrows as it is delegated. Administration traces every outcome: oversight scorecards and graduated recourse enforced by guardian agents at machine speed. The framing is useful and the delegation-scope rule is sound. Little of it is new, though. It repackages capability attenuation, OAuth token exchange and LLM-as-judge guardrails, and the published framework is still a v0.7 concept paper from a vendor.

## Key Takeaways
- **The opening gag works as a diagnosis.** No ID, no manager, shared passwords, working 24/7, never fired. That job description fits most deployed agents today.
- **Identity:** one unique ID per agent in a single shared registry. Every other control keys off it. An agent is a teammate with its own identity, not a "digital clone" acting as its user. Spinning up Claude "as me" is the anti-pattern.
- **Sponsor:** one named person, not a team or title, who owns the agent's purpose, its spend, and the incident call. It is the pool rule from his talk: "I have the kids" becomes "I have the agent."
- **Role vs mission:** the role (purpose, responsibilities, budget, success criteria) is set at onboarding by the sponsor and rarely changes. The mission is the per-call intent the agent declares at runtime, for example on each MCP tool call.
- **Authority narrows as it passes down the chain.** Sven has scopes {A,B,C,D}. Agent 203 has {C,D}. Agent 409 has {D,E,F}. Agent 409 may use E and F to do its work, but only D can travel back up to Sven. Effective authority is the intersection along the delegation lineage.
- **Never assume alignment.** The model's built-in alignment, incoming team context and outside agents are all outside the sponsor's control. Treat outside agents like contractors, with their own IDs and time-bound access. The sponsor's own definitions form a contract with two layers: deterministic rules as the floor (FGA-style policies) and probabilistic intents on top.
- **"Rules are checked, intents are judged."** Behaving well is not the same as succeeding. Oversight is a scorecard: authority rules (for example, invoices up to $40k only, write-only access to the ledger) next to role intents (PO match accuracy, reconciliation cycle time). The role and authority definitions set the weights.
- **Graduated recourse with confidence bands.** The intent-judge scores drive actions: around 90% confidence, redact; below 50%, escalate to a human; below 20%, block. Authority violations escalate from restricting the scope, to suspending access after five violations in a day, to suspending the agent after days of repeat behavior. Start with heavy zero trust and loosen it as the agent keeps succeeding.
- **Human role:** guardian agents and AI gateways are the cop. The sponsor is the coach, tuning role and authority definitions to improve results. Quarterly-review cadence is "4 million decisions too late."

## Architecture & Optimization Mechanics
- **Narrowing scope is capability attenuation.** It is the macaroon or biscuit-token pattern, and RFC 8693 token exchange with `act` claims. The weakness Tyler skips: under standard OAuth, the agent holding a token cannot narrow it, and the token is opaque about the delegation chain. So the intersection rule needs a gateway that rebuilds the lineage. The token alone will not enforce it.
- **The confidence-tiered recourse is a cascade router run in reverse.** It is the same control structure as LLM routing: a cheap scorer, thresholds, and escalation to a costlier resolver, here a human instead of a bigger model. The thresholds he cites (90/50/20) are illustrative and uncalibrated. Raw LLM-judge confidence is known to be poorly calibrated, so without calibration (temperature scaling, or conformal sets on a labeled audit set) these bands are not meaningful.
- **Guardian overhead is an inference-cost problem.** Per-call judges on model inputs, context and outputs can double or triple the token spend of each agent action. That is where Amit's work applies directly: distilled or quantized small judges, and judging only the calls a cheap deterministic pre-filter flags.
- **What is missing:** no metrics, no false-positive or false-negative rates for guardians, no latency budget, and nothing on how mission declarations are checked against the role. This is a governance taxonomy, not an engineering spec.

## Grounded Context (Web Enrichment)
The talk sends people to "agentaccountabilityframework.org" (also hosted at gravitee.io/agent-accountability). That document is the Agent Accountability Framework concept paper v0.7, dated 2026-09-23, with Tyler as editor, Gravitee as sponsor, and a CC BY 4.0 license still pending legal review. It lists six principles, among them Sponsor, Role, Authority (enumerated, derived from the role, time-bounded, revocable in real time) and Oversight (every action logged with its full delegation chain). Tyler says auditable controls already exist, but the paper itself says the working draft with testable controls is "still in preparation." Version 1.0 is reserved for the first release reviewed outside Gravitee. Treat it as vendor-authored positioning for Gravitee's agent gateway until outside reviewers sign off. Some of Gravitee's SEO "corpus" pages on the topic also contain obviously garbled content, which does not help its credibility.

The underlying protocol work is moving independently. MCP has treated authorization as OAuth 2.1 since March 2025 and reportedly moved closer to enterprise OAuth/OIDC in a July 2026 revision. MCP forbids servers from passing the client's token through, which pushes implementers toward RFC 8693 token exchange for narrower delegated tokens. A March 2026 arXiv preprint (2603.24775) states the gap plainly: OAuth tokens are opaque and lack holder-side attenuation, and DeepMind's "Intelligent AI Delegation" proposed macaroon-based delegation tokens without shipping an implementation. PermitIO-style analyses add that OAuth proves who connected but does not enforce action-level policy. That missing layer is exactly what Gravitee's gateway sells. Tyler's principles are directionally right and consistent with the field. The enforcement layer is the open problem, and no standard for it exists yet.

## Real-World Application / Actionable Step
- **For any agent or routing pipeline Amit runs:** give each agent and sub-agent its own service identity and a named owner, and stop running tool calls under his personal credentials. Log the full delegation chain (who called whom, with what scope) on every tool call. The cost is one middleware hook.
- **Build the guardian layer as a routing problem.** Run deterministic policy checks first (free). Then use a distilled small judge (a 1-3B model, quantized to INT4/FP8 and served in vLLM) for intent scoring. Escalate to a frontier judge or a human only below a calibrated threshold. Measure the judge's ECE on 200-500 labeled traces before picking the redact, escalate and block bands. Do not copy 90/50/20.
- **Research angle:** guardian-judge compression is under-explored. Benchmark how far a pruned or distilled judge can shrink before its calibration on policy-violation detection drops. That gives a concrete cost and quality curve for agent governance overhead, which nobody in this talk quantified.
