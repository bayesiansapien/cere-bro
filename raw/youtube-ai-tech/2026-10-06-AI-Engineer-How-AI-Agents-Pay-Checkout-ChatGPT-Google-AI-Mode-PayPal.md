# How AI Agents Pay: Checkout in ChatGPT and Google AI Mode (Sam Parsons, PayPal)

**Channel:** AI Engineer
**Published:** 2026-10-06
**Source:** https://www.youtube.com/watch?v=c5U-XbbEN-g

## TL;DR
A PayPal Enterprise Payments (formerly Braintree) staff engineer walks through three ways a merchant can accept agent-initiated payments today: (1) OpenAI's Agentic Commerce Protocol (ACP) via an MCP app that triggers ChatGPT's native checkout sheet, (2) Google's Universal Commerce Protocol (UCP) in AI Mode, where the merchant ships only endpoints and Google Pay tokenizes, and (3) a plain MCP app with a handoff to an external merchant-hosted checkout page. The common pattern is that the host agent tokenizes the card against PayPal, the merchant receives a scoped token and charges it like any other, and settlement, refunds and chargebacks stay unchanged. Useful as an architecture map, thin on numbers, and it skips the fact that ChatGPT's in-chat checkout has already been scaled back.

## Key Takeaways
- **ACP and UCP are near-identical specs.** Both model a merchant-owned checkout session, a tokenized payment credential and a "complete checkout" call. Expect convergence or adapters, not a winner-take-all fight.
- **ChatGPT path (ACP):** merchant builds an MCP app (UI widget in HTML/JS rendered in the host); the widget calls the host to open the native checkout; the host tokenizes the card with PayPal; the merchant's MCP server receives a `complete_checkout` tool call carrying the token.
- **Google AI Mode path (UCP):** no UI to build. Merchant publishes a `.well-known` UCP JSON declaring PayPal/Braintree as processor plus merchant ID and a public client key, and exposes checkout-session endpoints. Google Pay tokenizes against PayPal and Google calls `complete` on the session.
- **Scoped tokens are the safety primitive.** Each token is bound to one merchant, a max amount, a currency and an expiry, and is attributed to its source (e.g. "ChatGPT") in reporting. This is the delegated-spend constraint that makes agent payments tolerable.
- **External-checkout MCP app path:** maximum merchant control and any payment method, at the cost of a context switch out of the agent. Status syncs back into the widget via a merchant session.
- **MCP elicitation (URL mode)** is flagged as the coming way to do the external step more seamlessly, but host support is patchy.

## Architecture & Optimization Mechanics
The design is a classic separation of concerns. The agent host owns credential capture and tokenization (keeping PCI scope off the merchant and off the model), the merchant owns catalog, pricing and fulfillment state, and the processor issues a constrained, short-lived token. The LLM never touches a PAN; it only orchestrates tool calls that move session IDs and tokens. Structurally this is capability-based security: the token is a bearer capability with merchant, amount, currency and TTL caveats, much like a macaroon. For agent builders the key integration surfaces are small: one client-side call in the widget, one server tool (`complete_checkout`) or one REST endpoint (UCP session complete), plus a discovery manifest. The trade-off space is UX friction vs merchant control: native host checkout (lowest friction, least control), endpoint-only UCP (no UI, Google owns experience), external handoff (full control, highest drop-off).

## Grounded Context (Web Enrichment)
The talk presents ChatGPT Instant Checkout as a live growth channel, which is outdated. PayPal did adopt ACP in October 2025 for ChatGPT checkout starting 2026, but by March 2026 OpenAI scaled Instant Checkout back after weak uptake: reported buy-button conversion under 1% versus a 3 to 4% e-commerce norm, thin merchant adoption, and unresolved sales-tax collection. OpenAI pivoted to an app-based model where purchases complete inside partner apps (Instacart, Target, Expedia). The demo shown, a merchant MCP app (a travel booking) invoking checkout, is consistent with that app-centric model, so the integration still works, but the "in-chat buy button for everyone" thesis has already failed once.

Google's UCP launched with AI Mode Checkout in the US, co-developed with Shopify, Etsy, Wayfair, Target and Walmart, and endorsed by Visa, Mastercard, Amex, Stripe and Adyen. Payment runs through Google Pay with Wallet-stored details, and PayPal wallet support was announced as a future update, so PayPal's current role in UCP is as the processor behind Google Pay tokens, not as a consumer-facing button. MCP Apps became the first official MCP extension on January 26, 2026, with ChatGPT, VS Code and Goose support. URL-mode elicitation entered the spec on 2025-11-25, but Claude Desktop still lacked elicitation support, matching the speaker's "not supported in most hosts yet."

## Real-World Application / Actionable Step
- Low relevance to core compression and inference work. File as a reference for agent tool-calling architectures.
- If building agent tooling or routers that touch side-effecting actions, copy the scoped-token pattern: issue the agent a capability bound to target, budget cap, unit and TTL rather than a raw credential. The same pattern fits GPU/API spend delegation in an LLM router (per-route budget tokens with expiry).
- Treat ACP and UCP as one abstraction behind a thin adapter; do not build protocol-specific logic deep in an agent stack.
- Finance angle (secondary): PayPal is positioned as plumbing under both OpenAI and Google, which is a hedge, but the ChatGPT checkout retreat shows agent checkout volume is still tiny. Do not underwrite PYPL on agentic commerce until UCP volume or PayPal wallet-in-AI-Mode data shows up in earnings.
