# Advanced Workshop: Mastering AI Observability (Doug Guthrie, Braintrust)

**Channel:** AI Engineer
**Published:** 2026-10-06
**Source:** https://www.youtube.com/watch?v=hfEczxdNyvU

## TL;DR
Braintrust solutions engineer Doug Guthrie argues that tracing is table stakes and the hard problem is extracting signal from huge trace volumes. His answer is "active observability": attach two kinds of signal to every trace (online scores for known failure modes, and an LLM clustering pipeline called Topics for unknown unknowns), store them as SQL-queryable metadata, then let a coding agent (Codex or Claude Code plus the `bt` CLI and an open-source "agent improvement" skill) query production, curate failing traces into datasets, write new scorers, edit the agent, rerun evals and open a PR. It is a vendor workshop and the live demo was hobbled by venue Wi-Fi, but the closed-loop pattern is sound and reproducible with any trace store that supports SQL.

## Key Takeaways
- **Two signal types.** Scores (code-based, LLM judge, human-calibrated judge, and code scorers that call an LLM internally) target known failures. Topics target unknown ones: unexpected user intents, silent failures, latent feature requests.
- **Judge hygiene rules of thumb:** require the judge to output reasoning; use binary scores at launch rather than graded scales; build deliberately hard cases (100% pass means a weak dataset or a lenient scorer); include few-shot examples; use a stronger model to judge than to generate.
- **Topics pipeline:** preprocessor (default flattens the trace into a user/assistant/tool thread; custom preprocessors allowed) to facet prompt (built-ins: task, sentiment, issues; custom facets allowed, with a regex to drop "none" outputs) to summary to embedding to clustered topic map to per-trace labels. Requires about 100 facet outputs before a cluster map appears.
- **Cost claim:** Topics runs on Braintrust-hosted fine-tuned models at $0.06 per million input tokens and $0.40 per million output tokens, cheap enough for 100% of traffic. Bring-your-own models were tried and dropped because cluster quality collapsed.
- **Replace taxonomy judges with clustering.** Dropbox is experimenting with swapping a stack of LLM classification judges for Topics because judges could not scale to 100% of traces economically.
- **Sampling policy:** high online-scoring sample rates for new agents, decaying as known failures become rare and the marginal signal drops.
- **Scope controls:** scorers and topics can run per span, per trace, or per group (e.g. a conversation ID across many traces), with a delay window so long multi-turn sessions are scored once complete.
- **Automated flywheel in practice:** a GitHub Action runs Claude Code with the `bt` CLI and skill, writes SQL over traces, pulls regressions, adds cases, runs evals and opens a PR with eval deltas. One customer reportedly ships 5 to 10 extra PRs per day this way (anecdote, unverified).
- **Governance trick:** lock raw traces in a restricted project and let a service-account agent publish only aggregate SQL and analysis, so engineers get insight without PII access.
- **Deployment:** SaaS, BYOC, or hybrid (control plane hosted, data plane in your VPC; enterprise only). He claims about 90% of the big-logo customers self-host the data plane.

## Architecture & Optimization Mechanics
The interesting engineering is the economics of signal. A frontier LLM judge on every trace scales cost linearly with traffic and model price. Topics replaces that with a cascade: a heavy preprocessing step that compresses a megabyte trace into a short thread, a small specialized summarizer, an embedding, and unsupervised clustering. At $0.06/$0.40 per million tokens the per-trace cost is roughly two orders of magnitude below a frontier judge, which is the same distillation-for-a-narrow-task trade Amit uses in routing: a small model that only has to label, not reason, can run on all traffic while the expensive judge is reserved for sampled or flagged traces. The admission that BYO models produced bad clusters is a useful data point: the summarizer and embedder were co-trained for the clustering objective, so swapping either breaks cluster geometry.

The storage claim matters too. Braintrust says ClickHouse fell over at Netflix, Microsoft and Dropbox scale, so it built Brainstore in late 2024 (Rust, object storage, Tantivy indexing). Agent traces are deep, nested, long-lived spans with mutable updates (Braintrust lets you attach scores to existing spans), which is a poor fit for append-only columnar OLAP. The fact that SQL over spans is exposed to coding agents is the real unlock: the agent pulls only the labeled, filtered slice instead of stuffing raw traces into context.

Weak points: the clustering pipeline is a black box (no metrics for cluster purity or stability were shown), the built-in "issues" facet produced nothing on the demo agent, and the skeptical audience question (semantically similar traces yield trivially similar clusters) was answered with "customers disagree" rather than evidence.

## Grounded Context (Web Enrichment)
The claims mostly hold. Braintrust raised an $80M Series B led by Iconiq at an $800M post-money valuation in February 2026, with Notion, Replit, Cloudflare, Ramp and Dropbox as named customers. Topics is now GA on every plan and persists labels as SQL-queryable signals, matching the workshop. Brainstore is a Rust engine on object storage with Tantivy indexing; Braintrust markets it as 80x faster querying than competitors, a vendor benchmark with no independent replication. Note that Braintrust originally ran on ClickHouse (and Postgres plus DuckDB), so "ClickHouse fell down" is consistent with its own history.

The "competitors are now building their own databases, we are a year ahead" claim is directionally right. LangChain shipped SmithDB in May 2026 (Rust, Apache DataFusion, Vortex columnar format, object storage), now handling 100% of LangSmith US cloud ingestion with up to 12x lower latency. I could not confirm an Arize custom database launch from search. Meanwhile the open-source path went the other way: ClickHouse acquired Langfuse in January 2026, so the trace-store market is splitting into proprietary purpose-built engines (Braintrust, LangSmith) versus open-source ClickHouse-native (Langfuse). The lock-in risk is real: proprietary trace engines plus hosted-only Topics models mean your labeled history does not port.

## Real-World Application / Actionable Step
- **Build a two-tier judge cascade for routing evals:** cheap distilled classifier or embedding-cluster labels on 100% of router decisions, frontier judge only on a sampled or low-confidence slice. Track judge-vs-human agreement on the slice to calibrate.
- **Cluster production failures of compressed models:** embed summaries of traces where a pruned or quantized model diverged from the full model, cluster them, and turn each cluster into a targeted eval set. This finds the task types that compression breaks, which aggregate accuracy hides.
- **Adopt the judge rules now:** binary pass/fail, mandatory reasoning, harder cases until pass rate drops below 100%, judge model stronger than the generator.
- **Prototype the agentic flywheel cheaply:** any trace store with SQL (Langfuse on ClickHouse, or Braintrust free tier) plus a Claude Code skill that queries failures, appends them to a dataset, reruns evals and opens a PR. Gate merges on eval deltas, never on the agent's own judgment.
- **Avoid lock-in:** if you adopt Braintrust Topics, export labels and cluster assignments periodically so your failure taxonomy survives a vendor switch.
