# The Base Model Is Dead (Varun Singh, Arcee AI)

**Channel:** AI Engineer
**Published:** 2026-07-31
**Source:** https://www.youtube.com/watch?v=xbPriQWXtWM

## TL;DR
Arcee's pre-training lead argues the base model has quietly changed jobs. It used to be a compressed representation of human web knowledge, and post-training merely surfaced that knowledge through a chat template. Now that RL consumes as much compute as pre-training (and more at Cursor's Composer 2.5), the base model's real function is to install the atomic skills that RL will later compose. The evidence is in the data mixes: web text fell from ~85% of GPT-3's corpus to ~50% in Llama 3 to roughly 15% in MAI-Thinking-1, while code became the dominant subset and SFT-shaped conversational data is now pulled back into pre-training itself. His secondary and more actionable point is an MoE-specific one: mixing post-training-shaped data into pre-training prevents the expert load-balance collapse that occurs when the SFT distribution diverges sharply from the pre-training distribution.

## Key Takeaways
- **The classical picture is obsolete.** GPT-3 was ~85% web text including Wikipedia. Llama 3 still ~50% general knowledge. Post-training was chat-template adaptation and RL was a flavor adjustment, not a capability source.
- **Two contradictory industry answers on synthetic data.** MAI-Thinking-1 refuses all LM-generated data and actively filters AI-generated content out of its web scrape, staying in the human-knowledge paradigm. Nemotron 3 Ultra goes the opposite way, pulling large-scale synthetic and SFT-prefixed datasets directly into pre-training. Singh is openly on the synthetic side but presents both honestly.
- **Even the purist mix is radically different.** MAI-Thinking-1 uses no synthetic data and still drops web text to roughly 15%. The shift away from web text is happening regardless of the synthetic-data position. Code, which GPT-3 had no dedicated dataset for, is now the dominant pre-training subset.
- **Rephrasing is the validated synthetic method.** Take a seed item, generate multiple rephrasings so the model sees the same information in several forms. Used at scale in Arcee's Trinity Large, Kimi K2, and the earlier Swallow Code / Swallow Math datasets. The naive model-collapse worry does not apply when information originates in a real source document.
- **The MoE load-balancing argument.** Experts specialize during training and load-balancing objectives push toward equal utilization per batch or sequence. If post-training data looks nothing like pre-training data, the SFT phase induces severe expert imbalance. MAI-Thinking-1's fix was cranking the load-balancing coefficient way up during SFT. Singh's position: that is a patch, and you should not be perturbing balance that late. Get the distribution in early instead.
- **Mid-training is the same idea under another name.** Expose the model to the post-training/RL distribution at longer context, including agentic traces. But if pre-training already runs at long context, there is no reason those datasets cannot move earlier still.
- **A cleaner two-paradigm frame.** Forget pre-train / mid-train / post-train / RL. There is supervised next-token learning and there is RL. Compute allocation between them is now roughly equal (Xiaomi's MiMo Labs) and sometimes RL-dominant (Composer 2.5).
- **Atomic skills, then composition.** The cited result: the base model needs exposure to the atomic skills RL will need to compose, and given a sufficiently difficult environment, RL extrapolates from there. This makes "what atoms does RL need?" the correct pre-training design question.
- **Novel-shape data during SFT.** Reasoning traces do not resemble human output, so they are genuinely new distributions. Some labs also warm the model to specific test-time-compute schemes during SFT or pre-training, so it learns to explore well in RL.
- **The AlphaGo caveat.** Singh puts up the classic RL-overtakes-supervised graph and immediately hedges: human language is probably too wild a distribution to learn from RL alone. The direction is more RL, not zero supervised learning.

## Architecture & Optimization Mechanics
The load-balancing point is the highest-value item here for MoE work and it deserves restating precisely. Router assignments are learned functions of the input distribution. If you train the router on distribution A and then fine-tune on distribution B, the router's learned partition is miscalibrated for B, so tokens pile onto a subset of experts. Raising the auxiliary load-balance loss coefficient during SFT forces rebalancing, but it does so by fighting the router's learned specialization late in training, which trades expert quality for utilization. Singh's alternative (include B-shaped data from the start) means the router learns a partition that covers both distributions natively.

For inference-side MoE work, this has a direct consequence Singh does not draw out: a model whose router was rebalanced under a high auxiliary coefficient during SFT likely has flatter, less-specialized expert utilization than one trained with a mixed distribution throughout. Flatter utilization is worse for expert-parallel serving (less opportunity to skip or offload cold experts) and worse for expert pruning (fewer experts are genuinely redundant). Two models with identical benchmark scores can have very different expert-utilization entropy, and that entropy determines how much memory you can claw back. That is a measurable property and it is not reported in any technical report.

The atomic-skills framing also reframes pruning. If the base model's job is to hold composable atoms for RL, then pruning a base model before RL risks removing an atom that never appears in the pre-RL evaluation but is required for composition later. Pruning after RL is safer but forfeits the RL compute savings. This tension is worth an experiment.

## Grounded Context (Web Enrichment)
The MAI-Thinking-1 details check out. The technical report confirms training on publicly available and licensed human-generated data spanning web, GitHub code, books, academic papers, news, multilingual text, and domain-specific material, with an explicit decision not to use any LM-generated synthetic data and an effort to strip AI-generated content from collected sources. The architecture is a 35B-active / 1T-total sparse MoE pre-trained from scratch on 8K GB200s in Azure. The load-balancing detail Singh cites is real and more specific than he states: they use a global-batch load-balancing loss aggregating expert frequencies across data-parallel workers and micro-batches, and during SFT they combine an unusually high 0.15 dropout with a massive MoE load-balancing coefficient. The one number I could not verify is the 15% web text figure, which does not appear in the accessible reporting. Treat it as Singh reading a pie chart, directionally right, precise value unconfirmed.

Nemotron 3 Ultra (arXiv 2606.15007) confirms the opposite pole. It is an MoE hybrid Mamba-Transformer for agentic reasoning, and its pre-training datasets explicitly include synthetic collections (Nemotron-Pretraining-Legal-v1, Nemotron-Pretraining-Specialized-v1.2 for factual recall and generative/multiple-choice questions) alongside 173B tokens of fresh GitHub code. The SFT-in-pre-training claim is concrete: the long-context phase blend is 46% long-context data, comprising document-QA pairs and synthetic long-context SFT-style samples doing multi-document reasoning, retrieval, and synthesis at 128K to 1M tokens, plus 54% Phase 2 data. NVIDIA open-sourced the recipes, data, and RL environments, so this mix is directly inspectable rather than a slide claim.

Worth noting that Singh's own model, Arcee Trinity Large, is the subject of the Datology talk from the same event, and the two talks are describing the same pipeline from the data-vendor and the model-trainer sides respectively.

## Real-World Application / Actionable Step
1. **Measure expert-utilization entropy as a first-class model property.** For each MoE candidate in the serving stack, log per-expert token counts across a representative traffic sample and compute the utilization distribution. Models rebalanced late (MAI-style high-coefficient SFT) should show flatter distributions than models with mixed distributions throughout. Flat means less expert-pruning headroom and less benefit from cold-expert offload. This directly predicts how much memory a given MoE will actually give back, and nobody publishes it.
2. **Test the prune-before-RL versus prune-after-RL question.** If the base model holds atoms that RL composes, pruning before RL may remove capabilities invisible to pre-RL evals. Design: prune to target sparsity, run identical RL on pruned and unpruned, compare post-RL performance rather than post-prune performance. If the gap is larger post-RL than post-prune, pruning is destroying composability and the recovery protocol needs to change.
3. **Use the router-distribution-shift lesson for domain adaptation.** Any time an MoE is fine-tuned on a narrow distribution, expect router miscalibration. Before assuming a quality regression is a knowledge problem, check the expert utilization histogram. This is a five-minute diagnostic that distinguishes "the model forgot" from "the router collapsed."
4. **Read the Nemotron 3 Ultra recipe directly.** NVIDIA open-sourced the data blend, the recipes, and the RL environments. It is the most detailed public example of SFT-shaped data in pre-training, and the 46/54 long-context blend ratio is a concrete starting point for anyone constructing a mid-training mix.
5. **Track the RL-to-supervised compute ratio as a leading indicator.** If RL compute keeps rising relative to supervised, the value of a strong base model shifts from knowledge coverage to skill coverage. For routing work, that means model quality differences will increasingly show up in composition-heavy tasks rather than recall-heavy ones, which changes which benchmark categories are informative for router calibration.
