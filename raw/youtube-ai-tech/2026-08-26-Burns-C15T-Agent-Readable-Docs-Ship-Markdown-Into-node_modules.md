# How We Got LLMs to Recommend Our Open Source Library — Christopher Burns, Inth

**Channel:** AI Engineer
**Published:** 2026-08-26
**Source:** https://www.youtube.com/watch?v=V_5bn4q-vAI

## TL;DR
Burns founded Inth and built C15T, an open source cookie consent library aimed at developers rather than the marketers and lawyers every competing tool targets. He spoke at Next Conf when it had 1,200 downloads. It now has around 3 million NPM downloads, 45% month-on-month growth, and 2,800 production sites. The observation that produced the talk came from his onboarding form: from 13 April 2026, spikes in the "how did you hear about us" field started coming from Claude, ChatGPT, Codex and Gemini, and model recommendation is now his single largest inbound source. His prescription is a list of tactics, llms.txt written by hand rather than generated, llms-full.txt as a fetchable sitemap with descriptions, twin .md files for every page served three ways, and an emerging WebMCP surface. The genuinely valuable item is the last one, and it is buried: coding agents working on a library never visit your website. They read the repo and node_modules, and they fill the gaps from stale training data. So he bundles the markdown docs and an AGENTS.md pointer into the published package, and reports roughly 50% token savings across models versus the agent searching the web. He is honest that none of this is settled and does not claim expertise, which is more credible than the alternative. The awkward part, which the data supports strongly, is that the item he recommends starting with is the one with essentially no evidence behind it, and the item he mentions last is the one with a real mechanism.

## Key Takeaways
- The distribution shift is the actual news. Model recommendation became his top inbound channel, dated precisely to mid-April 2026, detected only because his onboarding form asked an open question. Most teams have no instrumentation that would surface this at all.
- "Collison install" to prompt install. Stripe's founders famously integrated the product on your laptop for you. Burns's YC-era equivalent is handing you a prompt. His framing that good developer experience primitives are now colliding with agent primitives is the right abstraction: the same properties that made a library easy for a human to adopt, legible naming, complete types, honest docs, are what make it easy for a model to adopt.
- Coding agents never read your documentation site when working on a library. They read the repo and node_modules, and reconstruct behaviour from compiled source plus stale training data. This is the observation the entire talk should have been built around.
- Shipping bundled markdown docs plus an AGENTS.md inside the published package puts the documentation where the agent is already looking. Claimed effect is roughly 50% token savings across models compared to web search plus fetch. It works without skills, and skills can point at it explicitly.
- Fast-moving libraries benefit most from in-package docs, because the docs version with the code. This is the strongest version of the argument and Burns states it in passing: a package pinned at version X ships the docs for version X, which eliminates the version-mismatch failure that training-data recall guarantees.
- Agents fetch, they do not browse. This is why llms-full.txt, a flat list of URLs with one-line descriptions, is more useful to an agent than site navigation. The failure mode being addressed is real even if the specific file format is not the fix.
- Forty good hand-written lines beat a thousand generated lines of noise, per his testing. Consistent with everything known about context dilution, and an argument against every auto-generation tool in this space.
- Markdown twins served three ways, because agent capability is uneven: append .md to the URL for manual copy-paste, content negotiation on an Accept header for agents that can set one, and a mode=agent query parameter for agents that cannot set headers. The link rel alternate header advertising the markdown version is what the best docs sites do, and Burns is candid that he does not know which agents honour it.
- HTML is expensive and carries no task-relevant information for a model. Serving markdown is the same token-efficiency move as returning markdown from a scraper API rather than raw DOM.
- WebMCP is where he sees this going, exposing search docs, get pages and ask docs as callable tools so an agent can interrogate the site rather than crawl it. He correctly flags it as very early.
- Testing harnesses for agent-readiness now exist, Cloudflare shipped one and he prefers Aura AI. He shows a score of 59 and notes it was higher three weeks ago, which is an honest illustration that the scoring criteria move faster than the sites do.
- The closing advice is the correct posture for a field this unsettled: do not chase perfection, every small increment matters, and nobody in this room is an expert including the person on stage.

## Architecture & Optimization Mechanics
There is one mechanism in this talk that is robust and several that are speculative, and the difference is worth being precise about because the talk does not separate them.

The robust one is putting documentation inside the package. Consider what a coding agent actually does when it encounters an unfamiliar library. It has a prior from training data, which is stale by construction and worse, is stale in a way it cannot detect. It can read the installed source in node_modules, which is often compiled or minified, so recovering intent from it is expensive and lossy. It can search the web, which costs a search call, several fetches, HTML-to-text conversion, and a large token spend on pages that mostly do not answer the question. Burns's move short-circuits all three: the authoritative, version-matched documentation is already on local disk, at a path the agent is already reading, announced by a file that agents are already trained to look for. The 50% token saving is entirely plausible and probably conservative, because the web-search path also has a long tail of failed fetches. The deeper property is correctness rather than cost. Docs shipped in the package cannot disagree with the installed version, which removes an entire class of confidently wrong agent output where the model writes code against an API that was removed two majors ago. Nothing else in the talk provides that guarantee.

The generalisation for anyone shipping a library, and this is the item to act on: your package is a context surface, and you are currently shipping an empty one. Every package published to NPM, PyPI or crates.io that omits agent-readable documentation is forcing every agent that touches it to reconstruct semantics from types and hope. The cost is paid per user per session, forever, and is invisible to you.

Now the speculative parts. The token-efficiency argument for markdown over HTML is straightforwardly correct, and the three-way serving strategy is a sensible hedge against uneven agent capability. The llms.txt argument is where the talk and the evidence part company, and it is not a small gap. The premise that a model needs a curated map to navigate hundreds of doc pages is reasonable. The problem is that nobody has established that any crawler reads the file, and the measurement data is not ambiguous. What makes the file a weak design in principle, independent of adoption, is that it is self-reported, uncheckable, and unranked. John Mueller's comparison to the keywords meta tag is exact: a signal every site can assert about itself and no consumer can verify carries no information at equilibrium, because every site asserts it is the relevant one. Compare that to the node_modules approach, where the docs are anchored to an artifact the consumer has already chosen to install and can verify against the source sitting next to it. One is a claim, the other is evidence. That structural difference, not adoption timing, is why one works and the other does not.

The version-mismatch problem is worth pulling out on its own because it is the highest-value unsolved issue for anyone using coding agents daily, and Burns solves it accidentally. A model's parametric knowledge of a library is a snapshot at training time with no version tag attached, so it produces API calls that were valid at some unspecified past point. The failure is silent: the code looks idiomatic, compiles or nearly compiles, and fails at runtime or, worse, uses a deprecated path that still works and is wrong. Every mitigation available today is a retrieval mitigation, and retrieval from the web reintroduces the version problem because the docs site shows latest. Retrieval from the installed package is the only variant where the version is guaranteed correct by construction, because the artifact and its documentation are the same artifact. That is a stronger claim than token efficiency and Burns should have led with it.

Finally, the AGENTS.md-plus-verify pattern he mentions almost in passing, telling the agent to read the bundled docs and verify they match the installed source, is the right shape. It is a cheap cross-check between two representations of the same thing, and disagreement between them is a signal that the package is inconsistent, which is exactly when an agent should stop and ask rather than guess.

## Grounded Context (Web Enrichment)
The llms.txt evidence as of mid-2026 is about as negative as an empirical result gets, and anyone acting on this talk should know it before spending a sprint. An SE Ranking study across 300,000 domains found roughly 10% adoption, and among the fifty most AI-cited domains exactly one had the file, which is close to a controlled experiment showing the file does not cause citation. Monitoring of over 500 million AI bot visits across a 90-day window found 408 requests targeting llms.txt. An Ahrefs analysis of 137,000 sites found 97% of llms.txt files received zero traffic in May 2026. No major provider, OpenAI, Google, Anthropic or Perplexity, has confirmed its crawlers read it. Google's Gary Illyes said in July 2025 that Google does not support it and does not plan to, and Mueller drew the keywords-meta-tag comparison. Search Engine Land reported eight of nine sites seeing no measurable traffic change after implementing it. Burns answers an audience question about where to start with "llms.txt is your first shout," and on this evidence that is the wrong first move. It is cheap enough that the cost of being wrong is an afternoon, but it should not displace the tactics with mechanisms behind them.

WebMCP is real but earlier than the talk suggests. It was published as a W3C Draft Community Group Report on 10 February 2026 with the latest revision on 23 April 2026, and it is not on the W3C standards track, with the API surface still changing between drafts. Chrome 146 Canary shipped a flagged implementation, and a public origin trial runs from Chrome 149 through Chrome 156, with stable rollout expected in Q4 2026. Google has named Expedia, Booking.com, Shopify, Credit Karma, TurboTax, Redfin, Etsy, Instacart and Target as origin trial participants. The reality check from independent write-ups in May and July 2026 is blunt: near-zero deployment on real sites and not one mainstream agent calling the tools. Burns's characterisation as "very early" is accurate, and building against it now is a bet on Q4 rather than a current-quarter optimisation.

Nothing in the search results independently verifies the 50% token saving, the 3 million downloads or the 45% month-on-month growth, and all three are self-reported. The token figure is the one that matters and it is also the most believable, since the arithmetic of local file read versus search-plus-multiple-fetches is not close. The C15T growth numbers are the kind of thing an NPM stats page would settle in thirty seconds and are peripheral to the technical claim either way.

One thing the talk does not mention that belongs in this picture: agent traffic to documentation sites is increasingly subject to the same access-control tightening as everything else, with Cloudflare's Agent-bot defaults changing on 15 September 2026 and signed-agent identity via Web Bot Auth becoming the verified path. That reinforces the in-package argument. Documentation shipped inside the artifact is the one distribution channel for your docs that no bot-management policy can interrupt, because it never touches your infrastructure.

## Real-World Application / Actionable Step
1. Ship documentation inside every package you publish. Bundle the markdown docs plus an AGENTS.md pointer into the artifact on NPM, PyPI or crates.io. This is the highest-value item in the talk, it costs one build step, and it is the only approach that guarantees the docs match the installed version.
2. Treat version-mismatch as the primary failure, not token cost. A model writing against an API removed two majors ago fails silently and looks correct. In-package docs are the only retrieval source where version correctness is structural rather than best-effort, and that is a stronger argument than the 50% saving.
3. Add a verify instruction to AGENTS.md, not just a pointer. Telling the agent to read the bundled docs and cross-check them against the installed source turns a single source into two independent representations, and disagreement between them is the signal to stop rather than guess.
4. Do not lead with llms.txt. Ten percent adoption, 408 targeted requests across 500 million bot visits, 97% of files with zero traffic, no provider confirming support, and Google explicitly declining. The structural defect is that it is a self-reported unverifiable claim, which carries no information once everyone makes it. Add it if you like, but rank it last.
5. Prefer signals anchored to artifacts the consumer already chose over signals you assert about yourself. This is the general rule the llms.txt failure teaches. Docs in the package, types in the package, examples in the repo, all verifiable against something. A manifest claiming relevance is not.
6. Serve markdown for every page, three ways, if you own a docs site. The .md suffix for copy-paste, Accept-header content negotiation, and a mode=agent query parameter for agents that cannot set headers. Advertise it with link rel alternate. Cheap, no downside, and the token argument holds regardless of which mechanism wins.
7. Instrument attribution with an open question, not a dropdown. Burns detected an entire distribution channel appearing on a specific date only because his onboarding form let people type "Claude told me." A fixed list of options would have shown nothing.
8. Hand-write curation artifacts, do not generate them. Forty deliberate lines beat a thousand generated ones, which is the same context-dilution result that shows up everywhere else. This applies to llms.txt, to AGENTS.md, to skill descriptions, and to system prompts.
9. Track WebMCP as a Q4 2026 item, not a now item. Draft Community Group Report, not on the standards track, origin trial through Chrome 156, near-zero real deployment and no mainstream agent calling the tools. Worth a prototype if you have a large public surface, not worth a roadmap slot yet.
10. Note the applicability outside libraries. The pattern is that your artifact should carry its own context to wherever it is consumed. A model checkpoint shipped without a model card describing quantisation scheme, calibration data and expected degradation forces exactly the same reconstruct-and-hope behaviour that an undocumented NPM package forces on a coding agent.
