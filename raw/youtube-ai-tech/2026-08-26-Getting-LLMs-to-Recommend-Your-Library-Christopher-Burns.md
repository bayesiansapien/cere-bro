# How We Got LLMs to Recommend Our Open Source Library (Christopher Burns, Inth)

**Channel:** AI Engineer
**Published:** 2026-08-26
**Source:** https://www.youtube.com/watch?v=V_5bn4q-vAI

## TL;DR
C15T, an open source cookie-banner library, went from 1,200 to roughly 3 million NPM downloads with 45% month-on-month growth, and its number one inbound source is now Claude, ChatGPT, Codex, and Gemini recommending it. Burns's claim is that this was not SEO but a stack of small, unglamorous optimizations for agent consumption, now packaged as an open source docs pipeline called Lead Type. The single most valuable insight in the talk has nothing to do with websites: coding agents do not visit your docs site at all, they read `node_modules`, so ship bundled markdown plus an `agents.md` inside the package.

## Key Takeaways
- **Distribution channel has shifted from humans to agents.** The old "Collison install" (hand someone your laptop and install Stripe for them) is now just a prompt. Good developer-experience primitives have become agent primitives, unchanged in substance.
- **Hand-write `llms.txt`, do not generate it.** Burns's testing: about 40 good lines beat 1,000 lines of generated noise. Then pair it with `llms-full.txt`, which functions as a sitemap with per-page descriptions, because agents do not browse, they fetch.
- **Serve markdown three ways, because agent capabilities are inconsistent.** A `.md` suffix per page, a Next.js config redirect that content-negotiates on an `Accept: text/markdown` header, and a `?mode=agent` query param for agents that cannot set headers. Also declare the markdown alternate in the HTML head, as Mintlify and Vercel do. Burns is honest that support is "all up in the air."
- **The `node_modules` insight is the real payload.** Coding agents working with your library read the repo and the installed package, not your website. They lean on stale training data and try to infer capability from compiled source. Shipping bundled markdown docs plus an `agents.md` pointing at them yields close to 50% token savings versus the agent searching the web, measured across several models. It works without skills, and better with them.
- **Web MCP is the next surface.** Lead Type already exposes three tools: `search_docs`, `get_pages`, `ask_docs`. Currently early and speculative.
- **Test harnesses exist now.** Cloudflare shipped one. Burns prefers aura.ai, and openly shows a score of 59, down from three weeks prior, because the scoring criteria keep moving.
- **The honest framing.** Burns explicitly disclaims expertise: he has just been hacking on this slightly longer than the audience. No perfection, only accumulating micro-optimizations.

## Architecture & Optimization Mechanics
- **Token cost is the actual optimization target, not ranking.** HTML is expensive to feed a model: markup, scripts, and nav chrome can dwarf the content payload. Stripping to markdown is a straight prefill-token reduction, which is why the 50% saving from `node_modules` docs is believable. Fewer prefill tokens means lower cost, lower TTFT, and less context pressure that would otherwise evict useful state.
- **Locality beats retrieval.** The `node_modules` trick works because it converts a multi-hop retrieval problem (web search, pick a result, fetch, parse HTML, extract) into a single local file read. Every hop removed is latency plus a chance to retrieve the wrong thing. This is the same argument for co-locating context with compute.
- **Content negotiation as a serving-layer concern.** Three parallel access paths for the same resource is unglamorous but correct engineering when clients are heterogeneous and cannot be upgraded.
- **Documentation as versioned artifact shipped with the binary.** For a fast-moving library, docs in the package version-lock to the code the agent is actually using. Web docs are always the head revision, which is wrong for anyone on an older version. This solves a real staleness bug, not just a token bug.

## Grounded Context (Web Enrichment)
Burns's hedging is well-founded, and the broader data is harsher than his talk suggests. A SE Ranking study of 300,000 domains found roughly 10% `llms.txt` adoption, and only 37 of the Fortune 500, or 7.4%, had shipped one by March 31, 2026. More damaging: crawler logs show GPTBot, ClaudeBot, PerplexityBot, OAI-SearchBot, and Google-Extended overwhelmingly skip `/llms.txt` and crawl HTML directly, and as of Q1 2026 no major lab (OpenAI, Google, Anthropic, Meta, Mistral) has publicly committed to reading or acting on the file in production. So the general-purpose "put `llms.txt` on your marketing site to get cited by AI search" pitch is largely unsupported, and Burns's answer to the agency asking exactly that question is the weakest part of the talk.

What the data does support is precisely his own case: developer-documentation sites adopted the format fastest because coding agents are the one consumer that demonstrably reads these files today, and `llms-full.txt`, pioneered by Mintlify and Anthropic, is fetched about twice as often as the index because a single concatenated file loads full context in one shot. That is consistent with the `node_modules` finding too. The honest conclusion is that this is a business-to-agent developer-tooling play with real measurable effect on coding agents, and a speculative bet on AI search everywhere else. Anyone copying this should prioritize the package-local docs and `llms-full.txt`, and treat the rest as cheap options rather than proven wins.

## Real-World Application / Actionable Step
- **Ship markdown docs inside every internal Python package Amit's team publishes, with an `agents.md` at the root.** If colleagues or agents are working against internal pruning, quantization, or routing libraries, this is the highest-leverage change available: it removes a web-search hop, halves the tokens spent on orientation, and guarantees version-correct docs. Cost is one build step.
- **Instrument the token cost of context acquisition, not just generation.** Burns measured a 50% saving on the *retrieval* half of the interaction. Most cost dashboards only track completion tokens by model. If agents in the loop are spending thousands of prefill tokens re-discovering documentation, that is a routing and caching problem hiding as a docs problem, and it is trivially fixable.
- **Prefer a single concatenated context file over many small ones for agent consumption.** The `llms-full.txt` finding generalizes: one fetch of a well-ordered blob beats N fetches, especially with prompt caching, where a stable concatenated prefix gets cached and subsequent calls are near free.
- **Treat compiled-source inference as a failure signal.** If an agent is reverse-engineering capability from your build output, your interface documentation is missing. Same applies to kernel and CUDA wrappers where type stubs and docstrings are usually thin.
