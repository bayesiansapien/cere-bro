# How to Test AI Agents When No Benchmark Exists (Nathanael Weill, Air Canada)

**Channel:** AI Engineer
**Published:** 2026-10-22
**Source:** https://www.youtube.com/watch?v=c_SPW__jF9w

## TL;DR
When there is no public benchmark and domain experts are scarce, invert the problem: start from a known answer, plant it in a synthetic input, and check with code whether the agent finds it. Weill used this "answer first" pattern to move a telecom RAG system from one expert-graded trial per week to dozens of automated evals per day, and is now applying it to an Air Canada supplier-contract review agent, cutting a 4-week expert feedback loop to a 5-minute script. LLM-as-judge was abandoned because judge noise rivaled agent noise.

## Key Takeaways
- **Core loop:** pick answer, generate input around it, run agent, grade by exact match or code. No opinions, no judge.
- **RAG version (2024, telecom, ~10k docs):** pick a page, have an LLM write a question about it, check whether retrieval returns that page. Result: complexity from papers mostly hurt; gains came from embedding choice, chunking, and BM25 hybrid alpha.
- **Five test-generation techniques for the contract agent (spot clause, retrieve support, write amendment, keep/drop classifier):**
  1. Past decisions: diff original vs signed contract. Failed because original versions were not retained.
  2. Rule-first synthesis: take a rule (e.g. liability cap above $1M), write a violating clause, wrap a contract around it. Produced 275 known-answer tests.
  3. Break a good contract: delete a clause from a signed contract and expect a "missing clause" flag. Hardest test; the agent missed most removals.
  4. Invariance (metamorphic) tests: change supplier name or address, reorder clauses, rerun the same input. Flag count must not change.
  5. Templates: experts' fill-in-the-blank templates, with arrays of values per blank. Some tuples violate rules, some do not. Combinatorial, code-graded.
- **Grading hierarchy:** exact match and code are fast and stable. LLM-as-judge was so noisy that fixing the judge was nearly as hard as fixing the agent.
- **Design for evaluability:** they re-architected the agent so its outputs were checkable, even at some cost to the original design.
- **Expert feedback improves tests, not the agent directly.** Synthetic suites are a dev-velocity tool, not a ship/no-ship gate.

## Architecture & Optimization Mechanics
- "Answer first" is mutation testing applied to agents. Planted defects give ground truth for free and scale to thousands of cases.
- Invariance tests are directly reusable for compression work: a quantized or pruned model should produce identical structured outputs under semantics-preserving perturbations. Divergence rate under perturbation is a cheap, label-free proxy for degradation.
- Same logic suits routing: a router's cheap-model branch can be validated on planted-answer tasks where correctness is code-checkable, avoiding judge noise in the routing reward.
- Weak spot: synthetic inputs generated by an LLM share its distribution, so the suite under-samples exactly the strange real-world contracts that break agents. The "remove a clause" test is the only one that uses real documents, and it was the most revealing.

## Grounded Context (Web Enrichment)
The judge skepticism is well supported by 2026 literature. "The Coin Flip Judge?" (arXiv 2606.13685) re-ran identical pairwise evaluations 50 times and found verdicts flipped ~13.6% of the time on average, with ~45% of score variance being within-judge noise. "Reliability without Validity" (arXiv 2606.19544, 21 judges, 9 providers) showed that high test-retest reliability can coexist with severe position bias, and judge rankings shift up to 14 places across benchmarks. So Weill's preference for code-checkable oracles is the correct default.

His invariance tests are a practical instance of metamorphic testing, which academic work (Cho et al., ICSME 2025, ~560k tests over 36 metamorphic relations) shows exposes LLM faults without labels. The known risk, raised in practitioner writing in 2026, is distribution sharing between generator and system under test, and preference leakage when a judge shares a model family with the generator. Using real documents with deletions, as Weill did, is the best mitigation.

## Real-World Application / Actionable Step
- Add a **metamorphic suite** to every quantization/pruning eval: entity renames, field reordering, formatting changes, repeated runs. Report flip rate vs the FP16 baseline. Cheap and label-free.
- For routing research, build **planted-answer tasks** (needle-in-context, rule-violation detection, text-to-SQL with known result sets) where correctness is code-graded, and train/evaluate the router on those instead of judge scores.
- If a judge is unavoidable, run it multiple times, randomize position, and report Cohen's kappa against a small human set.
- Use deletion-style tests (remove a real fact, expect a "missing" flag) to probe whether compressed models lose negative or absence reasoning first, a commonly underexplored failure mode.
