# 1,000 Claude Agents Formalized Fermat's Last Theorem | Lance Martin, Anthropic

**Channel:** AI Engineer
**Published:** 2026-11-25
**Source:** https://www.youtube.com/watch?v=wrfbI5eyLAI

## TL;DR
Two capability stories from Anthropic. **(1) Multi-agent:** In September, about a dozen Claude agents formalized FLT in Lean, but only with a domain-specific harness (Prove2Me) and heavy researcher steering, over 11 days. With Fable 5.2, **1 lead plus 999 helper agents** did it in **about 30 hours**, using only **Git plus a SQL database**, no domain harness, and no human steering on the solution. The lead invented its own coordination schema (announce, assign, notes, subtasks, landed tables) within 5 minutes. **(2) Memory:** Stronger models know *when* to write and read memory and *what* is salient. Offline "**dreaming**" (reflecting over transcripts and notes to correct, consolidate and re-represent them, e.g. as wikis) fixes poisoned memories and scales with compute.

## Key Takeaways
- **Harness:** Each of the 1,000 agents had its own sandbox with restricted network access, real-time monitoring of every tool call (escape detection), and an offline review every 10 minutes. The only primitives were Git and a DB, and the prompt just named the lead/helper roles, the tools and the problem statement.
- **Emergent orchestration:** The lead created the tables unprompted. Agents dynamically reallocated across about 60 top-level statements and built their own task trees for hard lemmas. Closing message: "total freeze of the origin... magnificent work all 999 of you."
- **Trend:** Scaffolding moved from the harness into the model. September needed Prove2Me's queryable proof graph. November needed nothing domain-specific.
- **Memory paradox (Kierkegaard):** "Understood backwards, lived forwards." Agents write memory greedily in-session, but memory must be globally coherent and non-redundant. The fix mirrors hippocampal replay: split daily notes from consolidated long-term knowledge.
- **CL-Bench (continual learning, 40 sequential DB questions, fresh session each time, optional memory directory, no memory-specific prompting):** Sonnet 4.6 barely benefits from memory (doesn't know when to write or read). Sonnet 5, then Opus, then Opus 5.5 improve progressively. Better models write *verified predictions* rather than raw logs.
- **Pokémon:** Claude 3.7's memory directory is huge and indiscriminate. Fable 5's is small and strategic, and Fable 5 progresses much further. Salience is a capability.
- **Dreaming results:** A wrong landmark in memory trapped the agent in a trapdoor loop until dreaming corrected it. On a Stainless corpus QA set (25 questions, from a company acquired in May), raw semantic search scored about 53%, the dream-built wiki improves with more dreaming tokens, and **wiki plus search beats both**. Dreaming also filled placeholder pages and created an index.

## Architecture & Optimization Mechanics
- **Coordination overhead is shrinking, which changes the routing math.** If 999 helpers coordinate through a shared DB without a bespoke harness, the open question for cost is *which* helpers need frontier capability. Most subtasks (lemma grinding, Lean boilerplate) are candidates for routing to cheaper or distilled models, with the lead and hard lemmas kept on the frontier. A heterogeneous 1,000-agent team could cut cost by an order of magnitude.
- **Lean as a perfect verifier:** Long-horizon agent work scales when there's an unfakeable oracle. That's the same pattern as Sumner's differential testing (see the 2026-11-24 page). For compression, the analog is logit-equivalence checks.
- **Memory salience is context compression.** The Fable 5 memory directory is small *and* performs better, so learned salience is a form of KV and prefix compression. Dreaming is offline amortization: spend batch compute once to cut per-session prefill tokens forever. That's the same trade as distillation: offline FLOPs for online savings.
- **Dreaming-token scaling** is a new test-time-compute axis: compute spent on memory representation instead of on answering.

## Grounded Context (Web Enrichment)
The September result is documented in Anthropic's own write-up (Sep 4, 2026): an internal model "roughly comparable to Fable 5.1," dozens of agents, about **11 days**, using Columbia's **Prove2Me** platform, following the Darmon-Diamond-Taylor simplification of Wiles, producing about **13M lines of Lean 4** and about 29.5K to 30.3K intermediate theorems, using only Lean's three standard axioms. **Kevin Buzzard reviewed it** and confirmed it proves FLT with no extra assumptions. The 1,000-agent Fable 5.2 run is reported by launch coverage at about 30 hours (some outlets compute 28.7h), with Lean kernel verification. One outlet reports **Opus 5.5 reached only 26% in 18 hours on the same setup**, which supports the claim that this is a model capability, not the harness. Caveats: no peer review yet, and much of the detail comes from secondary aggregators. Dreaming launched as a research preview for Claude Managed Agents (May 6, 2026), and the engineering post is "The components of agent memory." One summary reports a wiki score rising from **about 13% to 48% with dreaming** (Anthropic-internal evals). Critics note that transcripts contain non-agent-authored content that dreaming could entrench.

## Real-World Application / Actionable Step
- **Build a mini version for your own research loop.** Spin up 1 lead plus N helpers (N=20 to 50) on a compression sweep (e.g. a mixed-precision search across layers), sharing only a Git repo and a Postgres DB, with the oracle being perplexity plus a frozen eval suite. Route helpers to a cheaper model and keep the lead on the frontier. Measure the cost and quality gap against an all-frontier team. That's a direct, publishable routing-for-agents datapoint.
- Add a nightly "dreaming" pass to this wiki and to your experiment notes: a model that dedupes, corrects and indexes the notes. This repo's `wiki/` is exactly the representation Anthropic's results say pays off.
