# Cooking with Codex (Charlie Guo & Gabriel Chua, OpenAI)

**Channel:** AI Engineer
**Published:** 2026-10-06 (workshop recorded around June 29, 2026, AI Engineer World's Fair)
**Source:** https://www.youtube.com/watch?v=FwiS44-xyYw

## TL;DR
Two OpenAI developer experience engineers run a feature tour of the Codex desktop app framed as "six recipes": give context, build, take action, collaborate on long tasks, work over time, and embed Codex anywhere. The substance is in the long-horizon section: `/goal` loops with verifiable success criteria, natively trained compaction, sub-agents vs. user-visible thread-to-thread handoff, remote-to-local thread messaging, deterministic hooks, and heartbeat automations. The closing thesis is "loop maxing": stop prompting turn by turn, build loops that check verifiable criteria, and ask why each remaining step needs a human. It is a vendor demo with no metrics beyond wall-clock run times (5, 7, 15 and 40 hours), and since recording, DevDay (September 29) has moved several of these primitives into the API and cloud.

## Key Takeaways
- **Context is the main lever, prompt "magic phrases" are dead:** clarity still matters, but the gains come from feeding context. Inputs shown: appshots (screenshots with embedded text, from any app), dictation ("we speak faster than we type"), plugins (Slack, Gmail, Linear), AGENTS.md and custom instructions, opt-in memories, and Chronicle (screen-derived memory, Pro only). Memories and Chronicle cost extra tokens.
- **Plugins = skills + app config + MCP servers in one bundle.** Habit worth copying: after finishing a hard workflow, tell the agent "make this a skill/plugin" so it is never re-derived.
- **Three action surfaces, pick by need:** computer use for apps with no API (runs in background on macOS, does not steal the cursor); Chrome extension when the agent needs your logged-in session (avoids headless-browser CAPTCHAs); in-app browser for deep layout/DOM inspection of local web apps.
- **`/goal` works only with verifiable done-criteria.** Charlie calls it a genie: magical when criteria are crisp, "monkey's paw" when they are vague. Pattern shown: a `goals.md` with a series of milestones, a `progress-dashboard.html` for human visibility, and periodic spawned threads for code review and "goal audit" that nudge the main thread back on spec.
- **Sub-agents vs. thread handoff:** sub-agents when delegation only needs to be visible to the model (separate context, subcontractor semantics, configurable per-agent model and prompt in TOML); thread-to-thread when the human wants to watch each workstream (example: a "creative director" thread that art, music and mechanics threads must get sign-off from).
- **Remote/local split:** a cloud thread lacking a browser spawns a local thread on the laptop to do Chrome-based end-to-end QA, then receives the results. Side threads (`/side`) are for status checks and are ephemeral, so durable context must be pushed back to the main thread.
- **Unblocking pattern:** the agent marks a task blocked on credentials, finishes everything else, and pings via a Slack thread. Secrets are injected via an agent-generated shell snippet, not pasted into chat.
- **Hooks give determinism:** configured in `config.toml`, used for logging, secret scanning on prompts, tool allowlists before calls, and custom validation at turn end. More autonomy means more need for hooks.
- **Two automation types:** in-thread heartbeats (poll every N minutes until a condition holds, e.g. a provisioning droplet or CI pipeline) and scheduled automations that spawn fresh threads (weekly reports, triage). Useful self-improving loops: a weekly job that mines past threads to add, fix or prune skills; an email-drafting job paired with a second job that diffs drafts against the reply actually sent and updates a best-practices file.
- **App server is the embed point:** the open-source protocol behind the app, CLI and VS Code extension. Third-party UIs inherit compaction, steering and goals, and users can bill their own ChatGPT token budget.

## Architecture & Optimization Mechanics
The one genuinely model-level claim is compaction. GPT-5.1-Codex-Max (November 19, 2025) was the first model natively trained to work across multiple context windows by pruning its own history at the window limit, which is what makes 5 to 40 hour runs feasible. This is learned context compression: the model decides what survives, rather than a heuristic summarizer. For a compression researcher it is the same problem as KV-cache eviction, moved from tensors to tokens and optimized by RL against task success. The talk's "it only remembers the good stuff, so there is token efficiency" is anecdote, not measurement; nobody showed tokens per completed task.

The orchestration design is effectively a routing and cost architecture. Sub-agents can be pinned to a lightweight model (fast reviewer) or a heavy one (thorough reviewer) per role via TOML, which is static per-role model routing. Heartbeat automations replace a blocked agent spinning in a wait loop with cheap periodic wake-ups, which is the agent analogue of not busy-waiting on a GPU. The goal-audit thread is a drift detector: a separate context re-reads the spec and checks the trajectory, avoiding the self-evaluation bias of the main thread. Weak spot: none of this was quantified. No success rates, no cost per goal, no comparison of goal audit vs. no audit.

## Grounded Context (Web Enrichment)
The claims check out but are now dated. `/goal` shipped experimentally in Codex CLI v0.128.0 on April 30, 2026, with goals persisted per thread in SQLite, optional token budgets, explicit states (pursuing, paused, achieved, unmet, budget-limited), and app-server JSON-RPC methods (`thread/goal/set|get|clear`), so the "embed anywhere" claim includes goal control. The compaction history is accurate: OpenAI introduced GPT-5.1-Codex-Max on November 19, 2025 as natively trained across multiple context windows over millions of tokens, with internal runs past 24 hours and about 30% fewer thinking tokens than its predecessor. Chronicle is real but contentious: it sends periodic screenshots to OpenAI servers, stores resulting memories unencrypted on device, consumes rate limits fast, raises prompt-injection risk, and is unavailable in the EU, UK and Switzerland.

Since the June recording, DevDay 2026 (September 29) went further. Codex now runs in the cloud so work continues with the laptop closed, which removes the "leave your laptop open" hack the presenters joke about. The Agents API gained computer use plus Codex's multi-agent, tool search and compaction features as managed infrastructure. OpenAI also launched Dots, an always-on agent with its own cloud computer, a paid Ultrafast tier claiming up to 8x token speed (about 300 tokens/s), and GPT-6.1 Sol, pitched as near GPT-6 Astra quality at one-fifth the token price. Net: the workshop's primitives (goals, compaction, multi-thread orchestration) are now table stakes being productized for API builders, and the competitive driver is Claude Code, per Reuters' April 2026 report on OpenAI's refocus.

## Real-World Application / Actionable Step
- **Run compression sweeps as `/goal` jobs with machine-checkable stops:** e.g. "find the most aggressive GPTQ/AWQ config where MMLU and a task eval stay within 1% of FP16 and throughput on vLLM improves at least 1.5x; write results to `goals.md` and a dashboard." Set a token budget so a vague criterion cannot burn the account.
- **Add a goal-audit side thread to any overnight experiment loop:** a separate context that re-reads the spec every milestone catches the "monkey's paw" failure (technically met, wrong method) before you wake up.
- **Use heartbeats for GPU jobs:** poll training or eval runs every 10 to 15 minutes and trigger the next stage on completion, instead of an agent blocking or you checking manually.
- **Treat per-role model pinning as a routing baseline:** compare static per-role assignment (cheap reviewer, expensive implementer) against your dynamic router on agent traces; it is a realistic, underexplored workload for routing research.
- **Study compaction as a research target:** benchmark learned compaction (Codex-Max family) against heuristic summarization on long agent traces, measuring tokens per solved task. It is KV-eviction research at the token level, and an open measurement gap.
- **Do not enable Chronicle on a work machine** holding unreleased research or credentials; the screenshot upload and unencrypted local memory make it a poor trade.
