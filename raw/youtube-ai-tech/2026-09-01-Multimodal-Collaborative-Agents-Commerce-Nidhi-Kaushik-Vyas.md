# Multimodal Collaborative Agents for Next-Gen Commerce | Nidhi Kaushik Vyas, Google DeepMind

**Channel:** AI Engineer
**Published:** 2026-09-01
**Source:** https://www.youtube.com/watch?v=AhQpRalYlyg

## TL;DR
The problem Vyas names is the articulation gap: most agents are wrappers around a search bar that assume the user already has the right vocabulary, while real users arrive with a vibe rather than a query. Her framework is a three-phase loop, grounded in shopping but presented as applying to any consumer vertical. Discovery builds a working state from past conversations, reference images, personal context, and hard constraints, plus soft constraints extracted from multimodal input with confidence scores, then identifies the intent gap and picks the single next question with maximal information gain. Research decides how to elicit each preference (text for statable things, visual preference boards for subjective ones) and does the comparison work in the background. Response adapts the output format to the query type: bullets for policy questions, comparison tables for trade-offs, visual boards for inspiration. Every stage has its own auto-raters, and the auto-raters are treated as a system that evolves alongside the agent.

## Key Takeaways
- **The core insight, and it is the one worth keeping: elicit, do not just retrieve.** When a user cannot articulate a preference, asking harder does not help. Showing candidate options and reading the reaction does, because it establishes a shared vocabulary between agent and user. Her summary phrase is "show and ask" rather than always asking.
- **Information gain is the criterion for choosing the next question.** The agent enumerates unknown variables (room width, style confidence) and picks the one that most changes the direction of the conversation. Her example is exactly right: if the recommended furniture does not fit the room, every other refinement is wasted, so room width dominates.
- **Soft constraints carry explicit confidence scores.** Extracting style preference from a reference image is uncertain, so the working state records how confident the extraction is, and low confidence becomes a target for further elicitation rather than being silently treated as fact.
- **Real-time variables are separated from stable state.** Inventory has to be refreshed at response time, because a recommendation for something out of stock is worthless regardless of how well the preference was inferred.
- **Micro-signals feed the confidence model.** Hovers and clicks on a visual preference board update the agent's belief about style preference, so the elicitation is passive as well as active.
- **The auto-rater suite is the most transferable part of the talk, and it is unusually specific.** For working state: all facts retained (everything in context is represented in state), confidence calibration within an error bound, and counterfactual sensitivity, tested by flipping parts of the query and verifying that the relevant extracted constraints change while the irrelevant ones stay fixed. For collaborative strategy: blocker identification completeness, over-asking flagged as a failure, and question utility. For elicitation: efficiency at discovering hidden preferences measured against a user simulator seeded with known constraints, turn efficiency, and format selection accuracy. For response: format accuracy, data fidelity (no hallucination), and user actionability, meaning the format leaves the user confident enough to commit to the purchase.
- **A temporary bridge is built at runtime between the constraint being explored and the merchant's product ontology,** so that retrieved products can be mapped back to the knowledge base. Vyas is explicit in the Q&A that the merchant supplies this intelligence through their own ontology and domain expertise.
- **Response format is the agent's decision, not the merchant's.** She is clear on this: the format is part of the agent's intelligence, because Google needs a horizontal layer consistent across merchants and a seamless user experience.
- **Her answer on agent-to-agent commerce is the most honest moment in the talk.** They have not reached agents interacting with their agents yet, and MCP would be the expected interface. More interestingly, their user studies found people want to stay involved in upper-funnel discovery and inspiration, and delegate only the lower funnel (comparing, negotiating, price-checking across merchants). That is a real finding that cuts against the prevailing full-delegation narrative at this conference.

## Architecture & Optimization Mechanics
Two things here are directly transferable to Amit's work, and one of them is genuinely rigorous.

**Counterfactual sensitivity testing is the best evaluation idea in this entire conference corpus.** Flip one component of the input and assert that the extracted constraints which should change do change, and the ones which should not stay fixed. That is a two-sided test, and the second side is the part almost everyone omits. A system that responds to every perturbation is unstable, and a system that responds to none is ignoring input. Applied to Amit's domain, this is exactly the right way to validate a router: perturb a query along a dimension that should change the routing decision (difficulty, domain, length) and confirm it does, then perturb along a dimension that should not (paraphrase, formatting, irrelevant preamble) and confirm the route is stable. Router paraphrase-invariance is rarely measured and is precisely where heuristic routers fail. The same test validates quantized models: outputs should shift where numerics genuinely matter and remain stable where they do not.

**The user simulator seeded with known ground-truth preferences is the right way to evaluate an interactive loop,** and it solves a problem that blocks most multi-turn evaluation. You cannot measure elicitation efficiency without knowing what was there to elicit, so you construct a simulated user holding a specified hidden preference set and measure how many turns the agent needs to recover them. That gives you a scalar (turn efficiency) on a task that otherwise resists measurement. The direct analogue for Amit is evaluating any agent that must gather information before acting: seed the environment with known facts, measure turns to recovery, and you have a cheap, automatable, reproducible benchmark.

The over-asking penalty deserves emphasis because it is the failure mode that shows up whenever you optimise for information gain alone. Maximising information gain per turn, unbounded, produces an interrogation. The correct objective is information gain per unit of user cost, where user patience is the scarce resource. This is the same structure as any constrained optimisation in serving: quality per dollar rather than quality alone. Vyas handles it by flagging over-asking as an explicit auto-rater failure, which is the pragmatic version of the constraint.

The confidence-score-on-extracted-constraints design is also worth noting as a general pattern. Rather than committing to an inferred value, carry the uncertainty forward and let low confidence drive the next action. That is Bayesian in spirit and it is the correct alternative to the common pattern of extracting a value, discarding the uncertainty, and then failing silently when the extraction was wrong.

## Grounded Context (Web Enrichment)
The UCP reference in the Q&A is now a substantial standard, and it is worth knowing because it is the merchant-side counterpart to everything Vyas describes.

Google announced the Universal Commerce Protocol on January 11, 2026 at the National Retail Federation conference, co-developed with Shopify and with Etsy, Wayfair, Target, and Walmart as early partners, endorsed by more than 20 commerce and payments companies including Adyen, American Express, Best Buy, Flipkart, Macy's, Mastercard, Stripe, The Home Depot, Visa, and Zalando. It is an open standard spanning the full journey from discovery through purchase to post-purchase support, designed to work with existing retail infrastructure, and compatible with the Agent Payments Protocol (AP2) for payments. The specification is public at ucp.dev with a reference implementation on GitHub under Apache 2.0, Python and TypeScript samples, and an interactive playground for simulating agent requests.

The mechanism matters for interpreting her ontology answer. Under UCP, merchants declare the capabilities they support, including bespoke functionality, and agents discover those declarations and negotiate what they can handle before transacting. So the "temporary bridge between constraint and product ontology" she describes has a standardised discovery and negotiation layer underneath it, which is more concrete than the talk conveys. Google has also shipped a Universal Cart and agentic shopping in Google Shopping, so this is a live product surface rather than research.

Two caveats on the talk. First, everything is presented as a framework with sample code and no measured results. There are no numbers on how much the multimodal elicitation loop improves conversion, turn count, or preference recovery over a text-only baseline, and no comparison against the search-bar-wrapper approach she criticises. The auto-raters are described in detail and none of their outputs are shown. This is a design pattern talk from a product person, and it should be read as a well-considered architecture proposal rather than as evidence.

Second, there is an unexamined tension between her framework and her own user research. The system is designed to elicit preferences the user cannot articulate, using visual boards and micro-signal tracking to infer style from hovers and clicks. Her user studies found that people want to remain involved in exactly that upper-funnel discovery phase. Those findings are compatible, users staying involved is what makes elicitation possible, but they also mean the heavily-instrumented preference inference is operating on the part of the journey users consider most personal. Hover and click tracking to build a confidence model of taste is a recommender system with a conversational interface, and the privacy framing that would normally accompany that is absent.

## Real-World Application / Actionable Step
- **Adopt counterfactual sensitivity as a standing test for any classifier, router, or extractor Amit builds.** Two-sided: perturb what should matter and confirm the output changes, perturb what should not and confirm it does not. For routing specifically, paraphrase-invariance is the test nobody runs and the one heuristic routers fail. This is the single most valuable idea in the talk.
- **Build a seeded user simulator for any information-gathering agent.** Specify the hidden facts, measure turns to recovery, and you convert an unmeasurable interactive task into a scalar benchmark that runs automatically. Cheap to build, and it is the only credible way to compare two elicitation strategies.
- **Penalise over-asking explicitly, and formalise the objective as information gain per unit of user cost.** Unbounded information-gain maximisation produces interrogation. This is the same quality-per-dollar framing that applies to inference routing, and stating it as a constrained objective rather than a flagged failure mode is the cleaner formulation.
- **Carry confidence forward on every extracted value rather than committing to a point estimate.** Low confidence should trigger an action (ask, verify, fall back), not be silently promoted to fact. This is the pattern that prevents the most common silent failure in extraction pipelines.
- **Separate real-time state from stable state explicitly in any agent working memory.** Inventory is her example, and the general rule is that anything which can go stale between inference and action must be refreshed at action time. For Amit the analogue is capacity and pricing data in a routing decision: a route chosen against stale availability is a route that fails.
- **Note the user-preference finding, because it contradicts the conference consensus.** Google's own user studies say people want to drive upper-funnel discovery themselves and delegate only the lower funnel. Every other talk in this agentic-commerce track assumes full delegation. If the actual demand is for delegated comparison and negotiation but human-driven discovery, that is a materially different product, and it is the kind of finding that should update a roadmap.
