# Gadgets: Personal app vibe coding that is actually safe

**Channel:** AI Engineer
**Published:** 2026-08-05
**Source:** https://www.youtube.com/watch?v=RmS5s6Wbin4

## TL;DR
Kenton Varda, creator of Cloudflare Workers, argues that personal AI codegen breaks traditional cloud infrastructure, and that the word doing the work is "personal." Today's model is one blessed version of an app running on the developer's server for every user, which makes per-user customization structurally impossible. His alternative, demoed as "Gadgets," inverts that: every user gets their own instance of an app, with its own code and its own database, and can ask an agent to modify the app itself rather than file a feature request that dies in Jira. The load-bearing engineering claim is not the codegen, it is the sandbox. Client code runs in a null-origin iframe with a restrictive CSP whose only outbound channel is postMessage to the parent, server code runs as a Durable Object inside a dynamic worker sandbox that cannot reach the outside world, and the two are wired together over Cap'n Web RPC. Sharing and access control are implemented by the platform, not by the app, so the app cannot get them wrong. The consequence Varda states plainly: there is no security bug the generated code can contain that matters. This is Sandstorm.io, his 2014 startup, rebuilt on Workers now that LLMs supply the missing piece.

## Key Takeaways
- **The thesis is infrastructural, not about AI quality.** The plug-in-system death spiral he opens with (feature requests pile up, developer decides on a rewrite with a plug-in architecture, years pass, nothing ships) is the failure mode agentic per-user codegen dissolves. But 25 years of cloud architecture optimized for the opposite property, single-version-serves-all, and vibe-coding platforms mostly target that existing infrastructure.
- **Gadget is an instance, not an app.** One gadget equals one slide deck, not a slide-deck application. Multiple decks means multiple gadget instances. That granularity is what lets the platform own the sharing model: because each gadget is exactly the one thing you would want to share, a Google-Docs-style share dialog and its access control live in the platform layer, structurally out of reach of generated code.
- **Blueprints are code without data.** Export a gadget's code, drop the state, share it, and others instantiate their own gadgets from it. Distribution without centralization, and the fork point is per user.
- **The agent edits the app, not just the content.** Varda pointed Claude at a Google Doc describing his slides and explicitly authorized it to add features to the slides app itself. It added strikethrough, added text centering, and when asked for a diagram the app could not express, added a raw SVG paste box. That last feature is useless to a human and perfectly useful to an LLM, which is a genuinely new design category: features whose only consumer is the agent.
- **The XSS question is answered by architecture, not by review.** Pasted SVG can carry JavaScript. It does not matter, because the null-origin iframe has no cookie access and no network reach, and the server side is equally confined. The security argument is containment, not correctness.
- **No containers, no database.** Everything except the LLM runs on Workers primitives: dynamic workers for code loading, Durable Objects for state. And the whole demo ran locally on `workerd`, the open source Workers runtime, which is why a dead conference network broke only the LLM call. Varda wants this self-hosted in his basement driving Home Assistant and Spotify connectors.
- **The talk's one wrong prediction is its ending.** He apologized for not open sourcing it, saying the CTO asked him to hold it a few weeks. See below. That is no longer true.

## Architecture & Optimization Mechanics
The interesting mechanics here are about isolation cost, and they matter directly to anyone thinking about multi-tenant inference serving. The naive way to give every user their own app instance is a container per user, and the arithmetic kills you immediately: hundreds of milliseconds of cold start, tens or hundreds of megabytes of resident memory, and an idle instance you are paying for. Varda's stack avoids containers entirely. A dynamic worker is a V8 isolate, so the unit of tenancy costs single-digit milliseconds to start and kilobytes of overhead rather than a process image. Durable Object Facets then attach isolated SQLite storage to each dynamically loaded class, so per-instance state does not require per-instance database provisioning. The pattern is a supervisor Durable Object that uses the Dynamic Worker Loader API to load untrusted code, which exports a class extending DurableObject, which the supervisor instantiates as a facet. Isolation and statefulness both arrive without a container boundary.

That is the same trade Amit's serving work keeps hitting from the other direction. Per-tenant LoRA adapters, per-request routing policies, and per-customer eval harnesses all want tenant-shaped isolation, and the default answer is a pod per tenant, which is why the economics collapse past a few dozen tenants. The isolate model says: pick a runtime whose isolation primitive is cheap enough that per-tenant becomes the default granularity rather than an escalation. vLLM's multi-LoRA serving is the closest analogue in the inference world, sharing base weights across tenants while swapping small per-tenant deltas, and the conceptual move is identical. Make the shared substrate expensive and the per-tenant delta cheap.

The second mechanic worth stealing is capability-based confinement as a substitute for verifying generated code. Varda's claim that no security bug in the generated code matters is only true because the code holds no credentials and has no ambient network authority. Cloudflare's shipped version formalizes this as Gatekeeper Workers: the agent and the code it writes receive a scoped capability object representing permission to do a specific thing under a specific policy, never a raw API key, OAuth token, or database credential. The secret stays in the Gatekeeper and is never handed to the agent. This is the correct architecture for agentic tool use generally, and it is strictly better than the prevailing pattern of injecting tokens into an agent's environment and hoping prompt injection does not exfiltrate them. It also connects to the correlated-failure argument in [Goldsboro B-52 Nuclear Near-Miss](../deep-science/2026-08-04-Goldsboro-B52-Nuclear-Near-Miss.md): a sandbox boundary enforced by the runtime is causally independent of whatever the model got wrong, whereas a model-based output filter is not.

Third, note what this does to the routing problem. If every user runs their own app instance with its own code, the workload becomes enormous numbers of tiny, cold, heterogeneous requests rather than a few hot uniform paths. That is close to the worst case for batching efficiency and close to the best case for aggressive per-request model selection, because each request is small enough that the routing decision is a meaningful fraction of total cost. Personal-app infrastructure and cheap-model routing are complementary bets.

## Grounded Context (Web Enrichment)
The talk's closing apology is obsolete, and the reversal is the single most important update. Varda said he had promised to open source the project in his abstract but the CTO asked him to hold it for a few weeks. In fact Cloudflare shipped it on 5 August 2026, the same day this talk was published, as **Cloudflare OS**, under Apache 2.0 at `github.com/cloudflare/cloudflare-os`, self-hostable by any organization. It launched as part of Agents Week 2026 with a press release positioning it as an enterprise agent workspace. So the "few weeks" became roughly zero, and anyone acting on this talk should go straight to the repo rather than waiting. Varda has been explicit that this is a remake of Sandstorm.io, his startup from about ten years ago, with a gadget being the direct descendant of a Sandstorm "grain," a fine-grained app instance. The 2014 version failed partly because nobody wanted to write the per-user apps. LLMs removed that constraint, which is the actual reason the idea works now and did not then.

The platform primitives he glosses over as available are all real and shipped earlier in 2026. Durable Object Facets went to beta on the Workers Paid plan, announced during Agents Week, specifically to give each AI-generated app its own isolated SQLite database. Cap'n Web is a real open source MIT-licensed library, a schemaless JavaScript-native RPC system that Cloudflare positions as a sibling to Cap'n Proto, working over HTTP, WebSocket, and postMessage, under 10 kB compressed with no dependencies, with bidirectional calls, pass-by-reference for functions and objects, promise pipelining, and capability-based security. The postMessage transport is not incidental to this architecture, it is exactly what makes the null-origin iframe boundary usable as an RPC channel. Adoption is further along than a side-project framing suggests: Cloudflare gave employees a first version in May 2026 and by August thousands were using it daily for docs, decks, and small internal apps.

The Apple and Google gatekeeping rant is, if anything, undersold rather than exaggerated. Varda's joke about being told to go home and come back in 24 hours if you still want unsigned software is nearly literal. Google's developer verification regime requires all developers to verify identity before apps can install on certified Android devices even outside the Play Store, with unverified apps blocked outright, enforced by a dedicated system app called Android Developer Verifier with no expected opt-out. Rollout begins September 2026 in Brazil, Indonesia, Singapore and Thailand, expanding globally in 2027, and installing from unverified developers will require an advanced sideloading flow with friction aimed at confirming the user accepts the risk, or ADB. His claim that the open web has not turned into the security disaster Apple and Google predicted is fair as far as it goes, though it is worth noting the web achieves that through exactly the mechanism he is relying on here, aggressive origin-level sandboxing, rather than through the absence of malicious code.

## Real-World Application / Actionable Step
Clone `cloudflare/cloudflare-os` and run it on `workerd` locally this week. The specific thing to study is not the vibe-coding UI, it is the Gatekeeper pattern and the supervisor Durable Object that loads untrusted code as a facet. That is a working reference implementation of capability-scoped tool access for agents, and it is directly transplantable to any internal agent tooling where the current design injects API keys into an agent's environment. Replace one such credential injection with a scoped capability held behind a proxy the agent cannot read, and measure whether the agent's task success rate drops at all. If it does not, that is a security improvement with zero capability cost.

For the compression and serving side, treat the isolate-versus-container distinction as a live design question rather than a Cloudflare implementation detail. The next time a per-tenant requirement shows up, whether that is per-customer adapters, per-team routing policies, or per-user eval configs, price out the isolate-style answer before the pod-per-tenant answer. Concretely: benchmark cold start and resident memory for your smallest viable isolation unit, and if per-tenant granularity costs single-digit milliseconds instead of hundreds, the architecture that was uneconomic at fifty tenants becomes economic at fifty thousand, and that changes what products are possible rather than just what they cost.

The third takeaway is a design prompt worth keeping: build features whose only consumer is an agent. Varda's SVG paste box is useless to humans and exactly right for Claude. Audit your own tooling for the inverse problem, interfaces that are ergonomic for humans and hostile to agents, and add the ugly programmatic escape hatch. A raw-config endpoint, a dump-everything-as-JSON view, or a single text field that accepts a full specification will often unlock more agent capability than a better prompt.
