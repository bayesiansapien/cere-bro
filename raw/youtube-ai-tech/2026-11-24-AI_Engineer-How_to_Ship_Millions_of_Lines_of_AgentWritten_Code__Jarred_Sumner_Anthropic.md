# How to Ship Millions of Lines of Agent-Written Code | Jarred Sumner, Anthropic

**Channel:** AI Engineer
**Published:** 2026-11-24
**Source:** https://www.youtube.com/watch?v=TvsF67C2F54

## TL;DR
Jarred Sumner (Bun creator, now at Anthropic) used Claude agents to build a multi-million-line **ahead-of-time (AOT) compiler for JavaScript/TypeScript in Bun**, across five full rewrites in a bit over a month. Goal: make Claude Code faster and lighter without rewriting it in Rust. Result: about **4x less memory and about 2x faster startup** for Claude Code, and it beats the JSC and V8 JITs on most of JetStream 3. The core lesson: **in agent-scale engineering, your verification strategy determines your architecture.** Only trust tests that predate the project, use differential testing across execution modes, and fuzz. For an unshipped project, rewriting beats refactoring.

## Key Takeaways
- **Why AOT:** About half the CPU time of a typical JS app goes to on-demand JIT compilation. Pre-compiling kills that cost, which matters especially for many concurrent Claude Code sessions.
- **Why not rewrite Claude Code in Rust:** Bun's Rust port worked because its tests are TypeScript, independent of the implementation language. Claude Code's tests are TS too, so a rewrite means porting the tests, and "as soon as you rewrite the tests, you can't trust them."
- **TypeScript types are treated as predictions, not truths.** If the compiler can prove a site is monomorphic, it emits a direct field access. Otherwise it checks every time, with limited inline caching.
- **Verification stack:** Bun's existing suite plus WebKit tests plus Test262 plus Claude Code's tests. Bun's own test runner also runs in AOT mode. **Three-way differential testing** compares JIT vs AOT vs AOT-without-types, and if all match, the program is correct for that app. Claude also writes code generators to fuzz patterns, and the V8 fuzzer Fuzzilli was extended to cover TS types. Separately verify that tests *catch* bugs, because "it's easy to fool yourself."
- **The five rewrites:** v1 reused JSC internals, and Claude Code used 1GB. v2 added `bun check` (an in-Bun TS type checker) and got 2x startup and 3x less memory, but the code was slop (any `.archive` property access assumed the `Bun.archive` API). v3 used 140 parallel agents to dump all the code at once. v4 had clean code but a 50s compile. v5 has good code, builds in under 20s, and ships next week.
- **Workflow:** In the bulk-write phase, avoid incremental builds and run one build. In the fix-up phase, use many **long-lived sub-agents** that keep the relevant code in context. He moved away from scripted workflows with newer models.
- **Human role:** mostly typing "continue," plus leading questions ("why are we doing this?", "what's taking so long?"). Models invent fake constraints, underestimate what they can do, and mis-size the impact of ideas, which talks them out of good ones. Without pushing they settle for 0.1% gains instead of 10%.
- **Observability:** an hourly Slack scorecard showing metric deltas against the previous build.
- **Tradeoffs:** Code heavy on `eval` or `new Function` (UglifyJS) is slower. It's a breaking change because writes to `Object.prototype` are banned (anti prototype pollution, also faster). Single-threaded AOT Bun already beats the hand-ported TypeScript 7 Go compiler single-threaded.

## Architecture & Optimization Mechanics
- **"Types as predictions" is speculative optimization moved from runtime to compile time.** It's the same idea as speculative decoding: guess cheaply (types or draft tokens), verify, and fall back on mismatch. The monomorphic-site proof matches static expert routing in MoE: if you can prove the route, skip the gating overhead.
- **Differential testing across execution modes is the gold-standard harness for agent-written optimizers.** For compression work, the equivalent is FP16 vs quantized vs quantized-with-a-different-kernel on the same inputs, with logit-level agreement as the oracle. Agents can then run unattended because the oracle is unfakeable.
- **The JIT tax is the same problem as cold-start inference.** Paying compile cost per session corresponds to per-request graph capture or CUDA-graph warmup in vLLM. AOT is like ahead-of-time compiled engines (TensorRT-LLM engines, torch.export/AOTInductor).

## Grounded Context (Web Enrichment)
The context holds up. Anthropic acquired Bun in December 2025. Sumner's "Rewriting Bun in Rust" post (July 8, 2026) describes a mechanical Zig-to-Rust port, done mostly with a pre-release Claude model, using the unchanged test suite, which is exactly the "tests independent of implementation language" argument in the talk. The Register reports the merge in mid-May, Heise counts about 1M lines across 2,188 files, and Bun 1.4 (August 2026) was the first stable Rust release. Zig creator Andrew Kelley published a sharply critical response. Bun now documents `bun compile` AOT as experimental: the front-end lowers to IR, and JSC's B3/Air backends emit machine code embedded in the binary. An independent September 2026 measurement of an early prototype found about **24% faster time-to-interactive and about 48% lower memory** for Claude Code (macOS arm64, binary about 2x larger). That's well short of the talk's 2x/4x, but it predates the v5 compiler, so treat the headline numbers as the author's internal benchmarks until the public release is measured.

## Real-World Application / Actionable Step
- **Run your next agent-driven optimization project with Sumner's harness.** Before any agent writes kernel, quantization or routing code, freeze a pre-existing eval set and build a differential oracle (reference FP16 path vs optimized path, with tolerance on logits or top-k agreement), plus a fuzzer over shapes, dtypes and batch sizes. Post an hourly metrics scorecard (latency, memory, divergence) to Slack. Then let long-lived sub-agents iterate, and push for 10x ideas, not 0.1% tweaks. If the result is messy and unshipped, rewrite rather than refactor.
