# How We Got LLMs to Recommend Our Open Source Library | Christopher Burns, Inth

**Channel:** AI Engineer
**Published:** 2026-08-26
**Source:** https://www.youtube.com/watch?v=V_5bn4q-vAI

## TL;DR
Burns built c15t, an open-source cookie-consent library, and watched its primary inbound channel become LLM recommendation. From April 13, 2026 onward, the top answer to "how did you hear about us" is Claude, ChatGPT, Codex, or Gemini. Downloads went from 1,200 at Next Conf to roughly 3 million NPM downloads at 45% month-on-month growth, with 2,800 production sites. There is no single trick. It is a stack of small optimizations (hand-written llms.txt, per-page markdown twins, content negotiation on the Accept header, WebMCP tools, and critically, shipping bundled docs plus an AGENTS.md inside node_modules), which he has abstracted into a framework-neutral docs pipeline called Lead Type.

## Key Takeaways
- **Hand-write llms.txt, do not generate it.** Roughly 40 good lines beat 1,000 lines of generated noise in his testing. Write it as if answering the model's question directly.
- **Agents fetch, they do not browse.** That is why llms.txt needs a companion llms-full.txt acting as a sitemap: page URL, links, and a one-line description per page, so the model can pick a target in one hop instead of crawling.
- **HTML is a token tax.** Ship markdown. The pattern that has consolidated is the ".md twin" (append `.md` to any docs URL), plus three delivery paths because agent capabilities are uneven: the explicit `.md` suffix, a redirect in the framework config triggered when the request's Accept header indicates markdown, and a `?mode=agent` query parameter for agents that cannot set headers. Also declare the alternate markdown representation in the page header, which is what Mintlify, Vercel, and c15t all do. Support for that header signal is inconsistent (Perplexity and some agents honor it).
- **The highest-leverage insight: coding agents never visit your website.** For a library, they read the repo and node_modules, working from stale training data plus compiled source. So ship the bundled markdown docs inside the published package alongside an AGENTS.md that says "if you have a question, the docs are here." Burns measures close to 50% token savings versus the agent searching the web and reasoning over compiled output, and it works with no skills configured.
- **WebMCP is the next surface.** Lead Type already exposes three tools: search docs, get pages, ask docs. The point is that a static file cannot be interrogated, whereas an MCP endpoint can answer a specific question without the agent pulling whole pages.
- **Agent-readiness is now testable.** Cloudflare shipped one harness; Burns prefers aura.ai, which scores a site and returns recommendations. He shows a score of 59 and notes it was higher three weeks earlier, because the scoring criteria keep moving.
- **For non-library sites,** his priority order is llms.txt first, llms-full.txt second, then a `.md` file for every page. Most CMSs cannot produce per-page markdown, which is a real gap.

## Architecture & Optimization Mechanics
Strip the marketing framing and this is a straight retrieval-cost optimization problem, which is why it is relevant to Amit despite looking like a devrel talk.

The 50% token saving from in-package docs is the number to internalize. The agent's alternative path is: search the web, fetch HTML, strip chrome, read compiled JavaScript, and infer the API surface. Every one of those steps burns input tokens and adds a round trip, and inference over compiled output is exactly the kind of low-signal, high-token context that degrades attention quality. Placing dense markdown at a path the agent already reads converts a multi-hop retrieval with noisy context into a single local read with high information density per token. That is the same optimization as replacing multi-hop RAG with a precomputed context bundle, and it is the same optimization as pre-shaping data before agent analysis. Three separate talks at this conference independently arrive at it.

The llms.txt finding (40 curated lines beating 1,000 generated ones) is an information-density result, and it has a precise analogue in Amit's work. A long, generated index dilutes attention across low-value tokens, and retrieval quality degrades non-monotonically with context length even when the answer is technically present. Curated compression outperforms lossless dumping. This is the same argument as pruning: removing weights (or tokens) that contribute little often improves the effective use of what remains, rather than merely making things cheaper.

The three-path content negotiation (suffix, Accept header, query param) is worth noting as an engineering pattern for heterogeneous clients. It is capability detection for agents, and the fact that it takes three redundant mechanisms is a fair measure of how immature agent HTTP behavior still is.

## Grounded Context (Web Enrichment)
The specific tactics have consolidated into recognized standards since this talk, which strengthens Burns's case. AGENTS.md is now in use across more than 60,000 open-source repositories as of mid-2026 and is read by OpenAI Codex, Cursor, GitHub Copilot, Google Jules and Gemini CLI, Devin, Zed, Warp, VS Code, Aider, goose, and opencode. That breadth of reader support is what makes the node_modules trick work at all, and it is broader than Burns implies. GitHub's own study of AGENTS.md repositories found that specific runnable commands substantially outperform vague prose, an agent can execute `npm test` but cannot act on "make sure things work." That is a sharper version of Burns's hand-write-it advice and worth applying to his AGENTS.md content.

Vendors have also validated the pipeline: Snowflake shipped agent-friendly documentation on April 15, 2026, roughly two days after Burns's inbound spike began, which is consistent with the change originating in agent behavior rather than in any one publisher's tactics. The llms.txt convention itself remains a de facto standard with uneven honoring by crawlers, and Burns is appropriately honest about that ("who actually supports it? Don't ask me"). Treat the claim as: markdown-first, in-package docs and AGENTS.md have real, measurable effects today, while llms.txt support is genuine but patchier than its popularity suggests. His 59 score on aura.ai and its instability is the honest signal here, the measurement standard is not yet stable enough to optimize against precisely.

## Real-World Application / Actionable Step
- **Ship AGENTS.md and bundled markdown docs in every package Amit publishes.** For any internal or open-source inference or compression library, put the docs where the coding agent actually looks. He can measure the win directly: run the same task twice against an agent with and without in-package docs, and count input tokens and tool calls. Burns's ~50% is a testable claim on his own repos.
- **Use runnable commands, not prose, in that file.** Per GitHub's finding: exact benchmark invocations, exact quantization commands, exact eval scripts. An agent that can run `python bench.py --model x --quant gptq` will not hallucinate a config flag.
- **Treat curated compression as the default for any index the model reads.** The 40-lines-beats-1000 result generalizes to system prompts, tool descriptions, and retrieval indices. Test it: measure task accuracy against index length and expect a non-monotonic curve. That curve is a small, clean, publishable result in its own right.
- **Expose an MCP endpoint over docs rather than only static files.** Search, get-page, and ask are the three primitives. For Amit's tooling this means an agent can ask "what is the recommended group size for this GPTQ config" without ingesting the whole guide, which is the token-efficient path.
- **Do not chase the agent-readiness score.** The rubric is unstable (his score moved 20-plus points in three weeks). Optimize the underlying mechanics (markdown availability, in-package docs, dense indices) and let the score follow.
