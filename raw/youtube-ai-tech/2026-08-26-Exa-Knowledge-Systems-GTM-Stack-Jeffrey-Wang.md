# Knowledge Systems: The New GTM Stack | Jeffrey Wang, Exa

**Channel:** AI Engineer
**Published:** 2026-08-26
**Source:** https://www.youtube.com/watch?v=6pbQgnJ9Voc

## TL;DR
Exa's co-founder reframes go-to-market as a data problem: build a live, queryable model of your world (all internal product and customer data plus all external company, person, and news data) and expose it through APIs that agents can act on. Exa runs this on four artifacts: an ICP dashboard that semantically classifies essentially every company in their addressable market, a signal alerting system called Request Lens, a fleet of about a dozen Slack-resident coding agents that the go-to-market team hammers harder than engineering does, and "Jeffbot," a calibrated clone of Wang himself built over a winter break. Three principles: agent-first requires API-first, not everything should be a chatbot, and build-versus-buy is a false dichotomy where the real requirement is arbitrary customizability.

## Key Takeaways
- **Embeddings over the internet as a primitive.** Exa crawls the web and trains its own embedding models, which turns arbitrary semantic filtering of the entire company universe into a query. That is how the ICP dashboard enumerates the full addressable market by segment (model providers, AI coding platforms, GTM intelligence tools) with per-company metadata and anticipated annual spend, rather than sampling a list from a data broker.
- **Jeffbot is a persona-cloning recipe worth copying.** Analyze roughly 760 of your own emails to extract voice statistics (average 18 words per email, sign-offs, register). Then mine hundreds of past decisions out of Slack and email history, convert those decisions into an eval set, and calibrate the agent against it. The eval set is the part almost nobody does, and it is what makes the clone measurable rather than vibes-based.
- **Permission asymmetry solves the clone's security problem.** When Wang invokes Jeffbot it has broad read and write access across every system. When anyone else invokes it, it can only draft messages, and it is not granted the full MCP and tool set. Same agent, caller-scoped capability.
- **Crystallized UIs beat generated UIs for recurring tasks.** Wang concedes dynamic UI generation works, but argues a stable interface for a repeated use case has real value because users build muscle memory. His stack keeps both: fixed dashboards for recurring questions plus flexible chat agents for open-ended ones.
- **Arbitrary customizability is the actual requirement, not build-versus-buy.** Exa uses Salesforce, and it works because Salesforce exposes MCP so every agent can reach it. A purchased system that agents can drive is equivalent to one you built, without the road map burden.
- **The FDE role has collapsed two jobs into one.** Exa runs eight or nine forward-deployed engineers out of roughly 115 people. They both support and run deals and build and maintain the AI systems that support deals, which used to be two separate functions. Non-FDE go-to-market staff are trained heavy AI users but not generally vibe-coding the interfaces.
- **Product versus distribution is a fake debate.** You need both or you do not have a company. What changed in 2026 is that distribution is now tractable as an AI engineering problem.

## Architecture & Optimization Mechanics
The interesting technical claim is that embeddings over the whole web function as an arbitrarily powerful semantic filter, which turns classification of 60 million companies from a labeling project into a retrieval query. This is the retrieval-instead-of-inference trade at extreme scale: rather than running an LLM over every company to classify it, you precompute a dense representation once and answer arbitrary segmentation queries against it cheaply forever. Amit should read the cost structure carefully, because it is the same structure as any embedding-based routing scheme. The expensive step (embedding the corpus) is paid once offline on dedicated GPU capacity, and every downstream query is a vector operation. A router built on query embeddings has exactly this economics, and it is why embedding-based routing beats LLM-as-judge routing on cost by orders of magnitude even when it loses a few points of accuracy.

The Jeffbot construction is the more directly transferable idea. Wang built an eval set out of historical decisions and calibrated an agent against it. That is behavioral distillation with a retrospectively mined dataset, and the key move is recognizing that Slack history is already a labeled corpus of input-context-to-decision pairs. For Amit's work, the same trick applies to any expert judgment he wants to compress into a small model: the logs of past decisions are the distillation dataset, and no new labeling budget is required.

The caller-scoped permission model is a clean security pattern for agent deployment. One agent definition, capability set as a function of the invoking principal. This matters for inference infrastructure because it means you do not need N forked agents for N trust levels, you need one agent and a permission-resolution layer, which keeps the prompt prefix identical and therefore keeps the KV prefix cache shared across all callers.

## Grounded Context (Web Enrichment)
The infrastructure numbers behind Wang's casual "arbitrarily powerful search engine" framing are now public and they are substantial. Exa raised a $250M Series C led by a16z at a $2.2B valuation, announced May 20, 2026, roughly three months before this talk. The system is built in-house: custom crawlers monitoring over 500 billion URLs, proprietary embedding models trained on an internal GPU cluster, and a proprietary vector database running on the "Exacluster" (80 A100s plus a newer 144 H200 configuration). Customer base is over 5,000 companies and more than 400,000 developers, including HubSpot, OpenRouter, Monday.com, Cursor, and Cognition, which corroborates Wang's claim about powering the coding-agent ecosystem.

Notably, Exa's Websets feature puts it in direct competition with ZoomInfo and PitchBook, which means the ICP dashboard Wang demos is not just an internal tool, it is a demonstration of the product category Exa is selling into. Read the talk with that in mind: it is a genuine architecture report, but the "go-to-market is a data problem, and here is the search engine that solves it" framing is also the company's commercial thesis. The 144 H200 figure is worth flagging for Amit specifically. A company whose entire product is embedding retrieval over the web runs it on roughly 144 H200s, which is a useful anchor for how much serving capacity dense retrieval at web scale actually requires, and it is far less than most people assume.

## Real-World Application / Actionable Step
- **Mine decision logs as a free distillation dataset.** Wang's insight is that past decisions live in Slack and email, and converting them into evals costs nothing but scripting. For any judgment Amit wants to compress into a small model (which quantization config for which model family, which route for which query type), the historical log of his own choices is the training and eval set. Build that eval set before training anything.
- **Prefer embedding-based classification over LLM-per-item classification wherever the label set is stable.** Exa classifies 60 million companies this way. The same argument says an embedding router should be the default baseline in Amit's routing work, with LLM-judge routing as the accuracy ceiling to be justified against its cost.
- **Adopcaller-scoped capability rather than forked agents.** One agent definition plus a permission resolver keeps the system prompt byte-identical across callers, which preserves prefix-cache sharing. Forking an agent per trust tier silently multiplies cold-prefill cost.
- **Use the Exacluster figure as a sizing anchor.** Roughly 144 H200s serving web-scale dense retrieval for 400,000 developers is a concrete data point for capacity planning arguments, and a useful counterweight when someone claims retrieval infrastructure is prohibitively expensive.
- **Keep stable UIs for recurring queries even in agent-first systems.** Wang's crystallized-UI argument applies to research tooling: a fixed dashboard for the benchmark numbers Amit checks weekly is cheaper (zero inference) and more trustworthy than regenerating it, and the generated path should be reserved for genuinely novel questions.
