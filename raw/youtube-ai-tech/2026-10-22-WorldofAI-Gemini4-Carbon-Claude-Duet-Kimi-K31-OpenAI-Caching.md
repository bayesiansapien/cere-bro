## Architecture & Optimization Mechanics
- **Long-TTL prompt caching is the real systems story.** Moving from about 5 to 60 minutes of in-memory cache to 12 hours (or "permanent" for first-party apps) means OpenAI is persisting KV/prefix state off-GPU. That requires tiered KV storage (HBM to host DRAM to SSD or remote store) with prefix-hash lookup, the same design space as vLLM prefix caching plus LMCache or Mooncake-style disaggregated KV pools. Economically, cached-input pricing turns long-lived agents (Duet, Dots, Codex sessions) from O(context) per turn into roughly O(delta).
- **Proactive agents change the inference load profile.** Duet-style always-on agents produce many small, background, latency-insensitive calls over a large persistent context. That workload is ideal for (a) aggressive prefix reuse, (b) routing triage steps ("does this need attention?") to a cheap model and escalating only on action, and (c) batch-friendly scheduling. Anthropic says Opus 5.5 provides the judgment. A sensible production design would cascade, and Anthropic has not said whether Duet does.
- **Arena checkpoint churn is a weak signal.** Carbon "B," "C," and the latest checkpoint all differ. Battle-mode samples are single-shot, prompt-selected, and biased toward visual one-shots (SVG, three.js, voxel), which overweight aesthetic code generation and say little about long-horizon agentic coding.
- **K3-class MoE (2.8T total) is still the open-weight frontier.** A K3.1 point release is more likely post-training or RL refresh than a new architecture, so expect the same expert layout and serving footprint.

## Real-World Application / Actionable Step
- **Measure your cache hit economics now.** For any routing or agent pipeline on OpenAI, log `cached_tokens` per call and restructure prompts so static parts (system prompt, tool schemas, few-shots) form a stable prefix. If the long-retention tier is confirmed, set it explicitly and re-run the cost model. Long TTLs favor routing to a single provider over spraying queries across providers.
- **Prototype a cascade for proactive-agent triage.** Build a small router (cheap model or classifier) that decides "ignore / summarize / escalate to frontier model" over an event stream. This is the cheapest high-volume part of any Duet-style product and a direct LLM-routing research target: quality-at-cost on background triage, measured against Opus-everything.
- **Prototype tiered KV offload in vLLM.** Test LMCache or vLLM's CPU/disk KV offload with multi-hour session reuse to quantify TTFT and cost savings versus recompute. This is what makes 12-hour caching viable, and it is where serving infra competition is heading.
- **Ignore Carbon and K3.1 hype until there is a model card or API ID.** Do not re-plan evals around Arena screenshots. When K3.1 weights drop, re-check expert count and activated params for quantization and offload feasibility.
