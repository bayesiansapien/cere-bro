# Realtime multiplayer, automation, and you!

**Channel:** AI Engineer
**Published:** 2026-08-08
**Source:** https://www.youtube.com/watch?v=iQ5xldZ9StU

## TL;DR
Idan Gazit, who leads GitHub Next (the lab that produced Copilot), argues the personal-productivity phase of AI coding is played out. Multiplying one engineer into ten parallel agents is not where the value is, because a small misalignment now snowballs into wasted work at token cost. He demos two prototypes on that thesis. Agentic Workflows, in public preview, makes automation a markdown document with YAML frontmatter carrying deterministic guardrails, where the markdown is the source and the Actions YAML is a compiled artifact you never read. Ace is a Slack-shaped, cloud-microVM development surface where the agent reads the team's backscroll and acts on it, and where plans are markdown documents the team co-edits before saying "do it." His closing framing is the sharpest part: AI has spent years helping with typing, which is roughly 5% of the job, and the remaining 95% is understanding the system, its history, and what colleagues think should change.

## Key Takeaways
- The security position is the most reusable content: prompting your guardrails at the agent is not a guardrail, it is letting the fox into the henhouse, because anyone who can prompt-inject the agent can override an instruction. Guardrails must be enforced outside the model's reach.
- Four principles GitHub wants memorized: defense in depth (one layer is never enough), never let an agent see a secret (if it can, treat the secret as already compromised), stage and vet all writes, log everything.
- Secrets live outside the agent's jail. When the agent needs one it asks a warden process to make the call on its behalf, so the credential never enters the context window.
- `safe-outputs` is the concrete mechanism. The agent cannot write to the repo. It emits a structured request, and a separate narrowly-permissioned job applies only what frontmatter allows. Gazit caps his own workflow at one pull request per run explicitly to prevent an injected agent from opening 500 PRs as a denial of service.
- "Allowed to do nothing" is an explicit declared output. In a repo with many automations, noise is the failure mode, and agents denial-of-servicing their owner with low-value PRs is the thing that kills adoption.
- Network egress is allowlisted per workflow, not open. His Astro upgrade bot may reach the npm registry, GitHub, and the Astro docs he named, and nothing else.
- The authoring experience is a three-line Slack message to a junior developer. Copilot expanded "check for a new release, read the changelog, plan the upgrade, open a PR" into a full playbook and inferred which dependencies to watch by reading the codebase.
- The demo did a real two-major-version jump, Astro 5 to 7, found and fixed the breaking code changes, verified by running the build, flagged the manual steps it could not do, and shipped a Cloudflare preview deploy so the human could eyeball that nothing regressed.
- Iterate by editing English, not YAML. The markdown recompiles into the Actions workflow, which makes the automation itself reviewable by non-engineers.
- Shipped starter library: issue triager, repo assist (a swarm of cooperating workflows hunting low-hanging fruit and stale tickets), CI doctor, daily team and repo status. GitHub internally used the pattern to hunt N+1 queries in its own monolith.
- The Home Assistant example is the clearest "not possible with heuristics" case: an agent walks the Python stack trace on every submitted issue, decides whether the bug is in first-party or third-party code, and closes it if it is not theirs.
- Gazit's bet: background automation that runs while you sleep will be a bigger category than interactive AI.
- On collaboration, his claim is that planning is no longer before and review is no longer after. Both collapse into the build loop, so the artifact needs to be co-editable in real time. Ace makes the plan a shared markdown doc, teammates edit it live, then someone says "we updated the plan, do it."
- Chat is valuable specifically for the facts that are not in code. Agents can read code, so what humans must supply is political constraints, vendor economics (the Azure discount example), and taste.
- Agents are getting good at extracting the final state from a meandering engineering conversation, so humans no longer have to restate conclusions for the robot.
- Every Ace session is a branch checked out into a cloud microVM, nothing runs locally, which is what makes the multiplayer and the ambient team dashboard tractable.
- The inversion he names: the better you get at articulating goals, the less the agents need you, and the interface's job becomes letting the agent listen continuously and summon a human when it needs hands or a decision.

## Architecture & Optimization Mechanics
The compile step is where this stops being a demo and becomes infrastructure. `gh aw compile` turns the markdown into a `.lock.yml` that Actions actually executes, and during compilation it pins every action dependency to a SHA rather than a tag, validates the frontmatter schema, and runs three security scanners: actionlint for workflow correctness, zizmor for privilege escalation, and poutine for supply chain risk. That is a meaningful design choice. The natural-language layer is not trusted, so the trust boundary is moved into a deterministic compiler and a static analysis gate, and the resulting artifact is auditable and reproducible even though a model wrote it.

The `safe-outputs` split is the same architectural move as separating the LLM from tool execution: the model proposes, a privileged process disposes, and the privileged process derives its permissions from a declaration the model cannot edit at runtime. Combined with the warden pattern for secrets and per-workflow network allowlists, the effective threat model becomes "assume the agent is fully compromised and ask what it can still do." That is the correct posture, and it is notably absent from most agent frameworks currently shipping.

The parallel to draw for optimization work: the compiled-artifact pattern is exactly what you want for experiment configuration. A human-editable natural language spec, a compiler that validates it against a schema and pins dependency versions, and a lock file that is what actually runs. It solves reproducibility without forcing engineers to hand-write the reproducible thing.

## Grounded Context (Web Enrichment)
The Agentic Workflows details check out and the timeline is slightly ahead of the talk. It entered technical preview 13 February 2026 and public preview 11 June 2026, so it was already generally available when this was recorded. Workflow markdown lives in `.github/workflows/`, frontmatter declares triggers, permissions, allowed write operations, and which AI engine runs it. The safe-outputs guarantees are stronger than the talk conveyed: caps are per-run and configurable, and you can additionally constrain title prefixes and label sets, not just counts. Ace was said to be entering technical preview "later this month," meaning August 2026, and remains the less proven of the two.

The 5% typing figure is Gazit's weakest citation and he did not name the study. Published measurements do not support a number that low. Sonar's analysis puts new-code-plus-improvement at 32% of developer time, with another 35% on code management, maintenance, testing, and security response. Other frequently cited work lands under 10%. A separate longitudinal study of 43 developers over 10 months found 23% of time lost to technical debt alone. So the directional claim (typing is a minority of the job, and tools have optimized the minority) is well supported, but 5% appears to be the most aggressive number available rather than a consensus one. Worth noting alongside this: a longitudinal productivity study published March 2026 found AI tools deliver roughly 10% developer productivity gains rather than the marketed 2x to 3x, which is consistent with Gazit's own argument that the bottleneck moved somewhere the tools do not yet touch.

## Real-World Application / Actionable Step
1. Adopt the "assume the agent is compromised" test on your own tooling this week. If any agent in your inference or benchmarking pipeline has a Hugging Face token, a cloud credential, or a cluster scheduler key in its environment, that credential is compromised by GitHub's standard. Move it behind a small warden service that makes the call on the agent's behalf and returns only the result. This is a half-day change and it is the single highest-value item here.
2. Build one Agentic Workflow against the upgrade treadmill you actually suffer from. For optimization work that is vLLM, transformers, CUDA, and kernel library versions, where minor releases silently change performance characteristics. The high-value variant is not just "upgrade me," it is "upgrade in a branch, run the throughput and accuracy benchmark, and open one PR containing the before-and-after numbers." That converts a dependency bump from a risk into a measurement, and `safe-outputs` with a one-PR cap keeps it from becoming noise.
3. Steal the compiled-artifact pattern for experiment specs. Write pruning and quantization sweep configs as human-readable markdown, compile to a locked config with pinned library SHAs, and treat the lock as the reproducibility contract. Version both. Six months from now the lock file is the only thing that will let you rerun the ablation.
4. Take the "facts not in code" point seriously when writing agent context. The reason your routing policy is what it is (the contract pricing, the latency SLA a specific customer negotiated, the model your platform team refuses to host) is nowhere in the repo. Put it in a durable doc the agents read, because it is precisely the class of constraint an agent will confidently violate.
5. Treat the 95% claim as a prompt for where to point tooling next. In compression work the analogue of typing is running the sweep. The 95% is knowing which layers matter, why the last quantization attempt regressed on long-context tasks, and what a colleague already tried and abandoned. That knowledge is currently in Slack and in your head, which means no agent can use it.
