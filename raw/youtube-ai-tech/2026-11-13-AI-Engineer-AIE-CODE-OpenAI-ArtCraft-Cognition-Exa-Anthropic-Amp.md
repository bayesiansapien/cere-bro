## TL;DR
The day's consensus: coding agents now run 15+ minutes unattended, harnesses are getting simpler as models improve, and the bottleneck has moved to human attention and verification. "Software factories" (closed-loop systems that measure and improve agents on your own replayed tasks) were the dominant pattern. The highest-signal items for inference work: Bayesian auto-tuning of vLLM configs (+17.5% goodput on gpt-oss, 2x throughput on R1-Distill), agents writing kernels for brand-new Vera Rubin GPUs, "cheap reviewer, strong writer" routing that halved tokens while raising quality, KV-cache pages used as an anomaly-detection signal, and Google's tiered Gemini 4 Carbon/Hydrogen pricing claims.

## Key Takeaways
- **Agent autonomy trend (Armin Ronacher, Pi):** P90 agent run time rose from ~2.5 min (Opus 4.6, Dec 2025) to 14+ min on current models with an unchanged harness. Prompts per day are flat (~120-190); agent-active time is many multiples of the workday. Human attention is the scarce resource.
- **Code mode beats raw tool calls:** Orchestrating tools via generated JavaScript lets workflows call cheap non-LLM classifiers at each branch without paying for an active KV cache. Use flex-tier pricing and suspend agents plus sandboxes during stalls.
- **Cognition (Devin):** Merged PRs up 40x in a year with headcount up 2.7x. Shift from "tasks" to "jobs" (an agent owns a metric like P99 latency 24/7). An agent built the Android app to iOS parity in 44 days, merging 40-50 PRs a day.
- **Anthropic multi-agent (Lance Martin?):** With the Fable 5.2 launch, ~1,000 agents (1 lead, 999 helpers) re-formalized Fermat's Last Theorem in Lean in ~30 hours using only git plus a SQL DB, no domain harness. The lead built its own coordination tables within 5 minutes. Stronger models are better at deciding what to remember; offline "dreaming" consolidation fixes poisoned memories.
- **Google DeepMind (Melvin Johnson):** Gemini 4 Argon then Carbon shipped within 28 days; Hydrogen is the fast tier. Carbon is claimed #1 on Cursor Bench at 3.3x cheaper than #2. Hydrogen ~60% vs Gemini 3.8 Flash ~20% on Terminal Bench 4. AI writes ~75% of Google's new code. Fabrication rate 8% → 3% (Hydrogen) → 1.5% (Carbon). RL recipe: prune easy prompts (zero variance), rubric graders from real commits, action-based cheating penalties.
- **Exa:** 12.5M to 1.3B monthly requests in two years. Models are 4-8 months stale at use time. Agent queries average ~12 words vs ~3 for humans. Returning ~500-character extracts instead of full pages cuts tokens ~16x; Atlas benchmark 9% (no search) → 28% (keyword) → 56% (Exa) at 28% lower cost.
- **Bun AOT compiler (Jarred Sumner):** Multi-million-line agent-written PR adding ahead-of-time JS compilation; claimed ~4x less memory and ~2x faster startup for Claude Code. Verified only against tests that predate the project (Bun suite, WebKit, test262, Claude Code tests) plus type-extended Fuzzilli and three-way differential runs (JIT vs AOT vs untyped). Five rewrites, one using 140 parallel agents.
- **Agent CLI ergonomics:** In ~20K agent calls, 25% piped output to head/grep/tail (62% for git show and cargo test), hiding failures (`cargo test | head` exits 0). Adding selection flags and a compact output mode cut pipe rate 82% → 25%. Infracost went 0/6 → 6/6 on hard questions at 41% lower cost. Measure turns and correctness, not just tokens.
- **Code review architectures:** AWS Kiro Crew uses six yes/no reviewer agents including two code reviewers from different model families to cover model blind spots. Robinhood's hybrid reviewer: scripts check facts, agents judge, humans own protected decisions (~2% miss rate). Paper Compute fine-tunes Qwen 3 4B/8B "twin reviewers" on senior-engineer pushback, quantized onto an RTX 5090.
- **Organizational data:** Amazon internal study: teams that redesigned process got a median 4.5x; teams that bolted AI on got 1.1-1.2x. Uber's merge queue saw P95 land time go from 30 min to 3-4 hours under AI PR volume; Jaccard-scored conflict relaxation raised throughput 50%+ to ~250/hour.
- **Quality warnings:** SlopCodeBench (codebase evolution across checkpoints) puts GPT-5.5 at ~15% and Astra at ~16.3%. Slop patterns are increasing across model generations. ~30% of PRs reportedly merge without review.

## Architecture & Optimization Mechanics
- **Auto-tuning vLLM (Rohan?, likely DigitalOcean):** Optuna TPE searches serving configs per workload regime (chat-short, chat-long, RAG, batch-classify) with goodput as the objective. gpt-oss: 50 trials, +17.5% tokens, best config had a 256-sized knob (likely max-num-seqs), ~4-5 hours of search. DeepSeek-R1-Distill: 9 trials, throughput doubled and inter-token latency roughly halved. Takeaway: default vLLM configs leave large gains on the table, and the optimum is workload-shape dependent.
- **Agentic kernel work on new silicon (Cognition):** No optimized kernels existed for Vera Rubin. An agent with dedicated GPUs found 8-9 optimizations over about a week, taking Rubin from below GB300 throughput to "significantly better." This is a real proof point for agent-driven kernel autotuning on day-zero hardware.
- **Cheap reviewer, strong writer (TraceTune / Relate graph DB):** Downgrading the writer to Haiku hurt quality. Keeping a strong writer and giving cheap Haiku reviewers a zero-LLM-cost graph "neighborhood brief" raised PRBench 74 → 76 (Claude) and 82 → 86 (Codex) at about half the tokens. Routing insight: asymmetric tasks need asymmetric models, and the cheap model must be fed precomputed structure.
- **KV cache as a security signal (Pinter AI?):** Learn a baseline over KV pages (inside vLLM or via LMCache) and flag anomalous pages. Caught hidden spoken instructions in a Gemma 4 E4B voice agent with 16-token pages; on Qwen3 14B, 7-8 of top-10 alerts were real. Problem: every model and router choice has its own KV space, and a 256-token Qwen3-14B chunk is ~40MB. Pairs naturally with KV-aware routers (llm-d, NVIDIA Dynamo).
- **Tiered model economics (DeepMind):** Fast tier (Hydrogen) claimed 3x better and 3x faster than the prior Flash; frontier tier (Carbon) claimed 2-3.3x cheaper per task than competitors on agentic benchmarks. Per-task cost, not per-token price, is the routing metric.
- **Token efficiency is not cost efficiency:** DuckDB's agent mode cut output 59% but that was 0.5% of total tokens, so cost did not move. Profile where tokens go (input context dominates) before optimizing output.
- **Small-model post-training:** LoRA-style SFT on Qwen 3 4B/8B, quantized to a single 5090, is enough for a narrow reviewer. Speaker claims DPO needs 70B+ (debatable; DPO works fine on 7-8B models in published literature).
- **Not covered:** No talk addressed MoE, pruning, or quantization methods directly.

## Real-World Application / Actionable Step
- **Run an Optuna TPE sweep on your vLLM serving configs this week.** Define 3-4 workload regimes from real traffic (input/output length histograms), optimize goodput under an SLO, search max-num-seqs, max-num-batched-tokens, chunked-prefill size, and gpu-memory-utilization. Budget ~50 trials per regime. Repeat after every quantization change (GPTQ/AWQ shifts the memory-compute balance and therefore the optimum).
- **For routing research:** Test the asymmetric "strong generator, cheap verifier plus precomputed context" pattern. Measure per-task cost and quality, not per-token price. Add a cross-family verifier (Kiro's approach) and quantify how often the second family catches what the first missed; that rate is a routing signal in itself.
- **Prototype KV-page anomaly detection on LMCache** as a side benefit of KV-aware routing work: per-page summary statistics are cheap, and a shared KV representation across models is an open problem worth a paper.
- **Use agents for kernel autotuning:** Give an agent a dedicated GPU, a correctness test suite, and a throughput benchmark for a target kernel (e.g., a fused MoE expert GEMM or INT4 dequant-matmul) and let it iterate for days. The Rubin result suggests this works on hardware with no prior tuned kernels.
- **Verification discipline:** When agents generate optimization code, validate only against tests that predate the change plus differential runs against the reference implementation, as Bun did.
