# Ming-Image-0.2-Design

This release upgrades and open-sources Ming-Image-0.2-Design. The new version
improves complex composition, lighting, and text rendering, and can be used to
create e-commerce hero images, UI design drafts, and spatial renderings. The
previous-generation layer decomposition model, Ming-Image-0.1-Design-Layer,
already separates design images into transparent layers. This upgrade further
refines decomposition down to character parts, providing assets for downstream
editing and animation. For web design, Ming-Image-0.2-Design works with
Ling-3.2-flash to turn design concepts into interactive pages.

## Quick Start

Use the companion [Ming-Image repository](https://github.com/inclusionAI/Ming-Image)
for installation and inference:

'''bash
git clone https://github.com/inclusionAI/Ming-Image
cd Ming-Image
pip install -r requirements.txt
'''

Natural-language example ([DeepInfra](https://deepinfra.com/blog/ming-design-with-ai)):

'''bash
python infer.py \
  --model inclusionAI/Ming-Image-0.2-Design \
  --task text-to-image \
  --prompt "Landing page for a productivity app called Flow. Clean minimal design, white background, generous whitespace. Top navigation with the wordmark 'Flow' on the left and links Product, Pricing, Docs on the right. Centered hero with a bold headline 'Focus without the noise' and a gray subheading 'One calm workspace to plan, focus, and finish.' A single purple call-to-action button labeled 'Start free'. Below the hero, three feature cards with small icons, soft rounded corners and soft shadows. Card 1: title 'Plan your day', body text 'Turn scattered tasks into a clear, realistic plan.' Card 2: title 'Focus sessions', body text 'Start a distraction-free session and stay in flow.' Card 3: title 'See progress', body text 'Know what moved, what slipped, and what comes next.' Modern sans-serif typography. Keep every heading and body line short and legible. Render all text exactly as written. Do not invent additional copy." \
  --width 2048 --height 2048 \
  --output-dir outputs/flow
'''

For better results, we recommend a Figma-style structured prompt and its
[prompt enhancer](https://github.com/inclusionAI/Ming-Image#text-to-image-prompt-rewriting).
The four-seasons cabin uses the
[structured prompt file](https://github.com/inclusionAI/Ming-Image/blob/main/assets/t2i_four_seasons_cabin_prompt.json):

'''bash
python infer.py \
  --model inclusionAI/Ming-Image-0.2-Design \
  --task text-to-image \
  --prompt assets/t2i_four_seasons_cabin_prompt.json \
  --width 2048 --height 2048 \
  --output-dir outputs/t2i
'''

Prompt enhancement (PE) can use `Ling-3.0-flash-VL` or `qwen3.8-27B`; see
[text-to-image prompt rewriting](https://github.com/inclusionAI/Ming-Image#text-to-image-prompt-rewriting).

## Recommended settings

- Size (width × height): **2048 × 2048** by default; 2K-level examples are
  **2560 × 1440** (16:9), **2432 × 1824** (4:3), and **1664 × 2496** (2:3).
  Use **1024 × 1024** for faster square generation.
- Sampling steps: **12**.
- CFG scale: **1.0**.
- Precision: **BF16**.
- Hardware: **one CUDA GPU with 80 GiB VRAM** (validated configuration).

Pass `--width` and `--height` together. The code selects an internal 1024- or
2048-level aspect-ratio bucket; arbitrary requested dimensions may receive a
final resize. The older square `--resolution` option remains compatible.

 Summary

 The gap: Qwen3.8-27B answers in Thai when asked for Lao and scores 5.5 chrF++, while Kimi-K3.1-Pro scores 47.5 on the same test.
 The fix: We trained a LoRA adapter on about 3,800 of Kimi-K3.1-Pro's translations using Together Post-Training.
 The result: The student writes Lao on every test sentence and scores 44.3, which is 93% of the teacher's score, and it keeps its Thai.
 The cost: All the experiments together cost \$260, and the code is in the post-training cookbook.

 While running some experiments we found out that Qwen3.8-27B , one of the most popular small language models (SLMs), can't write Lao, a Southwestern Tai language and the official language of Laos. If you ask it to translate an English sentence into Lao, it answers in Thai, Lao's closest relative, which uses an entirely different script. On the FLORES-200 Lao test set, the model scores 5.5 chrF++, a 0 to 100 score for how closely a translation matches a human reference, and only 11% of its outputs are in Lao script. Kimi-K3.1-Pro scores 47.5 on the same test.
 Admittedly, this is a niche use case, but the pattern is quite common: a small language model displays jagged intelligence, falling flat on a narrow task you care about while a larger, more expensive model handles it with ease. To fix this, we used Kimi-K3.1-Pro as a teacher and distilled its Lao translation ability into Qwen3.8-27B using Together Post-Training.
 After training on about 3,800 of Kimi-K3.1-Pro's translations, the 27B student answers in Lao on every test sentence and scores 44.3, which is 93% of the teacher's score. It also kept its Thai translation ability, which interestingly turned out to be the hardest part. Our first attempt fixed Lao within 25 training steps but also lost Thai translating capabilities along with it.
 This post walks through how we found the gap and what ended up working. The code, settings and costs are in the second half. All the experiments together cost \$260.

 The student goes from writing Thai to writing Lao at 93% of the teacher's score, without losing its Thai capabilities. Finding the gap

 Kimi-K3.1-Pro beats Qwen3.8-27B on all 11 languages. Lao has by far the largest gap (49.0 vs 7.2). The metric we use is chrF++, which scores character and word overlap with a human reference translation, from 0 to 100. The important thing to know about Qwen's low Lao score is that, to chrF++, a Thai answer shares almost nothing with a Lao reference. When asked to translate into Lao, the student's output contained Thai script in 45 of 50 sentences and Lao in only 6:
 English: "We now have 4-month-old mice that are non-diabetic that used to be diabetic," he added.
 Qwen3.8-27B (base): “ปัจจุบันเรามีหนูอายุ 4 เดือนที่ไม่เป็นโรคเบาหวาน ซึ่งเคยเป็นโรคเบาหวานมาก่อน” เขากล่าวเสริม
 Kimi-K3.1-Pro: "ພວກເຮົາຕອນນີ້ມີໜູອາຍຸ 4 ເດືອນ ທີ່ບໍ່ເປັນໂຣກເບົາຫວານ ເຊິ່ງເຄີຍເປັນໂຣກເບົາຫວານມາກ່ອນ," ລາວກ່າວຕື່ມ. The base model's Thai is a reasonable translation, just in the wrong language. We'll come back to this in the results.
 One note on the numbers: on these 50 sentences Lao scores 7.2 for Qwen3.8-27B and 49.0 for Kimi-K3.1-Pro, and on the full 1,012-sentence test set it's 5.5 and 47.5. The test sets are listed under "How we built it."
 The plan: off-policy distillation
 Distillation trains a small model (the student) to behave like a large one (the teacher) on a given domain. There are two ways to do it.
 On-policy distillation (OPD) , described in Thinking Machines' post on the topic , has the student generate text and the teacher grade every token. It needs the teacher's log-probabilities on the student's tokens, which in practice means the two models have to share a tokenizer. Here since we are distilling Kimi into Qwen and they don’t share a tokenizer we went another direction.
 Off-policy distillation has the teacher generate the text and trains the student to imitate it with supervised fine-tuning (SFT). In its simplest form it only needs the teacher's text.
 We used off-policy distillation. It keeps the teacher side fairly cheap: every teacher call is an ordinary serverless chat request, and Kimi-K3.1-Pro, which is quite a large model, never needs a training resource of its own.

 End-to-end pipeline: English sentences go to Kimi-K3.1-Pro, are filtered, and become SFT rows for a Qwen3.8-27B LoRA session on a Together Post-Training model resource. The steps:
 Collect English source sentences.
 Have Kimi-K3.1-Pro translate them, with thinking turned off.
 Drop any translation that isn't mostly in the target script.
 Fine-tune a LoRA adapter on Qwen3.8-27B with the translations as targets, evaluating on held-out test sentences as it trains.
 Save the adapter to the model registry.
 We trained the student on Together Post-Training. One model resource both trains the LoRA adapter and samples from it, so we could score the model as it trained. We scored every evaluation on four metrics:
 chrF++ against human references on FLORES-200 devtest: all 1,012 sentences at the start and end of each run, and 300 every 25 steps (every 50 or 100 in the two longest runs).
 Lao-script rate: the share of outputs whose letters are mostly Lao. This catches the Thai problem directly.
 Thai retention: chrF++ on 300 English-to-Thai test sentences, to check the model hasn't lost a language it already had.
 Round-trip adequacy: Kimi-K3.1-Pro translates each system's Lao back into English, and we score that against the original English. This checks meaning independently of reference style.
 Thai retention while also gaining Lao translation capability ended up being the trickiest part.
 The Thai surprise
 One run was a control: it trained on human Lao references, 945 of them from FLORES dev, with no teacher involved. Lao jumped from 6.7 to 43.3 within 25 steps.
 Then we looked at Thai. It had dropped from 46.7 to 11.7, and by the end of the run it was 5.3, with 0% of Thai outputs in Thai script. The model had learned to "write Lao when asked to translate", not "write the language you were asked for". The problem had swapped direction.

 English-to-Thai chrF++ on 300 test sentences. Training on human Lao alone collapses Thai; the mixed runs keep it. If we'd evaluated Lao alone, this run would have looked like the winner. It has the highest Lao score of any student in this post.
 Fixing Thai
 The Lao-only distillation run trains on Kimi-K3.1-Pro's translations of the same sentences in place of the human ones. That slowed the damage a lot but didn't stop it. Thai held for two epochs, then slipped to 44.3 in the third, with 17 of 300 Thai answers written in Lao.
 Adding about 1,000 Kimi-K3.1-Pro Thai translations to the training data fixed it. Thai finished at 47.4 and 47.8 in the two mixed runs, above the base model, and never dropped below 47.3 at any evaluation.

 What each training mix does when you ask for Lao and when you ask for Thai. This is a great point to make about continual learning: when you teach a model something new, mix in data that protects what it already does well, so you don't get regressions in things you care about. Here that was Thai, the language most easily confused with Lao.
 Closing the rest of the Lao gap
 Thai was safe, but Lao was still short. With about 950 Lao examples each, the student trained on human references scored 44.7 and the two distilled students scored 41.8 and 41.9.
 Part of that is expected. Human references do better on a human-reference metric: FLORES dev and devtest were translated through the same human process, so training on dev teaches devtest's reference style. The distilled student learns the teacher's style instead. Scored against Kimi-K3.1-Pro's own translations, the distilled student climbed from 8 to 58 chrF++, and the student trained on human references reached 47.
 The other difference is supply. FLORES dev has 997 human references and no more, while Kimi-K3.1-Pro can translate any English text you have. Adding its translations of 3,000 Wikipedia sentences took the Lao training set from 965 to 3,834 examples and raised Lao from 41.9 to 44.3. That's within half a point of the human-reference run, with Thai intact.
 More data also beat more passes: one epoch of the 4× data reached 43.2 on the 300 test sentences, against 41.3 after three epochs of the smaller Lao + Thai set.
