# WePocketModel 1.0 4B · MLX

[![GitHub WePocketModel](https://img.shields.io/badge/GitHub-WePocketModel-181717?logo=github&logoColor=white)](https://github.com/Tencent/WePocketModel)
[![Hugging Face 4B safetensors](https://img.shields.io/badge/Hugging%20Face-4B%20safetensors-E0A800?logo=huggingface&logoColor=white)](https://huggingface.co/tencent/WePocketModel1.0-4B)
[![Hugging Face 4B GGUF](https://img.shields.io/badge/Hugging%20Face-4B%20GGUF-E0A800?logo=huggingface&logoColor=white)](https://huggingface.co/tencent/WePocketModel1.0-4B-GGUF)
[![Hugging Face 2B MLX](https://img.shields.io/badge/Hugging%20Face-2B%20MLX-E0A800?logo=huggingface&logoColor=white)](https://huggingface.co/tencent/WePocketModel1.0-2B-MLX)

Apple silicon build of [`tencent/WePocketModel1.0-4B`](https://huggingface.co/tencent/WePocketModel1.0-4B) for
[MLX](https://github.com/ml-explore/mlx). The weights are converted to the MLX layout and shipped with a
self-contained runtime (`runtime/`), so the model runs on the Apple silicon GPU with no PyTorch, no
`torchvision` and no video toolchain: tokenization uses `tokenizers`, and the Qwen3-VL image preprocessing
(`smart_resize` + patchify) plus the MGVB visual bottleneck are re-implemented in `numpy`/`PIL`/MLX.

One set of parameters still serves all three WePM capability families:

| Capability | Input and output |
| --- | --- |
| **Generation** | Generates text from text, images, or interleaved text and images (OCR, captioning, VQA, chat). Slotless decoding. |
| **Embedding** | Encodes text and images into L2-normalized vectors for retrieval and candidate ranking. Full dimension 2,048, truncated MRL dims 64/128/256/512/1024. |
| **Decision** | Evaluates application state and questions to return structured choices, ordinal scores, or binary judgments (JEV). |

## Files

| File | Description |
| --- | --- |
| `model-00001-of-00003.safetensors` … `model-00003-of-00003.safetensors` | Qwen3.5 backbone — Qwen3-VL vision tower + 32-layer hybrid language model — in MLX layout, bf16 (8.46 GiB) |
| `model.safetensors.index.json` | shard index |
| `task_modules.safetensors` | E/J slots, embedding head, decision head, MGVB parameters (bf16) |
| `config.json` | architecture and `task_slots_v1` contract, identical to the source release |
| `wepm_mlx.json` | conversion manifest: layout, shard count, norm convention |
| `tokenizer.json`, `tokenizer_config.json`, `chat_template.jinja` | tokenizer and the training chat template |
| `processor_config.json` | image-processor settings, kept for ecosystem compatibility |
| `runtime/` | `wepm_mlx` package and the `infer_mlx.py` CLI |
| `requirements.txt` | pinned dependencies (mlx, mlx-vlm, transformers, Pillow, …) |

The conversion changes layout only, never math: keys are renamed to the MLX module tree
(`vision_tower.*`, `language_model.model.*`), depthwise `conv1d` moves from `[out, 1, kernel]` to
`[out, kernel, 1]`, the Conv3d patch embedding from `NCDHW` to `NDHWC`, and RMSNorm gains are stored as
`weight` instead of the `weight - 1` delta form used by the original release.

## Quick start

'''bash
# Apple silicon; macOS version supported by the pinned MLX wheel
# About 9.1 GB of weight files; measured BF16 peak memory: 8.99 GiB
python -m venv .venv-mlx
source .venv-mlx/bin/activate
python -m pip install huggingface_hub
hf download tencent/WePocketModel1.0-4B-MLX --local-dir WePocketModel1.0-4B-MLX
cd WePocketModel1.0-4B-MLX
python -m pip install -r requirements.txt
'''

**Generation** — text, a single image, or interleaved image/text content:

'''bash
python runtime/infer_mlx.py --model . --task generate \
    --prompt "Describe this image in one sentence." --image demo.jpg \
    --max-new-tokens 64 --output out/generation.json

# content.json: {"content": [{"type": "image", "path": "a.jpg"}, {"type": "text", "text": "..."}]}
python runtime/infer_mlx.py --model . --task generate \
    --content-json content.json --max-new-tokens 64 --output out/interleaved.json
'''

**Embedding** — with optional MRL truncation:

'''bash
python runtime/infer_mlx.py --model . --task embed \
    --prompt "Find similar landscape photos." --image demo.jpg \
    --embedding-dim 1024 --output out/embedding.json
'''

**Decision (JEV)** — `choice`, `score` or `noul` requests:

'''bash
python runtime/infer_mlx.py --model . --task decision \
    --decision-json request.json --output out/decision.json
'''

Save the following as `request.json`:

'''json
{
  "state": "The user asks to book a table.",
  "questions": {
    "q": {
      "type": "choice",
      "instructions": "What should happen next?",
      "criteria": {
        "call": "call the restaurant",
        "menu": "show the menu",
        "ignore": "ignore"
      }
    }
  }
}
'''

For `score`, set `type` to `score` and use an ordered list of descriptions as `criteria`.
For `noul`, set `type` to `noul` and omit `criteria`; the result is the probability of yes/true.
Both require `state` and nonempty `instructions`.

From Python, run in the downloaded model directory after `export PYTHONPATH="$PWD/runtime"`:

'''python
import json
from pathlib import Path

from wepm_mlx.runtime import WePMRuntime

runtime = WePMRuntime(".")
content = [{"type": "image", "path": "demo.jpg"}, {"type": "text", "text": "Describe it."}]

try:
    print(runtime.generate(content, max_new_tokens=64)["text"])
    print(runtime.embed(content, dims=[256, 2048])["embeddings"]["256"][:8])
    request = json.loads(Path("request.json").read_text())
    print(runtime.decide(request)["answers"])
finally:
    runtime.close()
'''

`--quantize-bits 4` (or `8`) quantizes the linear layers at load time, no extra download needed: peak
memory drops from 9.0 GiB to 4.3 GiB and decoding gets ~2.2× faster.

## Parity with the PyTorch release

Compared against the official `inference/runtime.py` (CPU, fp32) on five cases: text generation,
single-image embedding, the compressed MGVB path, the bypassed small-image path, and a `choice` decision.
(A two-image 1058-token prompt was skipped: the fp32 reference does not fit in 36 GB of RAM.)

| Stage | Agreement |
| --- | --- |
| `input_ids`, including the MGVB placeholder count | bit-exact on all cases |
| M-RoPE position indices, including explicit visual positions | bit-exact on all cases |
| input embeddings | 0 for text; 0.35–0.87 % relative for visual tokens |
| last hidden state | cosine ≥ 0.99999 |
| embedding (64 / 128 / 2048-d) | cosine ≥ 0.99999 |
| decision probabilities | max deviation 4.6e-5 |
| greedy generation | token-for-token identical |

The remaining gap comes from floating-point reduction order and ±1 grey-level differences in bicubic
resampling — pin `Pillow==12.3.0`, since Pillow 13 changed the resize kernel.

## Performance

Apple M3 Pro (36 GB), MLX 0.32.4, 528-token prompt (one 1500-px image → 1645 native visual tokens
compressed to 512):

| Precision | Prefill | Decode | Peak memory |
| --- | --- | --- | --- |
| bf16 | 1.13 s (466 tok/s) | 13.9 tok/s | 8.99 GiB |
| 4-bit, group 64 | 0.82 s (646 tok/s) | 30.6 tok/s | 4.25 GiB |
