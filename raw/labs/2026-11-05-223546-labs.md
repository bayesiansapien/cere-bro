# Qwen3-30B-A3B MoE-Output Sparse Autoencoders

TopK sparse autoencoders (k = 100, 2^20 latents) trained on the MoE block output of
[Qwen3-30B-A3B](https://huggingface.co/Qwen/Qwen3-30B-A3B) at layers 4, 30 and 46, released with
the paper *Sparse AutoEncoders Reveal That MoE Experts Exhibit Human-Interpretable Fine-Grained
Specialization* ([project page](https://bytedance-seed.github.io/SAE-interprets-MoE/),
[code](https://github.com/ByteDance-Seed/SAE-interprets-MoE), paper: TODO).

## Files

'''
layer_4/sae.safetensors     layer_4/config.json
layer_30/sae.safetensors    layer_30/config.json
layer_46/sae.safetensors    layer_46/config.json
'''

Each SAE reads the output of `model.model.layers[L].mlp` (the `Qwen3MoeSparseMoeBlock`, before
the residual addition, layers 0-indexed) as is, without any normalization. `sae.safetensors`
(about 17.2 GB) holds four float32 tensors:

| Tensor | Shape |
|--------|-------|
| `W_enc` | `[2048, 1048576]` |
| `b_enc` | `[1048576]` |
| `W_dec` | `[1048576, 2048]`, rows have unit norm |
| `b_dec` | `[2048]` |

'''
f     = TopK_100(ReLU(y @ W_enc + b_enc))
y_hat = f @ W_dec + b_dec
'''

Latent `i` is column `i` of `W_enc` and row `i` of `W_dec`; the paper writes it as `L-F<i>`, e.g.
`30-F97783`. `config.json` lists the same settings.

## Usage

'''python
import torch
from huggingface_hub import hf_hub_download
from safetensors.torch import load_file
from transformers import AutoModelForCausalLM, AutoTokenizer

LAYER, K = 30, 100
DEVICE = "cuda"  # the SAE takes about 17 GB on top of the model

sae = load_file(
    hf_hub_download("ByteDance-Seed/Qwen3-30B-A3B-MoE-SAE", f"layer_{LAYER}/sae.safetensors"),
    device = DEVICE,
)

def encode(y):
    """y: [..., 2048] raw MoE output. Returns the activations and ids of the top-K latents, [..., K]."""
    pre_acts = y.float() @ sae["W_enc"] + sae["b_enc"]
    return torch.topk(torch.relu(pre_acts), K, dim = -1)

def decode(acts, ids):
    return torch.einsum("...k,...kd->...d", acts, sae["W_dec"][ids]) + sae["b_dec"]

model = AutoModelForCausalLM.from_pretrained("Qwen/Qwen3-30B-A3B", torch_dtype = torch.bfloat16, device_map = "auto")
tokenizer = AutoTokenizer.from_pretrained("Qwen/Qwen3-30B-A3B")

captured = {}
def hook(module, inputs, output):
    # Qwen3MoeSparseMoeBlock returns (hidden_states, router_logits) in transformers 4.x
    captured["y"] = output[0] if isinstance(output, tuple) else output

handle = model.model.layers[LAYER].mlp.register_forward_hook(hook)
inputs = tokenizer("def binary_search(arr, x):", return_tensors = "pt").to(model.device)
with torch.no_grad():
    model(**inputs)
handle.remove()

y = captured["y"][0].to(DEVICE)   # [seq_len, 2048]
acts, ids = encode(y)             # [seq_len, 100] each
y_hat = decode(acts, ids)         # [seq_len, 2048]
'''

The dense pre-activation takes 4 MiB per token, so encode long inputs in chunks.

## Training

Each SAE was trained independently on MoE block outputs collected from the Olmo 3 training
corpus: 5/8 Dolma 3 pretraining data, 1/4 Dolci-Think-SFT (reasoning chains of thought) and 1/8
Dolci-Instruct-SFT (instruction following). Training used a TopK activation with k decaying
from 1000 to 100 over the first 10,000 steps, an auxiliary loss, AdamW and about 3.2B tokens
per SAE; the full recipe is given in the appendix "SAE training details" of the paper.

# Cross-Layer Transcoder for Qwen3-8B-Base

A cross-layer transcoder (CLT) for [Qwen3-8B-Base](https://huggingface.co/Qwen/Qwen3-8B-Base): 36 layers × 32,768 latents. Each layer's latents read the residual stream right before that layer's MLP (`resid_mid`) and write to the MLP outputs (`mlp_out`) of that layer and every later layer. 94.2B parameters, fp32, 377 GB in total.

## Format

| File | Contents |
|---|---|
| `W_enc_{l}.safetensors` (l = 0..35) | `W_enc_{l}`: `[32768, 4096]`, encoder of layer `l` |
| `W_dec_{l}.safetensors` (l = 0..35) | `W_dec_{l}`: `[32768, 36 - l, 4096]`; `W_dec_norm_{l}`: `[32768]` (357 GB, decoding only) |
| `W_dec_norm.safetensors` | `W_dec_norm`: `[36, 32768]`, decoder-column norms for scoring |
| `factors.safetensors` | `resid_mid_l2`, `mlp_out_l2`: `[36]`, mean activation norms |
| `config.json` | `d_feature` (32768), `k` (10), base model and dimensions |

Hooks on the base model: `resid_mid` is the input of `model.layers[l].post_attention_layernorm`; `mlp_out` is the output of `model.layers[l].mlp`.

- **Encode:** `a_l = ReLU(W_enc_l · x_l)` (no bias). Score each latent as `a_l[i] · W_dec_norm[l, i]` and keep the `36 · k = 360` highest-scoring latents across all layers jointly.
- **Decode:** `mlp_out_hat[m] = Σ_{l ≤ m} a_l @ W_dec_{l}[:, m - l, :]`.
- The activation normalization used in training is already folded into the weights: the CLT takes **raw** `resid_mid` and reconstructs **raw** `mlp_out`. Do not apply the factors in `factors.safetensors` again.
- Tokens whose `resid_mid` or `mlp_out` norm on any layer reaches 20× that layer's mean norm are dropped, as in training (in practice the first token).
- The CLT was trained on fp32 activations; use fp32 for the base model too.

## Demo

Download the checkpoint, save the code below as `hf_encode_demo.py` next to the downloaded `clt/` directory, and run it:

'''bash
huggingface-cli download ByteDance-Seed/Cross-Layer-TopK-CLT --local-dir clt
torchrun --nproc_per_node 8 hf_encode_demo.py
'''

The demo encodes a hardcoded sentence, prints the active latents of every token, and decodes them back to `mlp_out`. Latents are split evenly across GPUs (any count dividing 32,768). Output (`latent_id:activation`, strongest first, ids are per layer):

'''
[0] 'Let': dropped as outlier
[1] "'s"  (layer: latent_id:activation ...)
  L00: 14503:23.44 9681:11.48 11356:8.68 24242:7.10 ...
  ...
Reconstructed mlp_out (positions, layers, d_model): (7, 36, 4096)
'''

In code, the result is `activations[pos][layer] = [[latent_id, activation], ...]` (`None` for outliers) and the reconstruction is `mlp_out_hat_nxlxh`.

To only encode, set `DECODE = False` in the code and skip the decoder files; one 80 GB GPU (`--nproc_per_node 1`) is then enough:

'''python
# Copyright (c) 2026 ByteDance and/or its affiliates
#

# you may not use this file except in compliance with the License.
# You may obtain a copy of the License at

"""Encode text with the Qwen3-8B-Base Cross-Layer Transcoder on multiple GPUs.

    torchrun --nproc_per_node 8 hf_encode_demo.py

Each GPU holds 1/N of every layer's latents. A token keeps its n_layers * k
latents with the largest activation * ||W_dec|| across all layers jointly.
"""
import json
import os

import torch
import torch.distributed as dist
from safetensors import safe_open
from transformers import AutoModelForCausalLM, AutoTokenizer

CLT_PATH = "clt"
LLM_PATH = "Qwen/Qwen3-8B-Base"
TEXT = "Let's go play rhythm games."
DECODE = True  # reconstruct mlp_out from the latents; needs the W_dec_*.safetensors files (357 GB)

dist.init_process_group("nccl")
rank, world_size = dist.get_rank(), dist.get_world_size()
device = torch.device("cuda", int(os.environ["LOCAL_RANK"]))
torch.cuda.set_device(device)
torch.set_grad_enabled(False)

# This GPU's slice of the latents. Activation scaling is folded into the weights.
config = json.load(open(f"{CLT_PATH}/config.json"))
d_feature, k = config["d_feature"], config["k"]
f_local = d_feature // world_size
lo = rank * f_local


def read_rows(name):
    with safe_open(f"{CLT_PATH}/{name}.safetensors", "pt") as f:
        return f.get_slice(name)[lo:lo + f_local].float().to(device)


with safe_open(f"{CLT_PATH}/W_dec_norm.safetensors", "pt") as f:
    W_dec_norm_lxf = f.get_slice("W_dec_norm")[:, lo:lo + f_local].float().to(device)
n_layers = W_dec_norm_lxf.shape[0]
W_enc_lxfxh = torch.stack([read_rows(f"W_enc_{l}") for l in range(n_layers)])
with safe_open(f"{CLT_PATH}/factors.safetensors", "pt") as f:
    mean_norm_2xl = torch.stack([f.get_tensor("resid_mid_l2"), f.get_tensor("mlp_out_l2")])[:, :n_layers].to(device)

# Hook the MLP input (resid_mid) and output (mlp_out) of every layer. The CLT was trained on fp32 activations.
tokenizer = AutoTokenizer.from_pretrained(LLM_PATH)
llm = AutoModelForCausalLM.from_pretrained(LLM_PATH, torch_dtype=torch.float32).to(device)
resid_mid, mlp_out = [], []
for layer in llm.model.layers[:n_layers]:
    layer.post_attention_layernorm.register_forward_pre_hook(lambda m, args: resid_mid.append(args[0][0]))
    layer.mlp.register_forward_hook(lambda m, args, out: mlp_out.append(out[0]))
input_ids = tokenizer(TEXT, return_tensors="pt").input_ids.to(device)
llm.model(input_ids)
resid_mid_nxlxh, mlp_out_nxlxh = torch.stack(resid_mid, dim=1), torch.stack(mlp_out, dim=1)
del llm

# As in training, drop tokens whose norm on any layer reaches 20x the mean (in practice the first token).
norm_2xnxl = torch.stack([resid_mid_nxlxh.norm(dim=-1), mlp_out_nxlxh.norm(dim=-1)])
outlier_n = (norm_2xnxl >= 20 * mean_norm_2xl[:, None]).any(dim=2).any(dim=0)

# Local top-K candidates (score, activation, layer * d_feature + latent_id), then the global top-K.
K = n_layers * k
acts_nxlf = torch.relu(torch.einsum("nlh,lfh->nlf", resid_mid_nxlxh, W_enc_lxfxh)).flatten(1)
score_nxk, idx_nxk = (acts_nxlf * W_dec_norm_lxf.flatten()).topk(K)
gid_nxk = idx_nxk // f_local * d_feature + lo + idx_nxk % f_local
cand_nxkx3 = torch.stack([score_nxk, acts_nxlf.gather(1, idx_nxk), gid_nxk.float()], dim=-1)
gathered = [torch.empty_like(cand_nxkx3) for _ in range(world_size)]
dist.all_gather(gathered, cand_nxkx3)
cand_nxwkx3 = torch.cat(gathered, dim=1)
top_nxkx3 = cand_nxwkx3.gather(1, cand_nxwkx3[..., 0].topk(K).indices[..., None].expand(-1, -1, 3))

if DECODE:
    # Each GPU decodes the selected latents it owns, streaming W_dec one layer at a time; then sum over GPUs.
    # Latents of layer l write to the mlp_out of layers l..n_layers-1.
    n = input_ids.shape[1]
    act_nxk, gid_nxk = top_nxkx3[..., 1], top_nxkx3[..., 2].long()
    layer_nxk, latent_nxk = gid_nxk // d_feature, gid_nxk % d_feature - lo
    mine_nxk = (latent_nxk >= 0) & (latent_nxk < f_local)
    pos_nxk = torch.arange(n, device=device)[:, None].expand_as(mine_nxk)
    acts_nxlxf = torch.zeros(n, n_layers, f_local, device=device)
    acts_nxlxf[pos_nxk[mine_nxk], layer_nxk[mine_nxk], latent_nxk[mine_nxk]] = act_nxk[mine_nxk]
    mlp_out_hat_nxlxh = torch.zeros_like(mlp_out_nxlxh)
    for l in range(n_layers):
        mlp_out_hat_nxlxh[:, l:] += torch.einsum("nf,fth->nth", acts_nxlxf[:, l], read_rows(f"W_dec_{l}"))
    dist.all_reduce(mlp_out_hat_nxlxh)

if rank == 0:
    # activations[pos][layer] = [[latent_id, activation], ...], strongest first; None for outliers.
    activations = []
    for top_kx3, is_outlier in zip(top_nxkx3.tolist(), outlier_n.tolist()):
        per_layer = [[] for _ in range(n_layers)]
        for _, act, gid in sorted(top_kx3, key=lambda x: -x[1]):
            if act > 0:
                per_layer[int(gid) // d_feature].append([int(gid) % d_feature, round(act, 4)])
        activations.append(None if is_outlier else per_layer)

    for pos, per_layer in enumerate(activations):
        token = tokenizer.decode(input_ids[0, pos])
        if per_layer is None:
            print(f"[{pos}] {token!r}: dropped as outlier")
            continue
        print(f"[{pos}] {token!r}  (layer: latent_id:activation ...)")
        for layer, feats in enumerate(per_layer):
            if feats:
                print(f"  L{layer:02d}: " + " ".join(f"{i}:{a:.2f}" for i, a in feats))
    if DECODE:
        print("Reconstructed mlp_out (positions, layers, d_model):", tuple(mlp_out_hat_nxlxh.shape))

dist.destroy_process_group()
'''

 Was this answer helpful?

 In Naples last month, at the European Conference on Machine Learning and Principles and Practice of Knowledge Discovery in Databases (ECML PKDD), Amazon senior applied scientist Hamed Karimi and colleagues won the 2026 ECML PKDD Test-of-Time Award for their 2016 paper “ Linear convergence of gradient and proximal-gradient methods under the Polyak–Łojasiewicz condition ”. The award recognizes research published a decade earlier that has had a lasting impact.
 The paper, written with Julie Nutini and Mark Schmidt while Karimi was a postdoctoral researcher at the University of British Columbia, has helped to organize a previously scattered field of machine learning optimization and offers useful approaches to analyzing new training methods.
 “When we wrote the paper in 2016, we genuinely didn’t expect it to make a splash,” Karimi says. “We did not know that the result would become part of the way researchers analyze optimization in machine learning.”
 Karimi and his coauthors showed that the Polyak-Łojasiewicz condition, a 1963 mathematical inequality that had been largely overlooked in machine learning, can prove that the standard method for training machine learning models closes in on the best solutions quickly, even when many different solutions could work equally well. Because modern machine learning models rarely have a single best solution, the result helped close a long-standing gap between what training methods do in practice and what theory could guarantee.

 Amazon senior applied scientist Hamed Karimi (right) receiving the 2026 ECML PKDD Test-of-Time Award from Donato Malerba, a professor of computer engineering at the University of Bari Aldo Moro in Italy and chair of the award committee. 

 Optimization landscape 

 In the classic supervised-machine-learning setting, a model’s billions of settings, or parameters, are adjusted so that the model’s outputs match labeled training data as closely as possible. The distance between the model’s output and the labeled data is measured with a loss function ; the goal is to tune the parameters to minimize the loss. This tuning is done through optimization processes, the most common approach being gradient descent or one of its variants.
 One way to understand gradient descent is to visualize a topographic map with peaks, valleys, cliffs, and plateaus. The lowest points on the map represent minimal loss, with each step downhill toward these minima representing parameter adjustments that optimize toward fewer errors. Ideally, researchers would like to know the quickest path to the bottom. Theory suggests that the fastest path shrinks the error by a constant fraction each step, a property known as linear convergence.
 The problem is that linear convergence is mathematically guaranteed only for a particular topographic shape: a steep bowl that uniformly curves upward, one that is strongly convex . A bowl like this has exactly one lowest point, so from any location, there is a single best move toward optimization.
 But many real problems don't work that way. When training data are redundant, as is the case with modern large language models, where the parameter count is disproportionately large compared to the amount of training data, the bottom of the landscape becomes a flat valley floor instead of a single point at the bottom of a bowl. These models — which exhibit weaker conditions than convexity — can be successfully trained with gradient descent, but the theory could neither explain why nor say how quickly, leaving a gap between what works in practice and what can be proven.
 By 2016, some 25 years’ worth of solutions to optimization problems with weaker conditions were in circulation, each with its own name, notation, and paper, but nobody had established how they related. Karimi and his colleagues’ paper settled those relationships.
 Researchers have since used variations of the paper’s method to rederive guarantees for essentially every standard optimization algorithm in machine learning. The paper has been cited over 2,000 times and has found a place in graduate textbooks.
 Tying it together 

 At the center of the paper is the Polyak-Łojasiewicz condition, an inequality published in 1963 by Boris Polyak in a Russian-language paper on gradient methods and by Stanisław Łojasiewicz in French that same year, independently and for unrelated reasons; Polyak was studying optimization, Łojasiewicz real analytic geometry. In the paper, Karimi and coauthors named the condition after both.
 If the condition holds, then even though the problem doesn’t exhibit a strongly convex geometry, the optimization is still guaranteed to converge at a linear rate. The proof of this is only three lines long.
 Karimi and his colleagues’ paper made three contributions. The first was a map of existing solutions for problems with weaker conditions, all of which make different assumptions about problem topology. For smooth functions that need not be convex, the researchers worked out every implication of competing assumptions, from strongest to weakest. For most of these functions, linear convergence had been proved before, but only in the convex case.
 Before Karimi and his colleagues’ work, little was understood about how these competing approaches related to one another. The map gave researchers a clear picture of the existing methods, showing which assumptions imply which, and identified the Polyak-Łojasiewicz condition as the weakest of the known conditions that still guarantees a linear rate.
 The second contribution extended the results to landscapes that combine a smooth function — one that slopes gradually and predictably at all points — with nonsmooth ones — those with corners, kinks, or edges, points where the slope is undefined. The paper introduced a variant of the Polyak–Łojasiewicz condition that guarantees the same linear rate, bringing many widely used models under the same short analysis.
 The third contribution was a reanalysis of the standard optimization algorithms, variants of gradient descent that include coordinate descent, sign gradient descent, and stochastic gradient descent. In each case, the analysis recovered the rate of convergence previously known only for strongly convex functions. In other words, the same short argument gives researchers a ready-made template for analyzing new training methods as they appear.
 Rate of influence 

 Two weeks after the preprint was posted, Polyak wrote the authors. “Actually, it was a surprise for me why the simple condition from my old publication attracted so little attention,” he said, “and now your work exhibits its importance.” He attached an English translation of his 1963 paper, largely unused in the five decades since.
 Karimi sees two reasons the condition has spread so far over the past decade. First, adopting it took almost no work. Many existing proofs that assumed the idealized bowl shape relied on just one consequence of it: loss, wherever it was measured in the landscape, would still be well above its minimum value. In other words, the ground slopes steeply enough to make real progress downhill. The Polyak–Łojasiewicz condition guarantees exactly that property, so those proofs still hold when the condition is swapped in.
 Second, and most consequentially, it made fast convergence on a nonconvex problem a provable statement, which is now part of how the field explains why the algorithms researchers run in practice work so well.
 The condition has also traveled well beyond the setting that Karimi and his colleagues studied. Variants now support convergence results in reinforcement learning, optimization over curved parameter spaces, and the sampling methods behind diffusion models. Ten years on, an inequality that sat unused for five decades has become one of the standard assumptions in the analysis of optimization methods for machine learning.

Chapter 01 : Summary 

 Johannes Hermle*, Ben Jones*, Lukas Althoff*, Ryan Heller, Thomas Lyttelton, Carolyn Stein, Nathan Wilmers, Maxim Massenkoff, Peter McCrory 
 *Lead authors of the report 
 Summary
 What we measure. AI could speed up scientific discovery, but by how much depends on what AI can do and how scientists use it. Using privacy-preserving methods, we study 207,000 Claude and Claude Code research sessions to understand how Claude is used across scientific fields and research tasks. We are conducting this research to help the public better understand the state of AI for science today and assess the impact that AI may have on scientific discovery in the future.
 Where scientists use Claude. Relative to the number of researchers in each field, Claude is used more in the formal sciences, such as computer science, mathematics, and statistics, and less in health and lab-based physical sciences. Scientists primarily use Claude to analyze data and to write. Data analysis alone accounts for about one-third of sessions on Claude and nearly half of sessions on Claude Code. Scientists use it less for idea generation and data gathering, even though, in an accompanying survey, they rank those tasks as the most important for scientific discovery. That said, specialized AI tools designed for scientific work could narrow the gap between the research tasks scientists use AI for and the ones they consider most important. On Claude Science, for instance, idea generation makes up about twice the share of use that it does on Claude.
 How Claude use tracks AI capability. We create a measure of how well AI can, in theory, perform each research task. The tasks AI is best suited to (the top 20% on this measure) get two to four times as much Claude use as the time researchers spend on them would predict. The tasks AI is least suited to (the bottom 20%), which include most physical work, get very little. We observe the same pattern across fields: fields where AI can perform many tasks well, such as computer science and statistics, use Claude more.
 What this could mean for the speed of scientific discovery. Using a simple model, we explore scenarios for how much AI could speed up research. If existing AI capabilities are widely adopted, they could double research output in some fields. If AI could carry out all non-physical research work, output in fields such as computer science and statistics could rise as much as 15-fold, while output in bench sciences such as chemistry and biology, which are held back by physical bottlenecks, would rise three- or fourfold. In our survey of researchers who actively use AI, about 40% expect AI models to carry out full research projects on their own by 2030.
 Introduction
 Science has been described as an “endless frontier” (Bush 1945). But how fast we explore that frontier has historically been limited by a scarce resource: the time and talent of human researchers. Artificial intelligence could ease that limit by amplifying what researchers can do, transforming both the process of discovery and the pace of exploration (Wang et al. 2023; Amodei 2024). Few applications of AI could matter more for human welfare. Given the highly cognitive nature of research compared with most sectors of the economy, AI’s effects may be particularly large and early in this domain.
 Recent examples show AI playing a growing role in scientific discovery. In structural biology, AlphaFold predicted the three-dimensional shapes of over 200 million proteins (Jumper et al. 2021; Varadi et al. 2024), and its creators shared the 2024 Nobel Prize in Chemistry. In materials science, GNoME predicted 380,000 stable new crystals (Merchant et al. 2023). In mathematics, researchers have used AI systems to help resolve decades-old Erdős problems, produce a potential proof for a Millennium Prize problem, and make progress on other major problems, from open conjectures to verifying landmark proofs (Anthropic 2026a, 2026b; OpenAI 2026a, 2026b; Tsoukalas et al. 2026).
 Beyond these developments, most scientific progress involves many specialized, interlinked research tasks, which can vary substantially across fields. How much AI accelerates scientific discovery depends not only on AI’s capabilities, but also on how it is adopted across these tasks. In this report, we use privacy-preserving infrastructure to study the scientific use of Claude, Claude Code, and Claude Science. We document how usage varies across fields and tasks, identify what explains these usage patterns, and outline scenarios for how AI could accelerate research.
 Claude use in science varies by field. Relative to their number of researchers, formal sciences such as computer science, mathematics, and statistics use Claude more heavily, while health and lab-based physical sciences use it less. Across research tasks, scientists use Claude more for analyzing data and writing, and less for gathering data or generating ideas and hypotheses. This is consistent with self-reported AI use from an accompanying survey of scientists.
 To understand these differences, we develop a measure of theoretical AI capability. Claude use is higher in tasks and fields that score higher on this measure. These also tend to be more cognitive in nature and better suited to reinforcement learning, in which AI learns from feedback on repeated attempts. In short, scientists appear to use AI where it works best.
 Based on these findings, we outline scenarios for how AI could accelerate scientific progress. With current capabilities, research output in some fields could as much as double, primarily from task-level augmentation. Researchers in our survey expect much greater capabilities to come. In a hypothetical scenario where AI fully automates all non-physical work, highly cognitive fields such as computer science or statistics could see up to a 15-fold increase in output. Because the fields with the largest potential for acceleration include those that produce AI itself, these gains could create an additional feedback loop, in which faster AI research produces more capable AI, which in turn could further accelerate research.
 While faster scientific discovery could bring substantial benefits to humanity, AI-driven research also carries risks and uncertainties. Less human oversight could lead to the pursuit of dangerous or unethical research. AI could also reshape researchers’ careers, making research work more or less rewarding, and alter the sense of purpose associated with the human pursuit of knowledge.
 How we conducted this research
 Our goal with this research is to measure the different ways scientists use Claude while protecting the details of their work. To do this, we use privacy-preserving infrastructure to analyze the scientific use of Claude on consumer plans. A language model, used here as a “classifier,” reads each session transcript and labels it with a fixed set of categories, such as the field and the research task it involves, according to a predefined taxonomy (SciNet taxonomy by Alamos and Althoff 2026). The resulting labels, such as “chemistry” or “data cleaning,” are the only information from these conversations retained and analyzed by the research team for this report. No classifier employed in this study extracts and stores open-ended information or details on research content, such as research datasets, hypotheses, experimental methods, early findings, or unpublished papers. Results are reported only in aggregate and only for cells that meet a minimum number of distinct accounts. All classifiers introduced in this study are listed in the Appendix .
 Our measurement involves two steps. A first classifier identifies whether a session transcript involves scientific work. A second classifier then assigns each of these transcripts to a field, subfield, and task in the SciNet taxonomy. SciNet contains 7,262 tasks, spanning 34 fields and 318 subfields. Some tasks in the taxonomy, such as drafting manuscripts, are universal to all fields. Others are specific to individual fields or subfields. For instance, in the taxonomy, the task of predicting optical absorption and emission spectra is specific to materials science. Together, the tasks cover the full process of producing a new research finding.
 Our main sample consists of 207,049 sessions on consumer plans from August 2 to September 30, 2026, which were assigned a scientific field and a research task: 128,914 from Chat and Cowork, two general-purpose interfaces for conversation and knowledge work, hereafter referred to as “Claude,” and 78,135 from Claude Code, an agentic coding tool that works directly with a user’s files, writing and running code. We also study a supplemental sample of Claude Science sessions. For details on sample construction, see the Appendix .
