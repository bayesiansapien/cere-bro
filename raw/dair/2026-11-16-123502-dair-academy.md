## Can LLM Agents Organize Their Own Memory?
- arXiv: 2611.11929 (https://arxiv.org/abs/2611.11929)
- DAIR page: https://academy.dair.ai/papers/can-llm-agents-organize-their-own-memory-2611.11929
- source: AI Papers of the Week | DAIR date: Nov 9 – Nov 15, 2026

DAIR curator's take and key points:

```text
Zichuan Fu, Junjia Qi and colleagues at City University of Hong Kong with Tencent Jarvis Lab introduce SoMem, in which an LLM agent organizes its own long-term memory as linked ordinary documents.
   Key points 01 Linked documents: The agent decides what to summarize, which topics to create, and when to revise them. Every summary stays linked to the original interactions, which are archived verbatim as evidence the agent can read but never edit.
 02 Runtime checks and views: A runtime validates each proposed edit before installing it, and then rebuilds timeline, relation graph, and recent-memory views from the organized content.
 03 Agent-controlled reading: At question time, the agent chooses what to search and read, follows links between documents, and inspects the original evidence when it needs to confirm an answer. SoMem beats the strongest baseline by 2.66 points on LoCoMo, 3.10 on BEAM-100K, and 2.00 on LongMemEval-S.
 04 Why it matters: Memory built by one model also works when read by another, and extra reasoning effort further improves answers. If your agent already reads and writes files, linked notes with source evidence are a simple design to try before adding a vector store.
 Abstract In most LLM agents, weights are fixed after deployment, so new information must be retained in external memory. Existing approaches often rely on predefined records and fixed organizational rules, which cannot readily accommodate evolving tasks and interactions. This raises the question: can LLM agents organize their own memory using ordinary documents? We introduce self-organized memory (SoMem), a framework that stores memory in linked documents. The agent decides what to summarize, how to group related information, and when to revise existing topics, and every summary it produces stays linked to the original interactions as evidence. The runtime validates updates and automatically derives temporal, relational, and recent-memory views from the organized content. At query time, the agent chooses what to search and read, following document links and inspecting original evidence as needed. On LoCoMo, BEAM-100K, and LongMemEval-S, SoMem outperforms the strongest baseline by 2.66, 3.10, and 2.00 percentage points, respectively. The constructed memory can be reused across models, and additional reasoning effort can further improve answer quality. These findings demonstrate the feasibility of agents organizing and using their own persistent memory through ordinary documents. Code is available at: https://github.com/Qi202/SoMem.
```

## No Second Run: Does RSI Stop at Frontier Pre-training?
- arXiv: 2611.10719 (https://arxiv.org/abs/2611.10719)
- DAIR page: https://academy.dair.ai/papers/no-second-run-does-rsi-stop-at-frontier-pre-training-2611.10719
- source: AI Papers of the Week | DAIR date: Nov 9 – Nov 15, 2026

DAIR curator's take and key points:

```text
The GAIR team at SII and Xinxu AI asks whether recursive self-improvement can reach frontier pre-training, where a run cannot be repeated and the goal is post-training headroom, and answers by training 801-30B-A3B in three months.
   Key points 01 Why the usual loop fails: A pre-training run costs hundreds of thousands of GPU-hours over months and cannot be repeated. Its real goal is headroom for post-training, which no single score shows, and what must improve is a whole production system of data pipelines, infrastructure, and teams.
 02 Smaller loops: The work splits RSI into loops that can close. Agents debug infrastructure and data, check post-training headroom with small SFT runs, and turn expert judgment into metrics for data pipelines. A shared context store keeps negative results so later proposals start from what earlier ones ruled out.
 03 Results: The run produced 801-30B-A3B-Base, a 30B MoE model trained on 11.8T tokens in three months by a newly formed team. As a base model it beats Qwen3-30B-A3B and Nemotron-3.5-Lightning-30B-A3B, trailing only the larger Qwen3.5-35B-A3B, and with 6B tokens of SFT and no RL it has the highest average on four agentic benchmarks against fully post-trained models.
 04 Why it matters: Post-training RSI assumes a strong base model, so bringing agents into pre-training improves the stage every later one builds on. The base model and the SFT data are open-sourced.
 Abstract Pre-training is where every foundation model begins; bringing recursive self-improvement (RSI) there would let AI improve the process that creates AI. Yet public RSI work has so far targeted only post-training, which starts from an existing base model, runs trials costing GPU-hours, and returns verifiable scores. Pre-training breaks all three conditions at orders-of-magnitude higher cost: a run consumes hundreds of thousands of GPU-hours over months and cannot be repeated; its objective, post-training headroom, cannot be read off any single score; and what must improve is not a model but the whole production system, from data pipelines and training infrastructure to the teams that run them. To our knowledge, we are the first to apply RSI to an entire frontier pre-training run from scratch and to report it in detail. RSI does not stop at frontier pre-training, but it changes form: since no end-to-end loop can close over a single unrepeatable run, we decompose it into smaller loops that can, each repairing a step the full run breaks. The result is 801-30B-A3B-Base, a 30B-A3B MoE trained from scratch on 11.8T tokens in three months by a newly formed team. We release it as a base model; the lightweight SFT reported here (6B tokens, no RL) only probes post-training headroom. As a base model, 801-30B-A3B outperforms Qwen3-30B-A3B and Nemotron-3.5-Lightning-30B-A3B, trailing only the larger Qwen3.5-35B-A3B, and keeps this position under identical SFT; with lightweight SFT alone, it achieves the highest average on four agentic benchmarks against fully post-trained models, including Qwen3.6-35B-A3B. Since post-training RSI presupposes a strong base model, bringing RSI into pre-training acts on the foundation every later stage builds on. We open-source 801-30B-A3B-Base and the lightweight SFT data at https://github.com/GAIR-NLP/801-30B .
```

## Don't Just Trust Your Memory: Evidence-Linked Memory Reduces Memory-Induced Degradation in LLM Agents
- arXiv: 2611.14320 (https://arxiv.org/abs/2611.14320)
- DAIR page: https://academy.dair.ai/papers/dont-just-trust-your-memory-evidence-linked-memory-reduces-memory-induced-degrad-2611.14320
- source: AI Papers of the Week | DAIR date: Nov 9 – Nov 15, 2026

DAIR curator's take and key points:

```text
Yukyeong Lee, Yumin Choi, Jinheon Baek and Sung Ju Hwang (KAIST, DeepAuto.ai) study memory-induced degradation, where an agent fails a task it would solve without memory, and build WikiTrace, a memory that links each lesson to the trajectory it came from.
   Key points 01 The cause: Lessons are inferred from runs labeled only as success or failure, then stored without the run itself. When a lesson is wrong, or the agent misreads a valid one, the agent has no way to verify it.
 02 Linked layers: A compiler turns each past run into a diagnosis of why it succeeded or failed and a set of short insights. Each insight links to that diagnosis and to the raw trajectory.
 03 Checking before acting: On a new task, the agent starts from all insights. When an insight lacks details, conflicts with another, or comes from a failed run, the agent follows its links with terminal tools to fill in or correct it before acting.
 04 Results: Across ALFWorld, ScienceWorld, PlanCraft, AppWorld, and τ³-bench Retail, WikiTrace scores 10.7 points above the agent without memory on average and 3.2 points above the same insights alone. The failure rate on previously solvable tasks drops from 6.5% to 4.5%, which shows the value of keeping evidence next to every stored lesson.
 Abstract External memory enables LLM agents to improve from experience by distilling trajectories of past tasks into concise lessons for new tasks. However, memory can also lead to memory-induced degradation, where an agent fails on tasks it would solve without memory, often because it follows a lesson that is incorrect, or misapplies or misreads a valid one. This is because lessons are inferred from trajectories labeled only with task success or failure, yet are typically provided without the trajectories they came from, leaving the agent no way to check them. To address this, we introduce WikiTrace, an evidence-linked memory system designed to let agents check each lesson against its original trajectory. Specifically, motivated by the finding that a trajectory often still holds the evidence needed to catch an erroneous lesson, WikiTrace stores each lesson as a concise insight linked to a summary of why its trajectory succeeded or failed and to the raw trajectory itself. Then, on a new task, the agent starts from all insights and, whenever one lacks details needed to act, conflicts with another, or comes from a failed task, descends through its links with terminal tools to fill in missing details or correct the insight before acting. We validate WikiTrace on five agentic benchmarks, showing that it consistently outperforms existing memory approaches and a baseline given the same insights alone, while also reducing memory-induced degradation. Our code is available at https://github.com/yukyeongleee/wikitrace
```

## LongCapHarness: Capability-Guided Auto-Harnessing for Long-Context Reasoning
- arXiv: 2611.10463 (https://arxiv.org/abs/2611.10463)
- DAIR page: https://academy.dair.ai/papers/longcapharness-capability-guided-auto-harnessing-for-long-context-reasoning-2611.10463
- source: AI Papers of the Week | DAIR date: Nov 9 – Nov 15, 2026

DAIR curator's take and key points:

```text
Tao Zhang and Yuhang He (Microsoft Research Asia) improve long-context reasoning by building a harness with recursive self-improvement instead of synthesizing data and post-training the model.
   Key points 01 Capability primitives: A harnessing agent studies the tasks in a development set and breaks each required capability into primitives. Reranking, for example, splits into relevance judgement and ordering with sequential control logic.
 02 Recursive self-improvement: The agent rewrites the primitive implementations, the state they track, and the control logic over many rounds on the development set. The finished harnesses are frozen and saved to a library that the model draws on at test time.
 03 Results: Llama3-8B gains 64.18 points on average across long-context benchmarks with no training. The harness built for Llama3-8B transfers to Qwen2.5-3B, and on HELMET and RULER it beats NExtLong and PolicyLong, which rely on data synthesis and training, at less than half their estimated cost.
 04 Why it matters: Before post-training a small model for long context, it is cheaper to try improving the harness around it. The harnesses are written by GPT-5.6-Sol, and the authors report a sharp drop when the small models build their own, so a strong harnessing agent is still required.
 Abstract Existing methods enhancing an LLM's long-context reasoning capability often rely on data synthesis and follow-up LLM post-training. However, the data synthesis strategy and the post-training recipes are empirically driven and computationally intensive. In this work, we propose a new framework, dubbed LongCapHarness, to instead harness the underlying capabilities for long-context reasoning. The harnessing process recursively revises and updates capability primitive implementation, capability state and control logic through recursive self-improvement on the development set. With neither data synthesis nor LLM post-training, LongCapHarness is applied to Llama3-8B and transferred to Qwen2.5-3B. LongCapHarness substantially outperforms recent data-synthesis-based baselines on HELMET and RULER benchmarks; its estimated development cost is less than 50% of the estimated training costs of NExtLong and PolicyLong. We hope these results motivate further research into harnessing the latent capabilities of LLMs to solve tasks beyond their explicit training.
```

## System Optimizations for Cost-Efficient Agent Harnesses
- arXiv: 2611.12122 (https://arxiv.org/abs/2611.12122)
- DAIR page: https://academy.dair.ai/papers/system-optimizations-for-cost-efficient-agent-harnesses-2611.12122
- source: AI Papers of the Week | DAIR date: Nov 9 – Nov 15, 2026

DAIR curator's take and key points:

```text
Jongseok Park, Ion Stoica, Alvin Cheung and colleagues at UC Berkeley study where agent harnesses spend tokens and build Agency, a platform that applies cost optimizations to existing harnesses such as Claude Code and Codex without changing the model.
   Key points 01 Where the cost goes: Reading existing context accounts for up to 73% of total cost even with caching. Tool calls add cost without adding tokens, agents use only 27% of tool outputs on average, and up to 89% of turns can go to searching the filesystem in retrieval-heavy tasks.
 02 Parallel subtasks: Agent traces contain 1.3 to 2.7 independent subtasks on average that could run concurrently, which reduces how much context each subtask has to share.
 03 Agency platform: Agency sits between off-the-shelf harnesses such as Claude Code and Codex and the model, and can monitor and modify context, tools, and the environment. An optimization written once works across harnesses and models, and five proof-of-concept techniques cut cost by up to 35% with marginal accuracy loss.
 04 Why it matters: The techniques are deterministic and do not require manual session resets or models trained to drop context. If an agent bill keeps growing, repeated context reads and extra tool calls are the first places to look before switching models.
 Abstract AI agent harnesses play the critical role of providing LLMs with an interface to a computing environment. Recent studies show that AI agents' task-execution accuracy depends mostly on the LLM used, while harness-side variances such as system prompts or tools have minimal impact. Rather, such harness-side variances show a larger impact on the cost of agent executions, achieving cost reductions up to 2.6 times on the same model and task. To further explore these harness-side cost optimization opportunities, we analyze the cost accumulation patterns across various agent traces and identify system opportunities to reduce token use and LLM calls without modifying the model or affecting task accuracy. Based on this analysis, we design Agency, a harness interposition platform that provides a unified abstraction and allows easy and portable implementation of harness-side system optimizations on existing off-the-shelf harnesses such as Claude Code or OpenAI Codex. Using Agency, we implement proof-of-concept optimization techniques based on our analysis and achieve cost reductions up to 35% across various real-world benchmarks on existing harnesses without compromising accuracy.
```
