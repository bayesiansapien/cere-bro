## GUARD: Stabilizing Recursive Self-Improvement with Regret Guidance
- arXiv: 2611.23476 (https://arxiv.org/abs/2611.23476)
- DAIR page: https://academy.dair.ai/papers/guard-stabilizing-recursive-self-improvement-with-regret-guidance-2611.23476
- source: AI Papers of the Week | DAIR date: Nov 16 – Nov 22, 2026

DAIR curator's take and key points:

```text
Minghe Zhang, Xuetao Kang, Chen-Yu Lee and colleagues at Google Cloud present GUARD, a grader-free loop that edits an agent harness (prompts, skills, tool rules, memory) from experience and only accepts an edit when its gains outweigh the regressions it causes.
   Key points 01 Self-checks before execution: Each task is split into self-checks before the agent runs it. Every round grades trajectories against these checks, pins rules the agent already handles, and ranks newly broken behaviors first.
 02 Gated edits: Parallel candidate edits compete on group-relative fitness, and a Soft-HURT gate accepts an edit only when its gains outweigh the behaviors it breaks. At test time, one frozen harness runs in a single pass.
 03 Results: On 43 hosted SDK tasks, GUARD reaches 80.80% accuracy, 8.89 points above the starting harness (p = 0.008). It beats Meta-Harness by 6.28 points with 54.5% fewer tokens per task. On procedural memory tasks it leads update correctness at 90.1% with zero memory pollution, while aggressive rewriters score similarly and triple pollution.
 04 Why it matters: Tracking regressions separately from unsolved tasks lets a self-improving harness keep what already works. The same gate also keeps the deployed harness small, which cuts token usage.
 Abstract Autonomous AI agents pair a frozen base model with an editable harness of prompts, skills, tool rules, and memory. Recursive self-improvement (RSI) adapts this harness from experience without weight updates, yet self-editing without external graders often backfires: reflection and scalar scores conflate what an edit newly broke with what remains unsolved, causing local regressions, skill forgetting, and memory bloat. We introduce GUARD (Grader-free Unsupervised Environment Design [UED] with Adaptive Rule Distillation), a closed-loop framework for reference-free continual harness evolution. Our key insight is to decompose each task into pre-execution self-checks and guide harness updates via directional regret. Each round grades trajectories against these checks, pinning mastered rules while prioritizing newly broken behaviors, and selects among parallel candidate edits by critic-free group-relative fitness. A Soft-HURT gate then promotes an edit only when gains outweigh regressions, scoping specialized fixes to prevent over-triggering and guaranteeing non-regression on its gated buffer. At test time, one frozen harness runs in a single pass. Across benchmarks on memory, skill evolution, continual task streams, and domain reasoning, GUARD consistently improves performance without catastrophic forgetting or memory pollution while substantially cutting deployment token usage.
```

## QDA: Closed-Loop LLM Quantization Design with Agents
- arXiv: 2611.23388 (https://arxiv.org/abs/2611.23388)
- DAIR page: https://academy.dair.ai/papers/qda-closed-loop-llm-quantization-design-with-agents-2611.23388
- source: AI Papers of the Week | DAIR date: Nov 16 – Nov 22, 2026

DAIR curator's take and key points:

```text
Xingyang Li, Tianlang Zhao, Song Han and Ligeng Zhu (MIT, NVIDIA) present QDA, a system in which an LLM agent designs the post-training quantization recipe for each model and precision.
   Key points 01 Fast evaluation. Scoring a quantized reasoning model normally takes tens of GPU-hours. QDA scores each candidate in minutes by its output KL divergence from the original model on reasoning traces the agent never sees, then checks promising candidates with long generations to catch repetition loops.
 02 Composable PTQ library. QDA ships public PTQ methods that work with each other and with new architectures, so the agent can combine them without hand-porting each codebase.
 03 Accuracy gains. Across four reasoning models, QDA beats the strongest public recipe by 0.9, 1.4 and 2.2 points on average at W4A16, W4A8 and W3A16, using 64 GPU-hours per search.
 04 Large MoE. On the 320B MoE GLM-5.3-Flash at NVFP4 W4A4, QDA recovers 98.3% of FP8 accuracy against 96.9% for the best vendor checkpoint, with no inference overhead on existing kernels.
 Abstract Post-training quantization is the standard way to serve large language models at low cost. However, the best quantization recipe differs across models and precisions. As a result, experts must redesign it for every new model, which is time-consuming and often sub-optimal. Fortunately, an LLM agent can take over this design by refining the recipe over rounds of building and evaluating candidates, so that more rounds lead to better recipes. However, evaluating one quantized reasoning model takes tens of GPU-hours, and combining methods from different codebases means porting each to the new architecture by hand. We present QDA, a system in which an agent designs the recipe for each model and precision. To make evaluation fast, QDA scores each candidate in minutes by its output KL divergence from the original model on reasoning traces that the agent never sees, and checks promising ones with long generations to catch failures such as repetition loops. To make building fast, QDA provides a library of public PTQ methods that are compatible with one another and with new model architectures. Across four reasoning models, QDA improves accuracy over the strongest public recipe by 0.9, 1.4 and 2.2 percentage points on average at W4A16, W4A8 and W3A16, using 64 GPU-hours per search. On the 320B-parameter MoE model GLM-5.3-Flash at NVFP4 W4A4, it recovers 98.3% of the FP8 model's accuracy, against 96.9% for the best vendor checkpoint. Every QDA checkpoint also runs on existing serving kernels with no inference overhead. We will release the library, the evaluator and the harness.

```text

We find that sufficiently capable models do self-improve under these conditions, demonstrating strategies that align with classic cognitive frameworks for self-regulated learning and constructs from machine learning literature on self-generated curricula. ## EfficientSkill: Learning Skills for Token-Efficient Multi-Turn Agents
- arXiv: 2611.19823 (https://arxiv.org/abs/2611.19823)

DAIR curator's take and key points:

```text
Deep Shah, Sanket Badhe and Nehal Kathrotia at Google, with Priyanka Tiwari at Purdue, introduce EfficientSkill, which first learns a skill for accuracy and then prunes it for token use under an accuracy guard, moving reusable code into workspace utilities that cost no prompt tokens.
   Key points 01 Phase 1, accuracy: Starting from a minimal seed, the optimizer repairs failed rollouts with no token penalty until the skill reaches a target accuracy.
 02 Phase 2, pruning: Warm-started from that skill, the optimizer compresses instructions, bounds agent turns, and moves reusable code into workspace utilities that cost no prompt tokens.  Abstract Reflective skill optimizers improve multi-turn LLM agents by revising instructions from failed and successful rollouts, yet accumulating edge-case rules bloats prompts, inflates token use, and pushes agents into long, error-prone loops. We introduce EfficientSkill, a two-step framework that first discovers a reliable skill without token penalties, and then warm-starts accuracy-guarded pruning from that skill to compress instructions, bound agent turns, and offload reusable code into workspace utilities with zero implementation prompt cost. Across four frontier, mid-tier, and open-weight models on MATH-500, ALFWorld, and SpreadsheetBench, EfficientSkill cuts output tokens over unconstrained EvoSkill on 11 of 12 configurations (by up to 80%) while raising mean accuracy on every benchmark, including +14.3 and +17.5 percentage-point gains on SpreadsheetBench with Gemini 3.8 Flash and Grok 4.1 Fast by replacing stalled loops with compact workflows. DAIR curator's take and key points:

```text
Researchers at Google Cloud AI and Google DeepMind, with Penn State, study what happens when a harness optimizer has to keep going after the benchmark or the policy model changes, and give the optimizer a memory of its own past edits, called Self-Improvement Memory (SIM).
   Key points 01 The transfer problem: An evolved harness can do worse than the plain seed when the model changes. In one workspace experiment, a harness evolved with Opus starts at 68.41 on Gemini, below the 73.89 of the seed harness.
 02 What SIM stores: Self-Improvement Memory groups past edits by the recurring harness problem they addressed.  Abstract Harness optimization is often studied with a fixed policy model and benchmark. We propose Self-Improvement Memory (SIM) for the harness optimizer, rather than the task-solving policy. SIM groups edits by recurring harness problem and records their rationale, predicted and observed outcomes, and evaluation context. New attempts extend this history as optimization continues. In our experiments across four domains, SIM achieves higher final scores than harness-only and root-cause-only continuation in cross-dataset and pairwise cross-model comparisons. ```text

## Budget Internalization: Fixed-Budget RLVR Trades Test-Time Scaling for In-Budget Accuracy
- arXiv: 2611.26172 (https://arxiv.org/abs/2611.26172)
- DAIR page: https://academy.dair.ai/papers/budget-internalization-fixed-budget-rlvr-trades-test-time-scaling-for-in-budget-2611.26172
- source: AI Papers of the Week | DAIR date: Nov 19, 2026

DAIR curator's take and key points:

```text
Ilia Zavidnyi and colleagues at JetBrains Research and Czech Technical University show that the fixed rollout cap used in RL with verifiable rewards becomes a learned constraint: trained models stop using extra tokens at test time and lose the accuracy gains of longer reasoning.
   Key points 01 The effect. Qwen3.5-4B trained with a 4k rollout cap gains 34.8 points on AIME at a 4k evaluation budget and loses 30.2 points against the base model at 64k, averaged over three seeds.
 02 Across models. Across six checkpoints from Qwen, Gemma and Nemotron, gains at the training cap range from 11.7 to 46.7 points, and deficits at the largest budget range from 17.2 to 35.0 points. The effect transfers from math training to science and coding.
 03 Ablations. Stronger KL regularization and less training-data truncation keep more test-time scaling, but stronger KL lowers in-budget accuracy. Forcing an answer on truncated rollouts removes the effect and most of the in-budget gain.

DAIR curator's take and key points:

```text

## Blind Spots Travel, Knowledge Stays Home: What RL Inherits from an LLM Judge
- arXiv: 2611.25191 (https://arxiv.org/abs/2611.25191)
- DAIR page: https://academy.dair.ai/papers/blind-spots-travel-knowledge-stays-home-what-rl-inherits-from-an-llm-judge-2611.25191
- source: AI Papers of the Week | DAIR date: Nov 18, 2026

DAIR curator's take and key points:

```text
Liang Yue and Eric A. Vance at the University of Colorado Boulder run 814 RL experiments that train 7-8B models to answer closed-book questions or abstain, to measure what a model actually learns from an LLM judge used as its reward.
   Key points 01 Knowledge does not transfer. A wrong answer the judge rewards is memorized for that one question only. Training with the answer key or a much stronger judge chooses which new questions to answer no better than sampling 32 answers and abstaining on disagreement. The judge's knowledge adds about one corrected answer per hundred questions.
 02 Biases do transfer. A judge that rejects eleven of twelve correct training answers about capitals of former states teaches the model to refuse 98% of such capitals on new questions. Accuracy and abstention rates do not show this loss.
 03 Twelve verdicts decide it. Changing only those twelve verdicts by hand moves the refusal rate from 5% to 90%. At answer-key leniency, two of four judges already cost 38-42% of these capitals. With "I don't know" blocked, the model answers 94% of them correctly.
 04 A judge is unnecessary. Rewarding the answer most of the model's own untrained samples agree on, with no labels and no judge, earns the answer key's reward and keeps the category.
 Abstract LLM judges serve as rewards where no answer key exists, in the hope that their knowledge passes to the trained model. In 814 RL runs that teach 7-8B models to answer closed-book questions or abstain, we ask what passes. What a grader knows about single answers stays home. A wrong answer that a judge rewards is memorised for that one question. A model trained with the answer key, or with a far stronger judge, chooses which new questions to answer no better than the untrained model does by sampling 32 answers and abstaining where they disagree; the grader's knowledge adds about one corrected answer per hundred questions. What a grader believes about a kind of question travels. A judge that rejects eleven of the twelve correct training answers about capitals of former states teaches the model to refuse 98% of such capitals on new questions, a loss that accuracy and abstention rates do not reveal. Changing only those twelve verdicts by hand moves the refusal from 5% to 90%, even for a grader that accepts as many answers as the answer key; at that leniency, two of four judges already cost 38-42% of these capitals. The capitals are not forgotten: with "I don't know" blocked, the model answers 94% of them correctly. The grader therefore needs no knowledge of its own: rewarding the model for giving the answer that most of its own untrained samples agree on, with no labels and no judge, earns the answer key's reward and keeps the category.

 03 It repairs a damaged copy. Given a corrupted copy of itself, it finds the damaged matrix and rewrites it without reading the undamaged weights. Working only from text math problems, the repair lifts six image benchmarks from 7% to 70%, 83% of the undamaged model.
 04 Only at scale. Across four sizes of one family, the 2B model makes no edit and the 4B and 9B models break themselves. The 27B model compares hidden states on answers that finish against answers that run out of tokens, and weakens the direction that separates them.
 Abstract Language models are trained once, frozen and deployed: improving one again takes another training run, and a prompt, a scaffold or extra computation at inference is gone once the task ends. A frontier model has been shown to edit the weights of a much smaller one. We ask whether a model can rewrite its own weights to make itself better, and find that it can, by its own reasoning, with no gradients and no training; we call this self-rewriting. Given its weights, graded answers and the ability to run itself, a 27B model diagnoses its failure and edits the weights behind it. It surpasses itself: its own edit makes it 6.6 points more accurate on 490 problems it never saw, in a test fixed in advance, and another session's edit also makes it significantly better. It keeps getting better: it submits an edit only when its own tests support it, each edit replacing the last, and over its first eight such sessions its accuracy only rises. Unlike test-time scaling, the gain persists in its weights and adds no cost per answer; unlike training, it needs no pre- or post-training infrastructure, only an open model and hours on one GPU. It repairs a damaged copy of itself: it locates the corrupted matrix and rewrites it with values of its own, never reading the undamaged weights; found on text math problems alone, the repair lifts the copy on six image benchmarks it never saw from 7% to 70% accuracy, 83% of the undamaged model's. And the ability emerges with scale: across four sizes of one family, the 2B model makes no edit and the 4B and 9B models break themselves; only the 27B model works on itself as a human would, comparing its hidden states on answers that finish and on answers that run out of tokens, weakening the direction that separates them. Like a human, a model need not separate training from inference; improving a language model may come to take a conversation rather than a training run.

## CrossEnv: Synthesizing Verifiable Cross-Environment Tasks for Long-Horizon Agent Training
- arXiv: 2611.22777 (https://arxiv.org/abs/2611.22777)
- DAIR page: https://academy.dair.ai/papers/crossenv-synthesizing-verifiable-cross-environment-tasks-for-long-horizon-agent-2611.22777
- source: AI Papers of the Week | DAIR date: Nov 17, 2026

DAIR curator's take and key points:

```text
Zhengfeng Yu and colleagues at Beijing Institute of Technology and Alibaba Group synthesize executable, verifiable training tasks that span several environments, such as flight, hotel and restaurant services, and train agents with a curriculum that moves from single-environment tool use to multi-environment coordination.
   Key points 01 Entity-tool graph. Environments are linked through shared entities, and task data is aligned so that, for example, a hotel has the same address in the booking and navigation environments. Without this, cross-environment tasks cannot be executed or verified.
 02 Curriculum. Training starts with tool use inside one environment, then adds more environments and business domains, and introduces user interaction last.
 03 Coordination gains. On Qwen3-8B, cross-environment RL beats single-environment RL from the same SFT start on output reuse (11.7% vs 1.7%), later-step success (33.3% vs 28.3%) and joint success (8.3% vs 0.0%), and scores 20.0 vs 15.4 on Claw-Eval.
 04 Fewer examples. Across four external benchmarks the approach is competitive with environment-trained baselines that use far more data, and construction cost falls to about 4.0k tokens per candidate task.
 Abstract Executable synthetic environments provide scalable training tasks and verifiable feedback for long-horizon agents. Existing environment synthesis methods primarily generate tasks within individual environments. However, these tasks do not adequately capture real-world interactions across services, where actions in one service depend on information obtained from another. Synthesizing such tasks is challenging because data generated across environments must remain consistent to support executable and verifiable interactions. To address this challenge, we introduce CrossEnv, a framework that uses an entity-tool graph to identify connections between environments and aligns task-specific data to synthesize executable, verifiable cross-environment tasks. We further propose CrossEnv-Curriculum, which progresses from single-environment tool use to coordination across more environments and business domains, before introducing user interaction. Across four external benchmarks, combining cross-environment training data with this curriculum achieves competitive performance with fewer training examples. Further analyses support the benefits of cross-environment data and curriculum training, and provide evidence of transfer to new environment combinations, external tasks less similar to the training data, and longer workflows.

## Higher-Scoring Coding Models Did Not Get More Work Done
- arXiv: 2611.23216 (https://arxiv.org/abs/2611.23216)
- DAIR page: https://academy.dair.ai/papers/higher-scoring-coding-models-did-not-get-more-work-done-2611.23216
- source: AI Papers of the Week | DAIR date: Nov 17, 2026

DAIR curator's take and key points:

```text
Yining Hua (Harvard University) uses a 19-day loss of access to Claude Fable 5 in June 2026 as a natural experiment to test whether a model that scores higher on coding benchmarks gets more real work merged on GitHub.
   Key points 01 Natural experiment. A June 12, 2026 export-control directive cut access to Fable 5 for 19 days. Most users switched to Opus 4.8, which scores 11 points lower on SWE-Bench Pro, while the people and projects stayed the same.
 02 Design. The study tracks pull requests of 297 Fable 5 users before, during and after the suspension, against 8,908 developers who stayed on Opus 4.8, using difference-in-differences with developer and date fixed effects.
 03 No significant gain. Fable 5 access raised the 7-day merge rate by 1.4 points [-1.4, +4.3], not significant. Pull requests merged per week rose 2.4% [-4.9%, +10.2%], also not significant.
 04 Upgrades show the same. Across five model upgrades (1,208 developers, 15,442 pull requests), the weighted mean change in merge rate is -0.9 points [-1.9, +0.2]. All five estimates are negative and all intervals include zero.
 Abstract New coding models advertise themselves on score improvements of coding benchmarks. Yet no study has tested if a model that scores higher on these benchmarks gets more real work done. On June 12, 2026, a U.S. export control directive banned access to Claude Fable 5 for 19 days, which forced users to switch to other models. During this time, most former Fable 5 users switched to Opus 4.8 (11 points lower on SWE-Bench Pro compared to Fable 5). We treat this suspension as a natural experiment, where the people and projects stayed the same and only the model changed, so we could isolate the effect of Fable 5 on user productivity. We tracked GitHub pull requests of 297 Fable 5 users before, during, and after the suspension. We used 8,908 developers who stayed on Opus 4.8 all the time as the control group. We also repeated the comparison across five model upgrades before and after the suspension in 2026 (1,208 developers, 15,442 pull requests). Fitting a difference-in-differences model with developer and date fixed effects, we found that having access to Fable 5 increased the 7-day merge rate of pull requests by only 1.4 percentage points [-1.4; +4.3], which was not statistically significant. Similarly, no significant increases of merge rates were found with the upgrades (weighted mean: -0.9 percentage points [-1.9; +0.2]); all five estimates were negative (95% intervals included 0, did not differ from each other). We also did not observe a significant increase in the number of pull requests merged per week (+2.4% [-4.9%; +10.2%]).
